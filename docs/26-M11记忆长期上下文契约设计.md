## 2. 领域模型

### 2.1 MemoryItem

统一记忆条目（fact / preference 以 `kind` 区分，不建两张表）。进程内为 dict、PG 为一行，字段一致。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 记忆 id；进程内 `mem-N`（租户级单调计数，reset 归零），PG 取 `storage_id_seq` → `mem-N`（同其他资源 id 字符串口径） |
| `kind` | `"fact"` \| `"preference"` | 事实 / 用户偏好；必填 |
| `content` | str | 记忆文本，1–2000 字；必填；remember 时据此算 embedding |
| `scope` | dict[str, str] | 业务绑定 / 作用域，缺省 `{}`；如 `{"user_id":"u-1","order_id":"o-1"}`；recall 时做**子集匹配**过滤 |
| `confidence` | float | 0–1，缺省 `1.0`（显式工具写入置信度满值；自动提取的 <1 场景随非目标缓做） |
| `source` | `"tool"` \| `"manual"` \| `"run"` | 来源，缺省 `"tool"`；图工具通道写 tool/run，REST 手动新建/编辑（docs/28 批 4⑩）固定 `"manual"` |
| `metadata` | dict | 附加结构化信息，缺省 `{}`，落 JSONB（PG 列名 `meta`，避开 SQL/保留字歧义） |
| `embedding` | list[float] | `content` 的向量，**内部字段、不进 API 响应**；维度 = `EMBED_DIM`（256） |
| `created_at` | str | UTC ISO-8601 字符串（同全仓时间口径） |

约定（同 docs/24 §1.2）：租户分区是**构造期关切**，`tenant_id` 由工厂注入、不进 Repository 方法签名、不进对外资源 JSON（PG 表带 `tenant_id` 列做语句级过滤）；id 由 store 内部生成；无 `updated_at`（批 4⑩ 允许白名单字段原地更新，但 created_at 不变、不保留字段级修改历史/审计，历史与审计随 D35；其余仍只追加/删）。

资源字段对外用 **snake_case**（`created_at` 等），与 feedback、demo messages、monitoring 等进程内沙盘资源同口径（这些内部资源未做 camel 映射）。

### 2.2 包落位（消歧义，须显式记录）

现有顶层包 `src/atlas/memory/` 目前只有 `database.py` / `settings.py`，语义是**平台 PG 连接层**（被 `storage/pg.py` 复用），与五层记忆的"memory"同名。**决策：扩用 `memory/` 包承载长期记忆领域，不新建顶层包**，文件分工：

- `memory/database.py`、`memory/settings.py`：**保持** PG 连接基础设施（历史命名，不动）。
- `memory/models.py`（新）：`MemoryKind` 字面量、`MemoryItem` pydantic 模型、入参校验（content 长度、confidence 区间、kind 枚举）。
- `memory/embeddings.py`（新）：`EmbeddingProvider` Protocol、`LocalDeterministicEmbedder`、`cosine_similarity`、`get_embedding_provider()` 工厂、`EMBED_DIM`。
- `memory/items.py`（新）：进程内 `MemoryStore`（实现 `MemoryRepository`）。
- `memory/adapter.py`（新）：`MemoryHarnessAdapter`（两能力）。

`storage/base.py` 加 `MemoryRepository` Protocol；`storage/memory.py` re-export `MemoryStore` 聚合（同 RecordingStore/MonitoringStore 先例）；`storage/pg.py` 加 `PgMemoryStore` + `PgBackend.memory_store(tenant_id)` 工厂。

## 3. Embedding 抽象与本地确定性实现

### 3.1 接口（`memory/embeddings.py`）

```python
EMBED_DIM = 256  # 与迁移 006 的 vector(256) 严格一致；改维度须另立迁移

class EmbeddingProvider(Protocol):
    dim: int
    def embed(self, texts: list[str]) -> list[list[float]]: ...

def cosine_similarity(a: list[float], b: list[float]) -> float: ...
def get_embedding_provider() -> EmbeddingProvider: ...   # v1 恒返回 LocalDeterministicEmbedder
```

形态对齐 `llm/decision.py` 的 `DecisionClient`（Protocol）+ `RuleBasedDecisionClient`（确定性默认/离线/黄金测试）+ `LiteLLMDecisionClient`（可选、函数内 import、无 key 不启用）。

### 3.2 LocalDeterministicEmbedder（纯 stdlib，默认）

- **分词**：英文/数字按正则 `[a-z0-9]+` 小写切词；中文按**单字 unigram + 相邻 bigram** 切（bigram 提中文召回）；纯 stdlib（`re`/`hashlib`/`math`），**不引 numpy**。
- **向量化（signed hashing trick）**：每个 token 用 `hashlib`（md5）哈希到 `dim` 个桶，再用哈希奇偶决定符号 `±1`（抵消碰撞偏置），按词频累加。
- **归一化**：L2 归一化为单位向量；空文本归一化为零向量（cosine 定义为 0.0）。
- **确定性**：无随机、无外部调用、无时钟依赖，同文本永远同向量——满足录制回放（D26）与黄金用例的确定性硬约束。
- **相似度**：`cosine_similarity` 为归一化向量点积，范围 [-1,1]。共享 token 时非负；**两段文本无共享 token 时因哈希碰撞可能出现小负值（实测 |c|<0.2，见顶部落码注记 1）**，recall 默认 `min_score=0` 过滤。

**明确局限（沙盘语义，须在文档与 UI 注明）**：这是**词法 / 哈希级**相似度（共享词命中即相似），**不是真语义**——同义词、跨语言、纯语义改写不召回。它用于验证记忆的写入/索引/检索/两档持久化机制与接缝；真实语义质量随商业 embedding provider 解锁（D35）。

### 3.3 商业 provider 接缝（缓做）

`get_embedding_provider()` 预留 env 切换位（拟 `ATLAS_EMBEDDING_PROVIDER`，缺省 `local`）。未来 `LiteLLMEmbeddingProvider` 只需实现 Protocol（函数内 `import litellm`、无 key fail-closed 回退 local 或显式报错，落码时定）；**v1 不实现该类体、不注册非 local 分支**，避免死代码。接入触发条件见 D35。**维度一致性约束**：商业 provider 维度通常 ≠256，接入时要么投影到 256，要么走向量重建/双写迁移，且两档必须同 provider 才能对拍。

## 4. 存储契约（MemoryRepository 两档）

### 4.1 Protocol（`storage/base.py`，第九个 Repository）

```python
@runtime_checkable
class MemoryRepository(Protocol):
    def remember(
        self, *,
        kind: str,                       # "fact" | "preference"
        content: str,
        scope: dict[str, str] | None = None,
        confidence: float = 1.0,
        source: str = "tool",
        metadata: dict[str, Any] | None = None,
    ) -> dict[str, Any]: ...             # 返回不含 embedding 的 MemoryItem dict

    def recall(
        self, query: str, *,
        kind: str | None = None,
        scope: dict[str, str] | None = None,   # 子集匹配：item.scope 须包含其全部键值
        top_k: int = 5,
        min_score: float = 0.0,
    ) -> list[dict[str, Any]]: ...       # 每项 = MemoryItem dict + "score": float，按 score 降序

    def list(self, *, kind: str | None = None, limit: int = 50) -> list[dict[str, Any]]: ...
    def delete(self, memory_id: str) -> bool: ...   # 不存在返回 False（跨租户同不存在）
    def clear(self) -> None: ...                    # reset 用，resettable 档
```

- 归 **RESET_RESETTABLE**（与 graph 同；记忆是演示运行数据，`reset_tenant` 清空）。
- 入参校验（kind 枚举、content 1–2000、confidence 0–1、top_k 1–20）在 models 层统一做，两档共享；非法参数据返 `StorageError` 或在适配器层折 `ActionResult.failed`（落码时与现有错误风格对齐，见 §5.3）。

### 4.2 进程内实现（`memory/items.py` MemoryStore）

- per-tenant 实例（由 TenantRegistry 装配，同其他 store）；持 `list[dict]` + `threading.Lock` + 租户级 `mem-N` 计数器。
- `remember`：经注入的 `EmbeddingProvider` 算向量后存入（embedding 随条目存内存）。
- `recall`：算 query 向量 → 按 kind / scope 子集过滤 → cosine 排序 → 截 top_k → 过滤 min_score。
- `list` 倒序（新→旧）；`delete` 按 id（实例天然只含本租户）；`clear` 清空并归零计数。

### 4.3 PG / pgvector 实现（`storage/pg.py` PgMemoryStore）

- `PgBackend.memory_store(tenant_id)` 工厂产出 `PgMemoryStore(engine, tenant_id, provider=get_embedding_provider())`。
- **embedding 由 Python 端 LocalDeterministicEmbedder 计算后写入 vector 列**（两档同一 provider、同一 dim，保证对拍一致；pgvector 只负责存与余弦距离运算）。
- 沿用全文件 `sqlalchemy.text()` 裸 SQL 风格（不引 pgvector.sqlalchemy ORM 类型）：
  - 写入：向量以字面 `'[v1,v2,...]'` 参数 + `::vector(256)` 强转；JSON 字段落 JSONB（同 graphs.definition 等）。
  - 检索：`ORDER BY embedding <=> :q::vector(256)`（余弦距离），`score = 1.0 - distance`；kind/scope 过滤后取 `LIMIT :top_k`，再在 Python 侧过 `min_score`（或 SQL 内 `1 - (embedding <=> :q) >= :min_score`，落码择优并对拍）。
  - scope 子集匹配：PG 侧用 `scope @> :scope::jsonb`（左包含右）；进程内侧用 dict 子集判定，二者语义一致。
  - id 用 `_next_id(conn, "mem")`（`storage_id_seq`，同其他 PG 资源）；行内 `tenant_id` 过滤、不用 RLS。
- 迁移：`db/migrations/006_memory.sql`（§4.4），由现有迁移拾取机制（集成测试按序号 glob、生产手动执行）加载。

### 4.4 迁移 `db/migrations/006_memory.sql`

> **落码以 `db/migrations/006_memory.sql` 实际文件为准（2026-09-19）**，与下方草稿三处细化：① `created_at` 用 **TEXT** 存 Python UTC ISO 字符串（非 `timestamptz DEFAULT now()`），对齐 002、两档形状一致；② 索引命名对齐 002 的 `idx_` 前缀，实际为 `idx_memory_items_tenant_kind`、`idx_memory_items_embedding`（草稿后缀式 `_idx` 弃用）；③ 读写强转在 SQLAlchemy `text()` 中用 `CAST(:p AS vector(256))`/`CAST(:p AS jsonb)`（非 `:p::type`）。ivfflat 空表建索引在 pgvector/pgvector:pg16 实测成功，未降级。

```sql
-- M11 长期记忆（docs/26 §2/§4）；vector 维度必须与 memory/embeddings.EMBED_DIM=256 一致
CREATE TABLE IF NOT EXISTS memory_items (
    id          text NOT NULL,
    tenant_id   text NOT NULL,
    kind        text NOT NULL CHECK (kind IN ('fact', 'preference')),
    content     text NOT NULL,
    scope       jsonb NOT NULL DEFAULT '{}'::jsonb,
    embedding   vector(256) NOT NULL,
    confidence  double precision NOT NULL DEFAULT 1.0,
    source      text NOT NULL DEFAULT 'tool',
    meta        jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (id, tenant_id)
);

CREATE INDEX IF NOT EXISTS memory_items_tenant_kind_idx
    ON memory_items (tenant_id, kind);

-- 余弦 ANN 索引（小表规划器可能顺序扫描、结果等价；若空表建 ivfflat 在目标
-- pgvector 版本报错，集成实测时降级为暂不建 ANN 索引，精确余弦已够沙盘数据量）
CREATE INDEX IF NOT EXISTS memory_items_embedding_idx
    ON memory_items USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

## 5. Harness 适配器（图接入，零新节点 / 零 DSL 改动）

### 5.1 身份与装配

- `adapter_id = "memory"`、`adapter_type = "memory"`（同 message 用领域名作 type 的先例）。
- 构造：`MemoryHarnessAdapter(repo: MemoryRepository, *, granted_permissions=None, audit_sink=None)`，对齐 `MessageHarnessAdapter(service=...)`；`observe()` 返空 `Observation()`（无外部页面，同进程内适配器）。
- 装配（`api/main.py`，照 message 两段式）：
  - 全局 `_demo_registry.register(MemoryHarnessAdapter(granted_permissions=_FULL_PERMISSIONS))`——**仅供 `/api/adapters` 发现**（repo 缺省，执行期不直接用）。
  - `_runtime_registry(services)` 中把 id=="memory" 替换为 `MemoryHarnessAdapter(repo=services.memory_store, granted_permissions=_FULL_PERMISSIONS)`，与 message 同一克隆注入点。
- `TenantServices` 增 `memory_store: MemoryRepository`；`TenantRegistry._create_services` 两档构造（memory 档 `MemoryStore()`、pg 档 `backend.memory_store(tenant_id)`）；`reset_tenant` 增 `services.memory_store.clear()`。

### 5.2 两个能力（input/output schema 守 Capability 白名单）

> schema 只能用 `harness/base.py _ALLOWED_SCHEMA_KEYWORDS` 子集（type/properties/required/items/enum/minimum/maximum/minLength/maxLength/minItems/maxItems/additionalProperties/description/default 等，**无 x- 扩展 keyword**）。

**能力 A：remember（写）**

- `name="remember"`、`action="memory_remember"`、`permission=Permission.WRITE`、`is_idempotent=False`。
- input_schema：

```json
{
  "type": "object",
  "required": ["kind", "content"],
  "properties": {
    "kind":     {"type": "string", "enum": ["fact", "preference"], "description": "记忆类型：事实 fact / 用户偏好 preference"},
    "content":  {"type": "string", "minLength": 1, "maxLength": 2000, "description": "要记住的内容（支持 {{变量}} 插值）"},
    "scope":    {"type": "object", "additionalProperties": {"type": "string"}, "description": "业务绑定，如 {user_id, order_id}"},
    "confidence": {"type": "number", "minimum": 0, "maximum": 1, "description": "置信度，缺省 1.0"},
    "metadata": {"type": "object", "additionalProperties": {"type": "string"}, "description": "附加信息（可选）"}
  }
}
```

- output_schema：`{type:object, properties:{ id, kind, content, confidence, source, created_at:{type:string} ... }}`（不返回 embedding/scope 可返回）。
- 行为：调 `repo.remember(...)`，成功 `ActionResult.success(item)`；校验失败/存储异常折 `ActionResult.failed(StructuredError(code,msg))`（错误码见 5.3）。

**能力 B：recall（语义检索，读，幂等）**

- `name="recall"`、`action="memory_recall"`、`permission=Permission.READ`、`is_idempotent=True`。
- input_schema：

```json
{
  "type": "object",
  "required": ["query"],
  "properties": {
    "query":    {"type": "string", "minLength": 1, "maxLength": 2000, "description": "检索语义的自然语言/关键词（支持 {{变量}} 插值）"},
    "kind":     {"type": "string", "enum": ["fact", "preference"]},
    "scope":    {"type": "object", "additionalProperties": {"type": "string"}, "description": "仅在该作用域内检索（子集匹配）"},
    "top_k":    {"type": "integer", "minimum": 1, "maximum": 20, "default": 5},
    "min_score": {"type": "number", "minimum": 0, "maximum": 1, "default": 0.0}
  }
}
```

- output_schema：

```json
{
  "type": "object",
  "properties": {
    "results": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "id": {"type": "string"},
          "kind": {"type": "string", "enum": ["fact", "preference"]},
          "content": {"type": "string"},
          "score": {"type": "number"},
          "confidence": {"type": "number"},
          "scope": {"type": "object", "additionalProperties": {"type": "string"}},
          "created_at": {"type": "string"}
        }
      }
    }
  }
}
```

- 行为：调 `repo.recall(...)`，返 `{"results": [...]}`；无命中返 `{"results": []}`（成功，不报错）。
- 工具 params 表单由 M3 FormRenderer 按上述 input_schema 自动生成；`content`/`query` 的 `{{变量}}` 插入与 M2 变量补全零额外开发。

### 5.3 错误与权限

- remember 需 WRITE、recall 需 READ；能力门由 HarnessAdapter 模板方法统一处理（不足返 `PERMISSION_DENIED`，审计照现有）。
- 业务错误码建议：`MEMORY_INVALID_INPUT`（kind/content/confidence/top_k 非法）、`MEMORY_NOT_FOUND`（delete 目标不存在，仅 REST 用）；存储故障折 `STORAGE_ERROR`（沿用 storage 层 `StorageError`）。落码时与 message 的 `MessageSendError` 折 `ActionResult.failed` 风格一致。

## 6. REST 契约（docs/12 §5）

按租户（principal.tenant_id）隔离。初版写入只走图工具、REST 仅读 + 删；**docs/28 批 4⑩（`ec0fd81`）起补 `POST/PUT`（operate，source 固定 manual）承担手动新建/编辑**——图工具仍是运行时自动写入的唯一通道，REST 不参与自动记忆。

| 方法/路径 | 角色 | 说明 |
|---|---|---|
| `GET /api/memories?kind=&limit=` | read（viewer+） | 当前租户记忆倒序列表（不含 embedding）；kind 可选过滤，limit 默认 50、上限 200 |
| `GET /api/memories/search?q=&kind=&top_k=&min_score=` | read（viewer+） | 语义检索，返 `{"results":[{...记忆字段, score}]}`；`q` 空 / 空白返 422 |
| `DELETE /api/memories/{memory_id}` | **admin** | 删除一条（隐私 / 管理动作，对齐 T15 admin 管 reset 的保守口径）；不存在或跨租户一律 **404**（不泄漏存在性，同 T15） |
| `POST /api/memories` | **operate**（docs/28 批 4⑩ `ec0fd81`） | 手动新建，body `{kind, content, scope?, confidence?, metadata?}`；**source 固定 manual、不接受入参**（extra=forbid，传 source/id → 422），201 返条目，校验失败 422 中文 |
| `PUT /api/memories/{memory_id}` | **operate**（批 4⑩） | 编辑白名单字段任意子集（空体 422）；source 归 manual、content 变才重算 embedding、id/created_at 不变；不存在/他租户 404、校验失败 422 |

- 跨租户访问 404、角色不足 403、未登录 401（T15 既有口径）。
- **docs/28 批 4⑩ 已补 `POST/PUT /api/memories`（operate；source 固定 manual、白名单字段、extra forbid、空体 PUT 422、不存在/他租户 404，U192–U201）**：运行时自动写入仍只走图工具（自动写入路径不变），REST 仅手动补录/纠错；批量造数仍可走 `scripts/dev/m11_seed.py`。
- docs/12 §4 原写 `GET/PUT /api/memories/{operator_id}`：现架构按 **tenant** 而非 operator 分区，本契约定为按租户的 `/api/memories`，operator / 用户维度降为 `scope.user_id` 过滤项；**以此为准订正 docs/12**。
