## 1. 基线实测（为什么这不算"已经做了"）

〔码〕逐条对当前 HEAD 实核，不是引旧文档：

1. **入站消费协议面缺失**：`message/webhook.py:15` 自写「v1 不做限流队列、入站消费、IM/短信」，入站现只有 Shopify 专用签名面（`channels/webhooks.py`，`shopify_webhook_ingress`）。通用入站接收/验签/去重/起 run 的链路不存在。
2. **去重与 DLQ 已有现成范式**：`channels/deliveries.py` 的 `DeliveryRecord`/`InMemoryDeliveryStore` 已实现 `note_duplicate_if_seen`/`record_received`/`record_dead`/`list_dead`/`resolve_replay`/`delete`/`metrics`，`pg_deliveries.py` 已有 PG 同形。但它是 webhook 专属字段（`webhook_id`/`binding_id`/`shop`）——BO 要**复用范式、不另造一套**。
3. **触发器类型已有 `schedule`/`cron`/`webhook`**（`dsl.py` `validate_node_config` 的 `triggerType` 白名单）；新增 `message_inbound` 是同族扩展，编译期校验照搬 webhook 的形状（无额外必填）。
4. **外部触发起 run 的范式已成熟**：`shopify_webhook_ingress` → `_webhook_deliverer.deliver` → `_webhook_trigger` → `_BACKGROUND_WORKER_POOL.submit(run_graph)`（`main.py:1339-1443`）。BO 的 `message_inbound` 触发器走同一"后台线程独立 run、失败落 failed 不回传触发方"路径。
5. **run 记录已预留扩展位**：`RunStore.begin` 刚被 BN 加了 `cycle_seq`/`cycle_group_id` 形参（`storage/base.py:153`）；再加 `agent_id` 是同形扩展。`runs` 表（迁移 002）无 agent 维度，agent 归因无从谈起。
6. **智能体底层件已有**：`skills/skill.py` 有 `Skill`/`Bot`/`CoordinatorConfig`（M7），`coordination/envelope.py` 有任务信封——但 run/节点**没有 agent 身份维度**，无法按智能体归因运行与成本。D74 把 `Bot` 升格为"可见、可管理的 agent 实体"。
7. **单副本硬约束（docs/62）继续有效**：入站端点只认领一次（仿 webhook 的 at-most-once），不解锁多副本。

## 2. 决策（落码不得偏离；改任何一条先改本文）

- **D-D1 入站入口＝新增 `POST /api/channels/inbound/{binding_id}`**（公开，独立签名校验，类比 `shopify_webhook_ingress`）。**可插拔 verify 钩子**：假供应商用固定/预共享 secret 或 passthrough；真钉钉/企微/飞书 verify 留 ⛔（D24），本批不实现。
- **D-D2 去重与死信复用 `channels/deliveries.py` 范式**：新增轻量 `inbound_deliveries.py`（同形 `InMemoryInboundStore` + `PgInboundStore`，复用 `DeliveryRecord` 形状），幂等键＝`(tenant, channel, message_id)`；重复 ⇒ `note_duplicate_if_seen`（不二次起 run）；触发失败 ⇒ `record_dead` + DLQ 列表/重放/删除/指标端点（仿 webhook 那套）。**不重新发明算法、不污染现有 webhook deliveries**。
- **D-D3 会话↔图映射挂渠道 binding**（D-P1 拍板，不做独立实体）：binding 上加 `inbound_mappings: [{conversationId, graphId, agentId?, enabled}]`；命中 ⇒ 起 run（`mode="message_inbound"`，`inputs` 含 `event`＋`conversationId`）；未命中 ⇒ 死信（不静默吞）。第三个需要独立注册表的领域出现前不进 SchemaRegistry 第八类。
- **D-D4 触发器类型 `message_inbound`**（`dsl.py`）：`triggerType="message_inbound"`，编译期校验与 webhook 同族（无额外必填）；图从 trigger 节点 BFS 起 run（复用既有 trigger 机制，04 补充项 1 不可达检测照旧）。
- **D-D5 多轮上下文**（D-P2 拍板）：**不做摘要**，只透传 `conversationId` 进 `inputs`/`globals`；跨轮状态靠 C 的 Loop（有 loop 配置则入站触发的 run 自动进入循环），无 loop 则每消息一次图。摘要留 D35（避免半实现）。
- **D-D6 agent 维度**：`runs` 表加 `agent_id`（迁移 051，或复用 BN 050 思路——给 `begin` 加 `agent_id=""` 形参，缺省逐字等价现状）；`/api/agents` CRUD（`admin` 建/`operate` 启停/改）＋ `Agents.tsx`（每个 agent 的执行日记／Token／决策明细）；agent 底层件复用 `skills/Bot`（D74「八大智能体只有底层件」——本批把 `Bot` 升格为可管理实体）。
- **D-D7 输出回原会话**：run 的 `outputs` 经绑定配置的回写通道；**本批假供应商 ⇒ 落进程内会话记录 + 前端会话视图可查**，真回写（IM/短信/卡片）留 D24。不静默丢弃（死信或明确 404）。
- **D-D8 零新错误码／零新依赖／无 ADR**（沿用 T24 谱系）；不解锁多副本（docs/62）。

## 3. 契约形状

### 3.1 `channels/inbound.py`（新增，纯新增）

- `InboundReceiver`：`receive(binding_id, raw, headers)` → 跨租户定位 binding → 验签（verify 钩子）→ 去重（`inbound_deliveries.note_duplicate_if_seen`）→ 映射命中（`binding.inbound_mappings`）→ 起 run（后台线程，仿 `_webhook_trigger`）→ 回写（落会话记录）。
- `InboundMapping` 数据类：`{conversationId, graphId, agentId?, enabled}`。
- 幂等/DLQ 复用 D-D2 的 `inbound_deliveries` store。

### 3.2 `GraphDSL` 触发器 `message_inbound`（`dsl.py` 扩展）

```
triggerType: "message_inbound"   # 新增枚举值；编译期白名单校验（与 webhook 同族）
# 无额外必填；inputs 由入站消息注入（event + conversationId）
```

编译期：`triggerType` 白名单加 `"message_inbound"`；trigger 节点 BFS/不可达检测照旧（04 补充项 1）。

### 3.3 迁移 051（`runs` 加 `agent_id` ＋ `inbound` 投递表）

```
ALTER TABLE runs ADD COLUMN agent_id TEXT NOT NULL DEFAULT '';   -- ''＝非 agent 运行
CREATE INDEX IF NOT EXISTS idx_runs_agent ON runs (tenant_id, agent_id);
-- inbound 投递表（复用 deliveries 形状，channel 维度；幂等键 (tenant_id, channel, message_id)）
CREATE TABLE inbound_deliveries (
    tenant_id TEXT NOT NULL,
    channel TEXT NOT NULL,
    message_id TEXT NOT NULL,
    binding_id TEXT NOT NULL,
    conversation_id TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'received',
    reasons JSONB,
    payload JSONB,
    duplicates INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    replayed_at TEXT,
    PRIMARY KEY (tenant_id, channel, message_id)
);
```

两档 store（`RunStore`/`PgRunStore`）`begin` 加可选 `agent_id=""` 形参；`GET /api/runs` 列表投影补 `agent_id`（read 面加列，零破坏）。
