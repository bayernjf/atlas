## 1. 基线实测（为什么这不算"已经做了"）

三条都是本批立项前逐行读码得到的事实，不是推测：

1. **用例里已经有整张图。** `RecordingCase.graph: dict[str, Any]` 是录制时冻结的 Graph JSON 快照（`recording/cases.py:52-70`），另有递归冻结的子图 `subgraphs`（D26）。所以 D68 **不是**"从动作序列反推一张图"，而是**把这份冻结快照升格成一张可编辑、可发布的新图**。docs/126 §4 当时把它写成"录制产物只是回归用例"，这句仍然成立——成立的是**没有任何路径能把用例的图变成新图**（`/api/recordings*` 只有 list/create/get/replay/delete 五端点，零 promote）。
2. **入参已经有一条既定的引用通道。** 运行 inputs 进 trigger 节点产出 `context.payload`（`graph/loader.py:8,518`），模板图里就是这么写的：`{{trigger-1.context.payload.order_id}}`（`template/graphs.py`）。因此"识别变量"的真实含义＝**把写死在节点 config 里的字面量换成 payload 引用**，不是发明新语法。
3. **`paramWizard` 做的是回放填空，不是成图。** `frontend/src/lib/paramWizard.ts` 文件头自述：「把录制用例的 inputs 按顶层键展开成可填空字段，再组装成 `inputs_override`」——产物是回放请求体，图一个字都没改。这就是 docs/126 §4 那条形状差的实证。

**边不带条件**：`EdgeDSL` 只有 `{id, source, target}`（`dsl.py:140-144`），分支语义全在节点 config（condition 的 `defaultTarget`／targets、ai_decision 的置信度阈值）。⇒ 指引渲染必须从**节点**取分支，不能从边取。

## 2. 决策（六条，落码不得偏离；改任何一条先改本文）

| ID | 决策 | 取舍与理由 |
| --- | --- | --- |
| **AT-D1** | **反导基准＝用例冻结图快照**（`case.graph`），不从 `steps` 反推节点 | steps 只有 `{node_id,node_type,output}`，没有 config 与连线，反推出来的图必然缺参；而快照本来就是完整 Graph DSL。`steps` 只用于两件事：剪枝判据与指引的"这一步实际产出" |
| **AT-D2** | **两阶段 promote＝plan（只读）→ promote（人勾选后返草稿）** | 自动字面量替换会误伤：同一个值既可能是入参也可能是阈值（299 既是 `amount` 也是 `min_amount`）。机器只负责**发现候选**，替换由人确认——与本项目 human-in-loop 的既定范式一致，也避免"改出来的图看着对、其实改了判定条件" |
| **AT-D3** | **替换位置白名单＝`tool_call` 节点 `config.parameters` 的标量（含一层嵌套）**；其余位置一律进 `skipped` | tool_call 参数是业务入参真正流经的地方；`human_approval.approver`、condition 的阈值、`retry.timeout` 同值也不能换——换了就是改流程语义。宁可少换，不可错换 |
| **AT-D4** | **promote 不落库**，只返回草稿 Graph JSON；保存走既有 `POST /api/graphs` | 自己写库＝出现第二套图创建路径（id 生成、租户分区、校验、版本），与 docs/62 单副本/一致性纪律相冲。复用现成创建通道，promote 就是"生成器" |
| **AT-D5** | **剪枝缺省关闭**（整图保留），`pruneToPath=true` 时剪到走过的路径，且**剪完必须试编译**，不可编译即回 issues 且不产出半成品图 | 剪枝会顺手删掉运营没走过的合法分支；默认保留＝草稿是原图超集，最坏情况是"多几条没用的分支"，而不是"分支没了" |
| **AT-D6** | **指引＝只读产物端点，不落库、不自动进知识库**；markdown 为主、`lang` 驱动双语 | 进不进知识库是运营的决定（走既有 `/api/knowledge/import`，category=sop）。自动写入会把"一次导出的预览"变成"未经确认的租户知识"，与 D60 的导入语义冲突 |
| **AT-D7** | **新增一个运行时错误码 `RECORDING_PROMOTE_ACCEPT_UNKNOWN`**（422，`params.unknown`）：accept 越表时整请求拒，不静默丢项也不部分应用。理由：前例＝打包 AR 的 `MESSAGE_TEMPLATE_NAME_CONFLICT`（`898f9ce` 实测该提交前 95 键、后 96 键，即实增 1 键），且前端 `TRANSLATABLE_CODES` 由目录派生、无需改前缀白名单。落码见 `src/atlas/api/main.py` promote 端点的 `PromoteRequestError` 折 422 分支。同步面：docs/03 索引行、frontend/src/locales/{zh-CN,en-US}/runtime.json（实测 96→97）、docs/13 U1403/U1403b。 | 零新依赖／零迁移；代价＝catalog 多一键。若坚持"零新码"原则，则把越表当内部断言失败（assert + 500），但那样运营看不到是哪一项机器没提议过——可读性更差 |

**〔2026-10-14 实测发现上游脱敏的窄残余并修正〕**：首稿要求"指引再脱一次"，但读码证实 run outputs 已在 `_redact_outputs` 处脱敏（`loader.py:3924/4230/4305`，docstring 明写"明文绝不落录制"），故指引的数据源本身不含明文；U1405 降为特征测试（断言上游脱敏有效＋指引不引入新明文来源）。然而 `_redact_sensitive` 原只判**整串相等**（`redact.py:15` `mapping.get(value, value)`），插值后的长文本（如 `"body": "token=<secret>"`）会漏明文——这是 docs/99 §3 承诺与实现之间的缺口，被 AT 的 U1405 探针量出。本批已补**子串替换**（长度≥8 才换，防短值啃坏无关文本），加两条反向门 `tests/test_variable_sources.py::test_u1199b/c`。

## 3. 契约形状

### 3.1 `POST /api/recordings/{case_id}/promote/plan`（鉴权 `operate`，只读）

```jsonc
{
  "caseId": "rec-3",
  "suggestedName": "退款自动审批（来自用例 rec-3）",
  "graph": { "version": 1, "variables": [], "nodes": [], "edges": [] },   // 冻结快照原样回显
  "inputsDeclaration": [ { "key": "order_id", "type": "string" } ],       // 来自 case.inputs 顶层键
  "substitutions": [
    { "path": "nodes[2].config.parameters.order_id", "from": "12345",
      "to": "{{trigger-1.context.payload.order_id}}", "inputKey": "order_id" }
  ],
  "ambiguous": [
    { "path": "nodes[4].config.parameters.amount", "value": 299,
      "candidates": ["amount", "threshold"], "reason": "同值多键，机器不选" }
  ],
  "skipped": [
    { "path": "nodes[1].config.approver", "value": "demo", "reason": "非替换位置（白名单＝tool_call.config.parameters）" }
  ],
  "prunePreview": { "keptNodeIds": [], "droppedNodeIds": [] },
  "compile": { "ok": true, "issues": [] }        // 对"全部 substitutions 采纳后"的草稿试编译，只报不写
}
```

### 3.2 `POST /api/recordings/{case_id}/promote`（鉴权 `operate`，返草稿**不落库**）

请求：`{ "accept": ["nodes[2].config.parameters.order_id"], "pruneToPath": false, "name": "可选新名" }`
响应：`{ "graph": <草稿 Graph JSON>, "applied": [...], "compile": { "ok": bool, "issues": [...] } }`
规则：`accept` 里不在 plan 候选表中的 path ⇒ 整请求 422（**不许接受机器没提议过的替换**）；`compile.ok=false` 时 `graph` 仍返回但必须带 issues，前端不得直接进发布流。

### 3.3 `GET /api/recordings/{case_id}/guide?lang=zh|en`（鉴权 `read`，只读）

响应：`{ "lang": "zh", "markdown": "...", "outline": [ { "nodeId": "...", "title": "...", "kind": "action|decision|branch|approval|wait", "branches": [ { "when": "...", "next": "..." } ] } ], "inputs": [...], "fromRecordedPath": bool }`

markdown 规则（可测）：① 线性流程明写「线性流程，无分支」；② 有分支的节点必须渲染 `when` 原文（表达式不译，避免译坏了语义）；③ 有 `steps` 时每个动作步附「这一步实际产出」摘要（脱敏后、单行、超长截断）；④ 入参表来自 `inputsDeclaration`；⑤ 双语走后端既有内容文案口径（照运行报表导出），前端 i18n 只负责按钮与标题。

### 3.4 错误码／迁移／依赖／ADR

- **零新迁移、零新依赖、无 ADR**。
- **运行时错误码＝0 新增**（理由照 docs/55 粗码治理与打包 AK 的撤销先例：永不发射的码会混进 U1149 可译集合造出假覆盖）。`accept` 越表、`case` 缺 `graph` 快照这两类都用**结构化 422**，落码时码名必须从 `frontend/src/locales/*/runtime.json`＋`docs/03` 实表里选既有的，不许新造；若实表里确无可复用码，**回到本文改 AT-D7 再落码**，不就地发明。
- 跨租户：`case_id` 不属于本租户 ⇒ 404（沿用录制五端点既有分区口径，不新增可达面）。
- 演示面档位：promote/guide 都是**纯本地计算**，不注册任何演示适配器，因此**不受 `ATLAS_ENABLE_DEMO_MOCK` 影响**、prod 档照常可用（这条要写进守护，防止有人误加档位门）。

## 4. 验收（用例号预留 **U1393–U1410**，docs/13 的 AT 小节）

正向 8 条：plan 出候选表／promote 替换真发生（草稿里该 path 逐字等于 `{{trigger-1.context.payload.order_id}}`）／草稿通过编译／`pruneToPath` 预览与产物一致／guide 出 markdown／guide 双语键集一致（进 `PARITY_PAIRS`）／guide 的 `outline.kind` 五档可覆盖／promote 响应不落库（`GET /api/graphs` 数量不变）。

反向门 10 条（每条都要**植缺陷实跑转红**才算成立）：
- R1 不勾 `accept` 时原值必须**保持不动**（防"默认全替换"）；
- R2 同值多键必须落 `ambiguous` 且**不进** `substitutions`；
- R3 非白名单位置（`human_approval.approver`、condition 阈值）必须落 `skipped`；
- R4 `accept` 越表必须 422；
- R5 剪枝导致不可编译时**不得产出半成品图**；
- R6 指引里出现 secret 明文必须红（播种一个 env/secret 变量＋让 output 带上展开值，断言 markdown 不含明文）；
- R7 跨租户 promote 404（摘掉租户过滤必须红）；
- R8 prod 档（未开演示面）promote/guide 必须仍 200（防误加演示面门）；
- R9 `/api/demo/reset` 后用例与 plan 仍可生成（录制是测试资产，reset 不清）；
- R10 三端点必须进 U909 匿名面 allowlist 的反面——它们要鉴权，匿名必须 401。

**真机端到端（不许拿单测代替）**：录一次真运行（演示档 refund-auto）→ plan → 勾替换 → promote → 存为新图 → 发布 → 用**不同** order_id 跑到终态 → 取 guide，人工核对指引读得懂。截图与读数写进 docs/13 的 AT 段与 handoff。
