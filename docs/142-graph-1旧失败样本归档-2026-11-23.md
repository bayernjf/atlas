# graph-1 旧失败样本归档（2026-11-23）

> 口径：这是对 handoff 中 `graph-1` 旧失败记录的归档，不是新功能，也不声称
> “所有 graph-1 运行都已修复”。关闭依据是错误形状可解释、旧样本不可复现、
> 当前有替代证据和守卫测试。

## 1. 旧样本事实

handoff 原记录：

```text
500 NODE_EXECUTION_FAILED / call start() before execute()
```

`call start() before execute()` 的唯一出处是 `src/atlas/web/adapter.py` 的
`WebHarnessAdapter._execute()`：浏览器未启动、`page is None` 时返回结构化
`ActionResult.failed(StructuredError("BROWSER_NOT_STARTED", ...))`。节点随后按
`retry.on_error="stop"` 抛 `RunNodeFailed`，API 层再映射成 500
`NODE_EXECUTION_FAILED`。这是一条 fail-closed 的预期守卫，不是进程崩溃或未捕获异常。

## 2. 为什么不再作为活跃失败

- 旧 `graph-1` 只剩 handoff 一行错误，没有保存图定义、请求体、运行 ID 或可重放输入；
  仓库里也没有 `graph-1` 的生产种子（`src/atlas/**` 零命中，只有测试局部构造）。
- 该错误属于先前进程内 `GraphStore` 的一次运行；重启后不可按原样复现，不能继续当作
  当前代码的开放缺陷。
- 当前浏览器路径已有替代证据：A-01 真实 Chromium 流程 `outputs/a01-web-flow/trace.json`
  `ok=true`（navigate/read/type/click/read + 故意失败可重试），见 `docs/138`。
- 本地副作用/审批/投递已有 A-05 证据 `outputs/a05-local-side-effects/`，见 `docs/139`。

## 3. 守卫测试

新增 `tests/test_web_adapter_egress.py::test_execute_before_start_is_a_structured_browser_not_started_failure`：
未 start 时 `execute()` 必须返回 `FAILED / BROWSER_NOT_STARTED`，且不触碰页面；
这钉住了旧样本的错误形状，防止有人把守卫改成裸异常或静默成功。

本次定向：`tests/test_web_adapter_egress.py` **22 passed**；`ruff` 通过。

## 4. 处理结论与边界

- handoff 该项置为 closed；不修改 `web/adapter.py` 行为。
- 旧样本不可复现，因此不伪造一次“修复后重跑成功”；替代证据只证明当前浏览器链路可达。
- 若未来图里再有 `web-playwright` 节点，必须由装配层调用 `WebHarnessAdapter.start()`
  （或 `with` 上下文）后再执行；否则仍会按设计显式失败，不会静默跳过。
