## 4. 新发现（按严重度；每条都带证据级）

### R1 · `ai_decision` 的运营配置是装饰，节点实为硬编码退款规则〔码〕——**B 档工程断口**

- 编译期**强制**填提示词：`dsl.py:1449-1450`（`NODE_AI_PROMPT_REQUIRED`）。
- 运行期只把它插值后回显：`loader.py:428`（`interpolate`）→ `loader.py:438`（`output = {"decision": result, "prompt_rendered": prompt}`）。
- 真正发给模型的是**代码里写死的 prompt**：`llm/decision.py:61-68`，且入参只取触发载荷的 `reason`/`amount` ＋ 全局变量里**字面名叫 `approval_limit`** 的限额（`loader.py:430-436`；没有这个变量就静默按 500）。
- 节点配置 `model`：`src/atlas/` 内**零读者**；`confidenceThreshold`：除模板字面量 `template/graphs.py:69` 与另一概念的 `skills/skill.py:26` 外**无读者** ⇒ 0.9 的置信度门槛不拦任何东西。
- 而契约侧承诺的是另一回事：docs/06 §6.2 的决策节点＝记忆检索 → 含目标/状态/记忆的 prompt → 强制结构化输出 → **置信度 < 阈值 ⇒ paused/request_human** → next_action。**四项皆无。**
- 前端仍把三个字段摆给运营：`frontend/src/lib/schemas/nodes/ai_decision.schema.ts:11-13`（含 `confidenceThreshold` 默认 0.6、`minimum/maximum` 校验齐全），且 schema 注释指向的 `04 §4.9` 其实是 Capability Schema 小节（指针本身也漂了）。
- **为什么以前没抓到**：单测与 golden 图断的是"决策结果对不对"，而规则壳在退款场景**结果本来就对**；没有任何测试断"运营写的 prompt 到了模型"。
