# 25 - 行业趋势对照与 Atlas 能力现状盘点

> 日期：2026-09-19
> 性质：**外部对照盘点文档**（非契约、非 ADR、非落码依据）。用于回答「行业在推的东西 Atlas 现在有没有」，登记现状事实与差距，供后续立项参考；不直接触发任何代码改动。
> 基线：dev 分支 HEAD `a9a2414`（2026-09-18），M1–M10 主线全闭合、D26 报告 v1 刚落。

## 1. 对照表来源与时间点

外部行业盘点表（2026-09 中，对同类 Agent 编排/运营体平台的横向观察）列了五项行业趋势，并给出当时对 Atlas（表中写作 flowkit）的判断：

| # | 行业在推 | 表中对 Atlas 的判断（盘点时点） |
|---|---|---|
| 1 | MCP / A2A 这类工具与智能体协议 | 未提及（只有仓内契约，无生态协议） |
| 2 | 记忆 / 长期上下文 | 恰好是我们挖出来的那个「共同空洞」 |
| 3 | Agent 评估（eval，不只是编辑期校验） | 无（只有 L1/L2/L3 配置校验） |
| 4 | 自然语言/对话式配置（chat-first） | 有设计（NL 六步）但没实现（#12） |
| 5 | Durable execution / 在途恢复 | 只到字段与语义声明（#10） |

该盘点时点约在 **2026-09-17 M5 立项前**。本文件逐条重新核对仓库现状，标注哪些已变化、哪些仍成立。

## 2. 逐条核对（2026-09-19，dev HEAD `a9a2414`）

### ① MCP / A2A 工具与智能体生态协议 —— 表判断仍成立

**现状**：仓库内无 MCP（Model Context Protocol）客户端/服务端实现，无 A2A（Agent2Agent）协议实现（`grep -ril "mcp\|a2a" src/atlas/` 零真实命中，早期命中均为子串误报）。

**已有的相邻能力**（均为仓内进程内契约，非生态协议）：
- `harness/`：Capability input/output_schema JSON Schema 子集白名单 + 适配器注册发现；
- `coordination/`：M7 落地的任务信封 Envelope / TaskStore / 退货退款沙盘 run_return_refund（进程内任务总线）；
- `skills/`：Skill / Bot / CoordinatorConfig 抽象。

**结论**：第 1 条判断准确。Atlas 目前只有仓内 harness 契约与进程内多智能体信封模型，没有对外的 MCP 工具协议出入口，也没有 A2A 智能体间协议。真正的生态化协议接入缓做（见 14 文档 D5 NATS / D6 多实例网关，触发条件均未满足）。

### ② 记忆 / 长期上下文 —— 表判断仍成立，确为真实空洞

**现状**：`src/atlas/memory/` 包仅两个文件：
- `database.py`：PostgreSQL 连接引擎工厂 + 连接健康探针 + pgvector 可用性检查（W1 骨架）；
- `settings.py`：只读 `DATABASE_URL` 环境变量，fail-closed。

文件头注释原文：

> 短期工作记忆（Redis）、Checkpointer 与各记忆表在后续周次接入。

`db/migrations/001_enable_pgvector.sql` 扩展已建，但**没有任何记忆表、没有向量检索业务逻辑、没有长期上下文读写路径**。运行时记忆只有单次 run 的 `outputs`/`globals`（进程内），M5b 落库的是 run 状态/中断帧，不是用户/租户长期记忆。

**结论**：第 2 条判断准确。在 19 提案定义的六类实体（节点/工具/技能/记忆/部署/卡片）中，**记忆是唯一完全没动的一类**——卡片（M8）、技能（M7 抽象）、部署/灰度（M9）均已落，记忆只留了连接骨架。这是当前最明确的产品化空洞。

### ③ Agent 评估（eval）—— 表判断基本成立，部分进展但未达「eval」

**现状**：
- ✅ 已有的：L1/L2/L3 编辑期配置校验（M1–M4）；`recording/` 操作录制 + 冻结快照回放 + 归一化深等（确定性回归）；D26 批量用例集报告 v1（通过率历史趋势，2026-09-18 刚落）；BENCHMARK.md 性能 p50/p99 基准。
- ❌ 没有的：LLM 输出质量打分、离线评测集、业务结果质量指标（如退款准确率/人工干预率/误决策率）、A/B 效果评估、人工标注集。
- T2 评估层在 06/13 中仅留接口，一直未立项目。

**结论**：第 3 条判断基本准确。D26 批量回放报告测的是「没坏」（回归通过率），不是「好不好」（Agent 行为质量）。**eval 体系仍为空**，是与记忆并列的两个真实能力空洞之一。

### ④ 自然语言/对话式配置（chat-first）—— 表判断半过时

**现状**：
- 已实现：`llm/nl_generate.py`（W9–W10 落地）——单轮「自然语言退款诉求 → 流程图草稿」，`POST /api/nl/generate`，前端可将草稿载入编辑器。这是 NL 六步设计里的第一步。
- 未实现：chat-first 多轮对话式配置（边聊边改、技能推荐 rank、自动组合校验、对话中增量改图）。M7/M9 落的是任务总线与路由，未触碰 NL 对话编辑面。

**结论**：表中「有设计但没实现」的判断**半过时**——单轮 NL→草稿已落地，但 chat-first 多轮对话式配置仍空。GitHub issue #12 的范围如覆盖整个 chat-first，则判断仍部分成立。

### ⑤ Durable execution / 在途恢复 —— 表判断已过时

**现状**：这条已被 M5b 真实推翻。
- M5 契约设计轮（docs/24，2026-09-17）+ ADR T18 拍板 B（自研暂停帧 + 续跑）；
- M5a：七 Repository Protocol + `storage/` 包骨架；
- M5b（2026-09-17/18）：`storage/pg.py` 六 store 落库、`storage/frame.py` 中断帧序列化、`storage/recovery.py` 恢复扫描器、loader `run_graph(resume=)` 续跑、`GET /api/runs` 查询端点；
- 脚本实测：「审批挂起 → 强杀重启 → 同 token 决策生效 → run completed」通过。

**结论**：第 5 条判断**已过时**。在途恢复已真实落地（v1 范围单实例），不再是字段与语义声明阶段。多实例/跨实例恢复仍缓做（14 文档 D5）。

## 3. 净结论

| # | 能力 | 盘点时点判断 | 2026-09-19 实际 | 变化 |
|---|---|---|---|---|
| 1 | MCP / A2A 生态协议 | 无 | 仍无（仅仓内契约） | 不变 |
| 2 | 记忆 / 长期上下文 | 共同空洞 | 仍空洞（仅连接骨架） | 不变 |
| 3 | Agent eval | 无 | 仍无（仅配置校验+确定性回归） | 不变（D26 是回归不是 eval） |
| 4 | NL chat-first 配置 | 未实现 | 单轮 NL 草稿已实现，多轮对话仍空 | 部分推进 |
| 5 | Durable execution | 仅声明 | M5b 已落码，单实例重启可恢复 | **已补齐** |

**三个真实能力空洞（按行业热度与产品价值排序）**：
1. **记忆 / 长期上下文** —— 六类实体中唯一未动；pgvector 连接与扩展已就位，缺记忆表、向量检索、长期上下文读写路径。
2. **Agent eval 体系** —— 缺 LLM 输出质量打分、离线评测集、业务结果指标；现有 recording/D26 只覆盖回归。
3. **MCP / A2A 生态协议** —— 缺对外协议出入口；受多实例/真实外部智能体接入触发条件约束，短期可继续缓做。

**后续建议**（非立项指令，仅供决策参考）：
- 若要继续推进主线，**记忆与 eval 是两个最值得立项的方向**；
- MCP/A2A 在 D5（多实例）/D22–D24（真实外部系统接入）触发前保持缓做；
- 本盘点不直接立项；任何一项正式启动前，按 10 文档 ADR 流程 + 08 文档立项条 + 03/04 契约同步矩阵走。
