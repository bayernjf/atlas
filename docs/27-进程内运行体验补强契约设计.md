## 2. C 包：可注入时钟与非确定日期函数

### 2.1 时钟模型（确定性优先）

- `run_graph(...)` 新增 keyword-only 参数 `now_override: datetime | None = None`（timezone-aware UTC；`datetime` 指 `datetime.datetime`）。
  - `None`（库直跑/普通运行/调试）：在 `run_graph` 入口取**一次** `datetime.now(timezone.utc)` 并在本次运行内固定；同一次图运行中多次调用 `today()`/`now()` 恒等，避免跨节点漂移。
  - 显式传入：录制 baseline、单用例 replay、发布门禁批量回放注入用例冻结锚点（§2.4）。
- 固定后的 now 经执行器透传到所有 condition 求值点：分支 condition（`loader.py` 约 684）、loop `continueExpression`（约 728）、调试条件断点（`debug/controller.py:61`）。
- `conditions.evaluate_expression(expression, context, *, now: datetime | None = None)`；`now=None` 时函数内取 `datetime.now(timezone.utc)`（库直跑单测也可用）。`_evaluate_function(name, args, now)` 透传 now。
- 时钟口径统一 **UTC**；`today()` 取 UTC 日期。不引入命名时区/本地时区（非目标）。

### 2.2 函数与类型（后端 `graph/conditions.py`）

在现有白名单（A3 已落算术、`abs/floor/ceil/round/min/max/len/lower/upper`、确定性日期 `date/year/month/day/daysBetween`）上**纯超集**新增：

| 函数 |  arity | 返回 | 语义 |
|---|---|---|---|
| `today()` | 0 | date | 当前 UTC 日期（`now.date()`），与 `date(y,m,d)` 同类型，可比较、可喂 `daysBetween`/`year/month/day` |
| `now()` | 0 | datetime | 当前 UTC 日期时间（注入时钟），新增 datetime 值类型 |
| `datetime(y,m,d,H,M[,S])` | 5–6 | datetime | 构造 UTC datetime（整数分量，非法日期/时间抛 `ConditionEvalError`） |
| `hoursBetween(a,b)` | 2 | number | 两个 datetime 的小时差 `(b−a)`，符号约定与 `daysBetween` 一致（b≥a 为正）；入参也接受 date（按 00:00:00） |

- 新增内部 datetime 值类型（Python 侧即 `datetime.datetime`，与现有 `datetime.date` 并列）；比较：datetime 间、date 间支持原有序/相等比较；**不允许跨 date/datetime 直接比较**（抛 `ConditionEvalError` 提示先统一类型），避免隐式语义。
- `daysBetween` 接受 datetime（先 `.date()`）。
- 静态层同步：`validate_expression`/`_infer_type`/FUNCTIONS 元信息识别 0 参 `today`/`now`（含变量的表达式仍推断 unknown）、`datetime` arity 5–6、`hoursBetween` 入参/返回类型；非法 arity/类型仍在编译/校验期报错（沿用 A3 静态校验，fail-safe 口径不变）。
- 文件头注释（现写「D15 不含 now()/today() 等非确定函数」）更新为「today()/now() 为非确定函数，其值由可注入时钟决定；录制/回放注入冻结时钟保证确定性」。

### 2.3 前端同构（`frontend/src/lib/conditions.ts`）

- 求值入口增 `now?: Date`（缺省 `new Date()`）；`FUNCTIONS` 表与后端同 arity/返回类型。
- 新增 `DateTimeValue`（或在现有 `DateValue` 上扩展时分秒，落码择一并保持与 Python ordinal/比较同构）；实现 `today()`（UTC 年月日）、`now()`、`datetime(...)`、`hoursBetween`；`toOrdinal`/比较与后端对齐（Howard Hinnant 日期公式已在用，datetime 比较在 ordinal 基础上补当日秒数）。
- 前端无回放概念：编辑器 L2/调试预判用真实当前时间；如未来需要前端预览固定时刻，经同一 `now` 参数注入（本批不接 UI）。
- 顶部注释同步（现写「不含 now()/today()」）。

### 2.4 录制/回放冻结锚点（确定性保证）

- `RecordingCase`（`recording/cases.py`）增可选字段 `recorded_at: str | None = None`（UTC ISO；**纯超集**，旧用例缺省 `None`，向后兼容，进程内/PG 两档存储形状一致——PG 侧 cases 落库若有列/JSON 需同步，落码核对）。
- **录制**（创建用例、跑 baseline 收集 steps 的端点）：baseline 运行开始时生成一次 `recorded_at=datetime.now(timezone.utc).isoformat()`，随用例持久化，并以 `now_override=parsed(recorded_at)` 跑 baseline，使录制下来的步骤即冻结时钟下的产物。
- **回放**：单用例 replay 端点与发布门禁 `recording/gate.py::_replay_one`（现每例都是标准 `run_graph`、实时 resolver 的原则不变）调 `run_graph` 时传 `now_override`：
  - `case.recorded_at` 存在 → 解析注入（与 baseline 同一锚点）；
  - 缺失（旧用例）→ 回退 `case.created_at`；再缺失才用真实时钟（并在回放报告 note 标注「无冻结时钟，非确定函数结果可能漂移」）。
- 子图内联快照（D26-b `subgraphs`）与时钟正交：子图重入继承父 run 的同一 `now_override`（run_graph 子重入透传 now），不另取时钟。
- 由此：含 `today()/now()` 的分支在同一用例 baseline 与 replay 间结果稳定，发布门禁不会因跨天/跨秒误判不一致。

### 4.1 运行中急停（协作式取消）

- **统一取消句柄**：新增进程内 `RunCancellationBroker`（每租户一个，挂 `TenantServices`，照 approval/debug broker 模式：token/run_id → `threading.Event`，reset 清空并置位释放）。`/run/stream` worker 启动时按 `run_id` 注册取消事件，结束（完成/失败/取消）后注销。
- `run_graph(...)` 新增 keyword-only `is_cancelled: Callable[[], bool] | None = None`；在 `_make_executor` 的节点边界（`node_start` 之后、节点逻辑之前，与 `DebugController.before_node` 同一位点）调用；命中抛新增 `RunCancelled(node_id)`（放 `graph/loader.py` 或 debug 包，落码定；语义＝协作式终止，非异常失败）。
  - 取消检查须透传进 loop/parallel/subgraph 子执行的节点边界（子图重入同样透传 is_cancelled；子图内命中则整图取消）。
  - **不在 wait/approval/tool 阻塞中点内强杀**：长节点执行中不打断，于下一节点边界生效（非目标，文档与 UI 注明）。
- **普通运行**：worker 捕获 `RunCancelled` → `run_store.finish(status="cancelled")`、monitoring 记 `status="cancelled"`（新增运行状态，落码核对 run/monitoring 状态枚举并同步）、SSE 下发新帧 `event: cancelled`，data `{type:"cancelled",node_id,reason:"user_cancel"}`，随后关闭流。
- **调试运行**：debug stream 同样注册 run 取消事件；`DebugController.before_node` 在现有 `session.cancelled` 之侧（或经同一 is_cancelled）检查运行取消，命中仍抛 `DebugStopped`（保持现有 `event: stopped` 帧与调试语义），不产生重复 cancelled。
- **新端点**：`POST /api/runs/{run_id}/cancel`（权限 `operate`）：置位本租户该 run 的取消事件；成功 `{run_id,cancelled:true}`；run 不存在/非本租户 404、已结束（无注册句柄）409（幂等口径落码定，重复取消已取消的 run 可返回 200 幂等）。
- 前端：运行中（含调试 continue 运行中）显示「急停」按钮，调 cancel 端点；按钮在流结束/暂停态禁用。SSE 收到 cancelled/stopped 复位运行态并提示。

### 4.2 断点命中计数（hitCount）与日志断点（logpoint）

- 断点结构由 `{node_id: expression|None}` 演进为**超集**：`/run/stream` body `debug.breakpoints[]` 每项在 `node_id`/`expression` 外新增可选：
  - `hitCount: int | null`（正整数；每第 N 次命中断点才暂停，`hits % N == 0` 口径；缺省/非法值按 1＝每次命中）；
  - `logMessage: str | null`（非空＝日志断点 logpoint：命中**不暂停**，下发一帧日志后继续运行）。
- `DebuggerBroker.create` 的断点表与 `_validate_debug`（api/main 约 907）同步接受新字段（校验 hitCount 为正整数、logMessage 为字符串，非法聚合成中文 422，沿用现有校验风格）；旧形状（expression 字符串/空）继续兼容。
- `DebugSession` 增 `hit_counts: dict[str,int]`（会话内每节点累计命中次数）与增强断点表；`DebugController._hit_reason` 判定顺序：
  1. 计算是否「命中」（step 模式 / 无条件断点 / 条件表达式为真；条件表达式异常仍 fail-safe 记 `last_condition_error` 不命中）；
  2. 命中则 `hit_counts[node_id] += 1`；
  3. **logpoint**（该断点 `logMessage` 非空）：经 emit 下发 `debug_log` 帧（`{type:"debug_log",node_id,hits,message}`，message v1 原样、可做最小 `{{...}}` 插值则落码注明，否则原样输出），**不 request_pause**，返回不暂停；
  4. 否则若设 `hitCount`：仅当 `hits % hitCount == 0` 才暂停，其它次返回不暂停；
  5. 普通断点照常暂停。
  - v1 口径：一个断点 `logMessage` 非空即按 logpoint（只记日志不暂停）；hitCount 仅对暂停型断点生效，二者不强行组合（文档注明，避免语义歧义）。
- 新 SSE 帧 `event: debug_log`（仅调试流）；前端调试日志区/运行日志追加显示（节点、第几次命中、消息）。
- 前端 `DebugConsole` 断点配置项增「每 N 次命中暂停（hitCount）」与「日志断点消息（logMessage，填了即不暂停只记日志）」输入；editorStore 断点结构由 `{expression?}` 超集为 `{expression?,hitCount?,logMessage?}`，组装 `/run/stream` debug.breakpoints（现 Editor 约 137–140）时透传。

### 4.3 暂停时变量改写续跑（resume globals 覆盖）

- 帧仍是**只读深拷贝快照**（`session.frame` globals/outputs  deepcopy，展示不变；前端不直接改帧对象）。
- 改写通道＝resume 请求声明覆盖：`ResumeDebugRequest`（api/main 约 1296）在 `action: step|continue|stop` 外新增可选 `globals: dict[str,Any] | None = None`。
- `POST /api/debug/{token}/resume`：在 `session.resolve` 前，若带 globals 且 action 非 stop，调用新增 `session.apply_overrides(token, globals)`：
  - **白名单/口径**：仅允许覆盖 `global` 作用域顶层键（不允许改 outputs、不允许改结构/删键）；键名须为合法 global 标识符、值须 JSON 可序列化；**顶层键浅合并**——提供的键整体替换其值（dict 值整体替换、不深 merge），未提供的键保持不变；非法键/不可序列化抛 422（中文 detail）。
  - 覆盖暂存在本次 `_Pause`（增 `overrides` 字段），resolve 首决生效口径不变；重复 resume 仍 409。
- `DebugController.before_node`：`session.wait(token)` 返回后、`end_pause` 后续跑前，若 action 为 step/continue 且本次 pause 有 overrides，把它们写回持有的 `state["variables"]["global"]`（浅合并），续跑即用新值；`action=="stop"` 忽略 overrides（现有 cancelled→DebugStopped 路径不变）。
- 前端暂停 Modal（Editor 约 886–922）：globals 区由纯只读展示增为**可编辑 JSON 文本框**（v1：一个 JSON 文本域，预填当前 globals，提交前前端 JSON.parse 校验，非法则禁用提交并提示）；outputs 仍只读。step/continue 时把编辑后的 globals 作为 `globals` 随 resume 提交；stop 不提交。

## 10. 风险与回归重点

1. **A 子层终帧/统计污染**：命名空间 emit 必须吞子层 `run_end`；子图内部 node_end 进入 worker `recording_emit.collected` 时按内部 node_id 记录，须确认 `extract_node_results(graph_view,…)` 按顶层 graph_view 过滤、不污染监控/运行产出（落码核对，必要时 wrapper 对监控采集做隔离）。
2. **B 取消传播面**：is_cancelled 须覆盖 loop/parallel/subgraph 子执行边界；只在节点边界生效，wait/approval/tool 阻塞中不强杀（UI/文档明示），避免误以为即时终止。
3. **C 签名穿透**：now_override/now 穿透 run_graph→executor→conditions→controller，默认 None 向后兼容；库直跑既有测试不传参＝真实时钟，旧断言不应受影响（today/now 仅在表达式显式调用时才取值）。
4. **回放确定性**：含非确定函数的用例必须 baseline 与 replay 同锚点；旧用例无 recorded_at 回退 created_at 并在报告 note 标注，不假装确定。
5. **回归**：A/B/C 均动运行/条件/SSE 核心，每批后跑 d26_smoke、m11_smoke、录制回放黄金用例与 A1/A2/A3（parallel/loop/condition）用例；前端 oxlint 不新增 warning、build 过。
