## 0. 已拍板决策（ADR T25）

1. **密码哈希用标准库 `hashlib.scrypt`，零新依赖**：参数 `n=2**14, r=8, p=1, dklen=32`，每口令 16 字节随机盐；存储串 `scrypt$16384$8$1$<salt b64>$<hash b64>`，验证明文恒定时间比较。不引 bcrypt/argon2-cffi（守「锁单外不扩依赖」；scrypt 是内存硬化 KDF、满足口令存储要求；若未来合规明确要求 argon2id，携依据重开本决策，旧串按前缀平滑重哈希）。
2. **账号进 `iam_users` 表（迁移 010）**：`(tenant_id, username)` 主键、`password_hash/display_name/role/status/created_at/updated_at`；memory 档对应进程内 `UserStore`（测试/dev 默认不变）。种子账号由**幂等 seeder** 写入：仅在用户不存在时插入哈希口令，已存在（含已改密）绝不覆盖。
3. **账号生命周期＝管理员代建，不开放自助注册**：admin 在**本租户内**建用户、改显示名/角色、禁用/启用、重置密码；任何登录用户可改本人密码（须验旧口令）。禁用用户、重置密码、改密成功 → **吊销对应用户全部既有会话**。不做用户删除（禁用替代，保留运行/录制外键与审计语义）。
4. **保留不透明 sess-token，不引 JWT；新增会话绝对 TTL**：迁移 011 给 `iam_sessions` 加 `expires_at`，默认 12 小时（`ATLAS_SESSION_TTL_HOURS` 可调）；过期 token → 401。存量行由迁移按 `issued_at + 12h` 回填。JWT 继续缓做：PG 会话已支持多实例共享，无状态 JWT 的诉求（独立网关/无 DB 校验）随部署批再评。
5. **登录失败节流用进程内滑动窗口**：键为 `username + 客户端 IP`，10 分钟内 5 次失败 → 拒绝登录（429）至窗口滑动出窗；成功即清零。多实例下计数不共享（本批交付仍是单实例；多实例时 PG 化尝试记录，随部署批）。
6. **口令策略**：长度 ≥ 8、≤ 128；内置一份小的弱口令黑名单（如 `admin123/password123/12345678` 等）；不强制符号/大小写混合（对齐现版口令指南「长度优先」）；用户名 3–64 位 `[a-z0-9_.-]`，租户内唯一。

## 1. 范围与非目标

### 1.1 范围（四项交付）

1. 口令哈希：`iam/passwords.py`（scrypt hash/verify + 存储串格式），种子账号迁移为哈希。
2. 账号存储与生命周期：迁移 010＋`iam/accounts.py`（UserStore、seeder），REST 用户管理端点（admin）与改密端点。
3. 会话 TTL：迁移 011＋过期判定（memory/PG 两档 SessionStore 同构）。
4. 登录节流：`iam/throttle.py` 进程内滑动窗口。
5. 前端：用户管理页（admin）、Header 改密入口、禁用/过期中文交互。

### 1.2 非目标（继续缓做，收口时登记 14）

- **SSO：OIDC/SAML/企业微信/飞书登录、MFA/2FA**（随首个有 SSO 要求的真实客户立项）。
- **邮箱找回密码/邮箱验证**：无真实邮件通道，随真实送达批次（docs/29 P0 #4 相关）。
- **开放注册/租户开通 CRUD/platform_admin 跨租户视角**：维持「无平台超管、平级租户」（04 §5.14）。
- **JWT、会话吊销列表（黑名单）、并发会话上限、"在其他设备下线"**。
- **完整登录审计日志、账号操作审计**：随 Phase 3 审计（04 §二7）。
- **多实例共享节流计数（PG login_attempts）**：随部署批。
- 出向适配器凭证加密/OAuth（D22）不属本批——那是「接真实世界」批 3 的范围。

## 2. 账号模型与存储

### 2.1 iam_users（迁移 010）

| 列 | 类型 | 说明 |
|---|---|---|
| tenant_id | TEXT NOT NULL | 与 token 推断的租户一致 |
| username | TEXT NOT NULL | 租户内唯一、小写规范化 |
| password_hash | TEXT NOT NULL | §0-1 存储串 |
| display_name | TEXT NOT NULL | |
| role | TEXT NOT NULL | viewer/operator/admin |
| status | TEXT NOT NULL | active/disabled，缺省 active |
| created_at / updated_at | TEXT NOT NULL | UTC ISO |

主键 `(tenant_id, username)`；不建外键到租户表（租户仍为种子常量）。

### 2.2 认证与装配行为

- 登录路径改为：取用户（租户由 username 全局唯一索引？——当前 username 全局唯一如 `admin-a`，登录不带租户；保持现语义，**全表按 username 查、命中后校验 status 与口令**。若未来允许跨租户同名，登录须加 tenant 字段，届时走契约变更）。
- disabled 用户登录 → 403 中文「账号已停用，请联系管理员」（不区分「用户不存在/口令错误」的 401 文案，防账号枚举；停用是已知道自己账号的用户，可明确提示）。
- 认证成功 → Principal（结构不变，04 §5.14），会话 issue 时写入 `expires_at`。
- `select_session_store()`（docs/30）保留：memory 档 SessionStore/UserStore 均进程内；PG 档两者落库。
- **seeder 时机**：不新增迁移外机制——seeder 作为应用启动步骤（entrypoint 迁移之后、uvicorn 之前）执行一次；内存档在 iam 模块初始化时惰性播种。幂等：只插入缺失行。

## 3. 账号生命周期 REST（契约同步 12，03 新增 `identity_user`）

| 方法/路径 | 权限 | 语义 |
|---|---|---|
| `POST /api/auth/change-password` | 登录用户 | body `{oldPassword,newPassword}`；旧口令错 → 400；成功吊销**本人除当前会话外**全部会话（当前会话保持，避免操作完被登出） |
| `GET /api/users` | admin | 本租户用户列表（不含 password_hash；含 status/role/时间） |
| `POST /api/users` | admin | body `{username,password,displayName,role}`；重名 409、策略不达标 422；创建即 active |
| `PATCH /api/users/{username}` | admin | 可改 `displayName/role/status`；跨租户用户名 → 404；降级自己（admin 改本人为非 admin）允许但二次确认在前端，后端不拦 |
| `POST /api/users/{username}/reset-password` | admin | body `{newPassword}`；成功吊销该用户全部会话 |

- 最终管理员保护：**不做**后端「租户必须剩一个 admin」硬校验（v1 从简；前端给确认提示；误用后可用种子重置脚本恢复——scripts/ops 提供 reseed 入口？结论：不新增，文档注明风险）。
- 列表/详情的 JSON 字段命名沿用现 camelCase REST 风格。

## 4. 会话 TTL（迁移 011）

- DDL：`ALTER TABLE iam_sessions ADD COLUMN IF NOT EXISTS expires_at TEXT`；回填：`UPDATE iam_sessions SET expires_at = (issued_at::timestamptz + INTERVAL '12 hours')::text WHERE expires_at IS NULL`。
- issue：`expires_at = now(utc) + ttl`；`principal_for_token`：行不存在/`expires_at < now` → None（过期行惰性删除：发现即 `DELETE`）。
- memory SessionStore 同构：内存 principal 旁带 expires_at；单测可注入时钟。
- TTL 配置：`ATLAS_SESSION_TTL_HOURS`，缺省 12，合法范围 1–168；登录响应不强制返回 expiresAt（可选附带，前端可用于提示）。
- **不做滑动续期**：绝对 TTL，到期重新登录（行为可预期、实现最简）。

## 5. 登录节流（iam/throttle.py）

- 纯逻辑滑动窗口：`record_failure(key, now)` / `is_locked(key, now)` / `reset(key)`；窗口 600 秒、阈值 5；窗口按失败时间戳队列裁剪。
- 键：`f"{username}|{client_ip}"`（IP 取 `request.client.host`；反向代理场景的 X-Forwarded-For 信任链随部署批，当前不读该头）。
- 锁定时登录返回 429，中文「登录尝试过于频繁，请稍后再试」；**锁定时不校验口令、不区分用户是否存在**（防探测），但仍不改变失败计数。
- 进程内单例（同 SessionStore 装配位）；单测覆盖：阈值边界、窗口滑出、成功清零、多键独立。

## 6. 前端

- **用户管理页**（admin 专属，主导航新增「用户」；沿用现有页面/AntD 模式）：用户表（用户名/显示名/角色 Tag/状态/创建时间）、新建用户 Modal、编辑 Modal（角色选择/停用开关）、重置密码 Modal（生成口令可复制）；非 admin 路由不存在该入口。
- **Header UserBadge 下拉**：「修改密码」（Modal：旧口令/新口令/确认，策略错误中文内联）；成功后提示「其他设备已退出登录」。
- **登录页增强**：429 锁定提示、停用提示；口令输入不变。
- 401（会话过期）沿用现有「清 token → 回登录页」链路，文案区分「登录已过期，请重新登录」。
- 不做角色级 UI 以外的元素（不做 SSO 按钮位）。

## 9. 风险

1. **scrypt 计算成本**：参数下单次校验约 50–100ms，登录接口可接受；批量校验（如未来迁移全表重哈希）需离线任务。
2. **进程内节流的多实例盲区**：水平扩容时每个实例独立计数，爆破阈值被实例数稀释；收口文档明确该边界，多实例必须先 PG 化尝试记录。
3. **seeder 与已改密环境**：口令列名/幂等逻辑出错会把演示口令写回生产；seeder 只 INSERT 缺失行、测试必须覆盖「已存在零改动」。
4. **TTL 回填存量行**：按 issued_at 文本解析依赖 ISO 格式（现有行均为代码写入的 UTC ISO）；解析失败的行策略：不回填（null 视为不过期）并在日志告警，避免迁移失败。
5. **改密吊销会话的实现面**：memory/PG 两档都需「按 username 批量删除会话」，漏接会导致旧 token 在 PG 档残留；列为 U228/U231 硬断言。
6. 明文种子口令（admin123 等）本身在弱口令黑名单内——seeder 插入走系统通道**不经过策略校验**；真实客户环境应首次登录强制改密（强制改密标记不在本批，登记缓做：随 onboarding 批）。
