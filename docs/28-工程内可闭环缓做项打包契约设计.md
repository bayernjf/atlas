## 2. 批 1：D26 四项

### 2.1 ① recordings PG 富字段持久化（缺口修复）

**现状缺口（实测 HEAD 2ad0b52）**：`PgRecordingStore.add` INSERT 仅 9 列（id/tenant/name/graph/inputs/steps/status/created_at/recorded_at），而 `POST /api/recordings` 经进程内签名演进一直传 `graph_id`/`subgraphs`，PG 档端点 500（`TypeError: unexpected keyword argument 'graph_id'`）；`_row_to_case` 8 位置参数、list/get SELECT 同形。进程内 `RecordingStore.add` 与 `RecordingCase` 已具全字段（id/name/graph_id/graph/inputs/steps/status/created_at/recorded_at/subgraphs）。

**落码**：

- 迁移 `db/migrations/008_recording_graph_subgraphs_tool_calls.sql`：
  ```sql
  ALTER TABLE recordings ADD COLUMN IF NOT EXISTS graph_id TEXT NOT NULL DEFAULT '';
  ALTER TABLE recordings ADD COLUMN IF NOT EXISTS subgraphs JSONB NOT NULL DEFAULT '[]'::jsonb;
  -- 历史行回填（DEFAULT 已覆盖新增，显式 UPDATE 幂等）
  UPDATE recordings SET graph_id = '' WHERE graph_id IS NULL;
  UPDATE recordings SET subgraphs = '{}'::jsonb WHERE subgraphs IS NULL OR subgraphs = '[]'::jsonb;
  -- 批 3 同批：monitoring_runs 工具调用埋点
  ALTER TABLE monitoring_runs ADD COLUMN IF NOT EXISTS tool_calls JSONB NOT NULL DEFAULT '[]'::jsonb;
  ```
  （`subgraphs` 为对象 map，DEFAULT 用 `'{}'::jsonb`；以落码实测 DDL 为准。）
- `storage/pg.py` PgRecordingStore：`add` 签名与进程内对齐（加 `graph_id: str = ""`、`subgraphs: dict | None = None`），INSERT 补两列、占位符与参数同步；`_row_to_case` 位置参数补到 10 个（graph_id、subgraphs 在 recorded_at 后，顺序照进程内 `RecordingCase` 字段）；list/get SELECT 列表同步。
- `storage/base.py` `RecordingRepository.add` Protocol 签名同步为超集（与实现一致）。
- 进程内档零行为变化（默认值兼容）。

**验收**：迁移应用后 `ATLAS_STORAGE_BACKEND=pg` 起 uvicorn 跑 `scripts/dev/d26_smoke.py` 24 断言全过（现状仅内存档全过）；内存档不回归；新增 PG integration 用例（ATLAS_RUN_INTEGRATION=1）覆盖富字段往返。

## 3. 批 2：D27 三项

### 3.1 ⑤ 暂停帧变量变化历史与来源追踪

**语义**：记录相邻两次暂停之间，全局变量（`variables.global` 顶层键）的变化与期间经过的节点；易失、随调试会话存活，不持久化、不进录制。

**后端（debug/sessions.py + controller.py）**：

- DebugSession 增：
  - `variable_history: list[dict]`（正序，上限 50，超出丢最旧）；
  - `_last_pause_globals: dict | None`；`_nodes_since_pause: list[str]`。
- `controller.before_node` 开头（取消检查之后、分类之前）调 `session.mark_node(node.id)`——语义＝「自上次暂停以来到达 before 的节点」，step 时区间恰为 `[当前节点]`（当前节点逻辑尚未执行，归入下一区间的起点，文档与 UI 文案用「经过/到达节点」而非「已执行节点」）。
- 暂停成立、`request_pause` 之前调 `session.snapshot_change(node_id, reason, globals_)`：
  - 与 `_last_pause_globals` 做顶层键 diff：新增/值变更记 `{key, old, new}`（新增 old=null；键删除 v1 不记——resume 浅合并只加不删，运行中节点可覆盖/新增）；值比较用 JSON 序列化后相等判定（不可序列化键 fail-safe 跳过）；
  - 首次暂停（基线为 None）`changes=[]`；
  - 记一条 `{seq, node_id, reason, since_nodes: list[_nodes_since_pause], changes}`，seq 为暂停序号（与 paused 帧同序）；
  - 记完清空 `_nodes_since_pause`、把本次 globals 深拷贝置为新基线。
- resume 写回 overrides 之后（controller 现有 globals_.update 处）调 `session.seed_baseline(globals_)`：用户手动改写同步进基线，**不被记为运行变化**。
- `frame()` 纯超集加 `"history": variable_history`（深拷贝；上限内全量）；PausedFrame 随之携带，不新增帧型。
- outputs 按节点 id 天然可溯源（帧内 outputs 快照已含），v1 不做 outputs 历史。

**前端**：暂停工具条 Card（Editor.tsx）加「变量变化历史」折叠区：按次展示 节点/原因 Tag/经过节点/变化键 old→new（中文原因映射复用现有 step/breakpoint/condition/exception）。

### 3.2 ⑥ 异常断点

**语义**：节点逻辑抛异常时，若该节点配置了异常断点则先暂停供观测；resume（step/continue）后**原样重抛**——v1 不改变失败语义，不提供「忽略继续」；stop 走 DebugStopped。

- `BreakpointSpec` 加 `exception: bool = False`；`DebuggerBroker.create` 从断点入参解析 `onException`（驼峰照 hitCount/logMessage 惯例）；`_validate_debug` 校验其为布尔（非 bool 聚合进中文 422）。
- controller 新增 `on_exception(node, exc, state) -> None`：
  - 查该节点 spec，未配置 exception（或缺省 false）直接 return（executor 随即重抛）；
  - 命中则 emit paused 帧：`reason="exception"`、帧纯超集加 `"error": {"type": exc 类名, "message": str(exc)}`，`request_pause` + wait；
  - wait 返回 stop → 抛 `DebugStopped`；step/continue → 正常返回（executor 重抛原异常）。
- executor 节点逻辑段（loader 现有 if/elif 链，现无 try 包裹）：仅当 `debug_controller` 存在时包：
  ```python
  try:
      <节点逻辑>
  except (RunCancelled, DebugStopped):
      raise
  except Exception as exc:
      debug_controller.on_exception(node, exc, state)
      raise
  ```
  未配置异常断点时 on_exception 立即返回、原样 raise，行为与现状逐字节一致（异常冒泡 worker → run error；子图内由 `_execute_subgraph` fail-safe 折叠）。
- `_execute_subgraph` fail-safe 现有 `except RunCancelled: raise` 之并列位置加 `except DebugStopped: raise`（否则子图内 stop 被通用 except 折叠成节点 failed——B 包急停穿透已修 RunCancelled，本包补 DebugStopped）。
- 子图内异常断点随 ⑦ 控制器透传而自然生效：子层暂停帧带 subgraphPath，resume 重抛后仍由 fail-safe 折叠为 subgraph 节点 failed，口径不变。
- 前端：DebugBreakpoint 加 `onException?`、PausedFrame.reason 联合加 `"exception"`、帧加 `error?`；editorStore 加 toggle action；PropertyPanel 断点块加「异常断点」Switch；Editor 两处 reason 中文映射（运行日志、暂停 Card Tag）加 `exception → 异常`，Card 内展示异常类型与消息。

### 3.3 ⑦ 子图内部断点与逐帧上屏

- `_execute_subgraph` 签名加 `debug_controller`，重入 `run_graph` 透传**同一** controller/session（与 is_cancelled/now_override/tracer 并列）；executor 调用 `_execute_subgraph` 处把当前闭包 debug_controller 传入；compile_graph/_make_executor 签名链同步。
- `_namespaced_emit` 白名单由仅 `node_start`/`node_end` 增放 `paused`/`debug_log`（同样附 subgraphPath；`run_end`/result/stopped/error/cancelled 等终帧仍吞，整图终帧唯一）。
- 同一 DebugSession 的 `threading.Lock` 门闩**不可重入但同线程顺序安全**：父 subgraph 节点 before_node 暂停→wait→resume 的 finally 已 `end_pause` 释放门闩，此后才进入节点逻辑重入子图，子层 request_pause 获取的是已释放的门闩；parallel 门闩串行既有逻辑不变。
- resume 端点/token 机制零改动（会话唯一、与层级无关）。
- 前端：PausedFrame 加 `subgraphPath?: string[]`（DebugLogFrame 落码时核对是否已随 A 包预留，缺则补）；暂停 Card 标题、日志前缀复用 `subgraphEvents.ts` 的 `subgraphPathLabel`/`subgraphPathPrefix`；子层 paused 同样展示 globals/历史/改写续跑。
- 契约改写：docs/03 debug_session「subgraphPath 预留（子图断点仍缓做）」「subgraph 内部不暂停」两处、docs/12 run/stream 行「子图内部不产生 paused」随本批改写为进程内已支持。

## 4. 批 3：D28 两项

### 4.1 ⑧ 适配器调用级埋点

**事件与采集**：

- executor tool 分支三处出口（SIMULATED、通用 JSON 通道、shop 通道）统一包 `time.monotonic()` 计时，结束后 emit 内部事件：
  ```json
  {"type": "tool_metric", "node_id": "...", "tool": "message/send",
   "duration_ms": 12.3, "action_status": "SUCCESS|FAILED|SIMULATED",
   "error_code": "STRING|null"}
  ```
  - action_status：SIMULATED 通道记 `"SIMULATED"`；其余取 `output["result"]["status"]`（大写归一）；
  - error_code：取 `output["result"].get("code")`，无则 null（成功通常无 code）；

**语义**：发布前告诉操作者「本次发布将把哪些 subgraph 引用钉到什么版本、相对当前已发布版本钉的是升级还是首次钉版」，引导先跑发布门禁回归；**不自动改草稿、不阻断发布、不做 pin 编辑器**。

  ```python
  def subgraph_upgrade_plan(graph_store, graph_id: str) -> list[SubgraphUpgrade] | None
  # 草稿不存在返 None（端点 404 判定）
  # SubgraphUpgrade: {node_id, sub_id, from_version: int|None, to_version: int, first_pin: bool}
  ```

## 10. 风险与边界

1. **executor 包 try 改变异常面**：⑥只在 debug_controller 存在时包裹，且 RunCancelled/DebugStopped 前置穿透、其余钩子后原样 raise；非调试路径字节级零变化，由既有 712 测试与异常流测试锁定。
2. **门闩重入误判**：⑦父子暂停在同线程但不嵌套持锁（end_pause 在 wait 返回时已释放）；parallel 既有串行锁保护；落码补「父节点 step→子层首节点 step」专门测试。
3. **DSL 注入面**：⑨只接既有递归下降求值器（无 eval/无属性遍历），上下文四白名单键、结果必须 bool、任何异常 fail-safe；前后端同构校验，恶意/非法表达式最多在 PUT 时 422 或运行时静默不告警。
