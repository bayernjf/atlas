# 打包 BM 演示可用性缺陷批（D57/D58/D59）v1 批契约设计

> 立项：2026-10-08，承接打包 BM（docs/18 种子验证入口打开）试用干跑实测登记的三条真实缺陷。
> 形状权威：本文档。用户批准：2026-10-08（「好的」授权推进推荐候选）。
> 编号：D57/D58/D59 各取回一件；本批落码后三条全部闭合（docs/14 逐行翻 ✅）。
> 零新依赖 / 零迁移 / 无 ADR。

## §1 背景与目标

打包 BM（docs/18 首次执行）干跑实测登记三条演示可用性缺陷，均直接削弱「15 分钟、无编程基础」的自助试用承诺：

1. **D57**：演示场景 B「转人工」没有真的进入人工——`GET /api/approvals` 与 `GET /api/interruptions` 实测为空，TRIAL.md §B 的问句「AI 拿不准就找人，这个边界让你放心吗」按演示现状答案是「它只是说了句要找」。
2. **D58**：SSE `error` 事件把原始异常文本（本例 `_DeadlockError: deadlock detected by _ModuleLock('litellm…')`）直接放进帧的 `message`，客户界面/网络层可见内部实现串；前端只能区分「是否翻译」，分不清「配错了」还是「服务器坏了」。
3. **D59**：`POST /api/demo/reset` 是 admin only 且无前端入口，指南却让客户自己敲 curl——与「不需要任何编程基础」冲突（BM 已临时把指南改对：换单号即可、重置归陪同人员）。

## §2 D57：refund-auto 模板真转人工

### §2.1 现状与根因（实测，非推断）

- `template/graphs.py: refund_template_graph()` 只有三节点：`trigger → ai_decision → tool_call(shop/process_refund)`，`ai_decision` 输出 `{"decision": result, "prompt_rendered": prompt}`，`result.action ∈ {approve_refund, request_human_approval}`（`shop/adapter.py:78`）。
- 打包 R（docs/78）已落「置信度闸门＝真挂起」：仅当 `confidence < confidenceThreshold`（缺省 0.6）时复用 `ApprovalBroker` 挂起转人工（人审通过⇒`approve_refund`，拒绝/超时⇒`request_human_approval`）。
- **根因**：模板 prompt 规则「主观原因或金额超限额时必须转人工」让模型对「该转人工」**高置信**输出 `action=request_human_approval`——不触发置信度闸门（`confidence ≥ 0.6`）→ 输出直接落到 `tool_call(shop/process_refund)` → loader 自动取 `decision.action` → shop 服务把订单标 `human_review` 结束。**没有任何人真被叫到**。

### §2.2 决策：模板图层面加真挂起分支（不动节点运行时语义）

新 `refund_template_graph()` 形状：

```
trigger-1 → ai_decision-1 → condition-1（{{ai_decision-1.result.decision.action}} == "request_human_approval"）
  ├─ 真 → human_approval-1（真挂起）→ approvedTarget → tool_call-approve（退款）
  │                                  └─ rejectedTarget → 终节点（无出边，标记拒绝）
  └─ 假 → tool_call-1（自动退款，action=approve_refund）
```

- **condition-1**：`branches=[{expression: "{{ai_decision-1.result.decision.action}} == 'request_human_approval'", target: "human_approval-1"}]`，defaultTarget 指 `tool_call-1`。表达式走 `graph/conditions.py` 既有语法（string token 支持，`==` 比较支持，conditions.py:95/238）。
- **human_approval-1**：`summary` 引用 `{{trigger-1.context.payload.order_id}}`/`amount`/`reason`；`approver` 空＝任何人可决（沿用 A4 语义）；`timeoutSeconds: 3600`；`onTimeout: "reject"`；`approvedTarget: tool_call-approve`、`rejectedTarget: tool_call-reject`。
- **tool_call-approve**：退款工具，params 显式 `{"action": "approve_refund", "note": "人工审批通过"}`（或走 `shop/execute_refund`，落码时按 loader 参数装配选更稳者）；**tool_call-reject**：拒绝记录（`shop/request_human_approval` 语义不对，需落码时确认是否有「拒绝」动作；若无则用无副作用终节点）。
- **不动**：ai_decision 运行时、置信度闸门（双通道都能转人工：低置信闸门 + 显式 action 分流）、其余 4 个模板、DSL/编译器/loader 核心。

### §2.3 影响面（落码时以全量回归为准）

`template/catalog.py` description、`nl_generate.py`（import `refund_template_graph` 生成 NL 草稿，自动跟随新形状，行为正确）、docs/03 模板契约行、docs/06 §9.2 黄金用例、`tests/test_refund_e2e_full_chain.py` 及录制黄金用例断言——凡断言「三节点形状」或「tool_call 直连」者需按新形状适配（行为收紧的预期结果，同 A4 fixture 适配先例）。

### §2.4 验收

U1213 起（新号段，BM 批已用 U1206–U1212；登记 docs/13）：
- 模板编译通过（新形状合法）；
- **转人工路径真挂起**：注入 `action=request_human_approval`（高置信）的 run → `GET /api/approvals` 有 pending、SSE 出现审批 payload；
- 审批通过 → 退款 tool 执行；审批拒绝/超时 → 拒绝侧执行、run completed；
- 自动退款路径（`action=approve_refund`）行为与旧版逐字一致；
- 低置信闸门（`confidence < threshold`）仍挂起（双通道并存）。

## §3 D58：SSE error 帧 message 收口

### §3.1 现状（实测）

`api/main.py:4354-4360`：`__error__` 帧已是 `{message, code, params}` 结构（`runtime_error_meta(exc)` 供码），但 **`message = f"{type(exc).__name__}: {exc}"`**——未知异常（统一 `RUNTIME_UNEXPECTED`）时内部实现串（`_DeadlockError: deadlock detected by _ModuleLock('litellm…')`）原样进帧：网络层可见、任何直连 SSE 的客户端可见、且前端 `resolveRuntimeError` 在码不可识别/占位填不满时回退 message 会原样上屏。

### §3.2 决策

- `runtime_error_meta` 返回 `errorCode == "RUNTIME_UNEXPECTED"`（未知异常）时：帧 `message` 改为安全文案「运行时发生未预期错误」；**完整异常细节（含 repr）只进服务端日志**（`logger.exception` 或既有日志通道）。
- 已知业务异常（`WaitNodeFailure`/`ConditionEvalError`/`AiDecisionUnavailable`/`ConditionClassifierUnavailable`/`SubgraphSuspendUnsupported` 等带 `code` 者）：`message` 保留中文业务文案（运营可读的「配错了」类信息），仅未知异常收口。
- 前端零改动（`resolveRuntimeDetail` 已按码翻译；RUNTIME_UNEXPECTED 在 zh/en runtime.json 均有键）。

### §3.3 验收

U 号段续：未知异常 → 帧 `message` 为安全文案、不含 `type(exc).__name__:` 前缀、日志有细节；已知业务异常 → `message` 保留、`code` 透传不变。

## §4 D59：演示面自助重置

### §4.1 现状

`/api/demo/reset` admin only（docs/12 档位表），前端无入口；`/api/health` 只回 `{"status":"ok"}`，前端无从得知演示面是否开启（prod 档该端点 404，见 docs/75）。试用账号即 `admin-a`（TRIAL.md），权限不是问题，缺的是**入口 + 能力位**。

### §4.2 决策

- **后端**：`/api/health` 响应追加 `"demo_surface": <bool>`（`demo_surface_enabled()`）。health 在公开 allowlist（docs/75 八条）内，**加字段不改路由集合**、不触碰 allowlist 守护；非敏感（prod 档 false）。
- **前端**：`apiClient` 加 `getHealth()`；Editor 页挂载时读 health：`demo_surface === true` 且登录角色 admin 时，工具条显示「重置演示数据」按钮（Popconfirm 二次确认）→ `POST /api/demo/reset` → 成功 message + 刷新当前视图。i18n 新键（zh/en 各 3：按钮、确认文案、成功提示）进 `PARITY_PAIRS` 守护面。
- **边界**：prod 档（demo_surface=false）不显示按钮；非 admin 不显示（虽然试用者即 admin）；reset 仍是 admin only 端点，鉴权不变。

### §4.3 验收

U 号段续：health 含 `demo_surface`（dev 真/ prod 假，档位切换实测）；前端组件测试——按钮渲染条件（demo_surface × 角色）、点击调用 reset、成功提示；i18n 奇偶守护过。
