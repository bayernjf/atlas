# D13 后端 i18n 元数据多语言设计注记

> **状态**：📋 docs-only 设计注记（2026-09-27 立），未立项落码。本文件是 D13「组件描述多语言」后端元数据侧的**形状权威与决策记录**，落码前先走 08/03 流程。零新依赖 / 零迁移 / 零新端点。

## §0 背景与现状

- 前端 i18n 已落地：`docs/17`（方案）+ `docs/57` 打包 D（en-US 全量翻译、运行时语言切换）。前端 `zh-CN`/`en-US` 两套 json 已 PARITY 守护。
- **后端完全没有 locale 处理机制**：grep `locale|Accept-Language|i18n` 在 `src/atlas` 零命中。所有对外元数据字符串写死中文。
- 受影响元数据两处：
  - 流程模板：`src/atlas/template/catalog.py` 的 `TemplateMeta.name/description/tags`（5 个只读内置模板，中文写死）。
  - 适配器：能力/适配器发现元数据 `src/atlas/web/adapter.py`（`name`/`description`）与 `harness/base.py` 的 `Capability.name/description`。
- `docs/08` B 组 `:508` 明确写「前端 en-US 已全量，缺的是**后端元数据**侧」——即本注记要补的缺口。

## §1 目标与范围

**在范围内**
- 后端在既有 GET 端点响应里，按请求 locale 返回本地化的模板 / 适配器 `name`、`description`（及 tags 是否翻译见 §2 D3）。
- 建立后端 locale 解析约定（来源、默认、未知处理）。

**不在范围内**
- 错误码 / 运行时失败文案的 i18n（已随 `docs/60` G1 落码，本注记不重复）。
- 用户自创作的图内容（节点 label、变量名等）本地化。
- 后端返回「全部 locale 由前端自选」还是「前端自带翻译表」——本注记采用**后端按 locale 选定返回**（与 B 组口径一致），不把翻译责任推回前端。
- 不解除 D12/D13 整体；本注记只取回「后端元数据」这一切片。

## §2 关键决策（ADR 级）

**D1 · locale 来源**
- 从请求头 `Accept-Language` 取**首档**，与 `{zh-CN, en-US}` 匹配；缺省、无法解析、或不在集合内 ⇒ 回退 `zh-CN`（fail-closed，绝不因 locale 解析失败报错）。
- **不新增 locale query 参数、不新增端点**：保持「零新端点」。
- **不引第三方 locale 解析库**：手写「取首个 `xx-XX` / `xx` 片段、按连字符归一化」即可（仅两档语言，无需完整 BCP47 实现）。

**D2 · 零新依赖 / 零迁移 / 零新端点**
- 双语元数据**内联为代码常量**（模板 5 个 + 适配器发现元数据），无 DB、无迁移。
- 响应形状**保持稳定的字段**（`name`/`description`/`tags` 仍原名字段），只把值换成按 locale 选定的串；**不新增 `name_i18n` 等副字段**，避免前端双写分支。

**D3 · 双语数据形状**
- `TemplateMeta` 增 `i18n: dict[str, LocalizedMeta]`，`LocalizedMeta{name: str, description: str}`；适配器元数据同理加 `i18n` map。
- `zh-CN` 为必填基线（现有中文串直接迁入）；`en-US` 必须补齐。
- **tags 不翻译**：标签是技术分类键（如 `退款`/`数据库`），作为分类检索键而非展示文案；若要展示文案由前端 i18n 层按 key 映射（沿用现有前端 i18n 习惯）。
- 专名不译（Shopify、PostgreSQL 等保留原文），只译描述性文字（沿用 `docs/17`/`docs/57` 约定）。

**D4 · PARITY 式断言**
- 新增 pytest 断言：每个模板 / 适配器实体在 `zh-CN` 与 `en-US` 两档都有非空 `name`/`description`，漏译即测试红（对照前端 `i18n.test.ts` PARITY 守护，但后端用单测而非前端测试守）。

## §3 数据结构（草案）

```python
class LocalizedMeta(BaseModel):
    name: str
    description: str

class TemplateMeta(BaseModel):
    id: str
    name: str            # 兼容字段，= i18n[resolved_locale].name
    description: str      # 兼容字段，= i18n[resolved_locale].description
    tags: list[str] = []  # 语言无关，不翻译
    i18n: dict[str, LocalizedMeta]   # {"zh-CN": ..., "en-US": ...}
    graph: dict[str, Any]
```

适配器侧在现有 discovery 投影上同理补 `i18n`。

## §4 接线端点与改动面

新增一个极小的后端 locale 工具（无新依赖）：
- `src/atlas/web/i18n.py`：`resolve_locale(accept_language: str | None) -> str`（返回 `zh-CN` / `en-US`）；`localize_meta(meta, locale)` 返回按 locale 选定的投影。
- 仅改动既有 GET 处理器：`GET /api/templates`、`GET /api/templates/{id}`、`GET /api/adapters`（及任何返回模板/适配器元数据的聚合端点）。处理器先 `resolve_locale`，再 `localize_meta` 后返回，响应形状不变。

## §5 验收与反向门

- G1：请求 `Accept-Language: en-US` ⇒ 响应 `name/description` 为英文；还原为 `zh-CN` 或不带头 ⇒ 中文（红→绿各一次）。
- G2：非法 / 缺失 `Accept-Language` ⇒ 回退 `zh-CN`，不报错。
- G3：pytest 断言所有模板 + 适配器两档 locale 均有非空翻译；故意删一条 en 翻译 ⇒ 测试红。
- 前端冒烟：切 en-US 后模板库 / 适配器列表显示英文 name/description。
