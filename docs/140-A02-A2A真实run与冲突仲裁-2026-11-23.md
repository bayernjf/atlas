# A-02：A2A 起真实 run + 多智能体冲突仲裁（2026-11-23）

> 口径：Atlas 现阶段 P0 的最后一条（A-01/A-05 已完成）。目标是证明 A2A 入口不再只是
> plan-only 咨询面，而能在租户绑定前提下真实执行一张已保存图的 run，并让多个调用方
> 在同租户/同图上按明确策略冲突仲裁；不是公网多副本、OAuth2 或机器账号表批次。
>
> **2026-11-25 后续（台账持久化）**：`ATLAS_STORAGE_BACKEND=pg` 时 A2A task ledger 已改为
> `PgA2ALedger`（表 `a2a_tasks`，迁移 061），`tasks/get` / `tasks/cancel` / 幂等重放跨重启
> 可读；memory 档仍按本文记录“重启即失”。`_active_runs` 单飞锁仍进程内。见
> [docs/144 §2.5](144-上线口径本地最大完成度-2026-11-25.md)。

## 1. 完成口径与结论

| 完成口径 | 本次落点 |
| --- | --- |
| `tasks/send` 起真实 run（非 plan-only） | 新 skill `run-graph`；`tasks/send` 同步执行租户图，写租户 `run_store`，artifact `mode="run"` |
| 调用方 token 绑定 tenant | 新 `ATLAS_A2A_TASK_TOKENS=caller:tenant:token,...`；legacy 单 token 仅 plan-only |
| 幂等 | `(tenant, idempotency_key)` → 原 task 快照；同 key 不同请求回 `-32004` |
| 冲突策略 | `(tenant, graph_id)` 进程内单飞；占用中回 `-32003`，带 `activeTaskId` / `activeRunId` |
| 3 Bot 沙盘换真实 run | 3 个 Bearer 身份（bot-a/bot-b 同租户、bot-c 异租户）经真实 HTTP 各起真实 run；不再用假执行体 |
| 单进程重启语义写清 | task 台账与 run_store 默认都在进程内存；重启后 `tasks/get` 丢失、run 记录丢失。2026-11-25 后：PG 档 run_store 与 task 台账均持久化，memory 档仍丢失 |

**结论**：A-02 本地口径完成。不是“A2A 全功能完成”——交互图续跑、任务台账持久化、
多副本、机器账号表、OAuth2、push notification 都不在本批。

## 2. 代码落点

### 2.1 鉴权与租户绑定（`src/atlas/a2a/auth.py`、`router.py`）

- `ATLAS_A2A_TASK_TOKENS=caller:tenant:token,...`，按 `split(":", 2)` 解析，token 可含冒号；
  每个 token 同时绑定调用方 id 与租户 id，日志/响应不回显 token。
- `ATLAS_A2A_TASK_TOKEN`（旧单 token）保留，但身份 `legacy` 且 `tenant_id=None`：
  只能走 plan skill；`run-graph` 回 `-32010`。
- 配了多 token 标签后**不再回退旧单 token**，避免旧凭证绕过租户绑定。
- prod 两组都未配置 ⇒ 401 fail-closed；dev/test 未配置 ⇒ 本地联调身份，同样不能真实 run。
- 任务端点把同步执行体放进线程池（`run_in_threadpool`），真实 run 不阻塞事件循环。

### 2.2 真实 run（`src/atlas/a2a/run.py`、`rpc.py`）

- 新 skill `run-graph`，参数：`tenant_id`、`graph_id` 必填；`inputs`、`release_version`、
  `idempotency_key` 可选。`release_version` 不传时读 latest 草稿，传则读冻结发布版。
- 从 `tenant_registry.get(tenant_id)` 取 `graph_store` / `run_store` / `approval_broker` /
  `event_wait_broker` / `memory_store`；不复制 `api.main` 私有全局。
- 执行注册表 `build_base_registry(demo_surface, resolve_database_client(demo_surface))` +
  `build_runtime_registry(services, base, secret_provider=None)`；database/shop/web 仍受
  演示面开关约束，prod 未开演示面时图里选不到。
- run 记录：`run_store.begin(run_id, graph_id, mode="a2a")` → `finish(status, outputs, trace)`；
  artifact 带 `runId/graphId/tenantId/outputs/trace/status`，`x-zeus-report` 明写
  `real run: mode=run (not plan-only)`。
- 图级 `globalErrorHandler` 的 `mark_only`/`route_to_subgraph` 以 `status="failed"` 返回时，
  不当“未知状态”丢弃：`global_error` 的 code/detail、outputs、trace 一并写 run_store 与
  artifact；`error` 直接可读（如 `NODE_EXECUTION_FAILED: boom`）。
- **交互图前置拒绝**：`human_approval` / `wait`（含可解析子图）在启动前回
  `INTERACTIVE_GRAPH_UNSUPPORTED`，不产生 run_store 记录；避免 A2A 线程永久挂起。
- 运行中才发现挂起（子图等）时，run 记 `suspended`、task 回 `input-required`；**A2A v1 不提供
  续跑**，仍回平台会话处理。
- LLM token 未计量：`cost.llmTokens=0` 仅对本次 demo SQL 图准确；报告里同时写
  `tokenAccounting="not-metered"`，不把“没计量”伪装成“零消耗”。

### 2.3 幂等与冲突

- 幂等：`(tenant, idempotency_key)` 映射到 task_id + 请求指纹；重复同请求直接返回原 task
  快照（同 task id、同 runId），不新建任务、不重跑；同 key 不同 graph/inputs/version 回
  `-32004`，并带原 `taskId`。
- 冲突：`(tenant, graph_id)` 进程内单飞锁。第二调用方在锁占用期间回 `-32003`，`data` 带
  `activeTaskId` 与 `activeRunId`；首个 run 结束（成功/失败）后锁释放。
- 租户：调用方 token 绑定 tenant 与参数 `tenant_id` 不一致回 `-32011`；A2A 不接受调用方
  自带租户越权。

### 2.4 卡片与协议

- Agent Card 升 `0.2.0`；skills 三项：
  - `plan-approval-flow`（plan-only）
  - `run-graph`（`real-run` / `tenant-bound`）
  - `diagnose-run`（plan-only）
- handshake `dataPolicy` 由 `read-task-scope` 改 `write-task-scope`；`notes` 说明真实 run、
  交互图拒绝、多 token 与单副本任务台账。
- JSON-RPC 新增 `-32003/-32004/-32010/-32011/-32012/-32013/-32014`。

## 3. 真机证据

脚本：`scripts/verify_a2a_real_run.py`。起本机 uvicorn `127.0.0.1:8942`，3 个 Bearer
身份经真实 HTTP 调 `/api/a2a/tasks`，进程内 demo SQLite 真跑图。

| 项 | 结果 |
| --- | --- |
| Agent Card | `0.2.0`，skills `plan-approval-flow / run-graph / diagnose-run`，`write-task-scope` |
| bot-a（a2a-alpha） | 真实 run completed，`graph-1`，run_store completed，SQL 返回 orders=2 |
| bot-b（a2a-alpha） | 真实 run completed，独立 runId |
| bot-c（a2a-beta） | 真实 run completed，独立租户 runId |
| 幂等重放 | 同 taskId、同 runId；`runStoreRecordsForGraph=1` |
| 冲突 | bot-a 的 `alpha-slow`（10,000,000 行递归 CTE）running 时，bot-b 同图调用回 `-32003`，带 activeTaskId/activeRunId；首个 run 最终 completed，第二调用未产生新 run |
| 租户隔离 | bot-c 传 `a2a-alpha` 回 `-32011` |
| 交互图拒绝 | `wait` 图回 task failed，`errorCode=INTERACTIVE_GRAPH_UNSUPPORTED`，run_store 记录 0 |
| 任务台账重启语义 | `reset_for_tests` 后 `tasks/get` 回 `-32001`；同进程 run_store 仍可查；真实进程重启两者都丢（memory 档） |

产物：`outputs/a02-a2a-real-run/` 的 `evidence.json`、`alpha-fast.json`、`alpha-slow.json`、
`alpha-interactive.json`。证据 JSON 顶层 `ok=true`。

## 4. 边界与未做

- **只接非交互图**：`human_approval` / `wait` 直接拒绝；没有 A2A 审批决策、没有续跑、
  没有 `tasks/cancel` 对真实 run 的取消信号。审批仍在平台会话。
- **任务台账仍是单副本内存**：30 分钟 TTL、500 上限；进程重启丢失。`run_store` 默认也是
  内存，`ATLAS_STORAGE_BACKEND=pg` 时 run 记录入库，但 A2A task/idempotency 仍只在内存。
- **没有机器账号表/OAuth2/凭证轮换**：多 token 是过渡方案；token 轮换靠改 env，无审计表。
  `docs/90` item 4 以“① 多 token 标签”收口，②/③ 留到统一账号体系或第三方接入。
- **没有多副本/跨进程锁**：单飞锁只在单进程内有效；多副本需要分布式锁或串行队列。
- **没有 push notification / 任务恢复**。
- **LLM 用量未计量**：真实 AI 节点图能跑，但 `llmTokens` 不是真实计费数；本批 demo 图不含 LLM。
- **没有改现有平台运行入口**：`POST /api/graphs/{id}/run`、`/run/stream`、审批、沙盘、
  适配器全部保留；A2A 只是新增入口。
