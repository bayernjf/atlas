### 0.2 用户所指的「占位」在一条**从 API 不可达**的路径上

- 占位本体：`src/atlas/engine/nodes.py:67 reflect_node` —— 形参收全量 `LoopState`，**实参只读 `variables["step"]`**，产出一句 `reflect@{step}: loop finished`；无 run／metrics／memory 入参。
- 它挂在 `src/atlas/engine/loop.py:32 build_graph()` 的 OODA 图上（`observe→orient→decide→act→[should_reflect_or_continue]→observe|reflect→END`）。
- **`run_loop`（`loop.py:73`）全仓零调用**：`grep -rn "run_loop" src tests frontend/src` 只命中它自己的定义行；`tests/test_engine_loop.py:3` 只 import `build_graph, initial_state`。真实运行时是 `src/atlas/graph/loader.py:run_graph`（API 唯一入口）。
- 结论：**把 `reflect_node` 写实，改的是一条没有任何调用方的骨架**；L2 的正确落位在 `graph/loader.py` 之外的离线 pass，不在 `engine/loop.py` 里（见 §2 D-2）。

## 2. 决策（D-1…D-8；工程侧推荐，改任何一条先改本文）

- **D-1 命名与切分**：三层固定称 **L1 平台级进化 / L2 单运营体反思 / L3 策略离线训练**；此后文档写「反思进化」必须带层号。L2 英文标识用 `reflection`（包名 `src/atlas/reflection/`），不用 `evolution`（后者易与 L1 混）。

- **D-2 落位＝离线 pass，不动 `engine/loop.py`**：L2 是 `graph/loader.py` 之外的一个**只读分析 + 候选产出**过程，输入是 §0.3 的证据投影，输出是候选；**不新增节点类型**（对齐 T23 记忆选「适配器而非新节点」的先例），**不在 `run_graph` 热路径里插同步反思**。`engine/loop.py` 的 `reflect_node` 占位处置见 §3 P-2。

- **D-3 证据源＝既有只读投影，零新存储**：v1 只读 `monitoring`（`per_version` 业务段 + `per_graph` + `failed_nodes`）、`recording` 的 replay/gate 报告、`shadow` 比对、`alerts`。**不新建证据表、不改 RunRecord**。反思 pass 自身可留一份 ring 报告（同 `ReleaseReport` 的 ring 100 先例），但那是产出物、不是证据源。

- **D-4 可调参数白名单＝v1 只许 §0.4 四项**：`approval_limit`（图全局变量）、节点 `confidenceThreshold`、`RuleConfig` 阈值、每图 `GateConfig` 阈值。**白名单外的任何字段（尤其 promptTemplate 之外的任意节点 config、任何 adapter/凭证/权限字段）一律拒绝**，越界即整份候选作废（fail-closed），不做「部分采纳」。
  - **提示词模板的特别条款**：docs/02 原文允许「调整提示词模板」，但提示词是无界文本，**v1 仅允许产出「建议文本」供人阅读，不写入任何节点 config**；真正改 promptTemplate 须人工在编辑器里改（即 v1 的 prompt 建议是**建议、不是候选变更**）。这一条是对 docs/02 原文的有意收窄，理由：无界文本无法门控、无法回滚语义化。

- **D-5 产出形态＝候选版本，不是活图变更**：反思产出 `ReflectionCandidate`（§4），落到**新的草稿版本**上，走既有 `versioning/publish.py` 冻结为不可变版本；是否放量走既有 `routing` canary 门控（指标不达标 → 自动回滚，**永不自动 promote**）。反思**不直接改当前活跃版本**——这是复用既有机制的关键，也是「可回滚」的语义来源。

- **D-6 触发形态＝显式触发，不做后台常驻**：v1 只提供「对某 graph 跑一次反思 pass」的显式入口（定时复用 `scheduling/` 的触发载体、或 REST 手动触发，二者取一，见 §3 P-4）。反思**不订阅** run 完成事件、不起后台线程——守 D-3/§1 的纯函数内核。

- **D-7 无 LLM 时确定性降级**：反思的「总结优劣」这一步走现有 `llm/decision.py` DecisionClient 三件套（LiteLLM）；**未配置供应商时返回结构化但建议为空的报告，不失败、不抛错**（对齐 T1「Demo 用 LiteLLM 接商业 API，密钥经 .env 切换」与既有条件分类器的 fail-safe 惯例）。统计类结论（哪些节点失败最多、哪版指标退化）**不依赖 LLM**，纯计算即可得。

- **D-8 租户边界**：反思在**单租户内**运行（证据、白名单参数、候选、报告全部按 `tenant_id` 分区），复用 `TenantServices`；跨租户**零可见**（同 04 §5.14 的 404 语义）。L1 需要的跨租户视角在此层被明确拒绝。

## 4. 契约形状（v1 草案；落码时同步 docs/03 契约总览行）

四个结构，全部**只读投影或建议物**，不含执行语义：

```text
ReflectionEvidence          # 只读证据包，一次 pass 的输入（D-3）
  tenant_id: str
  graph_id: str
  base_version: int                 # 反思基于哪个已发布版本
  window: {since, until}            # 证据时间窗
  per_version: [ {version, runs, business{...}, error_rate} ]   # 源：summarize_business
  failed_nodes: [ {node_id, count} ]                            # 源：summarize
  replay: {matches, total} | null                                # 源：replay.compare
  shadow: {match: true|false|null, total} | null                 # 源：ShadowComparison
  alerts: [ {rule, count, action} ]                              # 源：Alert

TunableParam                # 白名单条目（D-4），v1 恰四条，硬编码常量表
  key: str                  # 如 "approval_limit" | "node.confidenceThreshold"
                            #    | "monitor.failure_rate.rate" | "gate.run_error_rate"
  scope: "graph_variable" | "node_config" | "monitor_rule" | "gate_config"
  current: number|str
  bounds: {min, max}        # 允许的取值区间；候选越界即整份作废

ReflectionCandidate         # 产出物（D-5）：待落到新草稿版本的变更建议
  candidate_id: str         # refl-N（进程内 ring，同 ReleaseReport 先例）
  graph_id: str
  base_version: int
  changes: [ {param_key, from, to, reason} ]   # param_key 必须在 TunableParam 白名单内
  prompt_suggestions: [ str ]                  # D-4 特别条款：**建议文本，不写入 config**
  evidence_digest: str                         # 证据摘要（人可读）
  generated_at: str                            # UTC ISO-8601

ReflectionReport            # pass 的收尾记录（ring 100），供人查看与后续验收
  candidate_id: str | null      # 无建议时为 null（含未配 LLM 的降级路径，D-7）
  status: "ok" | "rejected_whitelist" | "rejected_bounds" | "no_evidence"
  reasons: [ str ]
```

**不定义的**：反思的调度状态（若 P-4 选 (a)，复用 `ScheduleRecord`）、反思的持久化表（v1 进程内 ring；PG 化随真实需求，同 D32 的切片先例）、任何自动 apply 的接口。
