# Atlas 种子客户验证计划（Phase 1）

> **用途**：08 文档 Phase 1「Demo 验证」的执行方案——目标客户画像、招募标准、试用脚本、验证指标与反馈收集机制。08 定义目标（3-5 家种子、验证核心价值），本文定义**怎么做**。
> **状态**：2026-09-13 初版。配套客户向一页纸操作指南：[TRIAL.md](../TRIAL.md)。
> **AI 使用提示**：试用反馈进入后的改动以此文目标为排序依据；新反馈项落 handoff「Active feedback/Active work」。

## 1. 验证目标

验证 [01 PRD](01-PRD-产品需求规格.md) 的核心价值假设，而非验证功能完备性：

1. **非技术人员能否自主搭出一条自动流程**（拖拽 + 自然语言生成）。
2. **AI 决策是否可信**：退款原因/金额判断符合商家预期（06 §9.2 黄金规则）。
3. **敏感操作安全感**：超限额/主观原因自动转人工，不越权退款。
4. **画布实时进度与结果是否看得懂**（可观测性价值）。
5. **从启动到跑通第一条退款链路的端到端耗时**（交付与上手成本）。

## 2. 目标客户画像与招募标准

**画像**：有售后退款处理的中小电商团队（1-3 人运营/客服），日均退款单 10-100 单，退款审批靠人工看后台。

**招募标准（3-5 家，08 Phase 1）**：

- 退款处理人是非技术人员（验证 DIY 假设）。
- 愿意提供 3-5 笔真实/脱敏退款单用于验证决策。
- 能安排一次 30-45 分钟的陪同试用 + 一份反馈表。
- 至少 1 家能试用真实 LLM（配 `LITELLM_MODEL`），其余可用离线规则兜底——验证两条路径。

**暂不纳入**：强定制 ERP 对接需求、要求移动端、要求私有化/数据落库（这些属 Phase 2+，见 [14 缓做登记](14-缓做事项登记表.md)）。

## 3. 交付与环境

- 一键交付：`docker compose up --build`（2026-09-13 已落，见 09 待定项 3、12 文档静态托管端点）。
- 每家试用前重置：`POST /api/demo/reset`（恢复 5 笔种子单、清空已保存图）。
- 默认离线可跑（规则决策，5 笔黄金用例 12345-12349）；提供 key 的客户走真实 LLM。
- 模拟商家后台：http://localhost:8000/demo/shop（demo/demo），用于观察自动登录/拉单/退款落账。

## 4. 试用脚本（对应 08 §7.3 七条验收）

按 [TRIAL.md](../TRIAL.md) 的三个场景执行，陪同记录：

| 场景 | 操作 | 验证假设 | 记录 |
|---|---|---|---|
| A. 自动退款 | 选 12345（破损/299）运行，看控制台该单消失 | 质量原因限额内自动执行，决策可信 | 是否认同结果、卡点、耗时 |
| B. 人工兜底 | 选 12346（不想要了/5000）运行，确认 human_review | 敏感场景不越权，安全感 | 兜底是否符合预期 |
| C. 自然语言生成 | 点"自然语言生成"输入退款描述，载入手改 | 非技术人员能用 NL+拖拽产出流程 | 生成结果可用度、需手改处 |

补充观察：SSE 节点状态/调试日志是否看得懂；变量传递（退款单→提示词→工具）是否需要解释。

## 5. 验证指标（试用后判断 Go/No-Go 进入 Phase 2）

| 指标 | 目标 |
|---|---|
| 无协助跑通场景 A 的客户比例 | ≥ 3/5 |
| 从启动到首次退款成功的耗时 | ≤ 20 分钟 |
| 5 笔黄金用例决策认同率 | 100%（规则路径）；LLM 路径记录分歧案例 |
| NL 草稿"无需大改即可运行"比例 | ≥ 3/5 |
| 愿意继续试用/付费意向 | ≥ 2 家明确愿意 |
| 每客户反馈 bug/建议数 | 记录数量与高频类别 |

未达标项反哺 08 排期：高频卡点优先于 Phase 2 新节点/新适配器。

## 6. 反馈收集机制

- **应用内**：编辑器"反馈"按钮 → `POST /api/feedback`（类型 bug/建议、内容、联系方式，进程内存储，与 Demo 同假设；陪同试用时由我们导出）。
- **试用后表**：TRIAL.md 末尾的反馈表模板（5 个问题，2 分钟填完）。
- **防丢**：未解决反馈按 [16 反馈工作流](16-反馈工作流.md) 进 handoff「Active feedback」，解决后在 Recently shipped 留痕。
- **节奏**：每完成一家更新本文 §5 指标实测值（追加"试用记录"小节，日期/客户代号/结果）。

## 7. 不做（边界）

- 不在种子阶段接真实电商平台（shop/ 为模拟目标系统；真实适配属 Phase 2 API 适配器）。
- 不做多租户、数据持久化、账号体系（进程内 + reset 足够陪同期试用；触发条件见 14 D7/11 S1）。
- 不承诺 bug 修复 SLA；严重问题当场记录、按优先级排期。
