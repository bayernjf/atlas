## 2. 本轮代码改动

### 2.1 本地回环放行（只给本地目标应用）

问题：`EgressGuard` 恒拦 `127.0.0.0/8`，而 A-01 的目标应用是本机 Loom 前端。此前 dev 虽注册了 `web-playwright`，但 `navigate("http://127.0.0.1:3000/...")` 仍会被拒绝，等于「注册了却打不开本地目标」。

改动：

- `src/atlas/security/egress.py`：
  - 新增 `WEB_LOCAL_LOOPBACK_ENV = "ATLAS_WEB_ALLOW_LOOPBACK"` 与 `web_local_loopback_permit()`。
  - 规则：`ATLAS_ENV=prod` 恒返回空；非 prod 默认放行 `127.0.0.0/8` 与 `::1/128`；显式 `ATLAS_WEB_ALLOW_LOOPBACK=0` 关闭。
  - `EgressGuard.from_env()` 增加可选 `permit_cidrs` 透传；其余消费点（HTTP/message/connections/channels）不传，行为不变。
- `src/atlas/web/adapter.py`：默认构造改为 `EgressGuard.from_env(permit_cidrs=web_local_loopback_permit())`。
- 只放回环，不放 `10/8`、`192.168/16`、链路本地与云元数据；`navigate` 初始 URL 仍先过同一把守卫。
- 新增 `scripts/verify_web_flow.py`：可重复的本机流程验证器，产出 trace 和截图。

### 2.2 安全边界（照实说）

- `ATLAS_ENV=prod` 不使用该回环放行；且 prod 未开演示面时 `web-playwright` 根本不注册（既有 U1130 守护）。
- `page.route()` 仍挡不住 3xx 跳转后的请求（Playwright 不为跳转目标回调）；本机 Loom 的 `/` → `/zh-CN` 就是 3xx。本次流程直接 `navigate` 到最终 `/zh-CN/analytics`，未把该绕过路径当作已修。D52 维持缓做。
- 本次流程是**只读筛选**：填日期 + 点「应用」；没有创建/删除/发布/退款等真实副作用。真实副作用属 A-05，不在 A-01 冒充完成。
