## 1. 范围

### A. Channel 内核（`src/atlas/channels/`）

- `base.py`：
  - `ChannelError`（结构化错误，code：`CHANNEL_NOT_BOUND` / `CHANNEL_UNAUTHORIZED` / `CHANNEL_UPSTREAM_FAILED` / `CHANNEL_INVALID_RESPONSE` / `CHANNEL_INVALID_PARAMETER`）。
  - `ChannelTransport` Protocol：`request(method, url, headers, json_body, timeout) -> {status, headers, body}`；`HttpChannelTransport`（stdlib urllib，**每次先过 `EgressGuard.check`**，超时默认 10s、follow_redirects=False，与 httpapi/webhook 同口径）。
  - `ChannelBinding`（`id, provider, connection_id, config, status, last_error, created_by, created_at`）。
- `shopify.py`：`ShopifyChannelClient`——
  - 构造参数：`shop`（`*.myshopify.com` 的店铺名或完整域）、`api_version`（默认 `2025-01`，正则 `^\d{4}-\d{2}$`）、`access_token`（由绑定连接在调用时解密注入，客户端不持久化）、`transport`（可注入 fake）。
  - base URL：`https://{shop}.myshopify.com/admin/api/{api_version}`；`shop` 归一化（去协议/路径/`.myshopify.com` 后缀，仅允许 `[a-z0-9][a-z0-9-]*`，非法 → `CHANNEL_INVALID_PARAMETER`）。
  - 每个请求带头 `X-Shopify-Access-Token: <token>`、`Accept: application/json`；401/403 → `CHANNEL_UNAUTHORIZED`；非 2xx → `CHANNEL_UPSTREAM_FAILED`（带 status）；JSON 解析失败 → `CHANNEL_INVALID_RESPONSE`；**绝不上日志明文 token**。
  - 操作（纯函数式参数构造，`_build_*` 可单测）：
    1. `list_orders(status="open", limit=50)` → `GET /orders.json?status=&limit=`（limit clamp 1–250；status ∈ open/any/closed），返订单精简投影列表 `[{id, name, email, financialStatus, fulfillStatus, totalPrice, currency, createdAt}]`（字段映射 `financial_status`→`financialStatus` 等，缺字段 null）。
    2. `get_order(order_id)` → `GET /orders/{id}.json`，返同上投影。
    3. `create_refund(order_id, amount, reason="", full_refund=False)` → `POST /orders/{id}/refunds.json`：先 `get_order` 取 line_items；`full_refund=true` → 每项 `refund_line_items:{line_item_id, quantity, restock_type:0}`；部分退款 → 同样回传全部行但 `quantity:0`（金额以 `transactions:[{kind:"refund", amount}]` 为准）；体 `{"refund":{"note": reason≤200, "notify": false, "refund_line_items":[...], "transactions":[{"kind":"refund","amount": str(amount)}]}}`；`amount` 必须为正数、≤ 订单 totalPrice，否则 `CHANNEL_INVALID_PARAMETER`；返 `{refundId, status, amount}`。
- `registry.py`：`ChannelStore`（绑定 CRUD，进程内实现 `channels/memory.py`：dict + 锁、`ch-N`、list/get/save/delete、clear；PG 实现见 D 包）与 `ChannelRegistry` 服务——
  - `bind(provider, connection_id, config, created_by)`：校验 provider ∈ `{"shopify"}`、`connection_id` 在本租户 connection_service 存在（跨租户/不存在 → `CHANNEL_NOT_BOUND` 语义 404 不泄漏）、同 connection 唯一绑定（重复 → 409）；保存并尝试连通性校验（见 test）。
  - `client_for(binding)`：从 connection_service 解密当前 access_token（连接未完成授权/错误 → `CHANNEL_UNAUTHORIZED`），构造 `ShopifyChannelClient`。
  - `test(binding_id)`：过期连接先走 T4 自身刷新逻辑；Shopify token 不过期无 refresh；返 `{ok, status, reason}`（Shopify 以 `GET /shop.json` 探活，不触发业务写）。
- 所有异常在适配器边界转 `ActionResult.failed(StructuredError(...))`，不向图抛裸异常。

### B. 图内工具（Harness 适配器形态）

- `shopify/adapter.py`：`ShopifyHarnessAdapter(HarnessAdapter)`，`adapter_id="channel:shopify:{binding_id}"`、`adapter_type="shop"`；由 `ChannelRegistry.adapters_for_tenant()` 按绑定动态产出，注册进该租户运行用的 `AdapterRegistry`（loader 装配点，同 GENERIC_JSON_ADAPTERS 模式）。
- 能力（均以绑定 id 隔离，多店铺 = 多绑定 = 多工具前缀）：
  - `shop/list_orders`（read、idempotent；input `{status?, limit?}`）
  - `shop/get_order`（read、idempotent；input `{order_id}` required）
  - `shop/create_refund`（**financial**、非幂等；input `{order_id, amount, reason?, full_refund?}`）
- 影子/回放不装配真实渠道适配器（与 T2 notifier 同口径），`run_graph(shadow=True)` 对写能力短路 SHADOW_DRY_RUN 的既有机制在 docs/33 已立；本批不为渠道写影子逻辑——影子运行里渠道工具不可见。

### C. REST（`/api/channels`）

| 方法 | 路径 | 能力门 | 语义 |
|---|---|---|---|
| GET | /api/channels | read | 列出本租户绑定（投影不含 token/secret） |
| POST | /api/channels | operate | body `{provider, connectionId, config:{shop, apiVersion?}}` → 建立绑定，201 |
| GET | /api/channels/{id} | read | 单个绑定 |
| POST | /api/channels/{id}/test | read | 探活（上游真实调用；连接错误 200 体 `ok:false`，不 5xx） |
| DELETE | /api/channels/{id} | administer | 删除绑定（不影响底层 connection） |

- 404 语义：未知绑定/绑定不属于本租户统一 404「渠道绑定不存在」；绑定引用的 connection 已被删 → 绑定 `status=error`，不自动级联删除。
- 审计：POST/DELETE 写审计 `channel.bind` / `channel.unbind`（不含 token；config.shop 在 path/query 之外不记录）。
- reset：**绑定不被 reset 清除**（同 connections，属客户配置；docs/35 reset 契约同步补一行）。

### D. PG 持久化（迁移 015）

- `015_channel_bindings.sql`：`id TEXT PK, tenant_id TEXT, provider TEXT, connection_id TEXT UNIQUE, config JSONB, status TEXT, last_error TEXT, created_by TEXT, created_at TEXT, updated_at TEXT`；按租户查询、连接删除后留 error 态（不 FK 强约束，跨表均为 TEXT 口径）。
- `channels/pg.py`：`PgChannelStore`，裸 SQL 风格对齐 connections/audit PG 实现；reset 不清。
- 内存档为默认；`ATLAS_STORAGE_BACKEND=pg` 时 registry 装配 PG store。integration 用例随 DATABASE_URL skip。

### E. 前端（Connections 页扩展，不新增页面）

- Connections 页底部加「销售渠道绑定」卡：列出绑定（店铺、provider、状态 Tag、来源连接）、绑定表单（选 provider=Shopify、选已有 connection 下拉、shop 名、apiVersion 默认 2025-01）、测试/删除按钮（删除 admin 门）。
- apiClient：`listChannelBindings/createChannelBinding/testChannelBinding/deleteChannelBinding` + 类型；`channels` i18n namespace（zh 填实、en-US `{}`）。
- Editor 适配器发现列表自动出现 `channel:shopify:*` 工具（既有 /api/adapters 通路，零额外改动）；画布节点引用不做专项 UI。

## 2. 非目标（写入 docs/14）

- 真实店铺 OAuth 授权联调（需真实合作伙伴账号/店铺，外部资源）；Amazon/其他平台适配器。
- 入站 webhook（订单/退款事件推送）与 HMAC 签名验收入站；订单增量同步落库、分页游标。

- 退款单与平台订单的自动对账报表。

## 3. Schema 契约（03 同步）

新增 `channel_binding`：

```text
ChannelBinding = {
  id:            str   # ch-N
  provider:      str   # "shopify"
  connectionId:  str   # 绑定的 T4 connection id（同租户、唯一）
  config: { shop: str, apiVersion: str }
  status:        str   # connected | error
  lastError:     str | null
  createdBy:     str
  createdAt:     str   # epoch 秒文本（对齐 connections 口径）
}
```

REST 请求体：`{provider: str, connectionId: str, config: {shop: str, apiVersion?: str}}`；
REST 投影：`{id, provider, connectionId, config:{shop,apiVersion}, status, lastError, createdBy, createdAt}`。

工具输入/输出形状以本文 §1 B 为权威；订单投影字段以 §1 A `list_orders` 为权威。

## 4. 运行时语义（06 同步）

- 调用链：tool_call `shop/create_refund` → ShopifyHarnessAdapter → ChannelRegistry.client_for（**每次调用现解密 token**，不缓存明文）→ EgressGuard.check(shopify URL) → transport → 错误码映射 → ActionResult。
- token 解密/出向校验失败均在节点边界失败，不阻塞其他节点；financial 能力门不变（loader 对 financial 工具的审批策略原样适用）。
- SSE：渠道工具沿用既有 tool_start/tool_end 帧，不新增帧类型；observe() 提供 `{shop, apiVersion, lastRequest?}`（不含 token）。
- 不装配点：影子、回放、续跑恢复之外的只读路径均不触发上游写；test 端点 GET 语义的上游 `/shop.json` 为唯一手动探活出站。
