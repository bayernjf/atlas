## 2. 范围决策（本批取回四切片，D35 不解除）

**决策 D-1：本批四切片全部走"默认值即现状"的向后兼容路径**——不开启任何新功能时，行为与 v1 完全一致：

- `auto_extract` 关闭时：写入仍只经显式工具 / REST 手动，`confidence` 由调用方给定；
- 注入开关关闭时：ai_decision 与现状逐字一致（图层接线显式 recall）；
- `update_policy` 缺省 `overwrite`（与现状"同 id 白名单覆盖"语义兼容），version/ask 为可选启用；
- decay 缺省关闭（排序 = 纯 cosine，与现状一致），开启时按半衰期加权。

**决策 D-2：auto_extract 落位＝LLM 结构化提取＋阈值门槛，走 llm 包既有通道**（不新引依赖、不新开 provider）：

- 复用 `llm/` 的客户端形态（参考打包 AB 的 classify_intent/extract_fields 结构化输出先例，docs/14 D14 已落）：新增一个结构化提取调用 `llm/memory.py::extract_memories(text, existing_facts)` → `{facts: [{content, confidence}], preferences: [{content, confidence}]}`；
- 提取结果逐条过 **置信度阈值 0.85**（docs/26 §1.2 原文），低于阈值丢弃、记 debug 日志不落库；
- 写入 source 固定 `"auto_extract"`（新增枚举值，REST 手动仍 `"manual"`、图工具显式仍 `"tool"`，docs/26 §2.1 source 枚举扩展）；
- 调用入口：新增图工具 `memory/auto_extract`（WRITE 能力、复用 harness 工具体系、params 由 Schema 自动生成），显式、可观测、可回放——**不做隐式钩子/事件旁路**（与 docs/26 §0 决策 3"零新节点类型、零 DSL 改动"的哲学一致，且回放/影子/黄金用例确定性不受影响）；
- 无 LLM 配置时 fail-closed：走规则兜底＝**不提取、返回空结果**（与 RuleBasedDecisionClient 语义一致），不抛错不阻塞图。

**决策 D-3：注入开关落位＝ai_decision 节点可选配置 `memoryInjection`**：

- `ai_decision` 节点 schema 新增可选字段 `memoryInjection: { enabled: bool (缺省 false), query?: string (缺省节点 promptTemplate 全文), topK?: int (1–20, 缺省 5), minScore?: float (0–1, 缺省 0) }`；
- 开启时：进入节点、构造 LLM 请求**之前**，以 `memoryInjection.query`（缺省用 promptTemplate 原样）走 `memory/recall` 语义等价调用（经注入的 MemoryRepository，非新工具——节点级直接调用与图层工具调用同库同源）；命中结果格式化追加到 user message（`【相关记忆】\n- {content}` 前缀，与 docs/06 §6.2 骨架一致）；
- **作用域语义**：注入检索 scope 固定取当前 run 的 `globals` 子集（user_id/order_id 等业务键，取与 `graph.scope` 有交集者），与图层显式 recall 一致；
- 关闭（缺省）时：节点执行路径与现状零差异（逐字不变，回放/黄金用例零回归）；
- 无记忆库（未装 memory 档）时：fail-safe 注入空段、不阻断（与现有 fail-safe 哲学一致）。

**决策 D-4：update_policy 落位＝存储层可选策略参数**：

- `MemoryRepository.remember` 新增可选参数 `update_policy: "overwrite" | "version" | "ask"`（缺省 `"overwrite"`）＋可选 `dedup_keys: list[str]`（缺省 `[]`）；
  - `overwrite`：命中 dedup_keys 同值（缺省 = 同 scope+kind+content）时**更新原条目 content/confidence/metadata、created_at 不变**（复用 docs/28 批 4⑩ update 的白名单合并语义，两档同构）；
  - `version`：命中时新建条目、`metadata.version` 递增（同 scope+kind 下 max+1，缺省 1）；
  - `ask`：命中时**不静默**——返回冲突标记 `{conflict: true, existing_id}`，由调用方（工具/REST）决定展示与确认；v1 不做自动挂起审批（与 D20/D36 审批域分离，不引 ApprovalBroker）。
- 两档（进程内 MemoryStore / PgMemoryStore）同构实现，PG 走 `scope @> :scope` 子集匹配先例（docs/26 §4.3）。

**决策 D-5：decay 落位＝recall 排序可选加权**：

- `recall` 新增可选参数 `decay: { enabled: bool (缺省 false), half_life_days: int (1–3650, 缺省 30) }`；
- 开启时：`score' = score * 0.5 ** (age_days / half_life_days)`（age 取 `created_at`→now，注入时钟 `now_override` 复用 docs/27 C 批先例保证回放确定）；
- 关闭（缺省）时：排序 = 纯 cosine 降序（与现状逐字一致）。
- 保留期裁剪：**非目标**（另见 D35 行，触发条件＝真实数据积累需求，本批不做删除策略）。

## 3. 前端

- **ai_decision 节点表单**：`nodeUiSchemas` 新增 `memoryInjection` 折叠区（enabled Switch、query TextArea、topK InputNumber、minScore InputNumber），中文 label/placeholder（同全仓节点字段惯例，en-US 随 D12 缓做）；数据层文案不立新 i18n 键。

- **记忆页**：不新增页面；列表如遇 `source=auto_extract` 显示来源 Tag（复用现有 kind 色系，新增一行 source 映射），v1 不做来源筛选/编辑策略选择 UI（策略属工具参数，非页面配置）。

## 4. 错误码与通道

- 无新增 REST 端点（四切片均为节点/工具/存储层能力，图工具经既有 tool_call 通道）。
- 错误码：新增 **1 个**校验码 `MEMORY_EXTRACT_FAILED`（LLM 提取通道异常且无兜底时——按 fail-closed 设计实际不会触发，保留码供显式调用方检测）；`update_policy`/`decay` 参数非法走既有 422 语义（复用 `INVALID_PARAMETER` 聚合，不新增码）。
- docs/03 同步：`MemoryItem.source` 枚举加 `auto_extract`；`memory/auto_extract` 工具 Schema；ai_decision `memoryInjection` 字段。
