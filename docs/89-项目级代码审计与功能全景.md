## 3 分域审计

### 3.1 核心引擎与图运行时（`graph/` `engine/` `scheduling/` `routing/`）

**结构**：`loader.py`(3,029) 是真正的运行时；`dsl.py` 静态校验；`conditions.py` 自研安全表达式（tokenizer+parser，**无 eval/exec**，`conditions.py:78/152`）。`engine/` 是 **W1 占位实现**（`nodes.py:3-5` 自陈五节点均为确定性桩，不调 LLM/Harness），`nodes/` 是空包。

**节点类型 9 种**（`dsl.py:26-36`）：trigger / ai_decision / tool_call / condition / loop / parallel / wait / subgraph / human_approval；挂起点＝`human_approval`+`wait`（`dsl.py:43`），parallel 分支区域内挂起已被编译期 `PAR_SUSPEND_IN_REGION` 拒绝。

**亮点**：合成网关机制干净（`loader.py:91-93`：`__join__` 汇聚屏障、`__break__`、`__skip__`）；条件表达式自研无 eval，安全边界清晰；续跑以帧内 `graph_snapshot` 为权威图（防图已改错位），`resume_consumed` 防循环体内顶掉后续审批（`loader.py:358-361`）。

**风险**：
- **P1 巨型函数**：`_make_executor.execute` 单函数 590 行 if/elif 分派（`loader.py:363-950`）；`compile_graph` 331 行、26 个 kwarg（`2416-2747`）；`api/main.py` 4,793 行。三者是维护成本的主要来源。
- **P1 静默吞异常**：`_namespaced_emit` `except Exception: return`（`loader.py:1268`）**无任何日志**；另有 1621/1636 同类兜底。事件丢失将不可诊断。
- **P1 续跑语义边界**：`_tail_subgraph`（`loader.py:2826`）只做可达闭包，**不携带并行侧支已完成 outputs** ⇒ 已由编译期拒绝规避（D46），但该限制是结构性的，非修复。
- **P1 `time.sleep` 阻塞**：`wait` 同步 sleep 至多 3600s（`loader.py:828`），不可中断、长期占满 worker 线程。
- **P2 无界/经验值**：`__join__` 靠超步空转等待（`2232-2244`），`_recursion_limit` 用 `2*len(region)` 经验估算（`2779-2784`），偏小即 `GraphRecursionError`。
- **P2 进程级单例 broker 无租户隔离**（`loader.py:102-103`），与 `scheduling/__init__.py:6-8` 自陈「不解锁多副本」互相印证。

**测试**：强——`test_graph_loader.py`(96.5KB)、`test_graph_dsl.py`(51.5KB)、`test_loader_resume.py`(26KB)、`test_frame_resume_claim.py`(15KB)。弱——`engine` 仅 1.05KB；`nodes` 无（空包）；`skills`/`logistics` 仅间接覆盖。

### 3.2 存储与持久化（`storage/` `memory/` `database/` `versioning/` `db/`）

**结构**：10 个 Protocol；`pg.py` per-tenant 工厂 + 语句级 `WHERE tenant_id`（无 RLS）；`recovery.py` 帧与认领；34 个迁移连续、零破坏性。

**双档一致性（关键发现）**：PG 档下 **debug_broker / cancellation_broker / event_wait_broker / task_store 仍是内存实例**（`iam/registry.py:142-147`），跨重启丢失；approval 仅帧与历史落库、pending+Event 仍内存（`registry.py:139`）。**这是「切到 PG 就万事大吉」这一直觉的最大反例**，也与 D27/D44 同源。

**租户隔离**：索引全表带 `tenant_id`（`002_storage.sql:16/26/45/62/72…`）；**租户 id 全部参数化绑定，未发现字面量拼接**（注入面干净）。三处**有意**的全局读：`recovery.py:113-122`（跨租户全表扫）、`pg.py:402`（清全部会话）、`pg.py:449/487/526`（按 username 全局查 ⇒ 跨租户 username 唯一）。

**中断恢复**：`ON CONFLICT (resume_token) DO UPDATE`（`recovery.py:79`）；认领 `UPDATE … WHERE resumed_at IS NULL` + rowcount==1（`recovery.py:25-43`，不引 advisory lock）；扫描器 `api/main.py:205-238`，输家 `RunSuperseded` 让位（`295-298`）。

**风险**：
- **P1 时间与类型分裂**：`interruptions.created_at` 为 TEXT（`002:56`）而 `deadline_at/resumed_at` 为 TIMESTAMPTZ（`029:9-10`），`pg.py:106/114/118` 靠隐式转换比较 —— 跨类型比较是潜在的时区/排序缺陷源。
- **P1 非原子**：认领（`recovery.py:33`）与写终态+清帧（`main.py:290-294`）分属两条事务；`pg.py:2044-2054` 先 SELECT 后 UPDATE 无 `FOR UPDATE`，并发编辑可丢更新。
- **P2 性能**：`recovery.py:121` 全表 `ORDER BY created_at` 而该列**无索引**（`002:62` 仅 tenant 索引）⇒ 启动全表扫+排序；`memory/database.py:37` 连接池仅 `pool_size=10, pool_pre_ping`，缺 `max_overflow/pool_timeout/pool_recycle`；`006_memory.sql:26` ivfflat 无 tenant+vector 复合索引。
- **P2 迁移 runner 无 checksum**（`migrations.py:36` 纯文件名 glob + 整文件 execute），已应用迁移被改写不可检出。
- **P2 可维护性**：`pg.py:2035/482/579/773` 存在 f-string/`.format`/`join` 拼 SQL 片段（当前来源均为内部常量，非用户输入 ⇒ 是**可维护性债而非注入**，但为将来留了缝）。

**测试**：常跑 `test_storage.py`、`test_migration_convention.py`（含反向门）、`test_retention.py`；integration 10 个 `*_pg_integration.py`（真库认领互斥 `test_storage_pg_integration.py:756/826/921`）。**缺口**：Protocol 合规测试只覆盖 7/10（Run/Memory/Connection 未做 isinstance，`test_storage.py:32-43`）；跨租户越权仅 1 条显式断言（`:701`）。

### 3.3 API 层与横切安全（`api/` `iam/` `security/` `harness/` `llm/`）

**端点全景**：143 条路由全在 `api/main.py`（无 `APIRouter` 拆分）。鉴权 `require("read"/"operate"/"administer")`（`iam/deps.py:107-113`）。

## 4 横切主题

### 4.1 租户隔离 — **强，且有一处有意例外**
语句级 `WHERE tenant_id` + per-tenant 实例，索引齐备，租户 id 全部参数化绑定；跨租户/不存在统一 404。**例外**是三处有意全局读（恢复扫描器跨租户扫、清会话、按 username 查账号）——其中「跨租户 username 唯一」是一条**隐含的全局约束**，值得显式写进契约。

### 4.2 安全面 — **基线扎实，两个真 gap**
扎实处：EgressGuard denylist fail-closed、HMAC 恒定时间比对、凭据信封加密 + prod fail-closed、LLM 双闸门、演示面档位闸门、前端零 innerHTML/eval。
真 gap：**① `web/navigate` 只判初始 URL**（重定向/子资源未过闸，已登记 D43 相关）；**② 前端 token 明文 localStorage**（XSS 可窃取）。另有「仓库明文种子口令」属演示资产，prod 已被引导口令取代。

### 4.3 中断恢复与单副本约束 — **纪律严明，代价显式**
at-most-once 认领 + 输家 `RunSuperseded` 让位 + PG 档落帧，是**有意收紧**（宁可永久卡住，也不重复扣款）。代价已显式登记为缓做：**D36**（卡住帧人工重放）、**D42**（卡住帧对运营不可见，已由只读投影 `/api/interruptions` 部分缓解）、**D46**（并行区域内挂起）。**单副本三道闸一条未撤**——这是当前最重要的架构约束。

### 4.4 测试策略 — **强在纯函数与契约，弱在 UI 与集成**
优势：2118 后端测试、大量「反向门」（植缺陷必红）、PG 档独立集成测试、迁移约定机检、handoff 完整性机检。
缺口：**前端零组件测试**（最大缺口）、Protocol 合规只覆盖 7/10、跨租户越权仅 1 条断言、integration 需手动开关（CI 是否每跑需确认，历史上 CI 无 postgres service 曾致 44 条永不跑）。

### 4.5 性能 — **热路径可接受，若干无界与轮询**
可接受：DSL 校验有增量调度与结构签名记忆化（M4 批 2，p95≈10ms@500 节点）。
隐患：`_alerts` 无界、`recovery.py:121` 无索引全表扫、`/metrics` 遍历全租户、前端 5s 全量轮询无退避、bundle 无分包、`time.sleep` 阻塞 worker。

## 6 改进建议（按优先级，均需先走 ADR/立项，不擅自落码）

**立即（低成本、高收益）**

2. 前端 token 从 localStorage 迁到 httpOnly Cookie（或至少加过期与形状校验）；这是**唯一一条 P1 前端安全项**。

4. `recovery.py:121` 补 `(tenant_id, created_at)` 或 `created_at` 索引；`_alerts` 加 ring 上限。

5. `api/main.py` 按域拆 `APIRouter`（monitoring / channels / openapi / demo / run…），是后续一切 API 层改动的前置。

**长期（架构级，须 ADR）**

## 8 典型用户旅程（今天走得通的路径）

1. **配置**：登录 → 从模板新建或拖拽 9 类节点 → Schema 表单填参 → Problems 面板看 L1/L2/L3 诊断 → quickFix 修悬空引用 → 编译 422 稀疏定位。
2. **试跑与调试**：`/run` 或 SSE `/run/stream` 实时看节点事件 → 打断点单步、看变量覆盖 → 审批弹窗人工放行或超时自动 reject。
3. **发布**：publish 冻结版本（subgraph 自动钉版）→ 发布前回放门禁 → 入站 Router 灰度 → 指标门控自动回滚。
4. **运营**：定时调度按 cron 触发（槽位认领、重启不补跑）→ 监控页看 p50/p95 与告警 → 告警静默/值班升级 → 审批页处理挂起 → 审计日志追溯。
5. **运维**：挂起帧只读投影查「谁认领、卡多久」→ retention 清理 → 备份轮转 → prod 用 `/metrics` + request-id 日志排查。
