## 1. 缺口①：Repository 接口形状

### 1.1 现状盘点（2026-09-17 实测）

| 资源 | 现类与落位 | 公开 API | reset 档 |
|---|---|---|---|
| 图定义 | `GraphStore`（**内联** `api/main.py`） | `save/get/list/clear` | resettable |
| 录制用例 | `RecordingStore`（`recording/cases.py`） | `add/list/get/delete` | persistent |
| 反馈 | `FeedbackStore`（**内联** `api/main.py`） | `add/list` | persistent |
| 登录会话 | `SessionStore`（`iam/sessions.py`） | `issue/principal_for_token/revoke/reset` | resettable |
| 审批挂起 | `ApprovalBroker`（`collaboration/approvals.py`） | `request/wait/resolve/complete_timeout/get/list_pending/reset` | resettable |
| 调试暂停 | `DebuggerBroker`（`debug/sessions.py`） | `create/get_session/list_pending/reset`（会话级 step/continue/stop 状态机在 `DebugSession`） | resettable |
| 监控 | `MonitoringStore`（`monitoring/records.py`） | `record_run/list_runs/list_alerts/get_alert/acknowledge_alert/resolve_alert/get_rules/update_rules/snapshot_metrics/reset` | resettable（计数器不重置） |
| 租户组合根 | `TenantRegistry`/`TenantServices`（`iam/registry.py`） | `get/reset_tenant`（按租户惰性装配 7 个服务实例） | — |

### 1.2 决策：按资源分组的六个 Protocol + 统一约定，不做单一胖接口

八个 store 职责异质（CRUD、等待-决断、指标聚合、组合根），捏成一个 `Repository` 胖接口只会得到 `get(id)/put(id, dict)` 式弱类型 API。**统一抽象落在三件事上**：

1. **每类资源一个 `typing.Protocol`**（结构化类型，实现类不强制继承）：`GraphRepository`、`RecordingRepository`、`FeedbackRepository`、`SessionRepository`、`InterruptionRepository`（审批+调试两类「挂起-决断」共享的语义基座）、`MonitoringRepository`。方法签名 **M5a 与现状一比一**（上表 API 即契约，不增删改名）。
2. **租户分区是构造期关切，不进方法签名**：接口统一经工厂 `for_tenant(tenant_id) -> Repository` 取用；进程内实现（现状）本就按租户各持一份实例，M5b 的 PG 实现同样按租户构造、行内物理携带 `tenant_id`（由工厂注入，语句级过滤；不引入 PG RLS）。因此 M5a 重构对 27 个端点**零签名变化**。
3. **统一生命周期约定**：① `reset()` 只存在于 resettable 档（§3.3 分层表）；② id 由 store 内部生成（进程内保持 `graph-N` 计数器；M5b 换 PG sequence，对外 `graph-N` 字符串格式不变）；③ 时间统一 UTC ISO-8601 字符串（现状口径）；④ M5b 事务边界＝单端点请求单连接，跨 store 操作最终一致，不引入跨库事务。

### 1.3 落位与迁移方式（M5a 执行，本轮只定形状）

- 新包 **`src/atlas/storage/`**：`base.py`（六个 Protocol + `Repository` 聚合协议 + reset 分档常量 + `StorageError`）、`memory.py`（八实现收拢：`GraphStore`/`FeedbackStore` 自 `api/main.py` 内联移出，其余五类自原模块移入并以原路径 re-export 过渡）、`pg.py`（M5b，复用 `memory/` 的 psycopg 连接层）、`recovery.py`（§2.4 恢复扫描器，M5b）。
- 迁移是**一次性纯搬移**（类名/方法/行为零变化，测试同提交改导入），不留长期新旧双路径；`iam/registry.py` 的延迟导入环随之消除（`storage` 不反向依赖 `api`）。
- `TenantRegistry` 保持组合根不变（DI 装配点），仅改构造 `storage/memory` 的实现。

## 2. 缺口②：中断状态落库路线（ADR T18，✅ 2026-09-17 拍板 B）

> 完整选项对照已登记 **10 §4 T18 行**；本节给设计依据。**已拍板 B（自研暂停帧落库 + 续跑）**（2026-09-17 用户拍板）；14 D19/D20（及同批 D27）原文「届时上 LangGraph interrupt/checkpointer 模型」的措辞已同步改写为自研暂停帧（登记表只改措辞不改触发时点）。

### 2.1 现状：三处「暂停」语义各异（M5 要统一的真正对象）

| 挂起类 | 现机制 | 挂起时持有 | 恢复信号 |
|---|---|---|---|
| human_approval | `ApprovalBroker`：token + `threading.Event`，执行线程 `wait(剩余 deadline)` | token、node_id、summary/approver、deadline、graph/run 上下文（**均不落盘**） | REST `POST /api/approvals/{token}/decision` → `Event.set` |
| debug 暂停 | `DebuggerBroker`/`DebugSession`：token + `Event` + step/continue/stop 状态机 | token、node_id、reason、paused 帧 globals/outputs 只读快照（**已有快照先例**） | REST `POST /api/debug/{token}/resume` |
| wait 定时 | 执行线程 `time.sleep(durationSeconds)` | 时长常量 | 到时自然继续 |

### 2.2 选项对照

- **A. LangGraph checkpointer（Sqlite/Postgres saver）+ interrupt**：图执行状态由库托管，interrupt/resume 语义现成。代价：新增 `langgraph-checkpoint*` 依赖与库管表结构；resume 语义要求「客户端携 resume 值重新 invoke」，现有同步 SSE worker 线程、`ApprovalBroker.wait` 阻塞模型、debug step 状态机全部要重构到 interrupt 范式（三处暂停两套机制并存）；threads 与 run/租户模型需适配层；库版本升级直接冲击运行时契约。**超配**：M5 验收口径是「单实例重启后可恢复」，checkpointer 的主收益（跨实例迁移执行中图、任意超步持久化）不在边界内（20 §3「不做」）。
- **B. 自研暂停帧落库 + 挂起点续跑（推荐）**：保留「同步执行线程 + broker Event」语义，新增**中断帧（InterruptionFrame）**这一种可序列化产物，进程内后端存内存 dict、PG 后端存一行 jsonb——两后端共用同一帧结构，M5a 可先行。改动面收敛为：帧序列化器、broker 持久化钩子（M5b）、`loader` 续跑入口、恢复扫描器。
- **C. 只做审批持久化、wait/debug 不做**：不满足 20 §3 验收口径（wait 事件等待恢复在验收清单里），且 D19/D20 同批中断模型的设计意图落空。排除。

### 2.3 B 路线的核心契约（拍板后写入 04 §5.5/§5.6 v2 与 03 注记）

- **帧结构**（契约名 **`interruption_frame`**，03 契约索引已登记；存储＝`interruptions` 行/内存条目）：`resume_token`（沿用 uuid4 hex，即现有 approval/debug token）、`tenant_id`、`run_id`、`node_id`、`kind: approval|debug|wait`、`created_at`、`deadline_at`（**UTC 绝对时刻或 null**；wait 的动态时长与审批超时都折算成绝对时刻，见 §3.1）、`graph_snapshot`（**图定义副本**——M6 版本化未落地前，帧内嵌保存时定义，防止恢复时图已被改而错位）、`resume_state`（续跑载荷：`inputs`、**截至挂起点的已完成节点 outputs**、已记录的 branch/target 决策、trace 前缀、retry 配置）。
- **可恢复边界（明确取舍）**：重启时仅 `suspended`（挂起帧）可恢复；`running` 中的运行不可序列化执行现场，**标 `interrupted`（失败档）**，不重放副作用。此边界写进验收（13 测试组断言）。
- **续跑语义**：不重跑上游——`run_graph` 新增 `resume=` 入参（帧的 `resume_state`），loader 把已完成节点视为已产出、从挂起节点继续沿边执行到 END；决策/事件语义（branch 记录、fail-safe、trace 追加）与正常执行同一套规则。
- **信号送达**：进程内照旧 `Event`；M5b 决策端点**双写**（内存 `Event.set` + 恢复表落行），执行线程改为「`Event.wait(剩余)` + PG 轮询（1s，`LISTEN/NOTIFY` 为可选优化不进验收）」复合等待——跨进程送达由轮询兜底。
- **重开判据（随 T18 生效）**：M7 任务总线要求跨实例迁移执行中运行、或 LangGraph 官方 checkpointer 提供与同步 SSE 模型兼容的轻量用法时，携实测案例重开评 A。

### 2.4 恢复扫描器（`storage/recovery.py`，M5b）

服务启动钩子触发：按租户读全部挂起帧 → 逐帧重建 pending（approval：重挂 `Event` + 按 `deadline_at` 计算剩余时长；debug：重挂暂停并恢复投影；wait：重排剩余 `sleep`）→ run 状态标 `suspended`。恢复过程幂等（重复启动不重复建帧），失败帧隔离并记日志不阻塞其余恢复。

## 3. 缺口③：04 §5.5/§5.6 v2 持久化语义（本轮结论，拍板后并入正文）

1. **超时计时＝绝对 deadline，不重计**：帧存 `deadline_at`（挂起时由 `now + timeoutSeconds` 算出）；重启消耗的真实时间照扣，恢复后按剩余时长等待，到点自动决策（`onTimeout`）不变。wait 同理（`deadline_at = 挂起时刻 + durationSeconds`）。**「重启即满额重计」被显式否决**（会绕过审批超时保护，退款类场景不可接受）。
2. **决策信号跨进程送达**：§2.3 复合等待（Event + 1s 轮询），决策端点请求-响应语义不变（`resolvedBy:"human"` 路径不变）。
3. **SSE 断线与重连**：执行线程与 SSE 连接解耦——M5b 起 `/run/stream` 的 worker 状态落 `runs` 表（`running|suspended|completed|failed|interrupted`），SSE 断开不取消执行；客户端重连走 `GET /api/runs/{run_id}` 查询挂起/最终态（缺口④端点），不再依赖重放事件流。
4. **`/api/demo/reset` 分层**（12 注记同步）：进程内后端行为不变；PG 后端＝truncate 运行时表（`runs`/`interruptions`/`graphs`/`iam_sessions`/`monitoring_*`）＋种子表重置，`recordings`/`feedback`（persistent 档）保留。

## 4. 缺口④：12 新增 REST 端点（M5b 落码，本轮定签名）

| 方法 | 路径 | 鉴权/角色 | 语义 | 响应 |
|---|---|---|---|---|
| GET | `/api/runs?status=suspended&graph_id=&limit=` | Bearer，`read`（与 `/api/monitoring/runs` 同档） | 本租户运行列表（新→旧；`status` 缺省=全部） | `{items:[{runId, graphId, status, startedAt, suspendedAt, kind?, nodeId?, deadlineAt?}]}`；`kind=approval` 时附 `resumeToken`（审批决策本就凭 token，无身份绑定，沿用现状口径） |
| GET | `/api/runs/{run_id}` | Bearer，`read` | 单运行详情：状态、节点产出摘要、trace、挂起信息 | `200 {runId, graphId, status, outputs, trace, suspension?}`；跨租户/不存在 → **404**（与 04 §5.14 全分区口径一致，不泄露存在性） |

- **不新增写端点**：审批决策仍 `POST /api/approvals/{token}/decision`、调试恢复仍 `POST /api/debug/{token}/resume`、wait 无需信号——新端点只承担「查询 + 重连后状态确认」，token 关系为零改动。
- 错误档：401 未登录 / 403 角色不足 / 404 跨租户或不存在 / 422 非法 `limit`/`status`（中文 detail，同 12 既有口径）。

## 7. 本轮明确不做

多实例部署与跨实例恢复（含执行中运行迁移）、NATS（D5）、Go 网关（D6）、wait 事件等待与动态时长的**表达式**形态（D19 的 `waitType=event` 属 M5b 之后的独立立项）、审批评论流/队列页（D20）、密码哈希/注册（D22）、幂等键与任务信封（M7）。
