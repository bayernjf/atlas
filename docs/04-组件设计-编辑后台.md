# 编辑后台组件设计（Atlas）

## 一、编辑后台的核心定位与通用化原则
编辑后台的本质： 它是一个低代码/无代码的“运营智能体工厂”，让用户把自己平台的页面、API、文档、SOP、客服话术等，配置成一个可自主运行、可自我进化的 AI 运营体。
要完全通用化，必须满足以下原则：
1. Schema 驱动：所有节点、工具、逻辑、变量都用结构化 Schema 描述，而不是硬编码。
1. 插件化与热插拔：适配器、节点类型、逻辑组件可以动态注册和卸载。
1. 声明式配置：用户只需声明“要做什么”，不需要写代码；系统自动生成可执行的 Graph 和 Loop。
1. 可组合性：任意节点/子图可以像乐高一样被组合、嵌套、复用。
1. 可观测与可审计：每一步操作、每一次决策、每一个变量变化都可追踪、可回放。
1. 人机协同默认开启：所有高风险操作默认需要人工确认，用户可以逐步“授权”给 AI。
## 二、编辑后台组件全景图

| 组件类别 | 核心作用 | 典型实例 |
| --- | --- | --- |
| 节点 | 执行单元，组成流程图 | 触发器、AI决策、工具调用、条件分支、循环、子图 |
| 工具 | 操作外部平台的能力 | 浏览器点击、API调用、数据库查询、发送邮件 |
| 逻辑 | 控制流程走向与状态 | 条件表达式、循环、并行、等待、异常处理、状态机 |
| 适配器 | 连接具体平台/系统 | Shopify适配器、钉钉适配器、企业微信适配器 |
| 数据 | 存储与传递业务信息 | 业务对象、数据表、上下文数据流 |
| 变量 | 存储临时/持久数据 | 全局变量、节点变量、环境变量、秘密变量 |
| 上下文 | 当前运行环境信息 | 用户上下文、会话上下文、系统上下文 |
| 知识 | 提供领域知识与文档 | FAQ知识库、SOP文档、产品手册 |
| 测试/发布 | 验证运营体正确性 | 沙盒测试、回放测试、灰度发布 |
| 运行时 | 实际执行与监控 | Loop引擎、Harness网关、日志中心 |

## 三、节点组件详细设计
节点是编辑后台最基础的积木。为了通用化，节点必须类型明确、参数可配置、输入输出可定义。
### 3.1 节点类型划分

| 节点类型 | 功能 | 输入 | 输出 | 典型配置项 |
| --- | --- | --- | --- | --- |
| 触发器节点 | 启动运营体 | 外部事件/定时 | 初始上下文 | 定时Cron、Webhook URL、手动触发 |
| AI决策节点 | 让LLM分析并决定下一步 | 当前上下文 | 决策结果/动作指令 | 提示词模板、输出Schema、模型选择 |
| 意图识别节点 | 判断用户意图 | 用户消息 | 意图分类+槽位 | 意图列表、示例、置信度阈值 |
| 信息抽取节点 | 从文本/页面提取结构化数据 | 文本/页面内容 | 字段值 | 抽取字段Schema、示例 |
| 内容生成节点 | 生成回复/报告/文档 | 上下文+模板 | 文本内容 | 模板、风格、长度 |
| 工具调用节点 | 执行Harness操作 | 动作参数 | 执行结果 | 选择工具、参数映射、超时 |
| 条件分支节点 | 根据条件走不同路径 | 变量/表达式 | 分支选择 | 条件表达式、默认分支 |
| 循环节点 | 重复执行子流程 | 条件循环 / 遍历循环（foreach，2026-09-23 立项，见 §5.3） | 循环结果 | while：继续条件表达式、最大次数；foreach：itemsExpression/itemName/collectTarget；循环体/退出目标 |
| 并行节点 | 同时执行多个分支（v1：全部成功/全部完成两策略，见 §5.4） | 无 | 汇总结果 | 分支列表、joinTarget、合并策略 |
| 等待节点 | 挂起指定时间或等待事件（v1 仅定时等待，见 §5.5） | 时间 | 继续信号 | 等待时长（事件监听 v1 不做） |
| 子图节点 | 引用另一个运营体/子流程（v1 进程内引用已保存图，见 §5.7） | 子图入参 | 子图出参 | 子图ID、入参映射 |
| 人机协作节点 | 暂停并请求人工（v1 进程内审批信号，见 §5.6） | 审批请求 | 人工决策 | 审批说明、审批人、超时策略、通过/拒绝目标 |

### 3.2 节点的通用化接口设计
每个节点都遵循统一接口：
node:
id: string
type: string
name: string
description: string
config: object          # 节点类型专属配置
inputs:                 # 输入映射
- name: string
source: string      # 变量名/上下文路径
required: boolean
default: any
outputs:                # 输出声明
- name: string
type: string
retry:                  # 重试策略
max_retries: number
backoff: string
timeout: number
on_error: string        # 失败处理：stop/continue/跳转节点
### 3.3 节点参数配置面板
- 基础属性：名称、描述、图标、颜色（区分类型）。
- 输入参数：从变量选择器中选择来源（上游节点输出、全局变量、上下文）。
- 输出参数：定义输出变量名，供下游节点引用。
- 高级配置：超时、重试、失败处理、是否断点暂停。
- 节点校验：实时检查配置完整性，缺失必填项时高亮提示。
## 四、工具/适配器组件详细设计
工具是运营体“操作外部平台”的能力来源，适配器是工具的载体。要实现完全通用化，需要把“适配器”和“工具”分层设计。
### 4.1 适配器分层模型

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 连接层 | 管理认证、会话、网络 | OAuth2、API Key、Cookie、浏览器会话 |
| 能力层 | 定义可执行的操作 | 点击、输入、查询订单、发送消息 |
| 数据层 | 定义操作输入输出的数据结构 | 订单对象、用户对象 |

### 4.2 适配器类型

| 适配器类型 | 对接方式 | 典型工具 | 通用化设计要点 |
| --- | --- | --- | --- |
| API适配器 | OpenAPI/Swagger/自定义HTTP | create_order, get_user | 自动生成工具定义，参数Schema化 |
| 浏览器操作适配器 | Playwright + 视觉模型 | click, type, screenshot | 元素定位三层冗余，操作录制生成 |
| 移动端适配器 | Appium + 视觉 | tap, swipe | 元素库管理，屏幕识别 |
| 桌面端适配器 | 图像识别 + 键鼠模拟 | click_image, send_keys | 模板匹配，OCR辅助 |
| 数据适配器 | JDBC/ODBC/数据仓库 | query_sql | 只读/读写权限控制，结果集摘要 |
| 消息适配器 | IM/邮件/短信 | send_email, reply_message | 消息模板，群发限制 |
| IoT适配器 | MQTT/Modbus | read_sensor, control_device | 设备影子，协议解析 |

### 4.3 工具定义 Schema
每个工具必须包含：
tool:
id: string
name: string
description: string          # 自然语言描述，供LLM理解
adapter_id: string           # 所属适配器
action: string               # 具体动作
input_schema: object         # 输入参数JSON Schema
output_schema: object        # 输出参数JSON Schema
permission: string           # 所需权限
timeout: number
retry_policy: object
is_idempotent: boolean       # 是否幂等
### 4.4 适配器注册与发现
- 注册中心：每个适配器启动时向 Harness Gateway 注册，声明自己的能力和工具列表。
- 动态发现：编辑后台通过网关查询可用适配器，用户拖拽到画布即可使用。
- 健康检查：适配器定期心跳，不可用时后台置灰并提示。
### 4.5 自定义适配器创建方式
为了让用户能自己对接平台，编辑后台提供四种创建适配器的方式：
1. API导入：粘贴 OpenAPI/Swagger 文档链接或JSON，自动生成适配器和工具。
1. 操作录制：用户在自己平台上手动操作，系统用浏览器插件/录制器记录步骤，自动转化为工具。
1. 自然语言生成：用户描述“我要对接XX平台，能查询订单”，系统调用LLM生成适配器配置。
1. 开发者SDK：高级用户用SDK编写自定义适配器，上传到平台。

### 4.6 API 适配器（通用 HTTP）v1 契约

> 本条为 API 适配器 v1 的唯一权威契约，03 契约索引指向此处。v1 对应 §4.2 的「自定义HTTP」形态；OpenAPI/Swagger 自动导入（§4.5 方式 1）为后续形态。**2026-09-23 更新：该后续形态已以 [docs/42](42-OpenAPI导入与工具自动生成批契约设计.md) 立项——v1 仅 OpenAPI 3.x JSON、进程内 per-tenant，合同权威在 docs/42；本条仍为通用 `http/request` 的权威契约。**

**标识与包位**：channel 包 `src/atlas/httpapi/`（`api/` 为 FastAPI 服务端包位，09 待定项 5，不可复用；包名决策见 09 待定项 7），`adapter_id="http"`、`adapter_type="api"`，Demo 注册进同一进程内 AdapterRegistry，发现/心跳/权限/审计沿用 §4.4 与 06 §6.4。

**能力**：v1 仅一个工具 `http/request`，permission=write、is_idempotent=false、timeout 默认 30s。节点 tool_call 的 `config.tool="http/request"`，`config.params` 为字符串，经 04 §6.3 `{{路径}}` 插值后必须是 JSON 对象：

```json
{"method": "POST", "url": "/orders/123/receipt",
 "headers": {"X-Trace": "{{trigger-1.context.payload.order_id}}"},
 "body": {"note": "自动处理"}, "timeout": 10}
```

- `method`：GET/POST/PUT/PATCH/DELETE 之一，缺省 GET；非法值 FAILED（INVALID_PARAMETER）。
- `url`：必填；相对路径拼连接默认 baseUrl（以 `/` 为界做 urljoin），绝对 URL 直接使用。
- `headers`：可选 JSON 对象，与连接默认 headers 键级合并（同名键节点优先）；非对象 FAILED。
- `body`：可选；对象/数组按 JSON 序列化（自动带 application/json，除非默认/节点 headers 显式指定 content-type），字符串原样发送。
- `timeout`：可选正数秒，缺省取能力默认 30s。

**连接默认值（混合配置）**：adapter 构造或环境变量 `ATLAS_HTTPAPI_BASE_URL` / `ATLAS_HTTPAPI_HEADERS`（JSON 对象）/ `ATLAS_HTTPAPI_TOKEN`（注入 `Authorization: Bearer <token>`）提供默认 baseUrl 与公共 headers；节点 params 可覆盖/补充。v1 无连接 CRUD UI；**凭证运行时注入已落（docs/32 §2，ADR T26=(a)）**：url/headers 中 `secret://<name>` 引用与 `enc$v1$...` 信封在发送前由 SecretProvider 解析（`ATLAS_SECRETS`/`ATLAS_MASTER_KEY`，AES-256-GCM），明文不落 last_request/observe/录制/日志，缺失 → `SECRET_UNAVAILABLE` 且零外呼；连接 CRUD UI 与设计态秘密选择仍缓做 D22/D30。

**结果语义（fail-safe 对齐）**：

- 只要收到 HTTP 响应（含 4xx/5xx）→ ActionResult SUCCESS，output 固定为 `{"status": <int>, "headers": <dict>, "body": <object|string>}`；body 优先按 JSON 解析，失败返回文本。下游用 condition 判 `{{tool-x.result.status}}` 自行分支，图整体 run 仍 completed。
- 传输层失败（DNS/连接拒绝/读写超时）→ ActionResult FAILED，StructuredError code 为 `HTTP_CONNECT_ERROR` / `HTTP_TIMEOUT`；参数类错误为 `MISSING_PARAMETER`（缺 url）/ `INVALID_PARAMETER`（坏 method/headers/timeout/params 非合法 JSON）。
- **出向重试与按 host 熔断已落（docs/32 §5）**：仅传输层异常与 429/502/503/504、且幂等方法（GET/HEAD/PUT/DELETE，或显式幂等的 POST/PATCH）做指数退避+全抖动重试（默认 3 次，429 尊重 Retry-After）；重试用尽仍折叠回 HTTP_TIMEOUT/HTTP_CONNECT_ERROR（不新增结果语义）。按 host 连续失败达阈值熔断，开闸期不发请求直接 FAILED `HTTP_CIRCUIT_OPEN`，冷却后半开试探。SSRF/凭证类配置错误不进重试/熔断；`follow_redirects=False`，不跨 host 自动跟随。

**安全边界（egress 已落，docs/32 §3）**：发起连接前对最终绝对 URL 做出向校验——仅 http/https，环回/私网/链路本地/云元数据（169.254.169.254）/CGNAT/保留地址与整数/进制 IP 绕过恒拦（`EGRESS_DENIED`/`EGRESS_INVALID_URL`，零外呼、不重试、不计熔断），DNS 解析器可注入；配 `ATLAS_HTTP_EGRESS_ALLOWLIST` 后仅命中项可出网（私网/元数据在白名单判定前恒拦），未配则仅 denylist（保 demo）。不读 X-Forwarded-For 做网络判定。DNS rebinding 的连接级 pin-IP 彻底修复随部署批（docs/32 §9）。OAuth2/token 刷新/连接 CRUD 仍缓做 docs/14 D22。

**Demo mock 目标**：后端内置 `GET /api/demo/mock/orders`（校验 `X-Demo-Token: demo-token`，缺失/错误返回 401 JSON；成功返回演示订单数组）与 `POST /api/demo/mock/orders/{id}/receipt`（回显请求体并标记 received），供离线端到端验证。

### 4.7 数据适配器（通用 SQL）v1 契约

> 本条为数据适配器 v1 的唯一权威契约，03 契约索引指向此处。v1 对应 §4.2 的「数据适配器 / query_sql / 只读读写权限」形态；JDBC/ODBC、数据仓库与 Schema 表单为后续形态（缓做 docs/14 D23）。

**标识与包位**：channel 包 `src/atlas/database/`（与平台自身存储 `memory/database.py` 分离——后者锁 postgresql+psycopg 且服务于记忆层，不可复用），`adapter_id="database"`、`adapter_type="database"`，Demo 注册进同一进程内 AdapterRegistry，发现/心跳/权限/审计沿用 §4.4 与 06 §6.4。

**能力（两个工具）**：节点 tool_call 的 `config.params` 为字符串，经 §6.3 `{{路径}}` 插值后必须是 JSON 对象。

1. `database/query`，permission=read、is_idempotent=true、timeout 默认 30s：

```json
{"sql": "SELECT order_id, amount FROM orders WHERE amount > :min",
 "params": {"min": 1000}, "limit": 500}
```

   - `sql`：必填字符串；`params`：可选对象或数组，作为 SQLAlchemy **绑定参数**传入（防注入的推荐路径，插值只用于动态结构）；`limit`：可选 1-1000 整数，缺省 500。
   - 输出 `{"columns": [..], "rows": [{...}], "row_count": <int>, "truncated": <bool>}`——结果集摘要，超 limit 截断并置 truncated=true。
   - 只读保障（docs/32 §4）：**SQLite/PG 两档 query 都先过 `assert_read_only_sql` 静态审查**（去注释、拒多语句、只放单条 SELECT/WITH…SELECT，违例 → `DB_SQL_NOT_READ_ONLY`）；PG 再叠加 `execution_options(postgresql_readonly=True)` 只读事务、查询结束 rollback。
1. `database/execute`，permission=write、is_idempotent=false：`{"sql": "INSERT ... ", "params": {...}}`，提交事务，输出 `{"rowcount": <int>}`。**外部 `ATLAS_DATABASE_URL` 连接默认只读（read_only=True），execute 在触库前 fail-closed `DB_WRITE_FORBIDDEN`（docs/32 §4）**；仅内置 demo engine（demo=True，建表/播种走 engine 直连不经适配器 execute）保留写能力。真实最小权限只读账号是部署侧职责（D23），与应用内 guard 叠加。

**连接默认值**：环境变量 `ATLAS_DATABASE_URL`（**适配器专用，与平台自身 `DATABASE_URL` 隔离，防止图操作误伤平台库**）；允许 scheme：`postgresql+psycopg`、`sqlite`。adapter 自建 SQLAlchemy engine（scheme 白名单校验），不复用 memory 层工厂。未配置且未注入 engine 时调用返回 `DB_NOT_CONFIGURED`；SQLAlchemy 执行异常 → `DB_SQL_ERROR`（错误与 observe 中的连接 URL 一律 `hide_password=True` 脱敏）；缺 sql、params 非对象/数组、limit 越界 → `MISSING_PARAMETER`/`INVALID_PARAMETER`。

**安全边界**：sql 文本经图 `{{路径}}` 插值，拼接式插值存在 SQL 注入面——绑定参数 `params` 仍是防注入主路径；**应用内只读强制 + SQL 静态审查已落（docs/32 §4：query 通道两档强制、外部 execute 禁用）**，但静态黑名单不替代最小权限只读账号与 PG readonly 纵深；语句审计落库/Schema 浏览/多数据源仍随 D23。

**Demo 形态**：`ATLAS_DATABASE_URL` 缺失时，后端内置 SQLite 单连接内存库（StaticPool），seed 一张 `orders(order_id, reason, amount, status)` 两笔演示订单（与 §4.6 mock 订单同形）；`/api/demo/reset` 重新 seed（显式配置的外部库不被 reset 触碰）。

### 4.8 消息适配器（进程内消息服务）v1 契约

> 本条为消息适配器 v1 的唯一权威契约，03 契约索引指向此处。v1 对应 §4.2「消息适配器 / 消息模板 / 群发限制」的**进程内演示形态**：只记录、不真实投递；IM/邮件/短信/webhook 真实渠道为后续形态（缓做 docs/14 D24）。

**标识与包位**：channel 包 `src/atlas/message/`，`adapter_id="message"`、`adapter_type="message"`，注册/权限/审计同 §4.4 与 06 §6.4。

**能力**：v1 仅一个工具 `message/send`，permission=write、is_idempotent=false、timeout 默认 30s：

```json
{"channel": "email", "to": ["ops@example.com", "boss@example.com"],
 "subject": "退款审批通知：{{trigger-1.context.payload.order_id}}",
 "body": "金额 {{trigger-1.context.payload.amount}}，请处理"}
```

- `channel`：必填非空字符串（email/sms/im 或任意渠道标识，v1 不路由）；`to`：必填字符串或字符串数组，**数组上限 20**（群发限制，超出 INVALID_PARAMETER）；`channel=="email"` 时每个地址须含 `@`；`subject`/`body`：必填非空字符串。模板能力由 §6.3 `{{路径}}` 插值承担，不另建模板系统。
- 输出消息记录 `{"id": "<uuid4>", "channel", "to": <展平数组>, "subject", "body", "sent_at": "<iso8601>"}`；记录保存在进程内 MessageService（重启清空），`GET /api/demo/messages` 陪同查看，`/api/demo/reset` 清空。
- 参数错误（缺字段/空值/超群发/坏 email 形状）→ `MISSING_PARAMETER`/`INVALID_PARAMETER`。

**边界**：v1 **无真实投递**（不连 SMTP/IM/短信/webhook），写入记录即 SUCCESS；规格中的 `send_email`/`reply_message` 分渠道专名、回复线程、入站消费/订阅型触发、消息模板系统、限流退避与重试统一缓做 docs/14 D24（与 D20 IM 通知同批评估）。

### 4.9 Capability JSON Schema 子集与发现投影（v1）

> 工程推导条（2026-09-16 立项，08 Phase 2 延伸项「设计态内核前置项」）。§4.3 为原文工具定义 Schema；本条是 v1 落码中 `input_schema`/`output_schema` 字段形状的唯一权威，03 契约索引的 `tool`/`adapter_schema` 字段概览指向此处。

**载体**：`src/atlas/harness/base.py` 的 `Capability.input_schema`/`output_schema` 为 dict，空 dict `{}` 表示未声明。schema 描述的是工具 params 字典与 `ActionResult.output` 的形状（output_schema 不描述 status/error 信封）。

**JSON Schema 子集白名单**（构造期校验，违例抛 `ValueError`，防止未评审 keyword 静默进入契约）：

- 子 schema 允许 keyword：`type`、`properties`、`required`、`items`、`additionalProperties`、`enum`、`const`、`oneOf`、`description`、`default`、`minimum`、`maximum`、`exclusiveMinimum`、`exclusiveMaximum`、`minItems`、`maxItems`、`minLength`、`maxLength`、`pattern`；其余 keyword 一律拒绝。
- `type` 允许 `string`/`integer`/`number`/`boolean`/`object`/`array`/`null`；`exclusiveMinimum`/`exclusiveMaximum` 允许 number 或 boolean（兼容既有 http schema 的 draft-04 布尔形态）；空 schema `{}` 表示任意类型（如 http body）。
- 根 schema 必须是 object schema（声明参数时 `type` 可省略但须以 `properties`/`required` 描述）；`properties` 值与 `items` 递归适用同一白名单。

**覆盖范围**：九个 demo 工具全部声明——shop 五工具由旧 `{"字段": "类型名"}` 简形迁移到本子集（login/list_pending_refunds/execute_refund/request_human_approval/process_refund），http/request、database/query、database/execute、message/send 已符合，output_schema 与各自 §4.6-§4.8 及 shop service 真实产出对齐。

**发现投影**：`GET /api/adapters`（12 §5）的 `tools[]` 在 `name`/`description`/`permission`/`idempotent` 之外增列 `input_schema`/`output_schema`，未声明时投影为 `{}`；前端变量插入与 NL 参数填充以此为路径/字段来源。

**边界（非目标）**：v1 不引 AJV（ADR T16 2026-09-16 收口：手写子集校验，零新依赖，M3 设重开判据，见 10 §4）；运行期**不**按 schema 拒绝参数（schema 仅供设计态校验与 NL 填充，运行时参数校验维持各 adapter 现状的 MISSING/INVALID_PARAMETER）；不据此生成 params 表单（D22/D29；**M3 2026-09-16 立项部分取回**：发现投影的 input_schema 驱动 tool_call params 表单的内部形态，不含 D22 的 OpenAPI/OAuth/凭证功能包，契约见 §4.10）；不做变量类型级校验（D30）。

> **前端 MetaSchema 扩展（2026-09-16 立项并于同日落码，08 Phase 2 延伸立项 M1「内置节点 Data Schema 提取」；本条为 `x-*` keyword 形状的唯一权威，03 `node_data_schema` 指向此处）**：M1 在前端新增 `frontend/src/lib/schemas/`（`metaSchema.ts` + `nodes/<kind>.schema.ts` 九份 + 只读 `index.ts` SchemaRegistry），把九类内置节点 config 的手写规则（`nodeCatalog.ts` 与 §5.2–§5.7 权威契约）提取为声明式 Data Schema。MetaSchema 与上方 Capability 子集**同源 20 个白名单 keyword**（type/properties/required/items/enum/minimum 等），另增加四个**仅前端设计态** keyword：
>
> - `x-variable`（boolean）：该字段接受 `{{路径}}` 模板引用，驱动变量插入与表达式编辑校验（L2 规则仍以 §6.5 为准）；
> - `x-widget`（string）：自定义渲染控件注册名。M1 仅声明、M2 不消费；**M3（2026-09-16 立项、2026-09-17 落码）起 FormRenderer 的 resolveWidget 识别本 keyword**（契约见 §4.10）；工具 Capability schema 拒绝 `x-*`，工具字段走类型结构默认；九节点 schema 随渐进迁移按需标注；
> - `x-ref`（object，形如 `{kinds?: string[]}`）：字段值必须是图内节点 id，且节点种类属于 `kinds`（缺省/含 `"*"` 为任意种类），用于 target/branches[].target/joinTarget/bodyTarget 等引用类字段；图级存在性/出边配对校验仍在 DSL L3，本 keyword 只声明字段语义；

>
> **边界**：① `x-*` 只允许出现在前端节点 data schema；**后端 Capability `input_schema`/`output_schema` 仍拒绝一切 `x-*`**（U32 不变，前后端不是同一份 schema 载体，禁止把节点 schema 发给 Capability 构造期校验）；② M1 的 SchemaRegistry 仅支持内置节点单一来源（`get(kind, version)` 只读表），工具/技能/记忆/部署/卡片五类实体入册仍缓做 D29；③ schema 是现状的**声明式投影、不重设计**（timeoutSeconds 10–3600、onTimeout 默认 reject、双 target 互异等已验证边界照抄硬编码）；④ M1 **零 UI 变化、零新依赖、后端无改动、不删手写校验**——`nodeCatalog.validate` 对外签名不变，dev 模式增加手写结果与 schema 派生结果双跑比对（U36），迁完一个删一个，禁止长期双轨；⑤ 不引 AJV——L1 字段校验器形态经 ADR T16（2026-09-16 收口，10 §4）定为手写最小子集（M1 解释器扶正、零新依赖，M3 设重开判据）。

## 五、逻辑组件详细设计
逻辑组件负责流程的控制和状态管理，是运营体从“线性脚本”走向“智能决策”的关键。
### 5.1 表达式引擎
- 用途：条件判断、变量计算、参数映射。
- 语法：支持常见表达式，如 {{user.age > 18 && order.total > 100}}。
- 内置函数：日期处理、字符串处理、数学计算、数组操作、JSON解析。
- 类型安全：表达式解析时做类型检查，错误即时提示。

> **首版语法白名单（Phase 2，2026-09-14 落地）**：条件表达式中 `{{路径}}` 只包裹变量引用，运算符写在花括号外，例如 `{{trigger-1.context.payload.amount}} > 1000 && {{status}} == 'paid'`（与 13 文档 U5 的裸表达式口径一致）。支持：比较运算 `> >= < <= == !=`、逻辑 `&& || !`、括号、数字（含负号）、单/双引号字符串、`true`/`false`/`null`；`{{x}} == null` 用于判缺失。**不支持**算术运算与内置函数（即上方完整表达式引擎目标缓做，触发见 14 登记表）；求值器为手写递归下降解析，禁止 eval。语法错误与纯字面量类型错误（如 `'a' > 1`）在保存/校验期一次性中文报错。

> **D15 表达式函数库扩展（2026-09-19 已落码，`ac8c718`，前后端同构 `graph/conditions.py` 与 `frontend/src/lib/conditions.ts`，禁 eval）**：在首版布尔白名单上开放**算术** `+ - * / %`（`/`、`%` 对零抛 ConditionEvalError；`%` 为截断式取模，`-7%3==-1`，前后端同构）与括号；**白名单函数** `abs/floor/ceil/round`（round=floor(x+0.5)）/`min/max/len/lower/upper` 与确定性日期 `date/year/month/day/daysBetween`（后端 datetime.date、前端 DateValue 序数同构）；**不含 `now()/today()`**——非确定时间会破坏录制回放确定性，随可注入时钟批缓做；含编译期常量折叠。**顶层必须产出布尔值**：比较/逻辑表达式方可作条件，直接使用算术结果/数值/字符串/日期报「条件表达式必须产出布尔值（比较或逻辑运算），不能直接使用算术结果/数值/字符串/日期」。condition/loop 表达式共用同一引擎，前后端中文文案逐字对齐。

> **C 包 可注入回放时钟与非确定日期函数（2026-09-19 已落码，`3415377`，docs/27 §2，D15 余部取回，前后端同构、禁 eval）**：`run_graph(..., now_override=None)` 新增可注入时钟（timezone-aware UTC；naive 当 UTC；`None` 时在运行入口取一次 `datetime.now(timezone.utc)` 并在本次运行固定，子图重入继承同一冻结时刻，condition/loop/调试条件断点全链透传）。白名单**纯超集**新增：`today()`→UTC date；`now()`→UTC aware datetime（新增 datetime 值类型，后端即 `datetime.datetime`、前端 `DateTimeValue`）；`datetime(y,m,d,H,M[,S])`→UTC datetime（5–6 参整数分量，非法日期/时间抛 ConditionEvalError）；`hoursBetween(a,b)`→小时数 `(b−a)` 总秒/3600（入参接受 date，按当日 00:00 UTC）；`daysBetween` 与 `year/month/day` 接受 datetime。**date 与 datetime 禁止跨类型有序比较（报错），跨类型 `==` 为 false**；常量折叠对非确定的 today/now 跳过（其值依赖运行时钟），`datetime()` 纯常量仍折叠以静态暴露非法日期时间。录制/回放确定性：`RecordingCase` 增可选 `recorded_at`（v1 锚点＝用例入库时刻、与 created_at 同 stamp；`POST /api/recordings` 不重跑 baseline，落码细化见 docs/27 顶部注记 1），单用例 replay 与发布门禁经纯函数 `recording.replay.clock_anchor(case)`（回退链 recorded_at→created_at→真实时钟并附中文 clock_note）注入 now_override，含 today()/now() 的分支在录制与回放间稳定。前端 conditions.ts 仅静态校验（无运行时求值入口），today/now 跳过常量折叠、类型按函数表推断。**仍缓做**：随机数/UUID、命名/本地时区（口径统一 UTC），随后续非确定函数批（docs/14 D15）。
### 5.2 条件分支
支持类型：
- 表达式判断（A > B）
- 多条件组合（AND/OR/NOT）
- LLM智能判断（当条件无法用规则表达时，交给LLM输出分支）
- 默认分支：必须配置，防止未覆盖情况。
- 可视化：分支连线标注条件，鼠标悬停查看详情。

> **condition 节点 config 契约（Phase 2 首版，2026-09-14；本条为唯一权威，03 契约索引指向此处）**：
>
> ```yaml
> type: condition
> config:
>   branches:                          # 有序分支，按数组顺序短路求值，第一个为真者胜出
>     - label: string                  # 分支名，非空，同节点内唯一；命中后写入 outputs.branch
>       expression: string             # 5.1 首版语法白名单内的布尔表达式，非空
>       target: node_id                # 目标节点 id，必须存在、非自环、且有对应出边
>   defaultTarget: node_id             # 必填；全部分支为假或求值失败时走此分支，须有出边
> ```
>
> 约束：`target` 在节点内互不重复且不得等于 `defaultTarget`；condition 节点的**每条出边必须被 branches∪default 覆盖**（不允许无标签死边），condition 不允许直连 END（终态由目标分支末端节点接 END）。边仍是 `{id, source, target}`（03 graph_definition），条件不挂边上、不进 edge 字段；画布上分支标签由 source 节点 config 反查渲染，多输出端口仅为编辑期视觉。
>
> 运行时语义（实现 `atlas.graph.loader`，经 LangGraph conditional edges）：执行器顺序求值一次并写产出，路由函数只读取值结果（不重复求值）。节点产出 `{branch, target, evaluation:[{label, expression, result}], expression_errors:[string]}`，默认分支 `branch="__default__"`；trace 增一行 `condition-x: branch=… → target`。含变量的类型错误或变量缺失无法静态发现时，**fail-safe 走 defaultTarget**，错误进 `expression_errors` 与 trace（安全默认：退款类场景默认分支应指向人工审核）。
>
> **condition LLM 语义判断分支 v1 追加段（D14 进程内 llm 子集，2026-09-23 落码收口 docs/48；本条为唯一权威）**：
>
> ```yaml
> type: condition
> config:
>   conditionMode: llm                 # rule | llm，缺省 rule（旧图零回归）
>   classifierPrompt: string?          # 可选附加判定要求，strip 后 ≤500
>   branches:
>     - label: string                  # 规则同 rule：非空、唯一
>       description: string            # 必填，strip 后非空、≤300；不允许 expression 字段
>       target: node_id                # 规则同 rule
>   defaultTarget: node_id
> ```
>
> 运行时：执行器把上下文（全局变量＋已完成节点 outputs，JSON 序列化截断 12000 字符）与分支 label/description 表一次性交给分类器（新模块 `atlas.llm.condition_classifier`，镜像 decision.py 三层：`LITELLM_MODEL` 非空走 LiteLLM——temperature=0、只输出 `{"branch":"<label>"}`、正则抽 JSON；未配置走 Offline 必抛错），每节点恰好一次调用。合法标签 → 按标签路由；返回 `__default__`、JSON 无法解析、标签不在分支集、调用异常 **全部 fail-safe 走 defaultTarget**（不新增错误码、不使节点/run 失败，原因进产出 `llm_errors` 与 trace）。分类器经 `run_graph(..., condition_classifier=None)` 注入，缺省工厂构建，子图重入透传，离线测试注入假分类器。节点产出 `{mode:"llm", branch, target, evaluation:[{label, description, result:bool|null}], llm_errors:[string]}`，`branch`/`target` 位置与 rule 模式一致；trace `condition-x: llm branch=… → target` / `… llm fallback → defaultTarget（原因）`。拓扑约束（出边全覆盖、不直连 END）两模式一致。
>
> 仍缓做（D14 不解除）：置信度阈值/多候选/澄清重问、每分支独立 prompt 或每分支调用、模型可选与按租户配置、发送上下文的字段级脱敏、structured outputs/函数调用、LLM 路由的录制回放断言。
> 并行等其他节点仍按校验拒绝（循环节点见 §5.3，并行节点见 §5.4）。
### 5.3 循环
- 遍历循环：对列表/数组逐项执行子流程。
- 条件循环：满足条件时持续执行，直到不满足或达到最大次数。
- 中断与跳过：支持break、continue逻辑。
- 循环变量：自动生成index、item变量。

> **loop 节点 config 契约（Phase 2 第二项，2026-09-14；本条为唯一权威，03 契约索引指向此处）**：
>
> v1 只实现**条件循环（while）**；遍历循环（列表逐项、item 变量、结果聚合）与 break/continue 缓做（见 14 登记表 D16/D17），循环变量 v1 仅暴露 `index`。
>
> ```yaml
> type: loop
> config:
>   mode: "while"                    # v1 固定 while
>   continueExpression: string       # §5.1 首版语法白名单内的布尔表达式，非空
>   maxIterations: 10                # 整数 1-100，必填
>   bodyTarget: node_id              # 表达式为真 → 进入/再次进入循环体
>   exitTarget: node_id              # 为假 / 达上限 / 求值异常 → 退出循环
> ```
>
> 拓扑约束（保存时静态校验，错误聚合中文报错）：
> - bodyTarget / exitTarget 必填、存在、非自环、互不相同；loop 节点**恰好两条出边**且目标集合 = {bodyTarget, exitTarget}，不允许直连 END（终态由退出路径末端节点接 END）。
> - **循环体**：从 bodyTarget 出发按出边 BFS（遇本 loop 节点与 exitTarget 停止）可达的全部节点。必须存在至少一条「回边」：某条边 target=本 loop 节点且 source ∈ 循环体（循环体末端连回 loop）；循环体不得泄漏到 exitTarget（退出路径只能由 loop 节点出发）。
> - 循环体内不得含 trigger 节点或其他 loop 节点（v1 不支持嵌套循环）。
> - **合法环白名单**：「loop → 循环体 → 回到同一 loop」的回边是唯一允许的图环。校验时把白名单回边临时移除后做环检测，剩余图中仍存在环 → 按 U7「循环依赖检测」拒绝（非法循环依赖）。
>
> 运行时语义（实现 `atlas.graph.loader`，经 LangGraph conditional edges + 回边）：loop 出边全部走 `add_conditional_edges`（与 condition 同约束，不与普通边混用），执行器可重入，每次进入读取自身上一次产出的 `iterations` 计数：
> 1. `iterations >= maxIterations` → 路由 exitTarget，exitReason=`max_iterations`（**fail-safe 退出**，trace 警告，运行仍 completed）；
> 2. 否则求值 continueExpression：求值异常/非布尔/变量缺失 → 路由 exitTarget，exitReason=`expression_error`，错误进 expression_errors（fail-safe）；
> 3. 表达式为真 → iterations 加 1 路由 bodyTarget（exitReason=null）；为假 → 路由 exitTarget，exitReason=`condition_false`。
>
> 节点产出 `{mode, iterations, index, target, exitReason, expression_errors:[string]}`：`iterations` 为循环体已执行次数，`index` 为当前一轮的 1-based 序号（首次进入前两者皆 0），循环体内节点可直接 `{{loop-x.index}}` 引用。trace 行：继续 `loop-x: continue (i/max) → bodyTarget`；退出 `loop-x: exit (reason) after N → exitTarget`。LangGraph recursion_limit 按 `2*节点总数 + 2*maxIterations*(循环体节点数+1) + 10` 派生传入，避免超步上限中断长循环。

> **D17 loop break/continue（2026-09-19 已落码，`5f87654`；纯拓扑 + 控制状态，不新增 DSL 节点类型）**：**break**＝循环体内某个 **condition 节点**以一条分支直连 loop 的 exitTarget。DSL `_validate_loop_config` 放开该出口：break_sources 为循环体内直连 exitTarget 的 condition 节点；非 condition 的体内节点直连 exit 仍报「退出路径只能由循环节点或体内 condition 的 break 分支出发…不能直接连到退出目标」；能反向走到 break 出口的节点豁免 stranded（不可达）检测；无回边但存在 break 出口亦合法。编译期把该 condition→exitTarget 的边 retarget 到合成内部网关 `__break__<loop-id>`（仿 `__join__`：读旧 loop 产出浅合并、保留 iterations/index、写 `exitReason="break"`、以 loop 节点自身补发 node_end），再由网关 add_edge 到 exitTarget；condition/human/loop 的 add_conditional_edges path map 统一以 retarget 后目标为键值（修了原以原始 target 为键导致 route 返回网关 id 时 KeyError 的缺陷），含 break 出口的 loop recursion_limit 额外 +2。**continue 无需新机制**——体内节点连回 loop 节点本身即重入并重新求值 continueExpression（回边白名单天然支持）。exitReason 取值集扩为 `condition_false | max_iterations | expression_error | break`。

> **D16 foreach 遍历循环（2026-09-23 立项，docs/45；同一 loop 节点、mode 切换；本条为唯一权威）**：`mode="foreach"` 时对**数组逐项串行执行**循环体并暴露 item、可选聚合结果。
>
> ```yaml
> type: loop
> config:
>   mode: "foreach"
>   itemsExpression: string        # §5.1 白名单语法，仅要求语法可解析；求值结果须为数组
>   itemName: "item"               # 可选，标识符；仅前端变量选择器展示别名，运行时路径不变
>   collectTarget: node_id | ""    # 可选；结果聚合来源节点（体内），空＝不聚合
>   bodyTarget: node_id            # 同 while
>   exitTarget: node_id            # 同 while；break 语义（体内 condition 直连此目标）同样适用
> ```
>
> 运行时语义（实现 `atlas.graph.loader._execute_loop`，细节权威见 [docs/45](45-循环foreach批契约设计.md)）：
> 1. 首次重入对 itemsExpression **求值一次并冻结**（写自身产出 `items`，后续不重新求值）：求值异常/变量缺失 → exitReason=`expression_error`；结果非数组 → `expression_error`；长度 >100 → `items_too_large`，均 fail-safe 路由 exitTarget；
> 2. 空数组 → exitReason=`empty` 立即退出；否则按 0-based 游标逐项暴露 `item` 路由 bodyTarget，回边重入时（collectTarget 非空则先把该节点产出追加到 `results`）游标加 1；游标到达长度 → exitReason=`completed`；
> 3. 节点产出增字段 `items`（冻结数组）、`item`（当前元素，首次前 null）、`results`（聚合数组），`index/iterations` 为 0-based 轮次；体内引用 `{{loop-x.item}}`、`{{loop-x.index}}`、`{{loop-x.results}}`（itemName 不改变路径）；
> 4. 拓扑约束（两出边/回边白名单/体内无 trigger·其他 loop/break 网关）与 while 完全一致；foreach 不使用 continueExpression/maxIterations；recursion_limit 以冻结数组长度派生。
>
> foreach exitReason 集：`completed | empty | expression_error | items_too_large | break`。**不做**：嵌套循环、并行 map-reduce、裸 item 全局短名、聚合字段拍平、skip-current 语义、>100 分批（非目标见 docs/45 §2）。
### 5.4 并行与合并
- 并行分支：同时执行多个子流程，等待全部完成或部分完成后合并。
- 合并策略：全部成功、任一成功、全部完成（无论成功失败）。
- 数据合并：将各分支输出汇总为数组或对象。

> **parallel 节点 config 契约（Phase 2 第三项，2026-09-14；本条为唯一权威，03 契约索引指向此处）**：
>
> v1 实现**静态扇出/汇聚**：分支在编译期固定，合并策略支持 `all_success`（全部成功）、`all_completed`（全部完成，无论成败）与 **`any_success`（任一成功 OR-join，2026-09-19 落码 D18/`f45daa9`，语义见本节末）**。动态 map-reduce（运行期按数据生成分支）v1 不做。
>
> ```yaml
> type: parallel
> config:
>   joinStrategy: all_success   # v1: all_success | all_completed
>   branches:                   # 2-10 个；label 非空且唯一；target 互不相同
>     - { label: "分支A", target: node_id }
>     - { label: "分支B", target: node_id }
>   joinTarget: node_id         # 汇聚后唯一出口节点
> ```
>
> 拓扑约束（保存时静态校验，错误聚合中文报错，前缀「并行节点 {id}」）：
> - branches 2-10 个；label 非空且节点内唯一；target 必填、存在、≠自身、互不相同；joinTarget 必填、存在、≠自身且不属于任一 branch target。parallel 节点**出边数 = 分支数**且目标集合 = branches targets，不允许直连 END（汇聚后由 joinTarget 路径接 END）。
> - **分支区域**：从所有 branch target 出发按出边 BFS（遇 joinTarget 与本 parallel 节点停止）可达的全部节点。区域内不得含 trigger 节点或其他 parallel 节点（v1 不支持嵌套并行）；区域内允许 condition 与自包含 loop（loop 回边白名单规则同 §5.3，其出口须留在区域内或指向 joinTarget）。
> - **不得交叉/外泄**：区域内节点的每条出边 target 必须 ∈ 区域 ∪ {joinTarget}（禁止分支之间交叉串接或绕到区域外）；每个分支入口都必须存在到达 joinTarget 的路径；joinTarget 的入边只能来自区域内。
> - parallel 本身不引入环；环检测仍按 U7（loop 白名单回边先摘除再 DFS）。
>
> 运行时语义（实现 `atlas.graph.loader`，经 LangGraph conditional edges 返回多目标扇出）：parallel 出边全部走 `add_conditional_edges`（router 返回 branches targets 列表，不与普通边混用），各分支同超步并发执行。**汇聚屏障由编译期注入的合成网关节点 `__join__<parallel-id>` 实现**（spike 实测 LangGraph 对普通多入边不做 barrier，不会等待全部前驱；冒号为 LangGraph 节点名保留字符故用双下划线前缀）：各分支末端编译期 retarget 到网关，网关每超步检查每个分支是否已有末端产出——未齐则返回空 messages 写自我循环（"wait" 超步，不发事件），齐后聚合一次并经 conditional edge 路由到真 joinTarget，故 joinTarget **只执行一次**（不等长分支同样成立）。`__join__` 节点事件不外泄；汇聚完成时网关以 parallel 节点自身补发第二次 `node_end`（fork 时第一次为 `status:"running"`）。为支持并发写状态，GraphState 的 outputs 通道使用 dict 合并 reducer（`_merge_outputs`，key 级合并），status 通道 last-write，节点只回写自身分片。
>
> **失败语义（fail-safe）**：分支路径上节点产出出现 `result.status=="FAILED"` 即记该分支失败。`all_completed` 总是汇聚；`all_success` 下若存在失败分支，parallel 产出 `status="failed"` 与失败明细，但 **joinTarget 照常执行、运行整体仍 completed**（不做短路终止；下游可用 condition 判 `{{parallel-x.status}}` 决定人工兜底，与 condition/loop 的 fail-safe 风格一致）。
>
> **any_success（OR-join，D18 已落码，`f45daa9`）**：任一分支 success 即汇聚 success 并短路。**取消语义＝只跳过尚未开始的节点**：汇聚网关判定 success 后，区域内未启动节点经 `_guard_any_success` 短路守卫返回 `{skipped:true,reason:"any_success_joined"}`，不发起 tool/wait/approval；**已发起的 tool 调用、已进入的 wait/human_approval 不回滚、不取消**（外部事实不可逆的 fail-safe 取舍），同一超步已启动的节点保留执行完。skipped 分支的末端不计 settled、不计 failure（`_branch_outcomes` 逐分支归并 settled/success/failure）；仅当全部分支 settled 且无一 success 时汇聚 status=failed，joinTarget 仍执行（fail-safe 同 all_success 哲学）。网关幂等（join_target 已有产出则空转），route_gate 在 join_target 已产出时返回新增 "done"→END，兜住汇聚后迟到的残留分支，避免 join 节点重复执行或网关二次 emit。分支被短路时其 branches[].status 记 `skipped`。

> 节点产出 `{mode:"parallel", joinStrategy, status:"success"|"failed", branches:[{label,target,status:"success"|"failed",error}], result:{<分支入口节点id>: <该分支路径末端节点产出>}, joinTarget}`；`result` 以分支入口节点 id 为键（label 可能含中文/空格，不作为变量路径键），可经 `{{parallel-x.result.<node-id>.…}}` 或数组下标引用（路径规则同 §6.3）。trace 行：扇出 `parallel-x: fork N branches → a, b`；汇聚 `parallel-x: joined (all_success) success` 或 `parallel-x: joined (all_success) failed: <label>（<error>）`。扇出不增加 LangGraph 递归深度，§5.3 的 recursion_limit 公式无需为本节点调整。

- v1 为**进程内引用式**（按已保存图 id 解析，同进程重入执行）；版本钉版与手动升级回归（§14）、子图市场/组织共享、跨运营体远程引用见缓做 D21。**发布前子图版本升级体检（只读、不阻断发布、v1 只扫顶层）已于 docs/28 批 4⑪ 落码（2026-09-20 `ba97088`/`19f31b4`，U202–U211）**：纯函数 `versioning/upgrades.py` + `GET /api/graphs/{id}/subgraph-upgrades`（read）+ ReleaseModal 门禁表上方体检区，详见 §14。

> **subgraph 节点 config 契约（Phase 2 第六项，2026-09-14；本条为唯一权威，03 契约索引指向此处）**：
>
> ```yaml
> type: subgraph
> config:
>   graphId: "graph-7"            # 必填非空，已保存 Graph 的 id
>   inputs:                       # 可选，默认 {}；子图入参映射
>     order_id: "{{trigger-1.context.payload.order_id}}"  # 子图入参键 → 父图 {{路径}} 或字面量
> ```
>
> 拓扑约束（保存时静态校验，错误聚合中文报错，前缀「子图节点 {id}」）：恰好 **1 条普通出边**（同 §5.5 wait，不经 conditional 路由），目标为已存在节点且≠自身、不直连 END；入边数量不限。节点可位于 condition 分支、loop 循环体、parallel 分支区域内。
>
> 引用校验（编译期，需图解析器；实现 `atlas.graph.loader` 经 `graph_resolver` 注入，Demo 由 GraphStore 提供）：graphId 必须可解析；禁止直接自引用；跨图引用环（A→B→A）拒绝；**嵌套深度上限 3**（父图为深度 0，即最多父→子→孙→曾孙三层引用，对齐 07 §8 递归深度护栏）；被引用图递归过完整图校验，错误以「子图 {graphId}：」前缀聚合。`inputs` 限对象：键非空且节点内唯一，值为字符串（运行时按父图上下文做 §6.3 `{{路径}}` 插值，缺失引用原样保留）。
>
> 运行时语义（实现 `atlas.graph.loader`）：执行器把渲染后的 inputs 作为子图 run inputs 进程内重入 `run_graph`（子图 trigger `context.payload` + 同名全局变量覆盖，语义同 W9-W10 webhook 载荷），复用父图同一套适配器注册表/决策客户端/审批 broker；**A 包（2026-09-19 已落码 `e594a4b`，docs/27 §3）起子图内部 `node_start`/`node_end` 以可选 `subgraphPath`（按进入层级有序存放每层父图 subgraph 节点 id，用节点 id 而非 graphId）命名空间上 SSE**——只转发节点级事件（含 node_start 上的 approval 载荷），吞掉子层 `run_end`/result 终帧（整图仅父层发一个 run_end，避免子图结束被误判为整图结束），嵌套重入路径在最外层一次性累加（如 `["sg-a","sg-b"]`）；命名空间回调 try/except 防御、回调故障不影响执行。此前 v1 为 `emit=None` 完全压制；子图 trace 始终完整收入节点产出。阻塞执行于 Starlette 线程池工作线程（同 §5.5/§5.6），不产生父图 LangGraph 超步，父图 recursion_limit 公式不变，子图有独立编译限额。子图运行期异常（含解析/编译失败与深度守卫）按 **fail-safe**：节点产出 `status:"failed"` 与 error，run 仍 completed，沿唯一出边继续，下游可用 condition 判 `{{subgraph-x.status}}`（同 §5.4 汇聚 fail-safe 哲学，不做成功/失败双出口）。子图内含 human_approval 时，其 node_start 的 approval 载荷（含共享 broker 全局唯一 token）经命名空间上屏，前端审批 Modal 以 `[subgraphPath] nodeId` 显示归属（如 `[sg-sub] c-approve`），复用既有 `/api/approvals/{token}/decision` 即可在等待期交互放行/拒绝、broker 释放子图执行线程（A 包进程内交互形态已取回，**无新端点**；持久化/多实例中断仍随 D20，见缓做 D21）；run inputs 预置与超时自动决策仍可用。retry 配置保留不生效。
>
> 节点产出 `{mode:"subgraph", graphId, status:"success"|"failed", error?:<失败时>, outputs:<子图 outputs dict>, trace:[<子图 trace 行>]}`，可经 `{{subgraph-x.status}}`、`{{subgraph-x.outputs.<子图节点id>.<键>}}` 引用（路径规则同 §6.3）。trace 行：`subgraph-x: graph-7 success (N nodes)` / `… failed: <error>`。
### 5.8 状态机
- 用途：管理业务对象生命周期（如订单的待支付→已支付→已发货→已完成）。
- 定义方式：在编辑器中定义状态节点和转移条件。
- 运行时行为：运营体根据当前状态和事件决定下一步操作。
- 与Graph的关系：状态机是Graph的一种特殊子图，可以嵌入流程中。
### 5.9 异常处理
- 局部异常：节点级on_error，可配置重试、跳过、跳转到指定节点。
- 全局异常：运营体级异常处理器，捕获所有未处理异常，执行统一降级策略。
- 自愈机制：操作失败时触发“诊断子图”，尝试修复后继续。

### 5.10 流程模板库（内置只读）
> **流程模板库 v1 契约（Phase 2 能力项，2026-09-15；本条为唯一权威，03 契约索引 `template_catalog` 指向此处）**：
>
> 模板是**预置流程的起点**：从模板新建即把模板的完整 Graph JSON 载入编辑器，用户改完后按普通图保存（graph-N）、运行，模板本身不被引用、不被修改。
>
> **元数据结构**（权威实现 `src/atlas/template/catalog.py`）：
>
> ```yaml
> TemplateMeta:
>   id: string            # kebab-case，目录内唯一，随代码稳定（前端不假设可枚举以外的 id）
>   name: string          # 展示名（v1 仅中文）
>   description: string   # 一句话场景说明
>   tags: [string]        # 展示标签（如 退款 / HTTP / 数据库 / 审批 / 消息）
>   graph: graph_definition  # 完整 version 1 Graph JSON，结构同 §5.2 graph_definition
> ```
>
> **v1 内置目录（5 个，全部仅使用 demo 已注册适配器：shop.*、http/request、database/query、database/execute、message/send，零配置可跑）**：
>
> | id | 场景 | 节点链 |
> |---|---|---|
> | `refund-auto` | 电商退款自动审批（golden 流程） | trigger → ai_decision → tool_call(shop/process_refund) |
> | `http-orders-branch` | HTTP 拉单 + 按响应状态分流通知 | trigger → tool_call(http/request GET /api/demo/mock/orders) → condition（`{{http-1.result.status}} == 200` / default）→ 2× message/send |
> | `sql-query-notify` | SQL 查询大额订单 + 条件通知 | trigger → tool_call(database/query，绑定参数 :min) → condition（`{{query-1.result.row_count}} > 0` / default）→ 2× message/send |
> | `sql-approval-write` | 写库操作先人工审批 | trigger → human_approval（3600s，超时拒绝）→ approvedTarget: database/execute（UPDATE）/ rejectedTarget: message/send |
> | `approval-timeout-reject` | 审批超时默认拒绝演示 | trigger → human_approval（10s，onTimeout=reject）→ approvedTarget / rejectedTarget 各一 message/send |
>
> 每个模板 graph 必须过 `parse_graph`/`validate_graph` 全部静态与拓扑校验（§5.2-§5.7），condition 每分支与 defaultTarget 均有出边、human_approval 恰好两条出边、trigger 根可达全部节点；节点 id 在模板内固定。
>
> **只读与加载语义**：
> - 目录随代码版本发布（Python 常量），v1 **无 DB 表、无创建/更新/删除端点**，`/api/demo/reset` 不影响模板目录；
> - REST 只提供 `GET /api/templates`（列表投影 `{items:[{id,name,description,tags,node_count}]}`，不含 graph）与 `GET /api/templates/{id}`（完整元数据含 graph，未知 id 404）；
> - 「从模板新建」= **整画布替换**：编辑器整体替换 nodes/edges/variables 为模板内容（与自然语言草稿载入、初始画布同一 `loadGraph` 路径），**不做节点 id 重映射**，不重写边、`{{node-id.path}}` 引用与 config 目标；替换前 UI 必须警示未保存修改会丢失；
> - 模板加载后与目录再无关联：保存产生新的 graph-N，模板更新不影响已保存图。
>
> **缓做边界**：用户自建/编辑/删除模板、模板市场与组织内共享、远程/URL 导入、模板版本钉版与升级、模板搜索评分缓做 14 D25；元数据多语言随 i18n（14 D13）；子图模板与子图市场仍在 14 D21。

### 5.11 操作录制与回放
> **操作录制 v1 契约（Phase 2 能力项，2026-09-15；本条为唯一权威，03 契约索引 `recording_case` 指向此处）**：
>
> v1 的「操作录制」指 §9.3/§9.5/§补充11 的**运行录制与回放测试**——把一次真实 Graph 运行（入参、逐节点产出、终态）录为回归用例，之后一键回放并做操作序列与变量值逐项比对（13 R1）。§4.5 方式 2「在外部平台手动操作、浏览器插件/录制器生成工具」不在 v1（仍缓做 14 D22），07 行为挖掘器为后续阶段。
>
> **用例结构**（权威实现 `src/atlas/recording/cases.py`）：
>
> ```yaml
> RecordingCase:
>   id: string               # "rec-N"，进程内自增
>   name: string             # 用户命名（1-100 字）
>   graph: graph_definition  # 录制时已保存图的完整快照（version 1），冻结不随后续编辑变化
>   inputs: object | null    # 录制时运行入参（trigger context.payload）
>   steps:                   # 逐节点终态，按 node_id 唯一
>     - node_id: string
>       node_type: string
>       output: object       # 该节点最后一次 node_end 产出（parallel 两次 node_end、loop 重访均取末次）
>   status: string           # 录制运行终态（completed）
>   created_at: string       # ISO8601 UTC
> ```
>
> **录制语义**：录制不引入专用运行端点。客户端在一次正常 `POST /api/graphs/{id}/run/stream` 中收集 node_end 事件（与画布所见完全一致，人工审批仍可实时交互），运行结束后把 steps 连同 `graph_id`/inputs/status 经 `POST /api/recordings` 提交；服务端按 graph_id 取已保存图的原始 JSON 作为**快照**存入用例（不重新执行、不保存 graph_id 活引用）。
>
> **回放与比对**（`POST /api/recordings/{id}/replay`）：
> - 服务端 parse_graph 快照，走标准 compile/run 链路（06 §6.9），无任何录制专用运行时；
> - **确定性**：从 baseline 的 human_approval 步骤抽取 `{node_id: decision}` 合并为回放入参 `inputs.approvals`（预置决策，04 §5.6 决策来源之一），回放不挂起等待人工；13 R3 的「暂停等待人工」由正常运行链路承担；
> - **操作序列**：回放的 node_end 节点序列须与 baseline 一致（多走/漏走节点即不匹配，分支漂移以此暴露）；
> - **逐节点变量**：output 深等前做**易变值归一化**——递归删除 `token`（审批令牌）、`sent_at`（消息时间戳）键；同层含 `sent_at` 的对象（消息记录）删除其 uuid `id`；`http/request` 产出的 `result.headers` 删除 `date`；human_approval 产出删除 `resolvedBy`（决策来源 human/timeout/input 属运行时来源，预置回放恒为 input）；trigger 产出删除 `context.payload.approvals`（预置决策通道随载荷回显）。业务标识键名为 `order_id` 等，不受影响；
> - 响应 `{matches:boolean, baseline_status, replay_status, steps:[{node_id, match, note, diff_keys?}]}`，不匹配给出节点级差异顶层键名。
>
> **生命周期与边界**：用例为进程内存储（重启清空，持久化随 11 S1）；`/api/demo/reset` **不清除**录制用例（测试资产，同 /api/feedback），但会清空 GraphStore——因图已快照进用例，回放不受影响；快照内 subgraph 节点引用的 graphId 不内联，reset 或删除导致引用缺失时回放折叠为 `replay_status:"failed"`、matches=false（不抛 500）。
>
> **REST**：`POST /api/recordings`（graph 未知 404、steps 形状非法 422）、`GET /api/recordings`（投影 `{items:[{id,name,node_count,step_count,status,created_at}]}`，不含 graph/steps）、`GET /api/recordings/{id}`（完整用例，未知 404）、`DELETE /api/recordings/{id}`（未知 404）、`POST /api/recordings/{id}/replay`。
>
> **缓做边界**：批量回放与报告、配置/模型更新后的跨版本差异对比（§补充11）、影子模式（§补充10）、Mock 工具响应、用例编辑与入参参数化、subgraph 引用快照内联缓做 14 D26；R2（页面元素变化的三层定位兜底回放）随 Web 操作适配器，不在本项。
>
> **发布前批量回放门禁（M9 已落码 2026-09-18（批 1-4＋收口，后端 602/前端 396，证据见 13 §9）；D26 部分取回，权威＝08 M9 立项条 + 10 §4 ADR T22）**：发布动作（§5.16）前对**当前 latest 草稿**批量重放本图录制用例并逐例比对，坏版本不允许发布：

### 5.12 单步调试与断点
> **单步调试 v1 契约（Phase 2 能力项，2026-09-15；本条为唯一权威，03 契约索引 `debug_session` 指向此处；产品语义见 §三 8/9）**：
>
> 调试是**运行期会话**，不产生新节点类型，**EdgeDSL 与 Graph version 1 不变**。断点不持久化进 Graph JSON（§5.2 node_schema 的 `breakpoint` 预留位 v1 不启用），只存于编辑器前端状态、运行时随请求传入；刷新页面即清空，持久化断点缓做 14 D27。
>
> **启动**：`POST /api/graphs/{id}/run/stream` 请求体增 `debug?: {breakpoints?: [{node_id: string, expression?: string}]}`；带 debug 即调试运行，启动时处于**逐节点（step）模式**——每个节点执行前都暂停。同步 `/run` 不支持 debug（422）。
>
> **暂停协议**：执行器在每个节点 node_start 之后、节点逻辑之前统一判定（所有节点类型同一挂点，无类型分支）：
> - step 模式为真 → 暂停（reason `"step"`）；
> - 否则 node_id 命中断点表 → 无 expression 暂停（reason `"breakpoint"`）；有 expression 则以当前上下文（`{"global": 全局变量, **已完成节点 outputs}`，与 condition 节点同一表达式引擎与变量路径，§5.1）求值，为真暂停（reason `"condition"`）；**表达式异常 fail-safe 视为不命中**（记录错误但不卡断运行）。
>
> ```yaml
> paused 帧:                                 # SSE event: paused
>   type: "paused"
>   token: string                            # "dbg-<uuid>"，resume 凭据
>   node_id: string                          # 暂停在该节点执行前
>   node_type: string
>   reason: "step" | "breakpoint" | "condition"
>   globals: object                          # 当前全局变量快照（深拷贝）
>   outputs: object                          # 截至暂停点全部已完成节点终态产出（深拷贝）
> ```
>
> **恢复**：`POST /api/debug/{token}/resume`，请求体 `{action: "step"|"continue"|"stop"}`：
> - `step`：执行当前节点，之后保持逐节点（下一节点前再停）；
> - `continue`：退出逐节点模式（step=false），后续仅断点（含条件）命中才暂停；
> - `stop`：取消本次运行，执行器抛 DebugStopped，SSE 发 `stopped` 帧 `{type:"stopped", node_id, reason:"user_stop"}` 后正常结束流（**无 result 帧**）；停止只在暂停点生效，v1 不做运行中强杀（D27）。
> - 未知 token 404；对同一暂停重复 resume 409（首决生效）。
>
> **变量查看/改写**：globals/outputs 快照随 paused 帧下发（深拷贝只读），前端展示全局与节点作用域值。**B 包（2026-09-20，`f9a1301`，docs/27 §4.3）取回进程内「暂停时 globals 改写续跑」**：resume 的 step/continue 可带 `globals`，仅 global 顶层键白名单浅合并（dict 值整体替换、不深 merge、不删未提供键），键名须合法标识符、值 JSON 可序列化，非法聚合成中文 422；`stop` 忽略 globals；帧本身仍只读、outputs 不可改。变量变化历史已于 docs/28 批 2（`038dcaa`）取回进程内易失形态（见本节末「docs/28 批 2」注记）；跨节点血缘来源追踪仍缓做 14 D27。

> - parallel 区域多个分支节点同时到达暂停点时，会话内串行化（一次只呈现一个暂停，恢复后下一个才暂停）；parallel 节点自身两次 node_end 的合成 `__join__` 网关不暂停；

### 5.13 基础监控告警
> **监控告警 v1 契约（Phase 2 能力项，2026-09-15；本条为唯一权威，03 契约索引 `monitoring` 指向此处；产品语义见 §9.3「实时监控运行状态，异常自动告警」）**：
>
> v1 为**进程内、零新依赖**的运行观测，与 §5.11 录制、§5.12 调试同构；正式可观测性栈（OTel 指标/追踪、Prometheus、Grafana 仪表盘、持久化多实例）缓做 14 D11/D28。监控是只读旁路，**EdgeDSL 与 Graph version 1 不变，执行器零节点类型分支**。
>
> **采集范围与健康定义**：只统计两个真实运行入口（同步 `POST /api/graphs/{id}/run`、流式 `POST /api/graphs/{id}/run/stream` 的非 debug 运行）；录制回放（§5.11 的 replay- 直调）、subgraph 重入、§5.12 debug 运行（step/continue/stop）均不记录。
> - **健康**：`status=="completed"` 且无失败节点。
> - 节点成败从运行终态 outputs 推断（node_end 帧本身无 status）：`output.status=="failed"`（parallel/subgraph fail-safe 折叠产出）或 `output.result.status=="FAILED"`（tool_call 的 ActionResult 数据化失败）；其余视为 success。
> - 执行器未捕获异常冒泡 = 运行级异常（同步端点 500、SSE `event: error`），`status=="error"`。
>
> ```yaml
> RunRecord:
>   id: string                  # "run-N"，进程内自增
>   graph_id: string
>   mode: "sync" | "stream"
>   status: "completed" | "error"
>   started_at: string          # ISO 8601 UTC
>   finished_at: string
>   duration_ms: number
>   nodes:                      # 逐节点（按 outputs 出现顺序）
>     - node_id: string
>       node_type: string
>       status: "success" | "failed"
>       error: string?          # 失败时取 error / result.message / result.code

>   node_failed:          {enabled: true}                 # 任一节点失败即告警（warning）
>   consecutive_failures: {enabled: true, threshold: 3}   # 同图连续不健康达 N（critical）
>   failure_rate:         {enabled: true, window: 20, min_samples: 5, rate: 0.5}
>                         # 同图近 window 次运行（含本次）样本≥min_samples 且不健康占比≥rate（critical）
> ```
>

>   message: string             # 中文摘要（含图、节点、阈值等）
>   first_seen: string          # ISO 8601 UTC
>   last_seen: string
>   count: integer              # 合并次数，首见为 1
>   status: "open" | "acknowledged" | "resolved"
>   last_run_id: string
> ```

> **契约权威 blockquote（M10，D34 进程内部分；形状权威＝docs/19 §2.3.4/§2.5 + 10 §4 ADR T21 + 08 M10 立项条；落码承载 `src/atlas/tracing/` + `graph/loader.py` + `coordination/` + `monitoring/records.py`）**：
>
> **最小 span 模型（与 OTel 同形、不引 SDK，ADR T21）**：`Span{traceId(32hex), spanId(16hex), parentSpanId, name, kind, startedAt, durationMs, status(ok|error), graphVersion, attrs, internal}`；kind＝`run/node/tool/parallel/subgraph/task_dispatch/task_done/approval`。traceId 一次 run（含 subgraph 重入与 M7 任务信封）一致；root 为 `run` span（parentSpanId 缺省）。纯 stdlib（uuid4/time/contextvars），零新依赖；OTel SDK/Collector/Exporter 与 W3C Trace Context 跨服务透传随 D11/D5。
>
> **进程内传播**：contextvars 记「当前 span」，供同线程节点执行器→`_execute_tool` 就近取父；Tracer 实例随 `run_graph(tracer=..., graph_version=...)` 显式参数透传进 `compile_graph`/执行器（守 §5.14/06 §6.12 后台线程不靠全局上下文——SSE worker 在独立线程跑 run_graph）。subgraph 重入复用同一 tracer、经内部 `_parent_span` 把子图 root 链到 `subgraph` span。
>
> **埋点层级**：run root → 每节点 `node` span（status 随产出，工具 FAILED→error）→ 工具 `tool` span（attrs＝adapter/capability）；parallel 节点 span 记 fork attrs（分支数/目标），分支节点各自 node span（合成 `__join__` 网关不建外泄 span，沿用 §5.4）；subgraph 建 `subgraph` span、子图内部 span 标 `internal=true`；M7 任务信封 dispatch 建 `task_dispatch`、complete 建 `task_done`（actor=assignee、attrs orderId）。
>
> **内部 span 可选不外泄**：`Tracer.to_tree(include_internal=False)` 把 subgraph（及未来 parallel 合成步）内部折叠为单个 span（保留 graphId/status attrs），把 subgraph 内部 span 折叠为单个 subgraph span（与 SSE 事件是否上屏无关——A 包后子图节点事件经 subgraphPath 上屏，但 tracer 内部 span 仍默认折叠投影，§5.7）；`include_internal=True` 返回完整树。开关只影响导出投影，不影响 span 实际记录。
>
> **SSE 超集（19 §2.3.4）**：node_start/node_end/run_end 在保留全部现字段前提下**只新增** traceId/spanId/parentSpanId（run_end 另加 graphVersion）；不新增事件类型，前端忽略未知字段即零改动。完整 span 树不进 SSE 高频帧，由 tracer 进程内 `to_tree()` 导出（单测断言/未来调试端点），span 调试端点与前端瀑布 UI 缓做。
>
> **关联落库**：`RunRecord` 加可选 `trace_id`（默认空、向后兼容），两真实运行入口（sync `/run`、`/run/stream` 非 debug worker）record_run 时写入；`Envelope.traceId` 由 M7 占位（=runId）改为真实 traceId 并带 parentSpanId。graphVersion＝发布版 `graphId@<releaseVersion:int>` / 草稿 `graphId@draft`（无 v 前缀，与 M6 钉版字符串 `f"{sub_id}@{pin}"` 一致；早期文案的 `@vN` 为记号示意）。
>
> **录制回放**：span 三元组在 SSE 事件顶层、不进节点 output，collect_steps 只取 output 天然不受影响；`recording.normalize` 另防御性剔除产出内 traceId/spanId/parentSpanId/graphVersion 键（随机 id 与时间戳不参与逐节点比对）。
>
> **边界**：debug 单步会话不埋点（同 §5.13 监控口径）、录制回放端点与 subgraph 重入不产生新 RunRecord；不做 metrics/alerts（§5.13 与 M9）、不做 span 持久化/导出后端、不做跨服务传播。

> **Trace 时间线钻取落码块（docs/33 §4，批 3 ⑤⑧⑨，D28/D34 进程内部分取回、不解除；2026-09-21 落码，后端 `4579843`/前端 `ce6cc23`，U270–U278）**：取回 M10 缓做的「span 持久化 + 钻取端点 + 前端瀑布」。`RunRecord` 纯超集加 `spans`（`tracer.to_tree()` 根 span dict，kind=run，DFS 含 node/tool 子 span；缺省 null），两真实运行入口 record_run 时落；**PG 迁移 012 给 `monitoring_runs` 加 `spans JSONB`**（内存档随 ring）。为控体积，列表端点（GET /monitoring/runs）**剔除 spans**，新增 `GET /api/monitoring/runs/{run_id}/trace`（read）懒加载，返 `{id, trace_id, spans}`；历史/debug/回放无 spans 记录返 `spans:null`，运行不存在/跨租户 404。前端监控页「最近运行」展开区增 **Trace 时间线 Tab**：三级缩进瀑布（run → 节点 trigger/tool_call → 工具），kind Tag、成功蓝/失败红横条、durationMs 标注（截图 `docs/assets/d28-trace-waterfall.png`）。**边界不变**：完整 span 树仍不进 SSE 高频帧；不引入 OTel SDK/Collector/Exporter、不做 W3C Trace Context 跨服务透传与 span 独立导出后端——外部可观测栈仍缓做 14 D28/D11/D5（不解除）。

### 5.16 灰度发布与门控回滚（M9 已落码 2026-09-18（批 1-4＋收口，后端 602/前端 396，证据见 13 §9））

> **契约权威 blockquote（M9，题二最后一个里程碑；形状权威＝docs/19 §2.3.3 rollout JSON + §2.5 灰度与回滚五条 + docs/20 §4.4/§7.5，工程决策＝10 §4 ADR T22 + 08 M9 立项条；落码承载 `src/atlas/routing/` + `recording/gate.py` + `monitoring/business.py`；03 索引 `rollout_config`/`route_decision`/`release_gate`/`business_metrics`，运行时见 06 §6.17）**：
>
> **定位**：M6（§9.2/ADR T19）已落「发布＝冻结不可变版本 `graphId@<int>` + subgraph 递归钉版」；M9 补齐发布**之后**的入站路由、灰度状态机与自动回滚闭环。Demo 形态为**进程内 Router + 每租户 RoutingStore**，复用现有 `/run`、`/run/stream` 端点与 M5b 中断帧 pin 机制，零新依赖、后端纯 stdlib；真实独立网关/多实例路由表同步/配置中心/热推送缓做 14 D6/D10b/D32。
>
> **① RolloutConfig（PUT /api/graphs/{id}/rollout，存配置不启动；非法 422 中文）**：
>
> ```yaml
> strategy: "progressive"        # v1 唯一值
> rules:                          # 求值顺序固定（v1 无 when 表达式解析器，字符串条件落为结构化字段）
>   - {to: "internal", tenants: ["t1"]}                 # 内部租户 allowlist
>   - {to: "lowValueBucket", field: "payload.amount", op: "<=", value: 200, percent: 100}
>   - {to: "canary", percent: 5}                        # 稳定哈希百分比
>   - {to: "full"}
> gate:
>   observeMinutes: 60            # 按 RunRecord.finished_at 时间过滤
>   autoRollback: true            # false 时越阈只告警不切流
>   minSamples: 3                 # 窗口内 candidate 样本不足不判（防冷启动误杀）
>   metrics:
>     - {id: "run_error_rate", threshold: 0.02}
>     - {id: "manual_escalation_rate", threshold: 0.10, compareWith: 6}  # 与 stable 版本对照
>     - {id: "refund_amount_diff_rate", threshold: 0.005}
> inFlightPolicy: "pin-to-version"
> ```
>
> **② Router 三段分桶（`routing/router.py` resolve_version 纯函数，19 §2.5 前三维度：租户→业务桶→订单 id 哈希）**：固定序求值——`internal`（event 租户 ∈ tenants）→ `lowValueBucket`（payload.amount 为数字且 ≤ value，低风险业务桶 100% 走新版）→ `canary`（桶键取 `payload.order_id`、缺省 `payload.id`，`int(sha256(f"{graph_id}:{bucket_key}").hexdigest(),16) % 100 < percent` 命中 candidate；**同一业务对象哈希恒定，灰度期内不会新旧横跳**；桶键缺失/非字符串 fail-safe 落 stable，segment 记 `fallback`）→ `full`（candidate 全量）；未命中任何段/无 candidate/未配置 → stable。tenant 取自会话 Principal，**不从请求体取**（防伪造越权进内部段）。
>
> **③ 入站接线与 pin-to-version**：`POST /api/graphs/{id}/run` 与 `/run/stream` 请求体增可选 `event?: {channel?: "api"|"webhook"|"im"|"embed"（缺省 api）, payload?: object}`。**不带 event＝编辑器手动运行，严格走草稿旧行为（零回归）**；带 event 经 resolve_version 解析并按版本加载不可变发布快照运行（含 M6 subgraph 钉版），图无任何发布版 → 409「图尚未发布，入站事件无版本可路由」。在途实例 pin **不新增机制**：M5b 中断帧 `build_frame` 已冻结 `graph_snapshot`，`_resume_run` 用帧内快照 model_validate 续跑——回滚后挂起实例恢复时仍跑启动时版本（U56 补帧快照断言）。
>
> **④ rollout 状态机（`routing/store.py` RoutingStore，每租户一个挂 TenantServices、reset 清空）**：
>
> ```text
> configure（存配置，不启动）
>   idle ──start──▶ canary ──promote──▶ full
>    ▲                │                     │
>    └──── rollback ───┴────────（任意态）───┘  → rolled_back（candidate 撤流、stable 接全量）
> ```
>
> - `POST .../rollout/start`：idle→canary，取最新两个发布版（stable＝前一版、candidate＝最新版）；发布版不足 2 个 → 409；
> - `POST .../rollout/promote`：canary→full，**唯一放量路径，仅手动——全仓无任何自动 promote 代码**；
> - `POST .../rollout/rollback`：*/→rolled_back，自动（actor="auto"）与手动（actor="manual"）走**同一幂等函数**，重复回滚幂等不报错；
> - `GET /api/graphs/{id}/rollout` 投影：`{status, stable, candidate, started_at, rolled_back_at, rollback_reason, traffic:{stable,candidate,segments:{internal,lowValueBucket,canary,full,fallback}}}`（分流计数仅进程内观测）。
>
> **⑤ 发布门禁（发布流闸门，D26 部分取回）**：详见 §5.11 末「发布前批量回放门禁」与 03 `release_gate`——`POST /api/graphs/{id}/release-gate` 对 latest 草稿批量回放本图录制用例；publish 增可选 `{gate:true}`，坏版本 409 不产版本、无用例明示 skipped 不假装通过。
>
> **⑥ 指标门控自动回滚（`routing/gate.py` evaluate_after_run）**：仅当本次 RunRecord 的 resolved_version 是某图 candidate 且该图 status=canary、gate.autoRollback=true 时，在 API 层 `record_run` 之后求值：取 observeMinutes 窗内该图 candidate 运行（finished_at 过滤），样本 < minSamples **不判**（fail-safe 防冷启动误杀）；`run_error_rate` 复用 §5.13 is_healthy，业务两率取 §5.13 末 business 段；任一越阈 → `rollback(actor="auto", reason=越阈指标/阈值/观察窗)` + 产 `rollout_gate` critical 告警（携带 action，见 03 `monitoring`）。`compareWith` v1 落为告警 message 中 stable 同期对照值（stable 样本不足明示），不做额外阻断。
>
> **金融灰度三条硬条款（19 §2.5.5 / 20 §7.5，不可简化、不可为 Demo 进度省略）**：
> 1. **业务桶**：灰度维度必须含业务属性分桶（低金额订单先行），不能只按随机百分比——v1 落为 lowValueBucket 段（payload.amount<=N 100% candidate）；
> 2. **门控指标必须含业务结果**：run_error_rate 之外必须有 manual_escalation_rate、refund_amount_diff_rate（系统成功率全绿但退款决策全错时必须能发现）；
> 3. **回滚不改外部已发生事实**：已退款/已转人工不可逆，自动回滚只切新流量（candidate 撤流），不补偿、不冲正；在途实例 pin-to-version 跑完启动版本。

> **REST 与权限**：rollout 配置（PUT）、start/promote/rollback 与 release-gate 对齐发布权限（operate/admin；viewer 只读 GET，落码时按 §5.14 角色矩阵核实并回填 12）；run/run-stream 的 event 字段对可运行角色开放。RoutingStore 进程内首版按租户分区（同 T20 TaskStore 先例），PG 档装配与 reset 清空在落码时两分支同步。

> **缓做边界**：真实 webhook/IM/embed 入站服务器与签名验签、多实例路由表同步/热推送、配置中心与独立网关（D6/D10b）、自动放量/智能放量、业务桶规则 DSL 与 when 表达式解析器、灰度 A/B 显著性分析与用户满意度指标、demo shop 退款金额字段改造、RoutingStore PG 持久化（随 11 S1 批次评估）、真实生产发布与多实例触发的 D32 解除条件，均缓做（14 D6/D10b/D24/D26 余部/D32）。

### 5.17 生产认证（账号/口令/会话 TTL/登录节流；P0 批 2 已落码 2026-09-21）

> **生产认证 v1 契约（P0 批 2，ADR T25，形状权威 docs/31；本条为账号/口令/会话生命周期的唯一权威，03 契约索引 `identity_user`/`identity_session` 指向此处。2026-09-21 落码收口：后端 `cd1133a`/`097c056`/`e65e4df`/`4224578`/`36ab54e`、前端 `222552d`，后端 822 passed/31 skipped、前端 509 passed/2 skipped、curl 23 项契约全绿、浏览器 8 截图）**：
>
> **口令哈希**：标准库 `hashlib.scrypt`（n=2^14/r=8/p=1、dklen=32、16 字节随机盐），存储串 `scrypt$16384$8$1$<salt b64>$<hash b64>`，`hmac.compare_digest` 恒定时间校验，零新依赖（bcrypt/argon2 随合规要求重开，见 14）。种子账号由幂等 seeder 写入 `iam_users`（迁移 010），只插缺失行、不覆盖后续改密，系统通道不经弱口令策略。

> **账号表与生命周期**：`iam_users`（迁移 010）以 `(tenant_id,username)` 复合主键，列 password_hash/display_name/role/status/created_at/updated_at；用户名 3–64 位 `[a-z0-9_.-]`，登录全局按 username 查。管理员代管、**不开放注册、不删用户（禁用替代删除）**。管理员可建用户、改显示名/角色/状态、重置任意用户密码；登录用户可改本人密码。改密吊销本人**除当前会话外**全部会话（当前会话保留）；禁用、管理员重置吊销该用户**全部**会话。v1 不做「租户必须剩一个 admin」后端硬校验（前端提示）。
>
> **口令策略**：8–128 位；内置弱口令黑名单（admin123、12345678 等常见口令）；不强制符号/大小写（避免制造可预测口令）；管理员建用户/重置、本人改密三处同一策略，不达标 422。

> **会话绝对 TTL**：不透明 `sess-<32hex>` token（不引 JWT、不设吊销黑名单）；迁移 011 给 `iam_sessions` 加 `expires_at`，签发时刻 = 当前 + `ATLAS_SESSION_TTL_HOURS`（缺省 12h、合法 1–168），**绝对到期、不滑动续期**；过期/被吊销 → 401 并惰性删行；回填旧会话 expires_at 为 NULL 视为不过期。

>
> **REST 与状态码**（详见 12 §3.10/§5）：`POST /api/auth/change-password`（登录用户，旧口令错 400、新口令不达策略/与旧相同 422）、`GET/POST /api/users`（admin；重名 409、策略 422）、`PATCH /api/users/{username}`（admin；他租户/不存在 404）、`POST /api/users/{username}/reset-password`（admin）。登录端点：未知用户/坏口令统一 401「用户名或密码错误」（不区分以防枚举）、停用账号 403「账号已停用，请联系管理员」、节流 429；其余端点未认证统一 401「缺少或无效的登录凭证」、角色不足 403、他租户对象 404（沿用 §5.14）。
>
> **非目标（缓做 14）**：SSO/OIDC/SAML/企业微信飞书登录、MFA/2FA、邮箱找回/验证、开放注册/租户 CRUD/platform_admin、JWT/吊销黑名单/并发会话上限/「在其他设备下线」、完整登录与账号操作审计、多实例共享节流、首次登录强制改密；出向适配器凭证加密/OAuth2/SSRF 白名单属下一批安全准入（docs/32，D22/D23）。

> **Harness 适配器（adapter.py）**：`ShopifyHarnessAdapter`，`adapter_id="channel:shopify:{binding_id}"`、`adapter_type="shop"`，由 `ChannelRegistry.adapters_for_tenant()` 按绑定动态产出、注册进该租户 AdapterRegistry（loader 装配点，同 GENERIC_JSON_ADAPTERS 模式）；工具 shop/list_orders（read）、shop/get_order（read）、shop/create_refund（**financial**，金融能力门不变）。所有异常在适配器边界转 ActionResult.failed，不向图抛裸异常。
>
> **REST / reset / 审计**（详见 12 §3.13/§5）：`/api/channels` 五端点，门 read / operate / administer；POST/DELETE 审计 `channel.bind` / `channel.unbind`；未知绑定/跨租户统一 404；引用 connection 被删 → 绑定 status=error 不级联。**绑定属客户配置，reset 不清除**（同 connections/audit）。
>
> **v1 边界（缓做 14 D22，本批不解除）**：无入站 webhook（订单/退款事件推送与 HMAC 验签）、无 Amazon/其他平台、无订单增量同步落库、无真实店铺 OAuth 授权联调（需真实账号，触发条件不变）。

### 5.19 入站 Webhook（入站 Webhook 批，ADR T29；2026-09-23 docs-only 立项，形状权威 docs/39）

> **入站触发 v1 契约（03 契约索引 `channel_webhook` 指向此处；落码承载 `src/atlas/channels/webhooks.py`，架在 docs/38 Shopify 出向渠道与 T4 connections 之上）**：
>
> **验签与投递内核（webhooks.py）**：`verify_shopify_hmac(raw_body, provided, client_secret)`——`base64(hmac_sha256(client_secret, raw_body))` 与 `X-Shopify-Hmac-SHA256` 经 `hmac.compare_digest`；provided 缺失/坏 base64 → False；**不抛、不记 body/secret**。`WebhookEnvelope {shop_domain, topic, webhook_id, triggered_at, data}` 从 headers＋已解析 JSON 构造；必需头 `X-Shopify-Shop-Domain`/`X-Shopify-Topic`/`X-Shopify-Webhook-Id`（缺任一 → 400）。`SUPPORTED_TOPICS = {orders/create, orders/updated, refunds/create}`；`build_trigger_event` 产 `TriggerEvent(channel="webhook", payload={topic, shop, data})`（data 为 Shopify 原始 body、不做投影）。`WebhookDeliverer.deliver`：幂等环（per-tenant 进程内 ring 200、惰性剔 1h，重复 → `{duplicate:true}` 不触发不审计）→ topic 无启用订阅 → `{ignored:true}` → 逐订阅经 `routing_store.resolve` 钉版本，版本 None → warning 跳过（不造失败 run），有版本 → 后台线程提交图运行（异步、不 SSE）；投递异常仅 warning。

> **REST / 安全**（详见 12 §3.14/§5）：公开免登录 `POST /api/channels/hooks/shopify/{binding_id}`——200 received/duplicate/ignored；400 缺头/非 JSON 对象；401 HMAC 缺失或不匹配（不区分）；404 未知绑定（统一文案、不 peek 惰性建租户）；503 client_secret 信封缺失/解密失败；**验签必须在 JSON 解析前、验签通过后绝不非 2xx**。订阅 `GET`（read）/`PUT`（**administer**，全量替换：topic 白名单、graph 同租户存在〔否则 404〕、键唯一、≤10、enabled bool；坏形状聚合中文 422）。

## 六、数据与变量系统设计
数据是运营体的血液，变量是数据的载体。通用化要求变量系统具备强类型、作用域、生命周期、可追踪特性。
### 6.1 变量类型

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 字符串 | 文本 | "订单已发货" |
| 数字 | 整数/浮点 | 100, 39.9 |
| 布尔 | 真假 | true |
| 对象 | 键值对 | { "name": "张三", "age": 25 } |
| 数组 | 列表 | ["A", "B", "C"] |
| 文件 | 图片/PDF等二进制 | 用户上传的截图 |
| 富文本 | 带格式文本 | 邮件正文 |

### 6.2 变量作用域

| 作用域 | 生命周期 | 可见范围 | 示例 |
| --- | --- | --- | --- |
| 全局变量 | 运营体定义期 | 所有节点 | 企业ID、品牌名称 |
| 节点变量 | 节点执行期 | 当前节点内部 | 临时计算结果 |
| 子图变量 | 子图执行期 | 子图内及调用方 | 子图入参/出参 |
| 会话变量 | 单次运行期 | 整个运行实例 | 当前用户ID、订单号 |
| 环境变量 | 平台/租户级 | 所有运营体 | 数据库地址、模型密钥 |
| 秘密变量 | 加密存储，运行时解密 | 授权节点 | API Token、支付密钥 |

### 6.3 变量引用语法
在编辑器中统一使用 {{变量路径}} 引用，例如：
- {{user.name}}：引用用户上下文中的姓名
- {{order.items[0].price}}：引用数组第一个元素的属性
- {{global.company_name}}：引用全局变量
- {{node_3.result.status}}：引用节点3输出结果中的status字段
### 6.4 数据流设计
- 节点输入：从变量/上游输出中映射。
- 节点输出：执行后写入指定变量，供下游引用。
- 数据持久化：关键变量持久化到数据库，支持断点续跑。
- 数据脱敏：日志和截图中自动脱敏敏感字段（手机号、身份证、银行卡）。

### 6.5 拓扑作用域与 L2 模板引用校验（v1）

> 工程推导条（2026-09-16 立项，08 Phase 2 延伸项）。§6.2 的六类作用域是规格愿景；v1 只落地 global 与节点输出两类，且节点输出可见性**按图拓扑推导**，替代前端早期的全局平铺清单。会话/环境/秘密变量与字段级可见性缓做 11 S1 / 14 D30。

**节点输出投影（权威，与 `graph/loader.py` 实际产出对齐）**：`{{<nodeId>.<路径>}}` 的静态可列路径如下——

| 节点类型 | v1 可列路径（`nodeId.` 之后） | 说明 |
| --- | --- | --- |
| trigger | `context.triggerType`、`context.cron`、`context.webhookUrl`、`context.payload`（根；payload 内部任意不校验） | 运行 inputs 无静态 schema |
| ai_decision | `decision`、`prompt_rendered` | |
| tool_call | `result` 及其下 output_schema `properties` 深层路径 | 工具声明了 output_schema 时按 schema 列字段（如 `result.status`）；FAILED 信封形状（code/message/error）不列入 |
| condition | `branch`、`target` | |
| loop | `index`、`iterations` | **仅循环体内节点可见**；体区域 = dsl.py `_loop_body_set`（自 bodyTarget 沿出边 BFS，遇 loop 自身/exitTarget 停） |
| parallel | `status`、`branches`、`joinStrategy`、`joinTarget` | `result.<分支入口节点id>.*` 为动态键，v1 不列（D30） |
| wait | `mode`、`waitType`、`durationSeconds` | |
| subgraph | `status`、`outputs`（仅根） | `outputs.<子图节点id>.*` 深层展开 v1 不做（D30） |
| human_approval | `decision`、`target`、`summary`、`approver`、`resolvedBy`、`comment`（M8 审批意见，缺省空串）；M8 命中卡片时另有 `card`（仅根 `{templateId,actionId}`，不深展开，同 parallel.result 动态键口径） | |

**全局变量**：`{{global.<name>}}`，name 须命中 Graph `variables` 中声明的全局变量；所有位置可见。

**visibleAt(nodeId)**：当前节点可引用的节点集合 = 沿 edges 入边反向 BFS 可达的全部上游节点（trigger 因此对所有直接/间接下游可见），叠加 loop 投影的体区域限制；节点自身不可见（loop 节点自身的 `index` 对体内节点可见是唯一例外）。反向 BFS 与 dsl.py 可达性校验共用同一拓扑口径。

**L2 引用校验（横切，与 JSON Schema 字段校验正交）**：对节点 config 中所有可含 `{{...}}` 的字符串（tool_call params、ai_decision promptTemplate、condition 表达式、human_approval summary、subgraph inputs 映射、wait/message 等模板字段），逐引用判定并一次性聚合；**M8 起 human_approval 配置 `cardTemplateId` 命中内置卡片时，该卡片 `sections.bindings[].value` 作为该审批节点的附加模板字段一并纳入 L2**（卡片是图的附属实体/第六类实体，可见集＝该审批节点 visibleAt，坏引用同样报 REF_NODE_NOT_FOUND/REF_PATH_NOT_FOUND 并进 Problems；action.output 的 `{{form.*}}` 引用表单字段、不走节点作用域 L2）：

| 错误码 | 判定 |
| --- | --- |
| `REF_NODE_NOT_FOUND` | 首段非 `global` 且图中不存在该 id 的节点 |
| `REF_NOT_IN_SCOPE` | 节点存在但不在引用方的 visibleAt（不可达上游、loop 输出越出体区域） |
| `REF_PATH_NOT_FOUND` | 节点在作用域内，但第二段起的路径不在上表投影或该工具 output_schema properties 中（payload 根下、空 schema `{}`、无 output_schema 的工具不报此码） |

## 八、适配方式设计
为了让用户用最自然的方式配置运营体，编辑后台应提供多种适配方式，并支持随时切换。

| 适配方式 | 适用用户 | 操作方式 | 生成结果 |
| --- | --- | --- | --- |
| 模板一键安装 | 新手 | 选择行业模板，填写参数 | 完整运营体 |
| 自然语言描述 | 业务人员 | 用中文描述需求 | DSL草稿+画布预览 |

# #  **通用化标准与关键机制**
要真正达到“完全通用化”，编辑后台必须落实以下标准和机制：
### 9.1 Schema 驱动
- 节点、工具、变量、知识、适配器全部使用 JSON Schema 定义。
- 前端根据 Schema 自动生成配置表单，后端根据 Schema 做校验。
- 新增组件类型时，只需上传 Schema，无需改代码。
### 9.2 版本化
- 每个运营体、适配器、节点类型、知识库都有版本号。
- 支持回滚、对比、灰度发布。
- 模板和适配器可独立升级，不影响已发布运营体。
### 9.3 可观测性
- 每一步操作、决策、变量变化都记录日志。
- 提供可视化回放，定位问题。
- 实时监控运行状态，异常自动告警。

> **v1 实现（2026-09-15，Phase 2）以 §5.13 权威契约为准**：进程内 ring（200 条）记录每次真实运行的图/状态/耗时/逐节点成败，聚合成功率与 p50/p95、节点失败 Top；四类内置规则（运行异常/节点失败/连续失败/窗口失败率，阈值可调）同步求值，站内告警中心支持确认/关闭与未关闭合并。逐条操作日志与可视化回放的正式形态、OTel/Prometheus/Grafana 栈缓做 14 D11/D28；§5.11 的录制回放覆盖「回放定位问题」的 v1 形态。
### 9.4 安全与权限
- 所有适配器连接使用加密存储。
- 高风险操作默认需要人工审批。
- 多租户隔离，数据权限控制。
- 敏感信息自动脱敏。

> **v1 实现（2026-09-16，Phase 2）以 §5.14 权威契约为准**：账号登录换进程内不透明 token（sess-），viewer/operator/admin 三角色端点级 RBAC，图/录制/反馈/监控/审批/调试/消息按租户全分区（跨租户对象 404、角色不足 403、未登录 401）。适配器凭证加密存储与敏感信息自动脱敏仍缓做（14 D22）；**平台账号口令已随 §5.17（2026-09-21）改为 scrypt 哈希存储、不再明文**（出向适配器目标系统凭证的加密仍缓做）；高风险人工审批已由 §5.8 落地。

### 9.5 可测试性
- 内置沙盒环境，可模拟运行。
- 支持录制回放测试。
- 发布前必须通过预置挑战集。
- 运行时定期抽检，质量下降自动熔断。

## 一、配置体验与编辑后台的“开发者体验”
### 1. 实时校验与错误提示
- 即时 Schema 校验：用户每填写一个字段，前端立即根据节点/工具的 JSON Schema 校验类型、必填、格式，错误就地提示。
- 依赖完整性检查：当变量引用上游节点输出时，系统自动检查上游节点是否存在该输出，不存在则高亮。
- 流程死锁检测：保存时检测是否存在不可达节点、循环依赖（loop 白名单回边除外，见 §5.3）、无条件分支缺失、并行分支交叉/无法汇聚（见 §5.4）。
- 一键修复建议：对于常见配置错误（如超时未设置、重试策略缺失），给出“一键应用推荐值”按钮。
### 2. 智能推荐与自动补全
- 节点推荐：根据当前流程上下文，AI 助手推荐接下来可能需要的节点（如“你已经获取了订单，是否要添加‘发送邮件’节点？”）。
- 工具推荐：当用户拖入“工具调用”节点时，根据节点名称或描述推荐匹配的 Harness 工具。
- 变量自动补全：在输入框中输入 {{ 时，弹出当前作用域下可选变量列表，支持模糊搜索。
### 3. 内联文档与引导
- 组件说明：每个节点/工具都有悬停提示和“查看详情”链接，展示用途、参数说明、示例。
- 新手引导：首次进入编辑器时，以分步任务引导用户完成“创建触发器 → 添加工具 → 设置回复”的完整流程。
- 视频/示例嵌入：在每个模板或适配器上提供 30 秒演示视频或交互式示例。
### 4. 画布性能优化
- 虚拟化渲染：当画布节点超过 500 个时，只渲染可视区域，滚动时动态加载。
- 聚合节点：将长串连续节点折叠为“聚合块”，点击展开。
- Web Worker 计算：将表达式解析、流程校验等 CPU 密集操作移到 Worker 线程，避免 UI 卡顿。

## 二、多租户与权限细节

> **v1 取舍（2026-09-16，Phase 2）以 §5.14 权威契约为准**：v1 只做到「端点级三角色 RBAC + 用户数据按租户全分区 + 无平台超管」（账号/口令哈希/会话 TTL/登录节流/账号生命周期已随 §5.17 于 2026-09-21 补齐生产认证）。本节愿景中的组件级权限（5）、跨租户共享与市场（6）、审计合规（7）均未实现：节点/工具/变量的细粒度权限随 14 D20/D22，组织内共享与跨租户市场随 14 D3/D25，配置/执行审计与数据地域随 Phase 3（§五16 配额同期）。

### 5. 组件级权限控制
- 节点权限：敏感节点（如“执行退款”）可设置仅特定角色可编辑、可执行。
- 工具权限：每个 Harness 工具可声明所需权限等级（只读/写/删除/资金操作），用户在配置时需具备对应权限。
- 变量权限：秘密变量（如 API Token）仅对创建者和管理员可见，其他用户无法查看或复制。
### 6. 跨租户组件共享
- 组织内共享：租户可将自己的适配器、子图、模板分享给组织内其他成员，设置“只读/可编辑”权限。
- 跨租户市场：通过审核后可发布到公共市场，其他租户付费或免费使用。
- 使用统计与计费：共享组件被其他租户使用时，平台记录调用量，用于收益分成。
### 7. 审计与合规
- 配置变更审计：记录谁在何时修改了哪个运营体的哪个节点、变量、工具，支持对比和回滚。
- 执行审计：所有运行时操作（工具调用、LLM 决策、人工审批）都有不可篡改的日志，可导出。
- 数据地域控制：租户可指定数据存储和处理的地域，满足 GDPR、等保等合规要求。

## 四、版本与发布管理细节
### 12. 运营体版本化
- 语义版本控制：自动生成版本号（主版本.次版本.修订号），支持对比任意两个版本的差异。
- 草稿与发布分离：编辑时保存为草稿，不影响线上运行；发布后生成不可变版本。
- 发布说明：要求填写本次修改内容，供团队审阅。
### 13. 灰度发布与 A/B 测试
- 流量分配：可将新版本分配给 5%、10% 等比例的触发事件，与旧版本并行运行。
- 指标对比：实时对比新旧版本的关键指标（成功率、响应时间、用户满意度）。
- 自动回滚：若新版本指标显著恶化，系统自动回滚到旧版本并通知。
### 14. 模板与组件的独立版本
- 适配器版本：适配器升级后，已发布运营体继续使用旧版本，直到用户手动切换。
- 子图版本：子图更新不影响引用它的已发布运营体，用户可在编辑器中手动升级并回归测试。**docs/28 批 4⑪（2026-09-20 落码）已补发布前只读升级体检**：打开发布 Modal 时与门禁并行拉 `GET /api/graphs/{id}/subgraph-upgrades`，对父图草稿顶层 subgraph 节点比对「本次发布将钉版本 to（子图最新发布版，无则 1）vs 父图最新发布快照所钉 from」，首次钉版显蓝 Tag、from≠to 显橙 Tag、无变化显空态；纯只读、不产版本、不阻断发布、不检测子图未发布草稿 dirty，升级后仍建议先跑发布门禁回归再发布。草稿 pin 编辑器/一键升级/子图市场仍缓做 D21。

## 五、运行时与性能细节
### 15. 冷启动与预热
- 浏览器实例预热：对于 Web 操作适配器，提前启动无头浏览器并缓存登录状态，减少任务执行延迟。
- 模型推理预热：模型服务保持常驻，避免请求时的冷启动。
### 16. 资源配额与限流
- 租户级配额：限制每个租户的并发运营体实例数、工具调用频率、存储空间。
- 节点级超时：每个节点可单独设置超时时间，避免单点阻塞整个流程。
- 降级策略：当资源不足时，自动将低优先级任务降级为排队或延迟执行。
### 17. 事件驱动与异步处理
- 消息队列：Harness 操作通过消息队列异步发送，前端通过 WebSocket 实时接收执行状态。
- 长任务处理：对于超过 1 分钟的任务，以异步任务形式执行，用户可离开页面稍后查看结果。

## 六、安全与合规补充
### 18. 提示注入防御
- 上下文隔离：系统指令与用户输入严格分离，使用特殊标记。
- 输入过滤：对来自外部的数据（用户消息、邮件内容）进行注入检测，发现可疑模式则警告或拦截。
- 工具输出过滤：LLM 生成的工具参数在执行前经过规则引擎校验，禁止执行危险操作。
### 19. 数据脱敏与加密
- 日志脱敏：自动识别并模糊手机号、身份证、银行卡、密码等 PII。
- 存储加密：敏感数据（密钥、用户数据）在数据库和传输中全程加密。
- 数据保留策略：可配置日志和记忆的自动清理周期，支持用户数据删除请求。
### 20. 高风险操作保护
- 二次确认：资金支付、数据删除、权限变更等操作必须人工确认。
- 金额阈值：可设置金额阈值，超过则需高级审批。
- 操作白名单：可定义允许执行的工具和动作列表，其他一概拒绝。

## 七、AI 辅助配置与自动化细节
### 21. 自然语言生成流程的准确性提升
- 意图拆解：将用户的一句话需求拆解为多个子任务，逐个生成节点。
- 确认式生成：生成草稿后，用自然语言总结流程，让用户确认无误再进入画布编辑。
- 交互修正：用户可继续用对话修正流程（如“去掉发送邮件的步骤”）。
### 22. 自动修复配置错误
- 错误诊断：当保存失败或测试失败时，AI 助手分析原因并给出修复建议。
- 一键修复：对于简单错误，用户点击“应用修复”自动修改配置。
- 学习用户偏好：记录用户的常见修改，逐渐优化推荐。

## 八、生态与市场细节
### 23. 组件市场
- 适配器市场：用户可发布自定义适配器，设置免费/付费/订阅，平台抽成。
- 模板市场：发布完整运营体模板，其他用户可一键安装并修改。
- 子图市场：发布可复用的子流程（如“电商退款处理”），供他人集成。
- 评分与评价：组件有评分、下载量、评论，优质组件获得推荐位。
### 24. 开发者 SDK 与文档
- SDK 支持多语言：Python/JS/Go 的 SDK，用于开发自定义适配器、节点类型。
- 本地调试工具：SDK 内置模拟环境，开发者可本地测试组件。
- 文档与教程：详细的 API 文档、示例代码、最佳实践。

## 九、协作与团队功能细节
### 25. 多人协作编辑
- 实时协同：多个用户可同时编辑同一运营体，采用 OT/CRDT 算法解决冲突。
- 评论与提及：在节点或连线上添加评论，@同事解决问题。
- 角色分配：可为运营体设置负责人、审核人、编辑权限。
### 26. 变更通知
- 订阅通知：用户可订阅运营体的变更、发布、异常事件，通过邮件/IM 接收。
- 日报/周报：系统自动生成运营体运行摘要，发送给团队成员。

## 十、移动端与多端支持
### 27. 移动端管理
- 监控与告警：在 App/小程序上查看运营体状态、接收告警、一键审批。
- 轻量编辑：支持在移动端修改简单参数（如阈值、开关），复杂流程仍在 PC 端编辑。
### 28. 多语言支持
- 界面多语言：编辑后台支持中/英切换，可扩展。
- 自然语言多语言：用户可用多种语言描述需求，系统自动翻译为统一内部表示。
- 组件描述多语言：适配器和模板的说明支持多语言。
