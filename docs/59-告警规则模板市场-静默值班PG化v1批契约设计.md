## 0. 已核实的现状缺口（2026-09-24 对活代码）

- **规则模板市场（D28 余部，零进展）**：自定义规则 DSL 已落（docs/28 批 3，`RuleConfig.custom`、`custom:{cid}`、白名单上下文 `{status,durationMs,failedCount,hasError}`，前端 List 编辑器），但用户需手写表达式、无内置预设、无一键启用。流程模板有成熟先例 `template/catalog.py`（只读 Python 常量 + `GET /api/templates`/`GET /api/templates/{id}`，无 DB/CRUD、不受 reset 影响）与卡片目录 `cards/`（`GET /api/cards`）。
- **静默 / 值班状态仍进程内（docs/33 §5 自述缺口）**：`monitoring/silences.py` 的 `OpsStore`（单锁，`_silences` list cap 100、`_schedule` OnCallSchedule、`_assignees` alert_id→人 map）被**内存档 `MonitoringStore` 与 PG 档 `PgMonitoringStore` 共用**。
  - PG 档告警本体在库（`monitoring_alerts`，迁移 021 已补 `rule_name/escalated_at/assignee` 三列、002 同步），但：
    - **静默不落库**：`POST/GET/DELETE /api/monitoring/silences` 在 PG 档仍委托进程内 `OpsStore`，重启清空、多实例不共享；`suppressed_count` 只活在内存对象。
    - **值班不落库**：`GET/PUT /api/monitoring/on-call`、`POST .../rotate` 同样委托 `OpsStore._schedule`，重启回到空表/ index 0。
    - **assignee 取自进程内值班**：`PgMonitoringStore._raise_or_merge_locked` 新建告警时 `assignee = self._ops.current_assignee()`（值班在内存，重启恒为 None），再 `remember_assignee` 写进程内 map；虽然 `monitoring_alerts.assignee` 列存在，但其值来源（值班表）不持久，merge/decorate 还用 `self._ops.assignee_of(...)` 兜底。
  - **惰性升级 `escalated_at` 已 PG 化**（docs/55，`_decorate_alerts_locked` 读时评估并 `UPDATE severity/escalated_at`），**本批不重做**，仅随值班 PG 化确认 assignee 来源持久。

## 2. F-1 规则模板市场契约

### 2.1 内置目录（`monitoring/rule_templates.py`）

```python
class RuleTemplateMeta(BaseModel):
    id: str
    name: str
    description: str
    tags: list[str] = Field(default_factory=list)
    config: dict[str, Any]   # 完整 RuleConfig 形状，必须通过 validate_rules

RULE_TEMPLATES: tuple[RuleTemplateMeta, ...]
def list_rule_templates() -> tuple[RuleTemplateMeta, ...]
def get_rule_template(template_id: str) -> RuleTemplateMeta | None
```

内置 4 个（config 均为完整 RuleConfig，四段 `run_error/node_failed/consecutive_failures/failure_rate` 齐备，落测试断言 `validate_rules(config) == []`）：

| id | name | 要点 |
|---|---|---|
| `default-balanced` | 默认均衡 | 四内置全开；consecutive threshold=3；failure_rate window=20/min_samples=5/rate=0.5；无 custom；不升级；recovery streak=1、无冷却（＝当前 `RuleConfig()` 默认，供一键复位） |
| `strict-sre` | 严格 SRE | consecutive threshold=2；failure_rate window=10/min_samples=3/rate=0.3；`escalation_ack_minutes=15`；`recovery_healthy_streak=2`；`recovery_cooldown_minutes=30` |
| `demo-lenient` | 演示宽松 | consecutive threshold=5；failure_rate window=20/min_samples=10/rate=0.8；不升级；recovery streak=1 |
| `custom-quickstart` | 自定义规则上手 | 四段默认 + 两条 custom（固定 cid，表达式经 `validate_expression` 合法）：`tpl-node-failed`「任一节点失败即 critical」`{{failedCount}} > 0`；`tpl-slow-run`「运行超 5 秒 warning」`{{durationMs}} > 5000` |

模板为静态只读常量，cid 固定无碍：一键应用是 **PUT 整包替换**而非追加，重复应用得到同一 config，不产生重复 custom 段。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/alert-rule-templates` | read | `{items:[{id,name,description,tags}]}`，投影不含 config |
| GET | `/api/alert-rule-templates/{id}` | read | 完整 `RuleTemplateMeta.model_dump()`（含 config）；未知 404 `{"detail":"规则模板不存在：{id}"}` |

## 3. F-2 静默 / 值班 PG 化契约

### 3.1 迁移 024（`024_monitoring_silences_oncall.sql`，手写幂等；002 同步）

```sql
CREATE TABLE IF NOT EXISTS monitoring_silences (
    id TEXT PRIMARY KEY,
    tenant_id TEXT NOT NULL,
    rule_id TEXT,
    graph_id TEXT,
    reason TEXT NOT NULL,
    created_by TEXT NOT NULL,
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,
    suppressed_count INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_monitoring_silences_tenant ON monitoring_silences (tenant_id);

CREATE TABLE IF NOT EXISTS monitoring_oncall (
    tenant_id TEXT PRIMARY KEY,
    members JSONB NOT NULL,           -- ["alice","bob"]
    rot_index INTEGER NOT NULL DEFAULT 0,
    updated_at TEXT,
    updated_by TEXT
);
```

（`index` 避用裸列名，取 `rot_index`。）002_storage.sql 新装库追加同样两表；ALTER/CREATE 均 IF NOT EXISTS 可重复执行。

### 3.2 PgMonitoringStore 方法演进（内存档不动）

- **静默**
  - `create_silence(...)`：开事务，先惰性 `DELETE ... WHERE tenant AND expires_at <= :now`；`_next_id(conn,"sil")`；Python 算 `expires_at`（created_at + duration_minutes，UTC ISO）；INSERT；cap 100：活跃行仍 >100 时删最旧（`ORDER BY created_at`  LIMIT 超额）。返回 `Silence`。
  - `list_silences(active=None)`：SELECT 全租户行（`ORDER BY created_at`）→ `Silence`；`active` 过滤复用纯函数 `is_silence_active`。
  - `delete_silence(id)`：`DELETE ... WHERE tenant AND id` RETURNING，命中 True 否则 False（API 404）。
  - record_run 内命中压下：新增 `_suppress_if_matched_locked(conn, rule_id, graph_id, now)`——SELECT 本租户**未过期**静默行，Python 端用单一事实源 `silence_matches(s, rule_id, graph_id, now)` 判定，命中首条即 `UPDATE ... SET suppressed_count = suppressed_count + 1 WHERE id` 并返回 True（不建/不合/不升级，对齐内存档）。
- **值班**
  - `get_oncall()`：SELECT 单行 → `OnCallSchedule(members=row.members,index=row.rot_index,updated_at,updated_by)`；无行返 `OnCallSchedule()`。
  - `set_oncall(members,updated_by)`：去重保序/丢空白（复用内存档同一规整逻辑），UPSERT（`rot_index=0`）。
  - `rotate_oncall(updated_by)`：SELECT 行，members 空则 raise `OnCallEmpty`（API 409）；否则 `rot_index=(rot_index+1)%len` UPSERT，返回新投影（current 由纯函数 `current_assignee` 算）。
  - 新建告警 assignee：新增 `_current_assignee_locked(conn)`——读 oncall 行后用纯函数 `current_assignee`；`_raise_or_merge_locked` INSERT 的 `assignee` 改用它（列 021 已存在）。
  - 删除 merge/decorate/rollout_gate 中对 `self._ops.assignee_of / remember_assignee` 的调用：PG 档 assignee 以列为唯一权威（`_alert_from_row` 本就读列）；rollout_gate 不指派 assignee（INSERT 不含该列，保持 NULL）。
- **reset**：事务内追加 `DELETE FROM monitoring_silences` / `DELETE FROM monitoring_oncall`（均按 tenant）。
- PG 档不再实例化/引用 `OpsStore`（`self._ops` 移除）；仍 import `Silence, OnCallSchedule, OnCallEmpty, silence_matches, is_silence_active, current_assignee`。
- 内存档 `MonitoringStore` 与 `OpsStore` 完全不改，既有进程内测试零改动。

### 3.3 持久化语义（相对 v1 的可观察变化）

- PG 档静默 / 值班 / 告警 assignee **跨重启与跨 store 实例保留**（集成测试用「新建第二个 PgMonitoringStore 实例」模拟重启/多实例）。
- 静默命中计数 `suppressed_count` 落库，GET 读回累计值。
- 时间均为 tz-aware UTC ISO 字符串，过期判定纯函数不变。
