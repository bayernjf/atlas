## 1. 背景与现状（落码前实证）

D28 监控告警产品化已多批取回（适配器埋点、自定义规则 DSL、Trace 钻取、静默/升级/值班、外部出口、PG lifecycle、规则模板市场、规则配置 UI 表单化）。仍缓做的一块是**面向运营的长保留运行报表与版本对比**。现状（读码确认）：

- **运行记录存储**：内存档 `MonitoringStore` 为 ring `RUN_RING_SIZE=200`（超出丢弃最旧）；PG 档 `PgMonitoringStore` 全量持久化（`monitoring_runs`，无 ring、**无时间范围筛选、无聚合、无保留清理**）。
- **现有端点**：`GET /api/monitoring/runs`（仅 `graph_id` + `limit 1–200`，列表新→旧，剔除 spans）、`GET /api/monitoring/runs/{id}/trace`。**无报表/聚合/导出端点。**
- **RunRecord 关键字段**：`graph_id`、`status(completed|error|cancelled)`、`started_at`（**UTC ISO，`datetime.now(timezone.utc).isoformat()`**）、`duration_ms`、`resolved_version`（入站 event 经 Router 钉住的发布版本；**手动运行/草稿为 None**）。
- **可复用**：发布报告导出 `reports.report_to_csv`（stdlib csv）＋UTF-8 BOM 的 `Response` 模式（`export_graph_release_report`）。

## 2. 本批范围（切片收敛）

**取回「报表聚合（按天/按版本）＋导出」最小一片，不做真·时序图表与保留清理。**

### 2.1 做

1. **聚合纯函数**（新模块 `monitoring/reports.py`，零新依赖）：
   - `aggregate_runs(runs, group_by)` → 分组桶列表，每桶：
     `key`（天＝`YYYY-MM-DD`（UTC）；版本＝`v<int>` 或 `manual-draft`）、
     `total/completed/error/cancelled`、`success_rate`（completed/total，空桶 0）、
     `duration_avg_ms/duration_p50_ms/duration_p95_ms`（total=0 时为 0）。
   - 分位数用确定性 nearest-rank（与既有 metrics p50/p95 口径一致），不引 numpy。
2. **store 报表查询**：两档各加 `list_runs_for_report(graph_id, since_iso, until_iso)`：
   - 内存档过滤现有 ring（数据有限，报表只覆盖 ring 窗口，照实不假装长保留）；
   - PG 档 `WHERE tenant_id AND started_at >= since AND started_at < until [AND graph_id]`（参数绑定、按 started_at 升序）。
3. **端点**：
   - `GET /api/monitoring/report`：参数 `graph_id?`、`days`（默认 7，整数 1–90）、`group_by`（`day` 默认 | `version`）；`read` 权限、按租户。窗口＝`[now - days, now]`（UTC，边界 `since <= started_at < until`）。
   - `GET /api/monitoring/report/export`：同参数 ＋ `format=csv|json`（默认 csv）；`read`。
4. **前端**：监控页新增「运行报表」区——时间范围（days 选择）、分组切换（按天/按版本）、聚合表格（计数/成功率/耗时分位）、导出按钮（CSV/JSON）；i18n zh/en。

### 2.2 版本口径（契约分叉，本批定）

- 版本对比**以 `resolved_version` 为准**：入站 event（真实线上流量）带版本号；`None`（手动运行/草稿）归入单独桶 `manual-draft`。
- **不新增 `graph_version` 字段、不回填历史**（手动运行本就不对应发布版本，回填＝造假）。
- 限制照写：按版本对比主要反映**经 Router 的线上流量**；手动/草稿混在一个桶，不细分。

### 2.3 不做（继续缓做）

- 真·时间序列图表（折线图）、仪表盘钻取（本批只到表格；图表随前端图表库决策另立）。
- 监控运行记录的保留期/自动清理（PG 无限增长问题）——属运维策略，随部署/retention 批。
- 跨实例汇总、多租户平台级报表、报表定时邮件订阅。
- 自定义分组/多指标选择、对比基线（两版本 diff 高亮）。

## 3. 错误码

- 复用参数校验：`days` 越界/非整数、`group_by` 非枚举、`format` 非枚举 → 422 `INVALID_PARAMETER`（端点内手工中文，沿用同族）。
- 不新增错误码、不新增迁移、不新增依赖、无 ADR。

## 4. 验收用例（U1306–U1316）

- **U1306**（aggregate 按天）：固定 runs 落正确天桶、计数与成功率。
- **U1307**（耗时统计）：avg/p50/p95 nearest-rank 值正确、空桶为 0。
- **U1308**（aggregate 按版本）：`resolved_version` 分桶、None 归 `manual-draft`。
- **U1309**（时间窗口）：`since <= started_at < until` 边界（恰好 since 入选、恰好 until 不入选）。

- **U1312**（两档一致）：同批数据内存/PG 聚合结果一致（PG 走集成通道）。
- **U1313**（CSV 导出）：表头/行数/数值、UTF-8 BOM；JSON 结构。
- **U1314**（导出 format）：非法 format → 422；Content-Disposition 文件名。
- **U1315**（前端）：报表渲染、days/分组切换重取、导出按钮；i18n。
