# 消息模板系统 v1（审批/告警通知模板化）批契约设计

> 状态：📝 立项（docs-only，落码另立批）｜号段 U1189–U1195｜形状权威：本文｜承接 docs/14 D24 剩余「消息模板系统」｜2026-10-07

## 1. 背景与边界裁定

**B4 勘察结论（2026-09-23）**：`graph/interpolation.interpolate` 已对 tool_call params / human_approval / 告警统一做插值，**插值接缝全覆盖、无独立模板层**。因此 D24 剩余「消息模板系统」的最小切片不是再建一套插值，而是**可复用/可编辑的模板实体**＋**两处硬编码通知正文改走模板**。

**现状实测**：
- 审批通知正文：`src/atlas/collaboration/notifications.py` `EmailApprovalNotifier`——subject 硬编码 `[Atlas] 审批待处理：{title}`、body 中文逐行拼接（`审批节点：…`/`审批说明：…`/`指定审批人：…`），T2 落码后未再动。
- 告警通知正文：`src/atlas/monitoring/notify.py`——`build_alert_subject`/`build_lifecycle_subject`＋进程内 `message/send`。
- 插值接缝：`graph/interpolation.py:19 interpolate(template, context)`。

**范围收敛（与 docs/14 D24 原文对照）**：原文「消息模板系统（变量/多语言/审批通知模板）」——**「多语言」不取**（模板由租户自定义内容，无内置 i18n/翻译，D13 触发条件不变）；**「变量」取**（模板声明变量＋消费时校验上下文完整性）；**「审批通知模板」取**（审批通知正文模板化）；**追加同类「告警通知模板」**（与审批通知同一模板实体机制，D24 与 D28 的 AlertChannel 同族，取回不越界——告警通知发送点已在 `notify.py`，加模板层零新增渠道）。

**非目标（保持缓做）**：短信/IM 应用 OAuth/入站消费/DLQ 定时扫描（D24 其余）、模板市场/共享（D3/D25）、多语言翻译（D13）、模板版本历史/回滚（D25 同族）。

## 2. 模板实体与存储

### 2.1 形状

`MessageTemplate`（第六类实体，独立于 user_template）字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | `mtpl-{n}`（进程内 seq；PG 同 id 生成，全局唯一） |
| `name` | str | 租户内唯一（casefold 比较），≤64 |
| `kind` | str | `"approval"` \| `"alert"`（枚举，缺省 `"approval"`） |
| `subject` | str | ≤200，可含 `{{var}}` 占位 |
| `body` | str | ≤4000，可含 `{{var}}` 占位 |
| `variables` | list[str] | 声明的模板变量名（≤20，去重，名字须匹配 `[A-Za-z_][A-Za-z0-9_]*`） |
| `created_at` | str | UTC ISO |
| `updated_at` | str | UTC ISO |

**未配置模板时**：消费点回退现有默认正文（notifications.py / notify.py 现状逐字保留），模板系统是**纯超集**。

### 2.2 存储

- 进程内：`src/atlas/message/template_store.py` `InMemoryMessageTemplateStore`（租户分区 dict、name 唯一、CRUD、`clear()` 重置 seq）。
- PG：`PgMessageTemplateStore`，**迁移 044** `message_templates`（tenant_id/seq/id/name/kind/subject/body/variables JSONB/created_at/updated_at，唯一键 `(tenant_id, name)`，照 034 样板）。
- 装配：`TenantServices` 增 `message_template_store`（registry 惰性，PG 档注入 Pg 实现）。

### 2.3 REST 端点（main.py，鉴权沿用模板库惯例）

| 端点 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `/api/message-templates` | GET | read | 列表（租户内，投影 id/name/kind/subject/variables/updated_at，**不含 body**；`?kind=` 过滤） |
| `/api/message-templates/{id}` | GET | read | 详情（含 body） |
| `/api/message-templates` | POST | operate | 创建（name 唯一 409 `MESSAGE_TEMPLATE_NAME_CONFLICT`；坏形状聚合中文 422） |
| `/api/message-templates/{id}` | PUT | operate | 全量更新（404 未知；name 撞他人 409） |
| `/api/message-templates/{id}` | DELETE | operate | 删除（404 未知；**引用侧不阻断**——消费点下次发送回退默认正文） |

**创建/更新校验（422，模板不变）**：
1. `kind` ∈ {approval, alert}；
2. `name` 非空 ≤64、租户内唯一（409 走上方码）；
3. `subject`/`body` 非空（subject 可空？——**subject 必填**、body 必填）；
4. `variables`：名字白名单正则、≤20、去重；
5. **正文占位一致性**：subject/body 中出现的 `{{var}}` 必须 ⊆ `variables` 声明（出现未声明变量 → 422 `MESSAGE_TEMPLATE_UNDECLARED_VAR`，detail 带变量名）；声明的变量允许不在正文出现（超集）。

### 2.4 消费接线（复用 `interpolate` 同一接缝）

- **审批通知**（`notifications.py`）：`EmailApprovalNotifier` 发信前查 `message_template_store` 取 `kind="approval"` 模板（租户内**首条**为准，无则回退默认正文）。上下文变量：`title`、`graph_id`、`node_id`、`summary`、`approver`、`decision_url`（与默认正文行一一对应）。**缺失变量**：`interpolate` 现有行为（未命中键 → 空串或原样，按 `interpolation.py` 现状），模板校验只保「声明一致性」，不保「上下文完整性」——运行期缺值按插值现状处理（不回退、不抛）。
- **告警通知**（`notify.py`）：`notify_lifecycle`/`notify` 发信前查 `kind="alert"` 模板。上下文变量：`title`、`severity`、`graph_id`、`run_id`、`message`、`transition`、`silence_url`（与 `build_alert_subject`/`build_lifecycle_subject` 现值对应）。
- **正文渲染**：subject/body 各经 `interpolate(text, context)`；未配置模板走既有 `build_*` 函数（逐字保留）。

### 2.5 前端

- 新增「消息模板」管理（路由 `/settings/templates` 或并入现有设置页 Tab，按前端现状取最小改动）：列表（name/kind/subject/updated_at）、新建/编辑表单（kind 选择、subject/body 文本域、variables 标签输入）、删除（确认框，注明"删除后通知回退默认正文"）。
- i18n zh/en：`settings.templates.*` 键（列表/表单/确认文案），过 PARITY。

## 3. 验收（U1189–U1195）

- **U1189（后端）**：CRUD——创建返回 id/投影正确；name 重复 409；坏形状（kind 非法/subject 空/variables 白名单外/未声明占位）422 且模板不变；GET 列表不含 body、详情含 body；DELETE 后 404。
- **U1190（后端）**：`?kind=` 过滤只回该 kind；跨租户隔离（他租户创建/读/删均 404 或 409 同文案）。
- **U1191（后端）**：消费接线·审批——配 `kind="approval"` 模板后 `EmailApprovalNotifier` 发信 subject/body 用模板渲染（插值上下文含 `{{title}}`/`{{summary}}` 等）；**未配置模板时正文与基线逐字相同**（反向对照）。
- **U1192（后端）**：消费接线·告警——配 `kind="alert"` 模板后 notify 正文用模板渲染；未配置回退 `build_*`（逐字对照）。
- **U1193（后端）**：PG 档——迁移 044 apply、Pg store CRUD 与内存档同语义（集成标记，真 PG 验证 name 唯一约束跨重启）。
- **U1194（前端 vitest）**：apiClient 五端点（list/get/create/update/delete）URL/方法/body；类型新字段。
- **U1195（前端 vitest）**：模板表单校验逻辑（variables 白名单、占位一致性提示、kind 切换）——纯函数提取到 `lib/messageTemplate.ts`。
