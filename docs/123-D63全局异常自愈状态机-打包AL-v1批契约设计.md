## 2. 范围决策（三块设计 + 用户拍板项）

### 2.1 全局异常处理器（块 1）

**设计**：`ai_flow`（运营体/图）级新增可选配置 `globalErrorHandler`：

```jsonc
// ai_flow DSL 顶层可选字段（纯超集，缺省整体不启用＝现状 fail-fast）
"globalErrorHandler": {
  "onUncaughtError": "mark_only" | "route_to_subgraph" | "escalate_to_human",  // 见拍板项
  "errorSubgraphId": "subgraph-xxx",   // route_to_subgraph 时必填
  "escalation": { "channel": "email" | "approval", "recipients": ["..."] }  // escalate_to_human 时可选
}
```

- **捕获面**：run 执行链中所有**未**被节点级 `on_error` 捕获的异常（含 `RunNodeFailed` 穿透、工具链路未捕获异常、子图 fail-safe 折叠后的 failed）；控制流异常（`RunCancelled`/`DebugStopped`/`RunSuperseded`）依旧穿透不触发。
- **执行时序**：run 终态判定前统一走 handler（`run_graph` 收口处，与 `run_store.finish` 同级），三选一动作（见拍板项 P-1）。
- **fail-closed 语义**：handler 自身异常→按 `mark_only` 兜底（仅标记），绝不让"降级动作再失败"把 run 变第二次错误。

### 2.2 自愈机制（诊断子图，块 2）

**设计**：复用 `on_error:"jump_to"` 的现有路由骨架（docs/121 D-6），在**图级**扩展为「失败→自动进诊断子图→诊断产出→决策继续/终止」：

- 新增 DSL 顶层可选 `selfHealing`：`{ "triggerOn": ["node_failed", "subgraph_failed"], "diagnoseSubgraphId": "subgraph-xxx", "maxAttempts": 1–3（缺省 1）, "continueWhen": "<condition 表达式>" }`；
- **触发语义**：节点/子图失败（且该节点自身无 on_error 或 on_error 已耗尽）→ 挂起当前分支、执行诊断子图（诊断子图可用 memory/recall、httpapi、condition 等任意现有节点自组装"检查→修复动作→验证"逻辑）→ 诊断子图产出 `outputs[id]["verdict"]`；
  - `continueWhen` 为真 → 分支继续（诊断产出并入 outputs，原失败节点产出标记 `healed_by: <subgraph id>`）；
  - 为假/异常 → 走全局异常处理器（块 1）或节点级 on_error（存在时）；
  - `maxAttempts` 耗尽仍失败 → 不再自愈，按块 1 降级。
- **回放/影子确定性**：诊断子图是显式图结构，走既有 subgraph 执行路径（含 SSE、span、工具埋点），非隐式钩子。
- **与 D56 区别（明写）**：D56＝崩溃后从持久化检查点续跑（恢复已发起的 run）；本条＝运行中失败时主动进修复分支（不重建 run）。两者共用"人工收敛出口"概念，但通道不同（本条 continueWhen 为假时走块 1 的 escalate_to_human，不走 interruption resume token）。

### 2.3 状态机子图（块 3）

**设计**：业务对象生命周期管理，作为 Graph 的**特殊子图类型**（新节点类型 `state_machine`，或复用 subgraph＋DSL 级状态声明，落码批择优）：

```jsonc
// 新节点类型 state_machine 配置
{
  "type": "state_machine",
  "config": {
    "objectRef": "{{globals.order_id}}",           // 业务对象标识
    "states": ["pending", "paid", "shipped", "refunded"],
    "initial": "pending",
    "transitions": [                                  // 事件驱动
      { "event": "pay_succeeded", "from": "pending", "to": "paid", "on": "<condition 表达式>", "action": "httpapi:create_refund" },
      { "event": "shipped", "from": "paid", "to": "shipped" },
      { "event": "refund_requested", "from": "*", "to": "refunded" }
    ],
    "store": "run_globals" | "memory" | "pg_table"    // 见拍板项 P-2
  }
}
```

- **语义**：节点执行＝对 `objectRef` 指向的业务对象做一次状态迁移（非法迁移→状态机校验失败，走节点级 on_error）；迁移可触发动作（复用工具适配器）；状态可见于 `globals`（如 `globals.order_status`），供后续 condition/变量引用。
- **编译期校验**：states 非空/初始态合法/transition from-to 引用存在/事件名唯一/`*` 通配仅 to 端；非法→422 新码（见 §4）。

### 2.4 用户拍板项（P-1/P-2，落码前必须拍）

> **P-1（块 1）全局降级策略形态**（docs/14 D63 触发条件原文"统一降级是什么动作"三选一）：
> - **A. `mark_only` 仅标记**：run failed 照旧，但产出/监控/审计带上 `global_error: {code, nodeId}` 结构化标记——零副作用、最小实现，与现状唯一差异是"可观测性补全"；
> - **B. `route_to_subgraph` 进指定子图**：失败后执行指定子图（如"通知值班人→重置状态"），子图完成后 run 终态按子图 verdict 定（继续/终止）——能力最全，工作量最大；
> - **C. `escalate_to_human` 转人工**：失败即创建人工审批/通知（复用 `collaboration/` 通知与审批通道），run 挂起等人工决策后恢复/终止——接现有审批闭环，语义最贴近"运营体"。

> **P-2（块 3）状态机子图「对象状态存哪」**：
> - **A. run_globals**：状态存当前 run 的 `globals`（`globals.order_status`）——进程内、随 run 生命周期，最简单，跨 run 不持续；
> - **B. memory 档**：状态作为 `kind=fact` 记忆条目（scope 绑对象 id）写入 `MemoryStore`/PG——跨 run 持续、天然多实例（PG 档），复用 M11 已落存储；
> - **C. 专用 PG 表**：新建 `business_objects` 表（对象 id、当前状态、版本、updated_at）——最正规，需迁移、需审计/历史设计（历史与审计随 D20 仍缓做）。

**建议**：P-1 推荐 **C（escalate_to_human）**（最贴"运营体"产品语义、复用已落审批/通知闭环、工作量中等）；P-2 推荐 **B（memory 档）**（零新迁移、跨 run 持续、两档齐备）。你拍 A/B/C 后我按选型出落码批。

> **✅ 用户拍板（2026-10-10，用户「按你推荐的继续搞」）**：
> - **P-1 = C：`escalate_to_human` 转人工**——全局降级动作＝创建人工审批/通知（复用 `collaboration/` 通知与审批通道），run 挂起等人工决策后恢复/终止；
> - **P-2 = B：memory 档**——状态机对象状态作为 `kind=fact` 记忆条目（scope 绑对象 id）写入 MemoryStore/PG，跨 run 持续、零新迁移。
>
> 落码据此：块 1 默认形态 escalate_to_human（onUncaughtError 枚举仍保留 mark_only/route_to_subgraph 三值，前端可切）；块 3 store 默认 memory（枚举保留 run_globals/pg_table 作未来扩展，前端可切）。

## 4. 错误码与通道

- 新增错误码（编译期校验，validation.json zh/en 同步）：
  - `GLOBAL_ERROR_HANDLER_INVALID`（onUncaughtError 非法/route_to_subgraph 缺 errorSubgraphId/escalation 缺 channel 或 recipients 非法）；
  - `SELF_HEALING_INVALID`（triggerOn 枚举非法/diagnoseSubgraphId 不存在或指向自身/maxAttempts 越界/continueWhen 非法表达式）；
  - `STATE_MACHINE_INVALID`（states 空/初始态非法/transition 引用不存在/事件名重复/`*` 配 from）；
  - `STATE_TRANSITION_REJECTED`（运行期非法迁移，携带 objectRef/from/to）。
- 通道：无新 REST 端点（配置随 graph DSL 保存；运行期经 SSE 帧 + run_store 产出）；`escalate_to_human` 复用既有审批/通知端点。
