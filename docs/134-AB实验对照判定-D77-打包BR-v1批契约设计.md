## 1. 基线实核（2026-10-15，只读）

### 1.1 分桶与灰度机器已成熟，实验分流可零新代码复用（D77 硬要求的兑现面）

- `src/atlas/routing/router.py`：`bucket_key`（payload.order_id 缺省 payload.id，int 转 str，缺键 None）＋`hash_hit`（`sha256(f"{graph_id}:{key}")%100 < percent`，同对象恒定不横跳）＋`resolve_version` 固定求值序（internal→lowValueBucket→canary→full，fail-safe 落 stable）。纯函数、无 IO。

- **关键观察**：canary percent 就是天然的双版本流量比例阀——50/50 的 A/B 实验＝`CanaryRule(percent=50)` 的 canary。实验与灰度共享同一 hash、同一桶键、同一 fail-safe，D77「灰度面复用同一分桶实现（不许另起一套分桶）」由此直接兑现。

- REST 面先例：`/api/graphs/{id}/rollout` GET/PUT＋`/start|/promote|/rollback`（`main.py:4058-4125`），RolloutError→409、ValidationError→422 中文、跨租户 404 的档位纪律已定型。

## 2. 形状与范围

### 2.1 实验实体与生命周期

- **`Experiment`**（`routing/experiment.py`，camelCase 出入 REST）：`{id（exp-N）, graphId, versionA, versionB, trafficPercent（1–99，缺省 50）, primaryMetric（GateMetricId 三选一）, minSamples（缺省 30，≥1）, status: running|concluded, priorConfig（RolloutConfig 快照，可空）, verdict（concluded 时冻结，可空）, conclusionAction: adopt_a|adopt_b（可空）, conclusionReason, createdBy, createdAt, concludedAt}`。
- 生命周期三段：**POST 创建即 running**（写实验配置＋启动分流一步完成，不要 draft 中间态）→ **GET detail 活判定**（每次读实时重算，建议性）→ **POST conclude**（冻结 verdict＋按 action 走既有 promote/rollback 收尾＋恢复 priorConfig）。重复 conclude 409。

### 2.2 分流＝复用 RoutingStore canary（BR-D1，零新分桶代码）

- 实验启动＝`routing_store.configure(graph_id, RolloutConfig(rules=[CanaryRule(percent=trafficPercent)], gate=<保留原配置 gate；无原配置则 GateConfig(autoRollback=False)>))` ＋ `routing_store.start(graph_id, versions, stable=versionA, candidate=versionB)`。
- 实验期分流**统一纯百分比**：原配置的 internal/lowValueBucket 段不混入实验配置（避免口径复杂化）；conclude 恢复原配置即恢复业务桶。
- `RoutingStore.start` 扩展：`start(graph_id, versions, *, stable=None, candidate=None)`——两参均 None 走原逻辑（`versions[-2:]`）；显式传入则校验**两版都在 versions 内且不相等**（否则 RolloutError→409）。不传参行为逐字不变（回归用例守）。
- 互斥天然成立：实验启动要求 rollout **idle**（非 idle 409）；同图已有 running 实验 409；实验期 rollout 已 canary，手动 `/rollout/start` 自然 409（状态机守）。

### 2.3 判定＝两比例 z 检验（`routing/experiment.py` 纯函数，stdlib 零依赖）

- **`arm_stats(runs, version)`** → `{samples, businessSamples, errorCount, manualCount, diffCount}`＋派生三率：样本＝`resolved_version == version` 的运行；error 分母＝samples（`is_healthy` 同源）；两业务率分母＝businessSamples（**复用 gate 同一实现**——`_business_rates` 去下划线公开化为 `business_rates`，gate 内部引用同步改，行为零改动）。
- **`two_proportion_z(x_a, n_a, x_b, n_b)`** → `(z, p_value)`： pooled `p=(xA+xB)/(nA+nB)`，`se=√(p(1-p)(1/nA+1/nB))`，`z=(pB−pA)/se`，双侧 `p=2(1−Φ(|z|))`（`math.erf` 实现 Φ）。退化（n=0 或 se=0〔两臂全无事件〕）→ `(None, None)`。
- **`judge(exp, statsA, statsB)`** → `Verdict{status, winner, metric, rateA, rateB, z, pValue, reason（中文）}` 三态：
  - 任一臂主指标样本 < minSamples → **collecting**（不指 winner，reason 报当前样本数）；
  - 样本足且 `|z| ≤ 1.96`（α=0.05 双侧）→ **inconclusive**（不显著，不指 winner）；
  - `|z| > 1.96` → **significant**，winner＝主指标率**更低**的臂（三指标皆"低者为优"）。
- **`required_samples(baseline_rate, mde)`** → 每臂近似所需样本（α=0.05、power=0.8：`n=2(z_α/2+z_β)²·p̄(1−p̄)/δ²`，`p̄=baseline+δ/2`；baseline≤0/≥1 或 mde≤0 → None）。只作 GET detail 的指导性展示，不做强制闸门。
- 判定窗口＝**实验 createdAt 起累计**（非 gate 的滚动 observeMinutes——安全门要新数据，判定要全量数据）。

### 2.4 REST 面（`/api/experiments`，四端点）

| 端点 | 档 | 语义 |
| --- | --- | --- |
| `POST /api/experiments` | operate | 创建即启动；body `{graphId, versionA, versionB, trafficPercent?, primaryMetric, minSamples?}`；graph 不存在 404、版本未发布/非该图版本 422、rollout 非 idle 409、同图 running 实验 409 |
| `GET /api/experiments?graphId=` | read | 轻投影列表（不含臂统计，避免逐实验扫 ring） |
| `GET /api/experiments/{exp_id}` | read | 详情＋两臂 `armStats`＋临时 `verdict`＋`splitActive`（routing 快照仍 canary 且 candidate==versionB）＋`requiredSamples` 指导 |
| `POST /api/experiments/{exp_id}/conclude` | operate | body `{action: "adopt_a"|"adopt_b", reason?}`；冻结 verdict、adopt_b→promote／adopt_a→rollback（幂等同既有）、恢复 priorConfig；已终态 409；跨租户 404 |

### 2.5 存储两档＋迁移 056

- `experiments` 表：`id text PK`（`exp-N`，走全局 `storage_id_seq` 跨实例不复用）、`tenant_id`、`graph_id`、`version_a/b int`、`traffic_percent int`、`primary_metric text`、`min_samples int`、`status text`、`prior_config jsonb NULL`、`verdict jsonb NULL`、`conclusion_action/reason text NULL`、`created_by text`、`created_at TEXT ISO-8601`、`concluded_at TEXT NULL`；索引 `(tenant_id, graph_id, status)`。（落码修正：时间列 TEXT 而非 timestamptz——同 031 rollout_states 先例，这些列不参与认领/唯一判定，读回投影与内存档逐键同型字符串，无 datetime 转换漂移。）
- 两档：`ExperimentStore`（进程内 ring 100，惰性裁）＋`PgExperimentStore`；`iam/registry.py` 装配 `experiment_store`（进程内＋PG 两档、reset 清租户）——实验是配置资产，跨重启不可丢（同 BQ adapter_drafts 理由）。

### 2.6 前端

- `Experiments.tsx` 管理面：列表（图/两版/主指标/状态/创建时间）＋创建表单（`saved-graph-select` 选图、版本下拉取自该图发布版、流量比例、主指标单选、minSamples）＋详情（两臂三率对照表、verdict 横幅〔collecting 灰/inconclusive 黄/significant 绿＋胜臂〕、requiredSamples 指导、`splitActive` 警示、conclude 两按钮带确认）。

## 3. 决策

### 3.1 G-P1 拍板＝显著性方法用两比例 z 检验（按推荐口径）

- 备选：卡方检验（2×2 列联表与 z 检验**数学等价**，z²=χ²，实现无差）；Fisher 精确检验（小样本金标准，但阶乘实现在 n 上百后昂贵，而 minSamples≥30 门槛保证正态近似成立）；序贯检验/mSPRT（允许随时看随时停，实现复杂）——**v1 取 z 检验**：stdlib `math.erf` 即足、零新依赖、与"低率为优"的三指标口径天然对齐。
- peeking 风险照实记：固定地平线纪律（达 minSamples 前不 conclude）写进 reason 与前端文案；**不**假装 v1 有序贯修正。

### 3.2 其余决策

- **BR-D1** 分流复用 RoutingStore canary（同一 `bucket_key`/`hash_hit`，零新分桶代码）；实验＝意图/判定层，灰度执行面零改动。
- **BR-D2** 对照两版显式指定（`versionA`/`versionB` 创建必填、须为该图已发布版）；`RoutingStore.start` 增 `stable=`/`candidate=` 显式参数，不传参行为逐字不变。
- **BR-D3** 判定口径：三指标沿用 gate 同三 id 同分母（`_business_rates`→`business_rates` 公开化，行为零改动）；主指标创建时三选一；低率为优；α=0.05 双侧；判定窗口＝实验创建起累计。
- **BR-D4** 判定只读建议、conclude 人决：verdict 不强制（人可对 inconclusive 甚至反向结论做 adopt，verdict 与 action 不一致照实记录）；conclude 走既有 promote/rollback，**不新增任何自动推广通道**；guardrail 自动回滚在实验期保持有效（越阈仍撤 B，实验 GET 以 `splitActive=false` 反映，conclude 幂等可用）。
- **BR-D5** 配置快照与恢复：启动存 priorConfig 入实验记录；实验期配置＝纯 canary 百分比（业务桶段不混入）；conclude 恢复 priorConfig（无则留实验配置，配置在 full/rolled_back 态惰性，照实记）。
- **BR-D6** 互斥与并发：同图同一时刻至多一个 running 实验；rollout 非 idle 不开实验；实验期手动 rollback 不删实验（人随时可撤流，判定层只反映不阻拦）。
- **BR-D7** 存储两档（进程内 ring 100＋PG 迁移 056）；`exp-` id 走 `storage_id_seq`；reset 清租户。
- **BR-D8** 零新依赖／零新错误码／无 ADR；前端零新控件；判定全中文 reason（与配置校验中文聚合先例一致）。

## 6. 边界与不触碰
