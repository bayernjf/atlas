## 第六部分：运行时引擎设计
### 6.1 Loop 主循环实现
基于 LangGraph StateGraph 构建持久运行的状态机（代码示例）：
class LoopState(TypedDict):
goal: str
messages: list          # 对话/执行历史
current_node: str
observations: list      # 感知结果
variables: dict         # 会话变量
status: str             # running/paused/completed/error
memory_id: str
# 构建主循环
graph = StateGraph(LoopState)
graph.add_node("observe", observe_node)      # 调用Harness感知当前状态
graph.add_node("orient", orient_node)        # 分析数据，定位进展
graph.add_node("decide", decide_node)        # LLM决策下一步
graph.add_node("act", act_node)              # 执行工具/操作
graph.add_node("reflect", reflect_node)      # 阶段性反思
graph.add_edge("observe", "orient")
graph.add_conditional_edges("orient", should_continue)
graph.add_conditional_edges("decide", should_act_or_wait)
graph.add_conditional_edges("act", should_reflect_or_continue)
```

> **Graph condition 节点执行语义（Phase 2 首版，2026-09-14；契约权威见 04 §5.2）**：编辑后台 Graph 中的 condition 节点编译为 LangGraph conditional edges——同一 condition 节点的出边**全部**走 `add_conditional_edges`（不得与普通边混用，否则双路激活）。执行器按 config.branches 数组顺序短路求值（第一个为真者胜出），全假或求值异常时走 defaultTarget；求值只发生一次并写入 `outputs[condition_id]`，路由函数仅读取其中的 `target`。含变量的运行时类型错误/缺失变量 fail-safe 走 defaultTarget，错误进 `expression_errors`；trace（messages）追加一行 `condition-x: branch=<label|__default__> → target=<node_id>`。表达式首版白名单（比较/逻辑/括号/字面量/`{{路径}}`，无算术与函数、禁止 eval）见 04 §5.1。

> **Graph loop 节点执行语义（Phase 2 第二项，2026-09-14；契约权威见 04 §5.3）**：v1 仅条件循环（while）。loop 节点的两条出边（bodyTarget/exitTarget）全部走 `add_conditional_edges`，router 只读 `outputs[loop_id]["target"]`；循环体末端以**普通回边**连回 loop 节点，形成 LangGraph 原生环（回边白名单由 dsl 静态校验保证，非法环保存时拒绝，见 13 U7）。执行器可重入：每次进入读取自身上次产出的 `iterations`，达 `maxIterations` 或表达式求值异常时 **fail-safe 路由 exitTarget**（exitReason 分别为 `max_iterations`/`expression_error`，运行整体仍 completed），表达式为真则计数加一路由 bodyTarget，为假路由 exitTarget（`condition_false`）。循环体节点经 `{{loop-x.index}}` 引用当前 1-based 轮次。LangGraph 默认 recursion_limit=25 会中断循环，`run_graph` 按 `2*节点总数 + 2*maxIterations*(循环体节点数+1) + 10` 派生并经 `invoke(..., config={"recursion_limit": n})` 传入。trace 行：`loop-x: continue (i/max) → body` / `loop-x: exit (reason) after N → exit`。遍历循环与 break/continue 缓做（14 登记表 D16/D17）。

> **Graph loop foreach 执行语义（2026-09-23 立项，docs/45；契约权威见 04 §5.3）**：同一 loop 节点 `mode="foreach"`。首次重入对 `itemsExpression` 求值一次并冻结进自身产出 `items`（后续重入不重新求值），按 0-based 游标逐项把元素写 `item`、路由 bodyTarget；体内回边重入时若 `collectTarget` 非空，先把该节点产出整体追加进 `results`，再推进游标。路由仍走同一 conditional-edge 族（router 读 `outputs[loop_id]["target"]`），回边白名单/break 网关与 while 同构。fail-safe：求值异常/非数组 → exitReason=`expression_error`，长度 >100 → `items_too_large`，空数组 → `empty`，正常遍历完 → `completed`；体内 condition 直连 exitTarget 的 break 同样适用。体内引用 `{{loop-x.item}}`/`{{loop-x.index}}`/`{{loop-x.results}}`（itemName 仅展示别名、不改路径）。recursion_limit 按冻结数组长度派生（公式同 while，以 len(items) 代 maxIterations）。foreach 为串行逐项，并行 map-reduce 仍缓做。

> **Graph parallel 节点执行语义（Phase 2 第三项，2026-09-14；契约权威见 04 §5.4）**：v1 静态扇出/扇入，合并策略仅 `all_success`/`all_completed`（any_success 真 OR-join 需取消其他分支，缓做 14 D18；动态 map-reduce 不做）。parallel 节点的 N 条出边全部走 `add_conditional_edges`，router 返回**分支目标列表**（`list[str]`）实现同超步静态扇出；分支末端全部汇聚到 config.joinTarget——**编译期注入合成网关节点 `__join__<parallel-id>` 做汇聚屏障**（spike 实测 LangGraph 对普通静态多入边不做 barrier、不会等待全部前驱）：分支末端 retarget 到网关，网关每超步检查各分支末端产出，未齐则空 messages 自我循环等待，齐后聚合一次再路由真 joinTarget，joinTarget **只执行一次**（不等长分支亦成立）；`__join__` 事件不外泄，汇聚完成以 parallel 节点自身补发第二次 node_end。支撑并发写的横切变更：`GraphState.outputs` 由无 reducer 的 LastValue 通道改为 `Annotated[dict, _merge_outputs]` **按键合并**通道，各执行器只返回自己的分片 `{"outputs": {node_id: output}}`（同 key 后者覆盖）；`messages` 仍为 `operator.add`，`status` 为 last-write。扇出不增加递归深度，recursion_limit 公式不变。分支成败判定：该分支路径上任一节点产出出现 `result.status == "FAILED"` 即失败（工具失败只写 FAILED 不抛错）。**fail-safe 汇聚**：all_success 下即便有分支 FAILED，joinTarget 照常执行、parallel 产出 `status="failed"` 与逐分支错误、运行整体仍 completed；下游可用 condition 判 `{{parallel-x.status}}`。聚合产出（写入 `outputs[parallel_id]`，入口先写 running 占位、汇聚时覆盖为终态）形状与 trace（`parallel-x: fork N branches → a, b` / `parallel-x: joined (all_success) success` / `… failed: <label>（<error>）`）见 04 §5.4、12 文档。

> **Graph wait 节点执行语义（Phase 2 第四项，2026-09-14；契约权威见 04 §5.5）**：v1 仅定时等待（`waitType:"duration"`，`durationSeconds` 为 1-600 整数常量，不支持变量/表达式动态时长）。执行器在发出 node_start 后同步 `time.sleep(durationSeconds)` 阻塞，到时发 node_end，沿唯一普通边继续（不经 conditional 边、不增加递归深度）。SSE 同步流生成器运行于 Starlette 线程池工作线程，阻塞不卡事件循环但占用一个工作线程，故上限 600 秒；等待不失败、不重试。节点产出 `{mode:"wait", waitType:"duration", durationSeconds}`（可经 `{{wait-x.durationSeconds}}` 引用），trace 行 `wait-x: waited 5s`。事件等待的进程内 v1 子集已落码（2026-09-23，见 §6.22/docs/47）；中断帧/恢复扫描器与多实例仍缓做 14 D19。**定时等待动态时长 v1 已落码收口（2026-09-23，docs/49；8580fcb/4eaaddd，后端 1472/59、前端 621/2，HTTP 冒烟 21/21）**：durationMode=dynamic 时 durationExpression 经条件引擎求值 1-600 秒（int(round)，bool/非有限拒绝），秒数同时作帧 timeout_seconds，坏表达式/非法结果 run failed WAIT_DURATION_INVALID 不 sleep；static（含旧图缺省）零回归。到点时刻/event timeout 表达式化/跨重启扫描器仍缓做 D19。**到点时刻等待 v1 已落码收口（2026-09-23，docs/50；12de72d/4f82a1c，HTTP 冒烟 21/21）**：durationMode=absolute 时 absoluteTime（ISO 8601/epoch 秒，支持 {{}} 插值，naive 按 UTC）解析目标时刻，按注入时钟取差值 1-600 秒等待，坏时刻/过点/越界 run failed WAIT_ABSOLUTE_TIME_INVALID 不 sleep；static/dynamic（含旧图缺省）零回归。event timeout 表达式化/跨重启扫描器仍缓做 D19。

> **Graph human_approval 节点执行语义（Phase 2 第五项，2026-09-14；契约权威见 04 §5.6）**：v1 为**进程内审批信号**——执行器在 `atlas.collaboration.approvals.ApprovalBroker` 登记 pending 请求（uuid4 token + `threading.Event`），node_start 事件 data 携带 `approval:{token, summary, approver, timeoutSeconds}`，随后阻塞等待，决策到达后发 node_end 并以 `add_conditional_edges` 按 `outputs[id].target` 路由（双出口，同 condition/loop 路由族；不增加递归深度）。决策三来源：① `POST /api/approvals/{token}/decision` 人工放行（resolvedBy="human"，首决生效、重复提交 409）；② run inputs 预置 `{"approvals":{"<node-id>":"approved"|"rejected"}}` 秒过（resolvedBy="input"，非交互/测试）；③ 等待满 `timeoutSeconds`（10-3600 整数）按 `onTimeout`（approve|reject，默认 reject）自动决策（resolvedBy="timeout"），运行仍 completed。阻塞发生在 Starlette 线程池工作线程，故 `/run/stream` 必须**真流式**（后台线程跑 run_graph、事件经 queue 实时下发；旧的「跑完再回放」实现会在审批节点死锁）。broker 为进程内单例、重启即失、不支持跨实例；真正的 interrupt/checkpointer 中断-恢复、多实例、IM 通知、动态审批人/鉴权缓做 14 D20。节点产出 `{mode:"human_approval", decision, target, token, summary, approver, resolvedBy}`，trace 行 `human-x: approved (human) → tool-refund`。

> **Graph subgraph 节点执行语义（Phase 2 第六项，2026-09-14；契约权威见 04 §5.7）**：v1 为**进程内引用式**——执行器按 config.graphId 经注入的 `graph_resolver`（Demo 为 GraphStore.get）取得子图 GraphDSL，把 config.inputs 各值用父图上下文渲染后作为子图 run inputs，**同进程重入 `run_graph`** 整体执行子图：子图 trigger `context.payload` 接收映射入参（语义同 webhook 载荷），复用父图同一套适配器注册表、决策客户端与审批 broker。编译期跨图校验由 `compile_graph(graph_resolver=...)` 递归完成：graphId 必须可解析，禁直接自引用与跨图引用环，**嵌套深度上限 3**（对齐 07 §8 递归深度护栏），被引用图递归过完整图校验。**A 包（2026-09-19 `e594a4b`，docs/27 §3）起子图内部 `node_start`/`node_end` 经命名空间回调上 SSE**：事件附 `subgraphPath`（每层父图 subgraph 节点 id，嵌套累加），仅转发节点级事件、吞掉子层 `run_end`/result 终帧（整图仅父层一个 run_end）；前端对内部节点只记带 `[path] ` 前缀的日志、不写入父图画布节点状态表（避免子图节点 id 污染画布），父 subgraph 节点由其自身无 path 事件驱动高亮。录制 collect_steps 与监控采集只收无 `subgraphPath` 的顶层 node_end。子图 trace 始终完整收入节点产出。（此前 v1 为 `emit=None` 完全压制。）子图阻塞于 Starlette 线程池工作线程（同 wait/human_approval），不产生父图超步、父图 recursion_limit 公式不变（子图 invoke 有独立限额，深度参数随重入传递）。**fail-safe**：子图解析/编译/运行期任何异常均捕获为节点产出 `status:"failed"`+error，父 run 仍 completed、沿唯一普通出边继续（不做成功/失败双出口），下游可用 condition 判 `{{subgraph-x.status}}`。子图内含 human_approval 时，其 node_start 的 approval 载荷（全局唯一 token）经 `subgraphPath` 上屏，前端审批 Modal 显示 `[path] nodeId` 归属，等待期内可经既有 `/api/approvals/{token}/decision` 交互决策、broker 释放子图线程（A 包进程内形态，无新端点）；inputs 预置与超时自动决策仍可用，持久化/多实例中断随 D20。节点产出 `{mode:"subgraph", graphId, status, error?, outputs:<子图 outputs>, trace}`，trace 行 `subgraph-x: graph-7 success (N nodes)` / `… failed: <error>`。版本钉版/手动升级回归、子图市场/共享、远程运营体引用缓做 14 D21。
### 6.2 决策节点实现（代码示例）
def decide_node(state: LoopState):
# 1. 从记忆中检索相关上下文
relevant_memory = memory_retriever.query(state.goal, state.messages[-5:])
# 2. 构建提示词（含思考缓冲区）
prompt = f"""
【目标】{state.goal}
【当前状态】{state.messages[-10:]}
【相关记忆】{relevant_memory}

请先进行内部推理（思考：
1. 当前进展如何？
2. 下一步应该做什么？
3. 有什么风险？
然后输出结构化决策。
# 3. 调用LLM，强制结构化输出
decision = llm.with_structured_output(DecisionSchema).invoke(prompt)

# 4. 置信度检查
if decision.confidence < 0.6:
return {"status": "paused", "request_human": True, ...}

return {"current_node": decision.next_action, ...}

class WebHarnessAdapter:
def click(self, element_desc: str, selector: str = None):

if selector:
try:
self.page.click(selector, timeout=3000)

except:

result = vision_llm.analyze(screenshot, f"找到{element_desc}并返回坐标")
if result.coordinates:
self.page.mouse.click(*result.coordinates)
return success()

return failed("元素未找到，三层定位均失败")


### 6.6 API 适配器（通用 HTTP）运行时

契约权威为 04 §4.6；本节补充运行时语义。

- **同步执行于线程池**：tool_call 执行器内经同步 httpx.Client 发出请求；SSE 真流式跑在 daemon 线程、同步 /run 跑在 Starlette threadpool worker，阻塞等响应不卡事件循环，占用模型同 wait/human_approval（600s 级长请求不适用，v1 上限取节点 timeout，默认 30s）。
- **不产生父图超步**：HTTP 往返发生在单个 LangGraph 节点内部，recursion_limit 公式不变。
- **结果不抛错**：收到响应即 SUCCESS（含 4xx/5xx），输出 `{status, headers, body}` 供 condition 分支；仅传输层异常（`httpx.TimeoutException`/`RequestException`）折叠为 FAILED（HTTP_TIMEOUT/HTTP_CONNECT_ERROR），run 仍 completed（fail-safe，对齐 parallel/subgraph）。
- **重试与熔断（docs/32 §5，2026-09-21 落）**：仅传输层异常与 429/502/503/504、且幂等方法（GET/HEAD/PUT/DELETE，或显式幂等 POST/PATCH）做指数退避+全抖动重试（默认 3 次、429 尊重 Retry-After），重试用尽仍折叠 HTTP_TIMEOUT/HTTP_CONNECT_ERROR；按 host 连续失败达阈值熔断（HTTP_CIRCUIT_OPEN，冷却后半开试探）。SSRF/凭证错误不重试、不计熔断；节点级 retry/on_error 仍作用于节点整体。
- **凭证边界（docs/32 §2，ADR T26=(a)）**：默认 headers（含 ATLAS_HTTPAPI_TOKEN）在 client 内合并且不写入图 JSON；url/headers 中秘密以 `secret://<name>` 引用或 `enc$v1$...` 信封承载，发送前由 SecretProvider（AES-256-GCM 主密钥运行时注入）解析，明文不落 last_request/observe/录制/SSE/日志（敏感头渲染 ***），缺失 → SECRET_UNAVAILABLE 零外呼。节点 params 仍不应内联明文密钥。
- **SSRF 边界（docs/32 §3，已落）**：建连前 EgressGuard 校验最终绝对 URL，仅 http/https，私网/环回/链路本地/云元数据/CGNAT/保留地址与整数/进制 IP 绕过恒拦（EGRESS_DENIED，零外呼），配 ATLAS_HTTP_EGRESS_ALLOWLIST 后仅命中项可出网（私网/元数据恒拦优先）；DNS rebinding 的连接级 pin-IP 彻底修复随部署批（docs/32 §9），OAuth2/连接 CRUD 仍随 14 D22。

### 6.7 数据/消息适配器运行时

契约权威分别为 04 §4.7（数据）与 §4.8（消息）；本节补充运行时语义。

- **同步执行于线程池**：database 经同步 SQLAlchemy `Engine`/`Connection` 执行 text()，message 为进程内内存操作；执行模型同 §6.6（daemon 线程 / Starlette threadpool），不产生父图超步，recursion_limit 不变；节点 timeout 默认 30s。
- **只读保障（docs/32 §4，已落）**：query 在 SQLite/PG 两档触库前都过 `assert_read_only_sql` 静态审查（去注释/拒多语句/只放单条 SELECT·WITH…SELECT，违例 DB_SQL_NOT_READ_ONLY）；PG 再以 `execution_options(postgresql_readonly=True)` 开只读事务、查询结束显式 rollback。外部 ATLAS_DATABASE_URL 连接 read_only=True，execute 触库前直接 DB_WRITE_FORBIDDEN；仅 demo engine（engine 直连播种）保留写。
- **结果不抛错**：SQLAlchemy 执行异常折叠为 FAILED `DB_SQL_ERROR`（错误文本与 observe 的 URL 一律 `render_as_string(hide_password=True)` 脱敏），run 仍 completed；未配置且未注入 engine 为 `DB_NOT_CONFIGURED`（fail-closed，不静默连平台库）。
- **SQLite demo 边界**：`ATLAS_DATABASE_URL` 缺失时后端用 StaticPool 单连接内存库 + seed 订单；`/api/demo/reset` 仅重建 demo 内存库，显式配置的外部 PostgreSQL 永不被 reset 触碰。
- **进程内消息 sink**：message/send 只写进程内记录（uuid4 + sent_at），**无真实投递、无网络 I/O**；重启清空、reset 清空，`GET /api/demo/messages` 陪同查看；群发上限 20 在服务层强校验。
- **注入与投递安全边界**：sql 经 `{{路径}}` 插值有 SQL 注入面——绑定参数 params 仍是防注入主路径，应用内只读 SQL 静态审查与外部 execute 禁用已落（docs/32 §4），但不替代最小权限只读账号/审计（仍随 14 D23）与网络层 egress；真实渠道投递（SMTP/IM/短信/webhook）与限流重试缓做 14 D24。
- **IM 群机器人（docs/51，2026-09-23 docs-only 立项）**：channel=dingtalk/wecom/feishu 经 `message/im.py` 向单 URL 投 text 消息（EgressGuard→10s→不重定向；钉钉/飞书 HMAC 加签，平台 errcode/code 非 0 判失败），失败 IM_SEND_FAILED 不落记录、EGRESS_DENIED 透传，成功 delivered 标渠道名；未注入投递器回退进程内。短信/富文本/入站/模板/限流仍缓做 D24。

### 6.8 流程模板库（无独立运行时）

契约权威为 04 §5.10；本节说明运行时边界。

- **模板即静态数据**：模板是随代码发布的 Graph JSON 目录（`atlas.template`），服务端不实例化、不缓存运行态、不持有任何模板相关状态；`GET /api/templates*` 只是只读投影，不存在模板创建/更新/删除路径，`/api/demo/reset` 不触碰目录。
- **加载是客户端行为**：「从模板新建」在编辑器内整画布替换（nodes/edges/variables 全量替换为模板内容，id 不重映射），与自然语言草稿载入、初始画布同一 `loadGraph` 路径；没有专门的模板实例化端点。
- **运行时零特殊路径**：模板加载后就是一张普通 Graph——保存为 graph-N、经标准 compile/run（含 SSE、审批、子图等全部语义）执行；模板更新不影响已保存图，图与模板之间不保留引用关系。
- **模板图与普通图同契约**：所有内置模板必须通过与用户图完全相同的 `parse_graph`/`validate_graph` 校验，仅可引用 demo 注册表中已存在的适配器工具（测试 U27 固化该不变量）。

### 6.9 操作录制与回放（无独立运行时）

契约权威为 04 §5.11；本节说明运行时边界。

- **录制即收集既有事件**：录制不引入节点类型、执行器分支或专用运行端点；客户端在标准 `/api/graphs/{id}/run/stream` 上收集 node_end 的逐节点终态产出（parallel 两次 node_end、loop 重访均取末次），随 graph_id/inputs/status 提交 `POST /api/recordings`，服务端只做图快照与入库，不重新执行。
- **回放走标准 compile/run**：`POST /api/recordings/{id}/replay` 对用例内冻结的图快照 `parse_graph` 后调用同一 `run_graph`（同 registry/approval_broker/graph_resolver，emit 收集回放事件序列）；录制存储不参与编译与状态。
- **审批确定性**：baseline 中 human_approval 步骤的决策被抽取并预置为回放 `inputs.approvals`（§5.6 决策三来源中的「run inputs 预置」），回放不阻塞等待真人，故同一用例可重复回放；实时人工交互只存在于录制时的正常运行链路（13 R3）。
- **比对归一化**：逐节点深等前剔除运行时易变值——审批 `token` 与 `resolvedBy`、消息 `sent_at` 与消息记录 uuid `id`、HTTP 响应头 `date`、trigger 载荷中回放注入的 `context.payload.approvals`（规则见 04 §5.11）；归一化后仍不同即判定该节点不匹配并给出差异键。操作序列（node_id 顺序）先于值比对，分支漂移表现为多走/漏走节点。
- **非幂等与外部态局限**：demo 适配器（message 进程内落记录、database demo SQLite、http mock）回放稳定；真实外部系统的写操作/累积状态（如重复退款、自增行）可能导致天然差异，跨版本差异对比、Mock 工具响应缓做 14 D26。
- **失败折叠**：回放本身的异常（如快照内 subgraph 引用的 graphId 已被 reset 删除）不抛 500，折叠为 `replay_status:"failed"`、matches=false 并在步骤报告注明。
- **回放冻结时钟（C 包，2026-09-19 已落码 `3415377`，docs/27 §2）**：`run_graph(now_override=)` 单次运行固定一个 UTC 时钟（naive 当 UTC、aware 转 UTC），经执行器透传 condition/loop/subgraph（子图重入继承同一冻结时刻）/调试条件断点；`today()`/`now()` 取该时钟。单用例 replay 与发布门禁每例经 `recording.replay.clock_anchor(case)` 取锚点（`recorded_at`→`created_at`→真实时钟）注入 `now_override`，使含非确定时间函数的分支在录制与回放间确定可比、发布门禁不因跨天/跨秒误判；两时间戳皆缺才用真实时钟并附中文 `clock_note`（单用例挂响应顶层、门禁挂对应 case 项）。v1 锚点＝用例入库时刻（`recorded_at` 与 `created_at` 同 stamp；POST /api/recordings 不重跑 baseline，细化见 docs/27 顶部注记 1）。

- **影子模式运行时边界（docs/33 §3 ④，2026-09-21 `cea7111`，D26 部分取回）**：影子不是独立运行时，而是同一 `run_graph(shadow=True)` 的旁路装配——独立 Tracer、独立 ApprovalBroker（预置全部 human_approval approved 秒过）、emit 仅收顶层 node_end；loader 工具分支按**编译期 adapter/capability→permission 表**短路（READ 透传真实执行，WRITE/DELETE/FINANCIAL 不调 `adapter.execute`、返 SHADOW_DRY_RUN 意图，含子图全链）。**零污染**：不写 run_store/RunRecord、不调 evaluate_after_run（故不刷指标/告警/灰度门控）、不发 tool_metric，异常沉淀为 status=error 不外溢生产链路。产出经 `extract_shadow_events` 纯函数归并 decisions/tool_intents、`compare_shadow` 纯函数算与 human_outcome 差异（无写意图 match=null）；ShadowStore ring 100/租户进程内、reset 清空。契约 04 §5.11 影子落码块；线上自动旁路/定时对比/PG 化仍缓做 D26。

### 6.10 调试运行时（单步调试与断点 v1）

契约权威为 04 §5.12；本节说明运行时机制。

- **唯一挂点**：调试判定位于统一执行器 `_make_executor.execute` 内 `emit(node_start)` 之后、按节点类型分派之前（loader.py），9 类可编译节点零分支全覆盖；节点未命中暂停时执行路径与非调试运行逐行一致（`debug_controller=None` 零开销）。
- **进程内会话**：`DebuggerBroker`/`DebugSession`（`src/atlas/debug/sessions.py`）与 ApprovalBroker 同构（uuid token + `threading.Event` + REST 首决生效），但**另建不合并**——调试会话无超时、无路由语义，携带 step/continue/stop 状态机与断点表；不引入 LangGraph interrupt/checkpointer（持久化中断-恢复随 14 D19/D20、11 S1）。
- **暂停协议**：命中（逐节点 step 模式，或断点表命中；条件断点以当前 context `{"global": globals, **outputs}` 经 §5.1 白名单引擎求值）后 emit `paused` 帧并阻塞在会话 Event 上；帧内 globals/outputs 为**深拷贝快照**，恢复后后续执行不改写已展示值。条件表达式运行时异常 fail-safe 视为不命中（记录到会话 last_condition_error，绝不抛出卡断运行）。
- **resume 状态迁移**：step 保持逐节点；continue 清 step_mode（此后仅断点/条件断点暂停）；stop 置 cancelled 并抛 `DebugStopped`。Event 唤醒后统一复检 cancelled，使 stop 与 reset 两条路径收敛到同一终止异常。
- **并行串行化**：parallel 区域多个分支节点同时到达暂停点时，经会话级锁串行进入暂停区（一次只存在一个活动暂停），单用户 Demo 下暂停帧顺序确定；合成 `__join__` 网关不经统一执行器，天然不暂停。
- **拓扑边界**：subgraph 重入 `run_graph` 时**透传同一调试控制器/会话（docs/28 批 2 `f6f7d30` 起）**，子层可逐帧 step、命中断点/logpoint/异常断点，子层 paused/debug_log 附 subgraphPath、整图终帧仍只父层一个（A 包后子图节点事件经 subgraphPath 上屏；此前 v1 控制器不透传、子图整段执行、内部不暂停）；wait 在 sleep 前暂停；human_approval 在审批 broker 注册前暂停，step 放行后既有审批等待与 Modal 链路不变。
- **停止冒泡**：`DebugStopped` 不被 run_graph/LangGraph 节点包装吞掉，冒泡至 `/run/stream` worker 转为 `__stopped__` 哨兵 → SSE `stopped` 帧，流正常结束且无 result 帧。v1 停止仅在暂停点生效，不做运行中线程强杀（D27）。
- **重置释放**：`/api/demo/reset` 对所有调试会话置 cancelled 并 set Event，阻塞在暂停点的运行线程立即走停止路径，杜绝悬挂。
- **B 包协作式急停运行时（2026-09-20，`f9a1301`，docs/27 §4.1）**：新增 `collaboration/cancellations.py` 的 `RunCancelled(Exception)`（携带 node_id，语义为协作式终止而非节点失败）与 `RunCancellationBroker`（run_id→`threading.Event`，register 幂等返回 Event、cancel 置位返回 bool、unregister、reset，挂 TenantServices、memory/pg 两档 registry 接线、reset_tenant 联动）。`run_graph`/`_make_executor` 增 `is_cancelled` 可调用并透传 loop/parallel/subgraph 全链，普通流在每个节点 `emit(node_start)` 之后、节点逻辑之前的统一边界检查——置位即抛 `RunCancelled`；`_execute_subgraph` 的 fail-safe 在通用 `except Exception` **之前**新增 `except RunCancelled: raise`，防止子图把取消折叠成节点 FAILED。**协作式而非强杀**：wait 的同步 `time.sleep`、human_approval 阻塞、tool 外部调用进行中点取消不立即中断（不回滚已发起外部事实），置位后于**下一节点边界**生效；wait 节点开始即落 suspended 但 worker 继续 sleep，期间 cancel 返 200、sleep 结束到下一节点边界才发 cancelled。
- **取消收敛与健康口径**：worker catch 序为 `DebugStopped`→`RunCancelled`→`Exception`（RunCancelled 是 Exception 子类，顺序错会被通用分支吞成 error）。RunCancelled 分支 `run_store.finish(status="cancelled")`＋`monitoring.record_run(status="cancelled")`，**不调** `evaluate_after_run`（急停不触发门控自动回滚），下发 SSE `cancelled` 帧后关流；`metrics.is_healthy` 认 `completed`/`cancelled` 且无失败节点，cancelled **不刷连续失败 streak、不产生告警**。调试流 before_node 同时检查会话 cancelled 与 `is_cancelled()`，命中折叠为现有 `DebugStopped`/`stopped`（不发重复 cancelled）。
- **hitCount/logpoint 与 globals 写回运行时（B 包，docs/27 §4.2/§4.3）**：会话维护每断点 `hit_counts`；`_classify_hit` 三态——step 直接 pause（不计数）；条件表达式异常 fail-safe 记 `last_condition_error` 不命中；命中先 `bump_hits`，`log_message` 非空则 emit `debug_log`（`{node_id,hits,message}`）后返回不暂停，否则 `hit_count` 为正整数 N 且 `hits%N!=0` 时不暂停、其余 pause。resume 的 step/continue 在 Event 唤醒后把 `_Pause.overrides`（apply_overrides 已做键名标识符正则＋JSON 可序列化校验、深拷贝、拒绝未知/已决 token）**浅合并写回 `state["variables"]["global"]`**（dict 值整体替换、不深 merge、不删未给键），stop 路径不 apply overrides。

### 6.11 监控运行时（基础监控告警 v1）

契约权威为 04 §5.13；本节说明运行时机制。

- **API 层埋点，执行器零分支**：监控不进入 loader/节点执行路径，唯一埋点是 `main.py` 的两个真实运行入口（同步 `/run` 与流式 `/run/stream` worker）；录制 replay 端点直调 `run_graph`（graph_id `replay-N`）、subgraph 重入、debug 运行（请求带 debug）天然不计入。新增节点类型无需改监控。
- **失败是数据不是异常**：节点成败由终态 outputs 推断——tool_call 的 ActionResult 携带 `result.status=="FAILED"`（含 code/message），subgraph fail-safe 折叠为 `{status:"failed",error}`，parallel 聚合各分支 `{label,target,status:"failed",error}`；监控以同一两形状判定（`output.status=="failed"` 或 `output.result.status=="FAILED"`），不依赖 node_end 帧（该帧无 status）。执行器未捕获异常才是运行级 error：同步路径捕获记录后原样 raise（保持 500），SSE worker 在 `__error__` 哨兵分支记录。
- **流式部分节点采集**：SSE 路径在非 debug 时包一层 emit，node_end 帧把 output 收入 `collected`（再透传原 emit）；运行正常结束用 result.outputs 推断全量节点，异常结束用已采集 outputs 记录部分节点。
- **ring + 单锁同步评估**：`MonitoringStore`（`src/atlas/monitoring/records.py`）以 `deque(maxlen=200)` 存运行、单把 threading.Lock 串行化「追加运行 → 连续失败 streak 维护（按 graph_id，健康归零）→ 四规则求值 → 告警新建/合并」；无后台线程、无调度器，单用户 Demo 下读数与写入强一致。
- **纯函数内核**：节点成败抽取（`metrics.extract_node_results`，以图定义提供 node_id→type）、nearest-rank 百分位与 summarize、规则求值（`alerts.evaluate_rules`，只产出触发意图，合并由 store 执行）均为无状态纯函数，全部由 U30 钉死。
- **与正式可观测性的边界**：v1 是进程内即时聚合（重启即失、无时间序列），不引入 OTel SDK/Prometheus client/Grafana；部署后正式栈（拉模型指标、Trace、持久化、多实例汇总）缓做 14 D11/D28，埋点位置（API 包装层）与 RunRecord 口径为将来 exporter 预留。
- **M9 业务指标与门控求值位置（M9 已落码 2026-09-18（批 1-4＋收口，后端 602/前端 396））**：业务结果提取 `business.extract_business` 为纯函数（契约 04 §5.13 末/03 `business_metrics`），RunRecord 加可选 `business`/`resolved_version`（纯超集），summarize 增 business 三率段（全局/per_graph/per_version，样本 0 为 null）。**门控求值 `routing.gate.evaluate_after_run(services, record)` 由两个真实运行入口在 `record_run` 之后调用**——仍守本节「API 层埋点、执行器零分支」：loader/节点执行路径不感知灰度，依赖方向为 routing→monitoring 只读（monitoring 不反向 import routing，避免环）；replay/debug/subgraph 重入同口径不触发。rollout_gate 告警携带可选 `action`（rollback 切流版本/原因/actor），Alert 其余规则不变。
- **批 3 适配器埋点与自定义规则（docs/28 §4，D28 进程内两项部分取回、不解除；2026-09-20，`a318d97`/`11b1ba7`/前端 `4256326`）**：⑧ 对本节「API 层埋点、执行器零分支」做**最小例外**——`graph/loader.py` 真实工具分支（非 mock）仅以 `time.monotonic()` 计时并经模块级 `_tool_metric_event` 归一后 emit 内部 `tool_metric` 事件，执行器**不 import monitoring、不写监控存储**；采集进 RunRecord、PG 落 JSONB、`summarize_tools` 聚合仍只在两个真实运行入口（API 层），mock 命中不发、子图内经命名空间白名单吞掉、debug 流发而不采、replay/gate/子图重入不采（顶层口径与 collect_steps 一致）。SIMULATED 纳 calls/simulated 但不纳 failed 与延迟分位，未注册适配器失败 error_code 可空。⑨ 自定义规则复用 `graph.conditions` 递归下降求值器（**禁 eval** 红线不变）：扁平白名单上下文 {status, durationMs, failedCount, hasError}（不含 graphId；durationMs 取 int 毫秒以满足引擎有序比较严格同型），非布尔结果或任何异常一律 fail-safe 不告警不阻塞，rule_id 为 custom:{cid}、纯超集 rule_name（PG alerts 表 v1 无该列读回 null、前端回退 rule_id），custom 规则随 monitoring_rules.config JSONB 承载、无 DDL。正式 OTel/Prometheus/Grafana、子图内/Mock 埋点、规则图级绑定与外部告警出口仍缓做 14 D28。

- **静默 / 惰性升级 / 值班运行时（docs/33 §5 ⑩，2026-09-21 `00bba8c`，D28 部分取回）**：告警写路径在「新建/合并」判定前先经 OpsStore 静默匹配（`silence_matches`，单锁与监控写路径串行）——命中仅 `suppressed_count+1`，不建/不合/不升级。**升级无后台线程**：`apply_escalation` 在 list/get **读时**对 open warning 按 first_seen（空回退 last_seen）惰性评估 `escalation_ack_minutes`，幂等（critical/ack/resolved/关配置/已升级不重复升）。值班 assignee 仅在告警**新建**分支取 `current_assignee`（合并/静默不取）。OpsStore 进程内挂 per-tenant monitoring bundle，内存/PG 两档共用、不落库；PG 档告警在库，assignee 走 `_assignees` map、escalated_at 读回按 first_seen 幂等重评。守本节「无后台线程/无调度器」与「纯函数内核」：匹配/升级/取值班均为纯函数或单锁同步；REST 6 个（GET read、POST/PUT/DELETE administer、viewer 写 403）。契约 04 §5.13 落码块；外部通知出口、自动轮换定时器、静默/值班/升级 PG 持久化与多实例仍缓做 D28。

### 6.12 认证鉴权运行时（多租户权限 v1）

契约权威为 04 §5.14（多租户/RBAC）与 §5.17（生产认证：账号/口令/会话 TTL/节流）；本节说明运行时机制。

### 6.18 邮件公开决策运行时（审批闭环批；2026-09-22 已落码，docs/36，ADR T27）

契约权威为 04 §5.6 邮件决策追加段、03 `email_decision_token` 与 docs/36；本节约定运行时侧。

- **无登录 Depends 链的独立路径**：email-view/email-decision 不经 `get_principal`；鉴权完全内建于 token 自身（capability：HMAC 签名 + 短 TTL + 首决生效）。模块级单例 `TokenIssuer()` 与 oauth state 签名同构；签名比较用 `hmac.compare_digest`，验证顺序＝段数→签名→payload 解析→exp。
- **peek 反枚举边界**：验签后经 `TenantRegistry.peek(tenant)` 取**已装配**租户服务——`get` 会惰性创建（可被坏 token 探针用于租户存在性枚举），公开路径一律 peek，不存在返回 None 并与「坏 token / 过期 / 未知审批 / 租户不符」折叠为同一 404，不区分原因。
- **决策单实现**：公开决策与登录态 `POST /api/approvals/{token}/decision` 共用 `_apply_approval_decision`（取 pending→409 预检→卡片 map_action_output/普通 decision 校验→broker.resolve），杜绝两条路径行为漂移；409/422 语义不变。
- **审计 fail-safe**：决策成功后写 `approval.email_decision:{decision}`、actor `email-link`；审计写入自身异常不回滚已生效决策（决策与审计非原子，审计仅旁证）。GET email-view 不写审计（防预取/轮询噪声）。
- **不做**：KMS/密钥轮换、邮箱-账号绑定校验、链接吊销列表（首决语义使吊销无必要）、真实外发（D24）、多实例中断（D20）。D20 本批仅再次部分取回、不解除。

### 6.19 审计页与决策结果通知运行时（审计可见与审批结果补强批；2026-09-22 已落码，docs/37）

契约权威为 04 §5.6 补强批追加段、03 `decided_approval` 与 docs/37；本节约定运行时侧。

- **结果通知旁路 fail-safe**：`notify_decided` 在每条决策路径成功后调用（人工/邮件链接经 `_apply_approval_decision`；超时/输入预置经 loader `_await_human_approval`），调用一律 `try/except Exception` 记 warning 后吞掉——通知与决策非原子，通知成败绝不改变 200/409 响应、不阻断图；首决语义保证重复决策不二次通知。
- **轮询边界**：Approvals 10s 轮询仅在「待处理」Tab 激活且文档可见时运行；「已处理」Tab 切到时加载＋手动刷新，不轮询。
- **审计页零后端改动**：AuditLog 复用既有 events/export 端点（Bearer blob 导出），端点与审计运行时语义不变。
- **不做**：已决历史持久化/多实例（D20）、SIEM/更多过滤（D11）、结果邮件模板化/重试/IM（D24）。

### 6.20 平台渠道适配运行时（真实渠道适配批；2026-09-22 docs-only 立项，docs/38，ADR T28）

契约权威为 04 §5.18、03 `channel_binding` 与 docs/38；本节约定运行时侧。

- **调用链**：tool_call（如 `shop/create_refund`）→ ShopifyHarnessAdapter → `ChannelRegistry.client_for`（**每次调用从 connection 现解密 token**，不缓存明文；连接未完成授权 → CHANNEL_UNAUTHORIZED）→ `EgressGuard.check`（shopify URL）→ HttpChannelTransport（urllib，10s、follow_redirects=False）→ 错误码映射 → ActionResult。
- **失败边界与能力门**：token 解密/出向校验失败均在节点边界失败（适配器边界统一转 ActionResult.failed），不向图抛裸异常、不阻塞其他节点；**financial 能力门不变**——loader 对 financial 工具的审批策略原样适用。
- **SSE 与观察**：渠道工具沿用既有 tool_start/tool_end 帧，**不新增帧类型**；`observe()` 提供 `{shop, apiVersion, lastRequest?}`，不含 token。
- **不装配点**：影子、回放均不装配渠道适配器（影子运行里渠道工具不可见，不为渠道写影子逻辑）；test 端点 GET 语义的上游 `/shop.json` 为唯一手动探活出站。
- **不做**：真实店铺 OAuth 联调（D22 不解除）、Amazon/入站 webhook/订单同步、渠道侧限流退避差异化。

### 6.21 入站 Webhook 运行时（入站 Webhook 批；2026-09-23 docs-only 立项，docs/39，ADR T29）

契约权威为 04 §5.19、03 `channel_webhook` 与 docs/39；本节约定运行时侧。

- **验签先行**：公开入口 `await request.body()` 取原始 body，**HMAC 校验必须在 JSON 解析前完成**；client_secret 经绑定连接的 SecretProvider 信封现解密（每次调用、不缓存）；401 不区分缺失/不匹配，503 仅用于信封缺失/解密失败（配置错误，触发 Shopify 重试）。
- **绑定定位防枚举**：binding→tenant 不经 `TenantRegistry.peek` 惰性创建；未知绑定统一 404 文案；订阅 PUT 中 graph 不属于本租户/不存在 → 404 不泄漏细节。
- **异步投递与主体透传**：投递于独立线程（同 SSE worker 模式），principal/tenant 显式传入、不依赖上下文变量；逐订阅 `routing_store.resolve(graph_id, tenant, event)` 钉版本——None 版本 warning 跳过不造失败 run，有版本才创建运行；RunRecord 可辨 `event.channel=webhook`。调用方响应在投递前已返回，投递内任何异常只 warning（重试可能重复，幂等环兜底）。
- **幂等环**：per-tenant 进程内 ring 200，键 `X-Shopify-Webhook-Id`，惰性剔 1h 以上旧条；重复 → `{duplicate:true}` 不触发不审计。
- **审计与能力层级**：仅验签通过且非 duplicate 落一条 `channel.webhook_received:{topic}`（元数据 binding/webhook id/shop，**无 body**）；订阅变更经既有写操作审计中间件。webhook 触发的图运行内工具调用仍走各自 permission/audit/审批门——来源公开不绕过任何能力门。
- **不做**：DLQ/重试调度/速率限制/投递指标、Shopify 侧注册 API、其他平台/IM 入站、幂等环持久化、同步等待运行完成（D22/D24 不解除）。

### 6.22 事件等待运行时（waitType=event 进程内 v1；2026-09-23 落码收口，docs/47）

契约权威为 04 §5.5 事件等待 v1 追加段与 docs/47；以下运行时约定已随 f647c96→aa82eed→1608002 兑现。

- **进程内 broker 接线**：`src/atlas/collaboration/event_waits.py` 的 `EventWaitBroker`（threading.Lock，`_Pending{event_key,node_id,graph_id,deadline_monotonic,payload,signaled}` + `event_key→set[token]` 索引，token=`wait-`+uuid4）挂 per-tenant TenantServices；内存/PG 两档均为内存实例（同 cancellation_broker），reset 清空。
- **线程模型**：等待发生在 Starlette 线程池工作线程，broker.wait 以 0.2s 切片同时检查信号与 `is_cancelled`；取消 → 移除条目抛 RunCancelled；超时由 monotonic deadline 判定、不依赖定时器线程。故上限 3600 秒。
- **信号竞态首决生效**：signal_key 广播释放全部同 key 条目（无 pending 返 0、信号不留存）；signal_token 直投未知 404、已 signaled 409；信号先于 wait 到达时条目保留到 wait 取走。payload 仅限 JSON 对象（≤4096 序列化、≤50 顶层键），不进日志/trace。
- **超时两策略**：continue 沿出边透传 `signaled:false`；fail 经节点失败使 run failed（`WAIT_TIMEOUT_FAILED`），与工具节点失败同构。run inputs `waitEvents` 预置不登记 broker（resolvedBy=input，控制键不回写记录）。
- **不做**：事件等待中断帧/恢复扫描器、跨重启与多实例、动态/表达式时长与绝对时刻等待、多事件竞速、公开免登录信号口、debug 流挂起（422）——D19 部分取回不解除。

### 6.23 LLM 语义分支运行时（conditionMode=llm 进程内 v1；2026-09-23 落码收口，docs/48）

契约权威为 04 §5.2 LLM 语义分支追加段与 docs/48；运行时约定已按 docs/48 原子序兑现（7f8392d/de3bc83；HTTP 冒烟 11/11、浏览器冒烟零控制台错误）。

- **分类器三层**：`src/atlas/llm/condition_classifier.py` 镜像 decision.py——`ConditionClassifier` Protocol（`classify(*, branches, context_text, instruction) -> label`）、`LiteLLMConditionClassifier`（懒加载 litellm、temperature=0、要求只输出 `{"branch":"<label>"}`、`re.compile(r"\{.*\}", re.DOTALL)` 抽 JSON，解析失败/标签越界抛 ConditionClassifyError）、`OfflineConditionClassifier`（`LITELLM_MODEL` 未配置，必抛 ConditionClassifyError）；`get_condition_classifier()` 读环境开关。
- **上下文序列化**：`json.dumps({"global":…, "nodes":已完成产出}, ensure_ascii=False, default=str)` 截断 12000 字符；截断不构成错误，序列化异常按分类失败处理。
- **注入与 fail-safe**：分类器经 `run_graph(..., condition_classifier=None)` 注入并沿执行链/子图透传；合法标签路由，`__default__`/解析失败/未知标签/调用异常（含供应商网络配额错误）一律走 defaultTarget，**不新增错误码、不使 run 失败**，原因进 `llm_errors` 与 trace。
- **不做**：置信度/多候选/澄清重问、每分支独立 prompt 或调用、按租户模型配置、字段级脱敏、structured outputs、LLM 路由的录制回放断言——D14 部分取回不解除。
