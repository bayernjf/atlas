## 1. 决策（六条；改任何一条先改本文）

- **D-1 用户模板是租户私有资源，与内置目录并列但不混写**：
  - `GET /api/templates` 返回纯超集加字段 `source: "catalog" | "user"`（内置条目恒 "catalog"）；
    用户条目投影额外带 `deletable: true`（内置恒 false；`source` 存在即权威，deletable 仅为前端便利）；
    排序＝内置在前（保持现目录序）、用户按 created_at 倒序接后。
  - 模板 id 空间：用户模板 id ＝ `utpl-<租户内递增 seq>`（与 graph-N/rec-N 同风格），
    永不复用内置 id；内置 id 与用户 id 同名冲突不可能（前缀分离）。
- **D-2 另存为模板：`POST /api/templates`（operate 权限）**：
  - 请求体 `{name: str(1-60, trim 后非空), description?: str(0-200，缺省 ""),
    tags?: string[](每项 1-20、至多 8 项，缺省 []), graph: object}`；
  - 服务端以 `parse_graph(graph)` **校验图可编译**（不过 compile_graph、不运行；校验失败
    422，detail 中文——沿用图保存端点口径），校验后原样存入（不做规范化重写）；
  - 201 返回完整用户模板（`TemplateDetail` 同形 + source/deletable/createdAt）。
- **D-3 删除：`DELETE /api/templates/{template_id}`（operate 权限）**：
  - 仅删用户模板：用户 id 不存在（含已删）→ **404**（中文 `模板不存在：{id}`）；
    对**内置 id 调删除同样 404**（不区分"内置不能删"与"不存在"，避免成为内置 id 枚举器）；
  - 删除幂等语义按 REST：第二次删除 404（不做 204 幂等）。
- **D-4 不做更新（无 PUT/PATCH）**：改名/改图即删旧建新；模板编辑器、版本钉版随 D25 余部缓做。
- **D-5 存储两档同构**：
  - 进程内：`template/user_store.py: UserTemplateStore`（单锁；租户内 seq 计数；
    list/add/get/delete/clear）；经 `TenantServices` 每租户一个，`reset_tenant` 随图等清空
    （与"用户运行时数据"同口径）。
  - PG：migration **034** 建 `user_templates` 表：
    `tenant_id TEXT NOT NULL, id TEXT NOT NULL, seq BIGINT NOT NULL,
     name TEXT NOT NULL, description TEXT NOT NULL DEFAULT '', tags JSONB NOT NULL DEFAULT '[]',
     graph JSONB NOT NULL, created_at TEXT NOT NULL,
     PRIMARY KEY (tenant_id, id)`，唯一索引 `(tenant_id, seq)`；
    `PgUserTemplateStore` 方法面与内存档逐字一致；插表 seq 取
    `COALESCE(MAX(seq),0)+1`（同租户行锁内，照 PgGraphStore 计数先例）；
    时间列 TEXT ISO（runs/recordings 同款）。
  - 装配：`TenantServices.user_templates`；registry pg 分支换 Pg 版。API 层只依赖 Protocol。
- **D-6 零新依赖／无新 ADR**：选型（每租户私有、不进市场）与 04 §5.10 模板库愿景一致，
  市场/共享/分类仍随 D25 余部及 D3 缓做。

## 2. 形状

- `template/user_store.py`（新）：`UserTemplate` pydantic（id/name/description/tags/graph/created_at）、
  `UserTemplateStore`（内存）、Protocol 同形。
- `storage/pg.py`：`PgUserTemplateStore`（或新文件 `template/pg_store.py`；落码时按 09 模块映射定，
  两档同构优先）。
- `iam/registry.py`：TenantServices 加 `user_templates`；两档装配；reset_tenant.clear。
- `api/main.py`：GET 列表合并＋source/deletable；POST /api/templates；DELETE
  /api/templates/{id}（内置 id 走"get_template 命中即 404"统一口径）。
- 前端：`apiClient.ts`（source/deletable/createdAt 类型、createUserTemplate、deleteUserTemplate）；
  `Editor.tsx` 模板浏览器（来源 Tag、用户项删除 Popconfirm）＋工具栏「保存为模板」小 Modal
  （名称必填/描述/tags 不暴露控件——v1 仅名称＋描述，tags 服务端收空）；i18n 两档。

## 4. 测试候选（U974 起；落码时定号）

- **U974（纯逻辑，template store）**：内存 store add 赋递增 id/created_at、get/list 顺序、
  delete 后 get None、clear；PG 档同形用例归 integration（建表 034、跨连接可见、seq 并发/跨重启）。
- **U975–U979（API）**：
  - U975 POST 另存：201、id=utpl-1、再存 seq=2；坏图 422、name 空/超长 422、description 超长 422；
  - U976 GET 合并：内置条目 source=catalog/deletable=false，用户条目 source=user/deletable=true、
    用户按时间倒序；
  - U977 DELETE：删用户 200/204（落码定，正文以 200＋{ok:true} 或 204，取与仓内既有 DELETE 一致）、
    再删 404、删内置 id 404；
  - U978 分区：B 租户看不到/删不到 A 的模板（直接 GET 合并无 A 项；DELETE A 的 id → 404），
    两租户 seq 各自从 1；
  - U979 权限：viewer POST/DELETE → 403，viewer GET 可见；reset 清空用户模板（与运行时数据同口径）。
- **前端 vitest**：apiClient 类型不做网络单测（既有模式）；Editor 模板 Modal 的来源 Tag/删除按钮
  与保存为模板表单校验由组件逻辑轻量覆盖（若 Editor 无测试先例，改抽纯函数
  `mergeTemplates(catalog, user)` 单测）；i18n PARITY 由既有守护覆盖新键。
