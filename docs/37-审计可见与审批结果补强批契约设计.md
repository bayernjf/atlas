## 2. 包 A：审计日志页（前端-only，契约不变）

后端端点已在 docs/35 T6 落码，本批不改动：

- `GET /api/audit/events?limit=&action=`（administer；倒序；limit clamp 1–500；action 为动作前缀，如 `POST /api/graphs`）
- `GET /api/audit/export?format=jsonl&action=`（administer；jsonl 附件下载，正序）

前端：

- 新页 `pages/AuditLog.tsx`：admin only；入口在 Dashboard 与主导航，仅 admin 角色渲染（viewer/operator 不显示入口；直接访问 API 仍 403）。
- Table 列：at（UTC 时间，原样显示不做时区转换）、actor、action（等宽字体）、statusCode（2xx 绿/4xx 橙/5xx 红 Tag）、path、ip。
- 过滤：action 前缀输入框（回车/按钮触发，空值恢复全量）；limit Select（50/100/200，默认 100）；首屏加载、显式刷新按钮，不做轮询。
- 导出：「导出 JSONL」按钮，带当前 action 过滤条件，经浏览器直接下载（用带 Authorization 头的请求取 blob 后触发下载，不用裸 `<a href>`——导出端点需要登录态）。
- 空态：「当前没有审计事件」；错误沿用全局 Alert 中文 detail。
- 新增 i18n namespace `audit`（zh-CN 填实、en-US 空 `{}`，照 17 文档既有口径）。

## 3. 包 B：已决审批历史

### 3.1 数据语义

现状：`ApprovalBroker.resolve` / `complete_timeout` 只在 `_Pending` 上写决策、**不移除条目**，已决数据已在 broker 内（进程内、reset 清空、重启即失）。本批只加只读投影，不改挂起/决策语义。

- `ApprovalBroker` 新增 `list_decided(limit=50)`：在锁内收集 `decision is not None` 的条目，按决策完成顺序倒序（最近处理在前），clamp 1–200。
- 已决条目的公开字段：`token, node_id, graph_id, summary, approver, createdAt, decision, resolvedBy, comment`；有 cardTemplateId 时附带。**不返回** card_context 快照、Event 等内部对象。
- `ApprovalRepository` Protocol（storage/base.py）同步补 `list_decided` 签名；内存 broker 为唯一实现（PG 档审批持久化仍随 D20，PG 整栈档目前同样装配进程内 broker，无需新增 SQL/迁移）。

### 3.2 REST

`GET /api/approvals/decided?limit=50`（read，全部登录角色可用；本租户分区）：

```json
{ "items": [ { "token": "...", "nodeId": "...", "graphId": "...", "summary": "...",
  "approver": "...", "createdAt": 1760000000.0, "decision": "approved",
  "resolvedBy": "human", "comment": "..." } ], "limit": 50 }
```

字段命名与现有 approval 投影一致（snake_case `node_id/graph_id`，与 `GET /api/approvals` 同形，不新造 camelCase）。limit clamp 50（端点层 1–200）。无新错误码。

### 3.3 前端

- `pages/Approvals.tsx` 改为 Tabs：**待处理**（现有队列，10s 轮询仅在该 Tab 激活且页面可见时运行）＋**已处理**（切到该 Tab 时加载，支持手动刷新，不轮询）。
- 已处理表列：createdAt、summary、node_id、graph_id、decision（同意绿/拒绝红 Tag）、resolvedBy（人工处理/超时/输入预置，中文映射）、comment（Tooltip 或展开）。
- viewer 保持只读（已处理 Tab 天然无操作列）；空态：「当前没有已处理的审批」。
- EmailApproval 深链页不接入历史（免登录路径仅看单 token）。

## 4. 包 C：决策结果邮件

### 4.1 收件人留存

- `_Pending` 新增字段 `notify_recipients: list[str]`（默认空）；`ApprovalBroker.request` 新增可选参数 `notify_recipients`，存入去重保序后的列表；`restore` 同形（恢复帧无收件人来源时为空，保持默认）。
- `graph/loader._register_approval`：把已解析的 recipients（`_resolve_notify_recipients` 结果，现有 fail-safe 逻辑不变）传入 `broker.request`。仅挂起通知实际发送成功或尝试过并不重要——收件人列表照解析结果留存即可；列表为空时结果邮件自然不发。

### 4.2 Notifier 扩展

`collaboration/notifications.py`：

- `ApprovalNotifier` Protocol 增加：
  `notify_decided(*, graph_id, node_id, summary, decision, resolved_by, comment, recipients) -> None`
- `EmailApprovalNotifier.notify_decided`：复用 MessageService 发 email，
  subject `[Atlas] 审批已处理：{title}`；正文含审批节点/图、结果（同意/拒绝）、处理来源、comment（非空时，截断 ≤200 字符防注入到正文的异常长文本）、应用入口。**不含**任何 token/决策链接（已决链接无用途，且不再签发新 token）。

### 4.3 触发点（全部旁路 fail-safe）

- **人工/邮件链接决策**：`api/main._apply_approval_decision` 增加可选参数 `notifier`（默认 None）；`broker.resolve` 成功后，从 broker 取 `notify_recipients`，非空则 `try: notifier.notify_decided(...) except Exception: logger.warning(...)`——通知成败绝不改变 200/409 响应与决策事实。两个认证决策端点（登录态、公开 email-decision）把当前租户 notifier（若已装配）传入 helper。
- **超时决策**：`graph/loader._await_human_approval` 在 `complete_timeout` 后，照挂起通知同样的 fail-safe 方式调 `notifier.notify_decided(resolved_by="timeout")`（notifier 已在 `_register_approval` 作用域可用；需要把 notifier 透传进 `_await_human_approval`）。
- **输入预置决策**（`resolved_by="input"`，回放/预置路径）：同样在 loader 内触发结果通知，保持「凡决策必有回执」；影子运行/回放不装配真实 notifier 时自然不发。

决策结果邮件不写额外审计事件（决策本身已有 `approval.decision` / `approval.email_decision` 审计）。

## 5. 非目标（仍缓做）

- 已决审批 PG 持久化/跨重启历史、多实例（D20）；本批历史进程内、reset/重启即失。
- 申请人邮箱字段与「通知申请人」（无该结构；结果邮件发给 `notifyEmails` 配置的收件人）。
- 审计页 SIEM 对接、按 actor/时间范围/状态码过滤、分页（v1 仅 action 前缀 + limit）、OTel（D11）。
- 结果邮件模板化/HTML、IM/钉钉结果通知、失败重试（D24）、真实 SMTP 联调。

## 6. 测试矩阵（落码编号在 docs/13 定稿）

- broker `list_decided`：空、仅 pending 不入、决策后倒序、limit clamp、字段不泄露 card_context。
- `GET /api/approvals/decided`：三角色可读、跨租户隔离、limit、401。
- notifier `notify_decided`：收件人/正文断言、comment 截断、无 token；通知抛异常时决策端点仍 200、超时路径不阻断。
- request 留存 recipients（含 loader 接线）；预置/超时/人工三来源均触发一次结果通知，重复决策不二次通知。
- 前端：AuditLog 表格/过滤/导出 blob、admin 入口门控；Approvals 已处理 Tab 数据/空态/轮询不越 Tab。
- 门禁增量：后端 1174 → 约 1200+；前端 571 → 约 600+（以实际落码为准）。
