## 2. T2 · 审批挂起邮件通知（D20 邮件子集）

### 2.1 DSL 契约

`human_approval.config` 新增**可选**字段：

| 字段 | 类型 | 语义 |
|---|---|---|
| `notifyEmails` | `string[]`，可选，缺省 `[]` | 审批挂起时的通知邮箱；每项支持 `{{路径}}` 插值（与 summary/approver 同一插值器）；插值后为空的项剔除；上限 **5** 个；每项插值后必须含 `@`，否则编译期 422 |

- 旧图无此字段 → 行为完全不变（不发通知）。
- 校验位置：`graph/dsl.py` `_validate_human_approval_config`，错误码复用 `APPROVAL_CONFIG_INVALID`（或现有 human_approval 配置错误码，落码对齐），pointer 落 `/notifyEmails`。
- 编译期逐字面值校验静态非法（无 @、超 5 个、非数组）；插值后运行时再过滤空值，插值结果无 @ 的项运行时丢弃并记日志（不阻断流程）。

### 2.2 运行时契约

- 新模块 `collaboration/notifications.py`：
  - `Protocol ApprovalNotifier`：单方法 `notify_pending(*, graph_id, node_id, token, summary, approver, timeout_seconds, recipients: list[str], public_url: str) -> None`。
  - `EmailApprovalNotifier(message_service, public_url)`：调 `message_service.send(channel="email", to=recipients, subject=..., body=...)`；纯文本 body，含 summary、approver、超时时长、应用入口 URL；**不内置一键决策链接**（邮件 GET 决策落地页属 D33 余部，缓做），邮件只通知「有审批待处理 + 入口链接」。
- 触发点：`graph/loader.py` `_register_approval` 在 `broker.request(...)` 成功后调用 notifier（若注入且收件人非空）。
- **fail-safe 铁律**：通知是旁路能力，任何异常（含 SMTP_SEND_FAILED）必须被捕获，**绝不阻断图执行、不改变审批语义**；节点输出在现有 approval 载荷基础上增加：
  - `notified: bool`（是否成功投递/记录）
  - `notifyError?: str`（失败原因，仅失败时出现；不进 trace 错误）
- 装配：`run_graph(..., approval_notifier: ApprovalNotifier | None = None)` 透传（照 approval_broker 参数模式，默认 None）；`api/main.py` 装配 `EmailApprovalNotifier(services.message_service, public_url=ATLAS_PUBLIC_URL)`，`ATLAS_PUBLIC_URL` 缺省 `http://localhost:5174`。
- demo/内存档：未配 SMTP 时 MessageService 回退进程内记录（delivered=in_process），通知仍可在 `GET /api/demo/messages` 看到，沙盘演示不回归。
- 决策结果邮件（approved/rejected 通知申请人）**本批不做**（无申请人邮箱字段）。

### 2.3 前端

`human_approval.schema.ts` 增加 `notifyEmails`（数组、邮箱、可空），uiSchema 用现有数组类控件（落码时对齐 widgets 注册表；无合适控件则用逗号/换行分隔 textarea + 前端拆分校验，保持提交值为 string[]）；i18n 文案走 editor namespace（zh-CN 填实，en-US `{}`）。

## 3. T3 · webhook 消息渠道（D24 子集）

### 3.1 MessageService 契约扩展

`message/send` 的 `channel="webhook"`：

- `to`：**单个** http/https URL 字符串（数组一律 422 `INVALID_PARAMETER`；webhook 不支持群发）。
- 行为：同步 `POST {url}`，`Content-Type: application/json`，body 为 JSON：
  ```json
  {"id": "<消息 uuid>", "channel": "webhook", "subject": "...", "body": "...", "sent_at": "<UTC iso>"}
  ```
- 出向前**必须**过 `security/egress` 的 `EgressGuard.check(url)`（私网/链路本地/云元数据 169.254.169.254/非严格主机字面量恒拦；`ATLAS_HTTP_EGRESS_ALLOWLIST` 配置时 fail-closed）。
- httpx 同步请求，超时 **10s**；2xx 记 `delivered="webhook"`；其余情况：
  - `EgressDenied` → 透传其 code（`EGRESS_DENIED` / `EGRESS_INVALID_URL`）；
  - 非 2xx、传输异常、超时 → 新错误码 **WEBHOOK_SEND_FAILED**；
  - 失败**不写消息记录**（照 SMTP 先例，非幂等写能力失败须显式）。
- 接缝：`MessageService(email_sender=None, webhook_sender=None)`；`Protocol WebhookSender.send(url: str, payload: dict) -> None`；`DefaultWebhookSender(guard: EgressGuard | None = None, post: Callable | None = None)`（post 可注入，测试不触网）；registry 内存/PG 两档均注入默认 sender（guard 走 `EgressGuard.from_env()`）。
- adapter input schema 的 channel 描述更新为 `email/webhook/sms/im 或任意非空渠道标识（sms/im v1 不路由）`。

## 4. T4 · OAuth2 连接管理 v1（D22 子集，P0 #1）

### 4.1 定位与边界

做**平台无关的 generic OAuth2 授权码流程连接管理框架**：连接配置 CRUD、授权 URL 构造、state CSRF 防护、授权码换 token、refresh token 刷新、连接测试、凭据 AES-GCM 信封加密落库、租户隔离、管理 UI。

**不写死任何真实平台**（Shopify/Amazon 等）的端点、scope、业务 API 调用；`provider` 为自由字符串标签。真实平台 API 调用与联调留实施口（见 §8 非目标）。本批交付后，「接一个标准 OAuth2 平台」从不可能变为按配置 + 少量平台适配代码即可完成。

### 4.2 数据模型（Connection）

新包 `src/atlas/connections/`。Connection 字段：

| 字段 | 说明 |
|---|---|
| `id` | `conn-N`（租户内顺序 id，照各 store 先例） |
| `tenant_id` | 租户隔离 |
| `provider` | 自由字符串标签（如 generic/shopify），非空 |
| `display_name` | 展示名，非空 |
| `auth_url` | 授权端点 https URL（创建时过 egress 校验） |
| `token_url` | token 端点 https URL（创建时过 egress 校验） |
| `client_id` | 非空明文（公开标识，不视为秘密） |
| `client_secret_envelope` | `SecretProvider.encrypt()` 信封，**绝不以任何形式回传前端** |
| `scopes` | `string[]`，可空 |
| `redirect_uri` | 可空；空则用服务端 `ATLAS_OAUTH_REDIRECT_URI`，再缺省 `http://localhost:8000/connections/callback` |
| `status` | `draft` / `connected` / `error` |
| `access_token_envelope` / `refresh_token_envelope` | 加密信封，可空（draft 时） |
| `token_type` | 通常 `Bearer`，可空 |
| `expires_at` | UTC iso 可空（无 expires_in 时视为不过期） |
| `last_error` | 最近一次换 token/刷新错误，可空 |
| `created_by` / `created_at` / `updated_at` | 审计字段 |

对外投影 `public_view()`：删除全部 envelope 与明文凭据，改出 `hasClientSecret: bool`、`status`、`expiresAt`、`scopes` 等；**列表与详情端点永远不返回 secret/token 明文或信封**。

### 4.3 OAuth 纯逻辑（connections/oauth.py，全部可注入 http post，不触网）

- **state（CSRF）**：`build_state(tenant_id, conn_id, *, secret, ttl_seconds=600)` → `base64url(json{tenant,conn,nonce,iat,exp}).hmac256`；`verify_state(token, *, secret, expected_tenant, expected_conn)` 校验签名/过期/租户/连接四要素，失败抛 `OAuthStateError`（state 签名密钥读 `ATLAS_MASTER_KEY`，缺失时用固定 dev 密钥并在启动日志 warning——state 仅防 CSRF 非凭据，凭据加密另走 SecretProvider）。
- `build_authorize_url(conn, state) -> str`：`{auth_url}?response_type=code&client_id={urlenc}&redirect_uri={urlenc}&scope={空格join urlenc}&state={urlenc}`。
- `exchange_code(conn, code, *, post_form) -> TokenBundle`：POST token_url，form：`grant_type=authorization_code&code&redirect_uri&client_id&client_secret`；解析 JSON `access_token`（必填）/`refresh_token`/`expires_in`（秒）/`token_type`；HTTP 非 2xx 或缺 access_token → `OAuthTokenError`。
- `refresh_tokens(conn, *, post_form) -> TokenBundle`：`grant_type=refresh_token&refresh_token&client_id&client_secret`。
- TokenBundle 落库：access/refresh（若有）经 SecretProvider 加密；`expires_at = now + expires_in`（无 expires_in 则 null）。
- 过期判定：`is_expired(now)` 留 60s 提前量；`test_connection` 对已过期连接先尝试刷新。

### 4.4 服务与存储

- `connections/service.py` `ConnectionService(store, secret_provider, *, post_form=None, state_secret=None, egress=None)`：create/update/authorize/exchange/refresh/test/delete/list/get；update 时 `client_secret` 缺省（未传/空串）保留原信封；authorize/exchange 校验 state 与连接归属；任何 token 异常把连接置 `status=error` + `last_error` 并折算中文 HTTPException。
- 存储两档：
  - 内存：`connections/store.py` `ConnectionStore`（per-tenant 实例，照 GraphStore 先例）。
  - PG：`PgConnectionStore` + **迁移 014 `014_oauth_connections.sql`**（表 `oauth_connections`，tenant_id+conn_id 复合主键，envelope 列 TEXT、scopes TEXT JSON、时间 TEXT，照 010 风格手写幂等 SQL）。
  - 进 `storage/base.py` Repository 协议与 `TenantServices.connection_store`，registry 两档装配（SecretProvider 用 `build_secret_provider_from_env()` 进程级单例）。

### 4.5 REST API（全部 /api 前缀，Bearer 鉴权）

| 方法/路径 | 权限 | 语义 |
|---|---|---|
| POST `/api/connections` | administer | 创建连接配置（201）；URL 过 egress；client_secret 立即加密 |
| GET `/api/connections` | read | 当前租户列表（public_view） |
| GET `/api/connections/{id}` | read | 详情（public_view），他租户/不存在 404 |
| PUT `/api/connections/{id}` | administer | 更新白名单字段；client_secret 缺省保留 |
| DELETE `/api/connections/{id}` | administer | 删除，幂等返 `{deleted:true}`，不存在 404 |
| POST `/api/connections/{id}/authorize` | operate | 返 `{authorizeUrl, state, expiresIn:600}`（前端 window.open） |
| POST `/api/connections/{id}/exchange` | operate | body `{code, state}`；验 state→换 token→加密落库→public_view |
| POST `/api/connections/{id}/refresh` | operate | 手动刷新 |
| POST `/api/connections/{id}/test` | operate | 返 `{ok, status, expiresAt}`；过期先刷新；draft/error 返 ok=false 中文原因 |
| GET `/connections/callback` | **无鉴权静态 HTML** | OAuth provider 回调落地页：JS 读 query 的 code/state 展示 + 复制按钮 + 引导粘贴到连接管理「完成授权」；**不产生任何服务端副作用、不发 token** |

### 4.6 前端

- `lib/connections.ts`：上述端点 client（照 memory.ts/monitoring.ts 模式）。
- `pages/Connections.tsx`：Table（display_name/provider/状态 Tag/过期时间/创建时间）+ 新建/编辑 Modal（provider、displayName、authUrl、tokenUrl、clientId、clientSecret、scopes（空格分隔）、redirectUri）+ 操作：授权（新窗口）、完成授权（粘贴 code 的小弹窗→exchange）、刷新、测试（message 反馈）、删除（Popconfirm）。
- Dashboard 加「连接管理」入口（operator 及以上可见；admin 可建删，operator 可授权/测试）；App.tsx Page 联合类型加 `connections`。
- 新文案走新 namespace `connections`（zh-CN 填实、en-US `{}`），纳入 i18n.test.ts 校验；遵守 set-state-in-effect 规避模式（loading 初值 true、cancelled cleanup、Modal afterClose reset）。

## 6. T6 · 审计日志与导出（docs/34 P1 #8）

### 6.1 模型与存储

- 新模块 `observability/audit.py`：
  - `AuditEvent`：`id`（`aud-N`，租户内顺序）、`tenant_id`、`actor`（username，未认证为 `anonymous`）、`action`（`METHOD 路由模板`，如 `POST /api/graphs/{graph_id}/publish`）、`status_code`、`path`（实际路径）、`ip`（`request.client.host`，可空）、`at`（UTC iso）。
  - `AuditStore`（进程内 ring，每租户上限 `ATLAS_AUDIT_RING` 缺省 2000）+ `PgAuditStore`（**迁移 013 `013_audit_events.sql`**，表 `audit_events`）；方法 `record / list(limit, action_prefix) / export_jsonl() / clear`。
  - 进 `TenantServices.audit_store`，registry 两档装配。
- **只记元数据，绝不记请求体、Authorization、密码、token、信封**；查询路径原样保留（审计面向 administer）。
- `POST /api/demo/reset` **不清审计**（审计是安全记录，reset 语义除外，文档注明）。

### 6.2 采集与端点

- `iam/deps.get_principal` 解析后把 principal 挂 `request.state.principal`。
- `api/main.py` 加 HTTP middleware：仅对 path 以 `/api/` 开头、方法 ∈ {POST, PUT, PATCH, DELETE} 的请求，在响应完成后记录（路由模板取 `request.scope["route"].path_format`，取不到降级实际 path）；中间件自身异常只 warning，绝不影响业务响应。
- 成功登录显式记一条（login 端点内，actor=username、action=`POST /api/auth/login`、status 200）；失败登录不进审计（由登录节流/日志覆盖，且无租户归属）。
- 端点：
  - `GET /api/audit/events?limit=100&action=`（**administer**，当前租户，倒序；limit 上限 500；action 前缀过滤）。
  - `GET /api/audit/export?format=jsonl`（**administer**，StreamingResponse，`attachment; filename=atlas-audit-<tenant>-<ts>.jsonl`）。
- v1 **不做前端审计浏览页**（curl/运维消费），docs/14 注明。

## 8. 安全边界与非目标

- 凭据/令牌一律 AES-GCM 信封（demo 无 master key 时 plain 信封并 warning，与 docs/32 现状一致）；任何 API 响应不回传秘密；gitleaks 保持绿。
- webhook、OAuth auth/token URL 全部过 SSRF egress；OAuth 回调页无副作用；state HMAC 防 CSRF。
- 通知/审计/指标/看板均为旁路或只读，失败不阻断主流程（审计中间件、notifier fail-safe）。
