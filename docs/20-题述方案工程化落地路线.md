- **冲突三层**：L1 幂等键（`资源|动作|版本`）+ L2 乐观锁 CAS（先在 demo shop 订单状态加 version 字段的进程内模拟，shop service 已是单例状态机，改造面可控）+ L3 硬约束 condition + 升级 human_approval（不做 Agent 投票）。
- **前置门**：M5（挂起/恢复）；D31 触发条件字面是「第二个真实 Bot 角色」——沙盘假 Bot 视为**语义验证期**，立项记录注明不解除 D31（真实 Bot 接入仍需触发）。
- **不做**：跨服务投递/NATS（D5）、自由 Agent mesh、Bot 间对话、任务级 SLA 看板。
- **契约门**：05（技能/协同协议愿景段加注 v1 以新契约为准）、03 新增 task_envelope 索引、06 新增协同运行时小节、12 内部接口+REST（任务查询/人工升级）、13 新增 U/I 编号。
- **验收**：退货退款沙盘链路（客服 Bot + 物流 Bot，dispatch→join→未签收禁放款 condition→escalate）端到端跑通；幂等重放返首结果、CAS 冲突一方放弃、超时升级 fail-safe 的单测与浏览器实测。

### 4.3 M8：交互模板系统（D33；题一内核的第六类实体）

- **对应题面**：B4 全条（审批卡片、sections.bindings 变量绑定、web/IM/邮件渠道渲染降级、actions 结构化回写）；同时以「第六类实体」复验题一 A1–A6 内核通用性（卡片 bindings 的 `{{}}` 走同一 ScopeIndex/L2）；对应 19 §2.2.3/§2.3.2。

- **目标**：19 §2.2.3/§2.3.2——卡片双向 Schema（sections.bindings 展示 + actions.output 结构化回写）、三渠道渲染降级（web 完整/IM 文本+两按钮/邮件只读+token 链接）。
- **仓内改动面**：新包 `src/atlas/cards/`（卡片模板目录，先内置只读同 template 包模式）；human_approval 产出增可选 `cardTemplateId`，旧 summary 字符串路径保留（v1 审批不回归）；Web 端审批 Modal 升级为卡片渲染器（FormRenderer M3 首次消费**节点/工具之外的第三类 schema 来源**——这一步验证 SchemaRegistry 多来源设计）；bindings 中的 `{{}}` 直接走 M0/L2 同一 ScopeIndex（卡片成为图的附属实体，可见集 = 该审批节点的 visibleAt）；actions 回调经现有 `/api/approvals/{token}/decision`，output 映射进审批产出；IM/邮件渠道 v1 只做**渲染降级产物 + message/send 进程内投递**（不接真实渠道，D24 不解除）。
- **前置**：M3（FormRenderer）、M7 不强制（卡片先服务现有 human_approval；escalate 场景在 M7 后自然复用）。
- **不做**：卡片 CRUD 市场、真实 IM/邮件外发、网页嵌入 SDK、表单回写任意节点（只回写审批决策）。
- **契约门**：05 交互模板愿景段、03 interaction_template 从愿景示例转工程契约、04 §5.6 追加 cardTemplateId、12 渲染/回调端点、13 用例。
- **验收**：退款审批卡片三渠道渲染快照（web DOM/IM 文本/邮件 HTML 进程内断言）；bindings L2 坏引用在编辑期被同一诊断流拦截；按钮回调结构化回写且首决 409 不回归。

### 4.4 M9：Router + 灰度发布 + 门控回滚（D32 后半）

- **对应题面**：B5 全条（Webhook/IM/网页嵌入三类 ingress 归一化、租户/业务桶/百分比灰度、自动回滚、在途 pin-to-version）、B6 的大半（业务指标、告警驱动动作、发布前批量回放门禁），并闭合 B1 步骤 6「人确认后发布为新版本」；对应 19 §2.2.4/§2.3.3/§2.5——题二交付物「灰度与回滚机制」在本期闭合。

- **仓内改动面**：① 入站归一化——TriggerEvent{channel,tenant,payload} 入口 + Router（新包 `routing/` 或 api 层模块）：租户 allowlist→业务桶（金额条件）→订单 id 哈希稳定百分比分桶；运行时从「graphId 解析 latest」改为「graphId@解析版本」，在途实例 pin-to-version（运行记录钉版本，M5 恢复后读老版本）。② 发布流端点：发布→批量回放门禁（D26 取回：recording v1 的用例集对候选版本批量回放，跨版本 diff）→灰度规则→观察窗。③ 门控：monitoring 扩**业务指标**（19 §2.5 退款金额差异率/自动退款率/升级率，与系统指标分列），规则越阈→Router 切 vN-1 + 告警（复用 alerts 通道，新增「告警动作」概念，现状告警只展示不驱动）。
- **强约束（19 §2.5.5）**：回滚不改外部已发生事实，gate 必须含业务结果指标，金融场景按业务桶而非纯百分比灰度——这是契约级硬条款，写进 04/06。
- **前置**：M5 + M6；批量回放依赖 D26 取回（随本期同批）；CD（D10b）/多实例/NATS **不是**前置——Router 进程内路由表即可沙盘验证（与 iam 进程内分区同策略）。
- **不做**：真实多实例流量分发、配置热推送 UI、自动放量（只做自动回滚，放量保持手动）。
- **契约门**：03 release/rollout/route 新索引、04 新增发布与灰度契约小节、06 Router 运行时、12 REST 一组、13 门控回滚测试（构造越阈指标→断言切流+在途钉版跑完老版本）。
- **验收**：沙盘演练——v6/v7 两版本，5% 分桶稳定（同订单不跳版本），注入失败率越阈自动回 v6、在途实例跑完 v7、批量回放门禁拦下坏版本。

### 4.5 M10：span 级追踪（D34）

- **对应题面**：B6 的链路追踪（traceId/spanId/parentSpanId 贯穿 run→Bot 任务→工具，graphVersion 标注）；指标/告警/回放三项已分别由 monitoring v1 与 M9 承接，本期补齐追踪形成 B6 闭环；对应 19 §2.3.4 与 §2.5 可观测小结。

- **范围**：traceId/spanId/parentSpanId 贯穿（run→节点→parallel/subgraph 内部→M7 任务信封→工具调用），graphVersion 标注（M6 后自然可得）；SSE 帧升级为 19 §2.3.4 超集（保留现有帧，加 span 字段）；monitoring RunRecord 挂 traceId。进程内传播即可（contextvars），跨服务传播随 D5。
- **前置**：M7（任务 span 才有意义）；OTel 合流仍缓做（D11），本期只定**与 OTel 同形的最小 span 模型**，不引 SDK（新依赖需 ADR）。
- **验收**：退货协同链路导出一棵完整 span 树的单测断言；parallel/subgraph 内部 span 可选不外泄开关；录制回放不比对 span 时间字段（归一化规则补一条）。

## 7. 风险与关键决策点

1. **AJV 之争（M2/T16）——✅ 2026-09-16 已收口为手写子集**：M1 实测九节点仅 1 处 oneOf、零 if-then/动态 dependencies，手写解释器（154 行）已由 102 个双跑用例证明零分歧，过早引 AJV 无收益；手写子集「长成半个 AJV」的残余风险以 M3 显式重开判据对冲（白名单外第二类结构扩张或候选分支语义失效时，携实测案例重开 T16）。
2. **Graph 容器版本 vs 发布版本（M6）**：EdgeDSL/Graph `version:1` 已被全栈（serializer/dsl/前端）硬编码，升容器版本代价大；releaseVersion 走 payload 新字段隔离，容器版本只在 Schema 真的破坏性变更时才动 2。
3. **M5 是最长关键路径**：存储抽象 + 中断恢复同时牵动 8 个进程内包与 SSE 语义；M5a/M5b 必须分拆，M5a 先独立交付价值（可测的 Repository 边界）。
4. **沙盘不替代触发条件**：M7 假物流 Bot、M8 进程内卡片、M9 进程内 Router 都只验证语义；14 文档 D31/D33/D32 不因此标「已落」，须在每期 08 记录里显式写明「沙盘中，触发条件未解除」。
5. **金融灰度硬条款**：业务桶 + 业务结果门控指标不可在后续期以「简化」名义拿掉（19 §2.5.5）。
6. **非目标重申**：全路线不引入 NATS/Go 网关/OTel SDK/真实 IM 渠道/多实例部署，除非对应缓做条目（D5/D6/D11/D24/D10b）被独立触发；技能/记忆/部署三类实体的表单化仍挂 D29 原触发条件，本路线不替它们立项。
