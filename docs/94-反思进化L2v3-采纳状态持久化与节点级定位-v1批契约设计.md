## 1. 范围与非目标

**范围内（v1）**

1. **反思候选/报告 PG 化**：新模块 `reflection/pg_store.py PgReflectionStore`（与 `ReflectionStore` 方法一比一），迁移 **041** 两表；PG 档装配替换、内存档行为不变。这是采纳状态跨重启可见的前提（docs/88 D-6「PG 化随真实需求」，本批即触发）。
2. **候选级采纳状态**：每候选一个处理标记 `decision_status ∈ "adopted" | "dismissed" | null(pending)`＋`decided_at`；写端点 `PUT /api/reflection/candidates/{id}/decision`（`operate`）；候选详情与报告列表均带该状态。
3. **节点级定位**：`Change` 增可选 `node_id`；候选生成侧确定性补全（见 E-3）；前端 node_config 且 node_id 存在时跳转编辑器并选中居中该 ai_decision 节点。
4. **前端采纳操作**：候选面板加「标记已采纳 / 忽略」按钮与状态徽标；修复 §0.7 的 actions 列缺陷（「去修改」按钮真正渲染，node_config 行携带节点定位）。
5. i18n `reflection.json` 两档补键；vitest（U1121–U1124）；后端测试 U1115–U1120。

**非目标（明写，避免静默扩张）**

- **change 级逐条采纳状态**：v1 状态挂在候选上（一份候选一个处理标记）；逐条 change 各自标记登记缓做（触发＝真实运营出现「采纳一条、忽略另一条」的常态诉求）。
- **任何自动 apply / publish / promote**：决策标记**只是人的处理记录**，不改图、不发布、不碰路由唯一放量路径（守 docs/88 D-5 与 T22 不变量）；真正采纳仍由人经「去修改」跳转后的既有写端点完成。
- **决策的长期归档/审计报表**：PG 档候选/报告仍惰性裁到最近 100 行（照 pg_shadow 先例），不做长期保留、不做采纳率统计页。
- **摘要器 prompt 改造**：v1 不要求 LLM 回 node_id（不改 system prompt、不影响录制对拍）；解析侧**预留**接受可选 node_id 并做存在性校验，定位以代码侧确定性补全为准。
- **其余三条白名单 key 的定位增强**：只有 `node.confidenceThreshold` 有节点语义；graph_variable/monitor_rule/gate_config 的更精确定位（如定位到具体规则行）不在本批。
- **L1 平台级进化／L3 策略离线训练**：D2/D3/D4/D25 门控全部不变、不解除。

## 2. 决策（E-1…E-7；工程侧推荐，改任何一条先改本文）

- **E-1 决策粒度＝候选级，三态**：`pending`（缺省，序列化为 `decision_status=null`）／`adopted`（已采纳）／`dismissed`（已忽略）。重复 PUT **允许覆盖**（人会改主意：dismissed→adopted），每次覆盖刷新 `decided_at` 并各记一条审计；不做审批式首决 409（反思决策无并发裁决语义，与 human_approval 不同）。

- **E-2 PG 化范围＝reports＋candidates 两 ring 整体**，而非只落决策表。理由：决策状态必须附着在跨重启仍可读的候选上才有意义；若只落决策而候选 ring 进程内清空，重启后 `refl-N` 计数器归零还会复用旧 id 撞上旧决策行。两 ring 一起 PG 化后，PG 档 id 走 `storage_id_seq` 单调不复用，自洽。内存档（demo/测试默认）行为与现状逐字一致（进程内 ring、reset 清空）。

- **E-3 节点定位＝代码侧确定性补全为主，LLM node_id 仅校验接受**。候选落库前对 `param_key == "node.confidenceThreshold"` 的 change 执行 `resolve_node_ids(changes, graph_snapshot)`：
  1. change 已带 node_id（LLM 回包经 `_parse_payload` 透传的非空字符串）⇒ 校验该 id 在快照节点中**存在且 `type=="ai_decision"`**，通过则保留，否则置 None；
  2. 仍为 None 时，扫描快照全部 `ai_decision` 节点：**恰好 1 个** ⇒ 自动填入该节点 id；**0 个或 ≥2 个** ⇒ 保持 None（照实不猜，多节点时无法确定建议针对谁）；
  3. 快照取不到（未发布/版本缺失/异常）⇒ 全部保持 None，**不因此中断 pass**（定位是增强不是主链路，异常只 warning）。
  其余三条 key 的 change node_id 恒为 None。

- **E-4 写端点形状**：`PUT /api/reflection/candidates/{candidate_id}/decision`，请求体 `{"status": "adopted" | "dismissed"}`（pydantic `Literal`，非法值 FastAPI 自动 422）；权限 `require("operate")`（read 角色 403）；候选不存在/跨租户 404；成功返回更新后的候选详情投影（同 GET 候选）；记审计 `reflection.decide`（path 含 candidate_id 与 status）。

- **E-5 列表带状态**：`GET /api/reflection/reports` 的每条 report 对 `candidate_id` 非空者附 `decision_status`（PG 档 LEFT JOIN candidates、内存档查 candidates ring）；候选已被 ring 裁掉则为 null（照实，不报错）。`ReflectionReport` 模型增 `decision_status: str | None = None`，旧形状纯超集。

- **E-6 前端节点通道＝App state 扩一对**：`editorNodeId` state 与 `editorGraphId` 同置；`onOpenEditor(graphId, nodeId?)` 扩可选参；`Editor` 增 `initialNodeId` prop，在 `initialGraphId` 的 `loadGraph` 完成后，若节点存在则 `selectNode(nodeId)`＋`setCenter`（照 ProblemsPanel 计算，measured 缺省 180×80、zoom 1.1、duration 300），节点不存在则只打开图不报错。`gotoTargetFor(scope, graphId, nodeId?)` 的 editor 目标形态增可选 `nodeId`。

- **E-7 U1108 机检演进（不废除、改口径）**：docs/92 的「页内零写调用」升级为「**写调用面白名单仅 `putReflectionDecision`**」。`lib/reflection.ts` 导出 `API_WHITELIST`（原四只读＋`putReflectionDecision`），机检断言：① lib 从 apiClient 的 import 面 ⊆ 白名单；② Reflection.tsx 不直接 import apiClient、无 POST/PUT/DELETE method 字面（写只经 lib 的 `markDecision`）；③ `changeColumns` 含 `key: 'actions'` 列且 actions 渲染「去修改」（钉死 §0.7 缺陷不复发）。

## 3. 契约形状

### 3.1 存储（迁移 041 `reflection_persistence.sql`）

```sql
-- 反思收尾报告（每租户 seq 倒序 ring；报告无业务 id，seq 走 storage_id_seq 仅用于排序，不进投影）
CREATE TABLE IF NOT EXISTS reflection_reports (
    tenant_id    TEXT NOT NULL,
    seq          BIGINT NOT NULL,
    candidate_id TEXT,
    graph_id     TEXT NOT NULL,
    base_version INTEGER NOT NULL,
    status       TEXT NOT NULL,
    reasons      JSONB NOT NULL DEFAULT '[]',
    generated_at TEXT NOT NULL,
    PRIMARY KEY (tenant_id, seq)
);
CREATE INDEX IF NOT EXISTS idx_reflection_reports_tenant_seq
    ON reflection_reports (tenant_id, seq DESC);

-- 反思候选（id＝refl-N 走 storage_id_seq；决策状态随候选存）
CREATE TABLE IF NOT EXISTS reflection_candidates (
    tenant_id       TEXT NOT NULL,
    id              TEXT NOT NULL,
    seq             BIGINT NOT NULL,
    graph_id        TEXT NOT NULL,
    base_version    INTEGER NOT NULL,
    changes         JSONB NOT NULL DEFAULT '[]',
    prompt_suggestions JSONB NOT NULL DEFAULT '[]',
    evidence_digest TEXT NOT NULL DEFAULT '',
    generated_at    TEXT NOT NULL,
    decision_status TEXT,                       -- null=pending；adopted|dismissed
    decided_at      TEXT,
    PRIMARY KEY (tenant_id, id)
);
CREATE INDEX IF NOT EXISTS idx_reflection_candidates_tenant_seq
    ON reflection_candidates (tenant_id, seq DESC);
```

两表均 `CREATE … IF NOT EXISTS` 幂等；首行为注释（migration convention 守护门要求）；不改 002。

### 3.2 模型增量（`reflection/candidate.py`）

```text
Change:
  + node_id: str | None = None            # 序列化字段 node_id；旧数据缺省 null
ReflectionCandidate:
  + decision_status: Literal["adopted","dismissed"] | None = None
  + decided_at: str | None = None
ReflectionReport:
  + decision_status: Literal["adopted","dismissed"] | None = None   # 列表投影用
ReflectionStore:
  + record_decision(candidate_id, status, decided_at) -> bool       # 不存在 False
PgReflectionStore（新模块，方法一比一）:
  next_candidate_id / add_candidate / add_report / list_reports /
```

`get_candidate` 投影含 `node_id`（changes 内）与 `decision_status/decided_at`；`list_reports` 投影含 `decision_status`。`from/to` 别名语义不变。
