### 2.1a 完整镜像构建修复

- 根因：`Dockerfile` 虽然设置了 `npm_config_registry=/COREPACK_NPM_REGISTRY`，但 pnpm 12 的包下载仍落到 `registry.npmjs.org`；构建日志实测约 8–12 KiB/s，`#17 pnpm install` 长期卡住。
- 修复：
  - 新增 `frontend/.npmrc`：`registry=https://registry.npmmirror.com`。
  - `Dockerfile` 增加 `NPM_CONFIG_REGISTRY`，并在安装层显式 `pnpm config set registry https://registry.npmmirror.com --global` 后再 `pnpm install --frozen-lockfile`。
- 结果：完整构建 `atlas-demo:full-20261125` 成功（id `1bac77272753`，1.08GB），pnpm 安装层 **48.5s** 完成；构建日志中 `registry.npmjs.org` 命中 **0** 次。
- 镜像内 `/app/frontend/dist` 为本次构建产物（2.2MB、`index.html` 时间戳 `2026-11-25 15:58`），不再是旧镜像前端 dist。
- 边界：镜像构建自当前工作区（HEAD `7e8cc0e` + 本轮 15 处改动），不是纯 HEAD 产物；但前后端均从源码重建，结构上不再有 overlay 的旧前端问题。
- 清理：旧 overlay 镜像 `atlas-demo:local-20261125`（id `2198054f26a5`）已删除，不再作为证据。

### 2.2 空卷首启崩溃修复

### 2.5 P1：A2A 任务台账 PG 化

- 新增 `src/atlas/a2a/ledger.py`：`PgA2ALedger`，表 `a2a_tasks`（迁移 061），存任务快照、`state`、`expires_at`、幂等键与指纹。

- `tasks/get` / `tasks/cancel` 先读进程内，未命中回读 PG；幂等重放先查进程内幂等表，未命中查 PG。

## 4. 本轮踩到并修掉的问题

1. 完整镜像构建卡在 `pnpm install`（npmjs 约 8–12 KiB/s）。先后用 overlay 镜像快速迭代，最终通过 `frontend/.npmrc` + `NPM_CONFIG_REGISTRY` + `pnpm config set registry` 修复；完整镜像 `atlas-demo:full-20261125` 构建成功并重跑全链。
2. 空卷首启 `iam_users` 不存在崩溃。修复见 §2.2。
3. prod preflight 拒绝 `http://localhost`。本地改用宿主机 LAN `192.168.1.104`；未用 `host.docker.internal`（OrbStack 解析到 `0.250.250.254`，命中保留段）。
4. 第 10 段同步 `/run` 在人工审批时阻塞超过 30s httpx 超时。改为后台线程跑 `/run`、主线程轮询审批并批准。
5. 审批 403：graph `approver="ops"` 与登录用户不匹配；改为 `user:admin-a` 后通过。
