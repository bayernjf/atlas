## 1. 基线实测（为什么这不算"已经做了"）

〔码〕逐条对当前 HEAD 实核，不是引旧文档：

1. **`src/atlas/engine/` 是 W1 历史骨架，不是运行路径**：`nodes.py` 五个节点全是确定性占位（产出 `observation@N`、`orient@N: progress acknowledged` 这类字符串，`decide_node` 只比 `step >= max_steps`），`loop.py:run_loop` 的 docstring 自陈"**全仓零调用方**"，且 `nodes.py:70`/`loop.py:6` 两处写明「打包 ZH（docs/88 §3 P-2(a)）冻结：只标注、不删除、不实现」。引用方只有 `tests/test_engine_loop.py`、`tests/test_reflection.py`、`scripts/benchmark.py`。
   ⇒ **"复活 engine" 这条路是错的**：它的 decide/act 没有真实语义（图执行才是 act），把它接进运行期等于让占位逻辑接管产品。
2. **真实运行是 `graph/loader.py:run_graph`，一次触发一次执行**：四个运行入口（同步 `/run`、流式 `/run/stream`、后台 worker、续跑 `_resume_run`）各自 `uuid.uuid4().hex` 生成 run_id，终态写 `run_store.finish` ＋ `monitoring.record_run`。
3. **圈级成本已有数据源**：打包 AU（[docs/129](129-LLM用量与成本计量-D70-打包AU-v1批契约设计.md)）落地后，`llm_usage` 每行带 `run_id` ⇒ **按 run_id 求和即得该圈的 token 消耗**。这是 C-P1 预算闸门能落地的前提（D70 是本批硬前置，不是巧合）。
4. **圈层要碰的三个挂起出口都已存在**：审批（`human_approval`）、事件等待（`wait` event）、到点等待都经 `frame_sink` 写 `interruptions` 帧，启动时 `recover_pending` 扫描恢复。**打包 R 的 D44 教训**：若圈层自己也写帧，恢复扫描器会把圈级记录误当审批续跑、产生第二个 approval token。
5. **`runs` 表（迁移 002）**列：`id/tenant_id/graph_id/status/started_at/suspended_at/finished_at/error/kind/node_id/deadline_at/resume_token/outputs/trace`，索引 `(tenant_id)`。docs/127 为本批预留 **迁移 050「runs 两列」**。
6. **单副本硬约束（docs/62）**：入口脚本 `--workers 1` fail-closed、`compose replicas: 1`、at-most-once 认领三道闸。圈状态放**进程内**不违反该约束，但**不得**以此为由解锁多副本。
7. **图级顶层配置已有纯超集先例**：`GraphDSL.globalErrorHandler` / `GraphDSL.selfHealing`（打包 AL，[docs/123](123-D63全局异常自愈状态机-打包AL-v1批契约设计.md)）——`None` ＝整体不启用，启用才校验。圈配置按同形挂 `GraphDSL.loop`。

## 2. 决策（八条，落码不得偏离；改任何一条先改本文）

- **C-D1 圈层落点＝新增 `cycles/` 服务层（supervisor），`engine/` 一行不改**。一圈＝**一次真实 `run_graph`**（不是再套一层 StateGraph）：这样每圈都继承既有语义——审批/事件等待/子图/断点/录制/监控/回放/影子，一样不少。`engine/` 的冻结（docs/88 §3 P-2(a)）继续有效，`run_loop` 仍零调用方。
- **C-D2 启用面＝图级 `loop` 顶层配置，缺省 `None` ＝ 不启用**（纯超集，现状逐字不变；编辑器图设置面板按打包 AL 的 `globalErrorHandler` 形态接入）。**不发版即改变任何现有图的行为**。
- **C-D3（C-P1 拍板）预算三闸门全设，缺省各自封顶**：`maxIterations` 1–50（缺省 10）、`maxWallClockSeconds` 30–86400（缺省 1800）、`maxTokens` 正整数（缺省 200000）。任一触顶 ⇒ 本圈跑完即终止，`cycle_state="budget_exhausted"` ＋ 记明是哪一道。**token 读 AU 的账**（按本圈 run_id 求和；无用量记录按 0 计，不报错）。
- **C-D4（C-P2 拍板，修正我先前的口头建议）终止判定＝规则优先**：运营在 `completeWhen` 写一条表达式（对**本圈 outputs＋globals** 求值，复用既有 `conditions` 引擎，零新语法）；`judgeMode` 默认 `"rule"`。`"llm"` 为**可选二段**，须显式开启且必须给 `judgePrompt`，调用经 `llm/structured.py` 既有结构化客户端，**成本进 AU 的账**。**理由**：每圈问模型既烧钱又让"为什么还没停"不可复现——终止判定必须能回放。
- **C-D5（C-P3 拍板）圈内允许人工审批挂起，但圈层不等待**：圈内出现 suspended（审批/事件等待/到点等待）⇒ 圈层**立即退出**并把控制权交还既有帧机制（节点级 `interruptions` 帧照旧写——那是**节点帧**，与 C-D6 的"圈帧"是两件事）；`runs.cycle_state="suspended"`，续跑完成后由 `_resume_run` 出口询问 supervisor 是否开下一圈。**理由**：圈层在进程内等一个要人来点的审批＝把自己的线程挂死。
- **C-D6（C-P4 拍板）不写"圈帧"**：圈状态只落 `runs` 两列 ＋ 进程内 supervisor 状态；`interruptions` 表**只留节点级帧**。理由沿用打包 R 的 D44（恢复扫描器会把圈级记录误当审批续跑、产生第二个 token）。
- **C-D7 carry 语义**：下一圈的 `inputs` ＝ 本圈 `inputs` ＋ `carry` 声明的映射（`carry: {"order_id": "{{ai_decision-1.decision.action}}"}`，值走既有插值通道）。**缺省无 carry**＝每圈从同一 payload 起跑（可复现）。carry 值同时进 `variables.global` 与 trigger payload——与现状 `inputs` 的双角色语义一致（`initial_state`）。
- **C-D8 停止与观测**：停**一圈**＝既有 `POST /api/runs/{id}/cancel`；停**整条圈会话**＝新增 `POST /api/runs/{id}/cycle/stop`（置 supervisor 的 stopped 集合，进程内、单副本语义，不解锁多副本）；观测＝新增 `GET /api/runs/{id}/cycle`（read）返圈会话投影（圈序号/累计 token/累计墙钟/终止原因/各圈 runId/状态）。

## 3. 契约形状

### 3.1 `GraphDSL.loop`（顶层，纯超集）

```
loop: {
  enabled?: true,                    # 缺省 true（配了 loop 就启用；顶层为 None 才是关闭）
  maxIterations?: int,               # 1-50，缺省 10
  maxWallClockSeconds?: int,         # 30-86400，缺省 1800
  maxTokens?: int,                   # 正整数，缺省 200000
  completeWhen?: str,                # 表达式，对本圈 outputs+globals 求值；缺省 ""＝永不判定达成（只靠预算/停止）
  judgeMode?: "rule" | "llm",        # 缺省 "rule"
  judgePrompt?: str,                 # judgeMode="llm" 时必填
  carry?: { <key>: "{{路径}}" },      # 缺省 {}＝无 carry
  intervalSeconds?: int              # 1-3600，缺省 0＝圈间不休眠；>0 时圈与圈之间 sleep（本进程内）
} | None
```
编译期校验（`dsl.py`，与打包 AL 同族）：类型/区间/`judgeMode="llm"` 缺 `judgePrompt` 报错；**`completeWhen` 表达式在编译期过一次语法解析**（引用了不存在的节点输出 ⇒ 422，沿用 `validate_graph_report` 的既有形状）。

### 3.2 `cycles/`（新包，纯新增）

- `state.py`：`CycleSession`（`group_id`／`tenant_id`／`graph_id`／`seq`／`runs: [run_id]`／`tokens_spent`／`started_monotonic`／`state`（`running|suspended|completed|budget_exhausted|stopped|failed`）／`stop_reason`）＋进程内 `CycleRegistry`（按 `group_id` 持有，**有界 ring**（200 条会话，超出淘汰最旧）；单副本语义，不落库）。
- `judge.py`：`evaluate_complete_when(expr, outputs, variables) -> bool`（纯函数，复用 `graph/conditions.py` 引擎；异常 ⇒ fail-safe 返 `False` 并记 warning，**不炸运行**）＋ `llm_judge(...)`（可选二段，走 `llm/structured.py`，无模型 ⇒ `LLMStructuredUnavailable` ⇒ 折 `False` 并 warning——**不静默当达成**）。
- `supervisor.py`：`start_cycle(...)`（四入口在 run 触发时调用：`loop` 为 `None` ⇒ **立即返回 None，零行为变化**）／`advance(...)`（一圈终态后：判 suspended 让位 → 判 stop → 判 completeWhen/judge → 判三闸门 → 否则开下一圈）／`stop_cycle(group_id)`。**每次开新圈都生成新的 `run_id`**，与既有四入口的 run 生命周期逐字同构（begin/finish/record_run/frame_sink 照旧）。

### 3.3 迁移 050（`runs` 两列，与 docs/127 预留一致）

```
ALTER TABLE runs ADD COLUMN cycle_seq INTEGER NOT NULL DEFAULT 0;      -- 0＝非圈运行（现状）
ALTER TABLE runs ADD COLUMN cycle_group_id TEXT NOT NULL DEFAULT '';    -- ''＝非圈运行
CREATE INDEX IF NOT EXISTS idx_runs_cycle_group ON runs (tenant_id, cycle_group_id);
```
两档 store（`RunStore`／`PgRunStore`）`begin(...)` 加可选 `cycle_seq=0`／`cycle_group_id=""` 形参（**缺省逐字等价现状**）；`GET /api/runs` 列表投影补两字段（read 面加列，零破坏）。

### 3.4 REST（两个新端点，零新错误码）

| 端点 | 鉴权 | 说明 |
|---|---|---|
| `GET /api/runs/{run_id}/cycle` | read | 圈会话投影：`{groupId, graphId, seq, state, stopReason, tokensSpent, elapsedSeconds, maxIterations, maxTokens, maxWallClockSeconds, runs:[{runId, seq, status, totalTokens}]}`；该 run 不属圈 ⇒ **404 `CYCLE_NOT_FOUND`**（查询参数校验走既有纯文本 422 风格，不新增码） |
| `POST /api/runs/{run_id}/cycle/stop` | operate | 停整条圈会话；已终态 ⇒ 200 幂等（`state` 照实回）；未知圈 ⇒ 404 |

### 3.5 前端

- 编辑器图设置面板新增「自主循环」区（打包 AL `globalErrorHandler` 面板同形：启用开关＋三道预算＋`completeWhen`＋judgeMode/judgePrompt＋carry 映射），序列化 roundtrip 走既有 `serializer` 通道。
- 运行记录（Monitoring 页）行内加圈徽标「第 N 圈」＋点开看圈会话投影（复用现有 Drawer/Table 形态）。
- 新 `i18n` 键入既有 `editor`/`monitoring` namespace（两档 parity 守护已在册）。

## 4. 验收（用例号预留 **U1427–U1442**，docs/13 立"打包 BN"小节）

**正向（10 条）**

- **U1427** `loop` 缺省／`None` ⇒ 四入口行为与现状**逐字相同**（无 `cycle_seq`、无第二圈）。
- **U1428** 三道闸门各自触顶即停：迭代数、墙钟、token 各一条（token 用 AU 的账：预置两条用量行后跑圈）。
- **U1429** `completeWhen` 为真 ⇒ 终止且 `state="completed"`、`stopReason="complete_when"`。
- **U1430** `judgeMode="llm"` 显式开启 ⇒ 走结构化客户端、成本进 AU 的账（用量行 `caller="content_generation"` 或约定 caller，见 §3.2 落码定稿）；无模型 ⇒ `LLMStructuredUnavailable` 折 `False` 并 warning（**不静默当达成**）。
- **U1431** carry 注入：第二圈的 `inputs` 含第一圈产出，且 `variables.global` 与 trigger payload 两个角色都在（各一条断言）。
- **U1432** 圈内审批挂起 ⇒ 圈层退出、`cycle_state="suspended"`、节点帧照旧写；`/api/runs/{id}/cycle` 可见 suspended；**续跑完成后开下一圈**（真机端到端覆盖，单测只到"退出且状态对"）。
- **U1433** 取消语义分层：取消**一圈**（既有 cancel）不阻止下一圈；停**整条圈**（新端点）后再开圈请求被拒。
- **U1434** 图内 `loop` 非法配置 ⇒ 编译期 422（区间/`judgePrompt` 缺失/`completeWhen` 引用不存在输出）。
- **U1435** `GET /api/runs/{id}/cycle` 对非圈 run ⇒ 404；匿名 ⇒ 401。
- **U1436** 前端：图设置面板 roundtrip（存→导出 JSON 含 loop→回读一致）＋运行记录圈徽标（vitest SSR）。

**反向门（四条，各自植缺陷实跑转红）**

- **U1437** 摘掉**任一**预算闸门（迭代数）⇒ U1428 的迭代数那条必须红（防"只有墙钟在拦"）。
- **U1438** 让 `completeWhen` 恒真（表达式解析器桩）⇒ 圈必须**只跑一圈**（证明"达成即停"不是恒假）。
- **U1439** carry 写错键路径 ⇒ 第二圈 `inputs` **不含**该键（证明 carry 不是无脑整包透传）。
- **U1440** 摘掉 supervisor 的 stopped 集合检查 ⇒ U1433 的"停整条圈"必须红（防"停了还在跑"）。

**收口门**

- **U1441** 四道门零回归（后端默认＋PG 集成＋前端 vitest/build＋oxlint）。
- **U1442** **一次真机端到端**：真模型（仓库 `.env` 凭据）跑一条启用 `loop` 的图，`completeWhen` 由**第一圈的模型产出**驱动 ⇒ 实测跑通 ≥2 圈、圈序号与 token 累加可见、`GET /api/runs/{id}/cycle` 投影与 `llm_usage` 汇总**对账相等**；探针 `scripts/dev/cycle_probe.py`。无真凭据时探针跑规则判定腿并记 BLOCKED 点名缺什么（不许拿单测代替）。
