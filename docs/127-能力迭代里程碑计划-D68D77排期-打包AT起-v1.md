## 1. 里程碑 A｜教一遍就能跑（D68＋D72，打包 AT）

**闭环节判据（Done-when，逐条可验）**：一次真操作（浏览器或 HTTP 链）→ 录制 → `promote` 出 Graph 草稿 → 草稿**编译通过** → 发布 → 跑到终态 → 出一份**双语指引**且运营读得懂下一步。

原子序（七步，各自独立提交）：
1. `docs(package)`：契约 docs/128 ＋ 08 立项块 ＋ 13 预留 U 号 ＋ 14 D68/D72 两行注记 ＋ handoff。
2. `feat(recording)`：`recording/to_graph.py` 反导器——动作序列→节点、被参数化字段→`{{}}` 占位、比对分支→condition（口径见 A-P1）。
3. `feat(api)`：`POST /api/recordings/{case_id}/promote`——返回草稿＋`compile` 校验结果；**不写库、不发布**。
4. `feat(frontend)`：编辑器「从用例生成图」入口＋i18n 双档（进 `PARITY_PAIRS` 守护）。
5. `feat(api·frontend)`：`GET /api/recordings/{case_id}/guide`（步骤树→双语产物）＋指引预览（形态见 A-P2）。
6. `test`：正反向门（反导产不出合法图时必须显式失败并点名缺哪一段；指引必须含分支条件文案，不许只列步骤）。
7. `docs`：收口回填（13/14/08/handoff/CHANGELOG）＋一次真机端到端（**照打包 Q 的教训：验产物就必须连产生它的日常路径跑一遍**）。

**待拍板**：~~A-P1 反导口径／A-P2 指引形态~~ **两项已由契约吸收（2026-10-13 立项当日）**——基线实核发现 `RecordingCase.graph` 已冻结整张图，"反导"这个前提不成立，于是 A-P1 变成 **AT-D1 基准＝快照**，替换与形态变成 **AT-D2 两阶段 promote＋AT-D3 白名单＋AT-D6 指引只读形态**（权威 [docs/128](128-机器人试教成图与操作指引-D68D72-打包AT-v1批契约设计.md) §2）。**里程碑 A 现无待拍板项，可直接进落码批。**
**不触碰**：D43／D52（真浏览器 prod 注册与逐跳 egress）——本批只出文档产物，不开浏览器出向面。
**风险点名**：`to_graph` 容易与 D66 的节点输出权威再次分叉——反导出的输出引用必须走 `graph/node_outputs.py` 单源，不在 recording 侧另写一份键表。

## 2. 里程碑 B｜算得清账（D70，打包 AU）

**Done-when**：跑一次带 LLM 的图 → `GET /api/monitoring/usage` 出真实 token；Models 页与运行报表读**同一份数**；供应商不返 usage 时落 `null` 而非 0（**落 0 就是假账**，与 docs/73 那批"静默降级报绿"同族缺陷）。

原子序：契约 docs/129 → 迁移 **049** `llm_usage`（memory＋pg 两档 store）→ 四消费点回写（`llm/decision.py`、`condition_classifier.py`、`structured.py`×3 节点、`nl_generate.py`，顺带 `reflection/adapter.py`）→ 聚合端点（按模型／租户／图／日）→ 前端两处接数 → 测试（含"不返 usage 的桩"与"跨租户不串数"反向门）→ 收口。
**待拍板**：**B-P1** 落 PG 新表还是先进程内 → 推荐**落表**（成本账跨重启不可丢，C 的预算闸门要读历史；进程内版本会让 C 被迫重做一遍）。
**边界**：不改模型解析优先级（节点 > BYOK > 内置 > env，docs/93 既定）；不引入任何计费/预算新依赖。

## 3. 里程碑 C｜真的在循环（D69，打包 BN）

**Done-when**：一张图被 loop 连续驱动 N 圈，每圈＝一次 Graph 执行＋一次 reflect；**四闸门任一命中即停**（预算／最大迭代／终止条件／手动停止）；重启后**不自走**；运行记录看得出圈序与圈间差异。

原子序：契约 docs/130 → `engine/loop.py` 由 `/run` 外层驱动（**不替换 loader**，`api/main.py` 不新增第二套执行路径）→ 四闸门＋停止端点 → runs 表加 `loopId`/`iteration`（迁移 050）→ 前端 Loop 页（延续 D40 运行时操作台口径，别再做成只读投影）→ 测试＋一次真机跑（**含"终止条件真的停"的判别对照**：不装对照就等于没测）。
**待拍板（四个，绕不过，落码前必须全部有答案）**：
- **C-P1 预算单位**＝迭代数／墙钟时长／token 成本 → 推荐**三者都设上限**（只设迭代数会烧钱，只设成本会失控圈数）。
- **C-P2 reflect 判定者**＝LLM／表达式 → 推荐**表达式起步**（LLM 判定进回放就不可重现，与打包 V 的回放契约正面冲突），LLM 作可选项并显式标注非确定。
- **C-P3 loop 内允许 `human_approval` 挂起吗** → 推荐**允许**，但圈级超时即停整个 loop（挂着的 loop 等于一个没人看的黑洞）。
- **C-P4 是否写 interruption 帧** → 推荐**不写**，沿用打包 R 的 D44 口径。理由照实：写帧会让 `recover_pending` 把圈级挂起当审批续跑，产生第二个 token——当年打包 R 就是靠"不写帧"躲开这一类。
**风险点名**：C 是本计划唯一改**运行期行为**的批次，且与单副本硬约束（docs/62）相互作用；落码前先在 docs/130 写清"重启不自走"的判据与测试，否则会出现"看起来在循环、其实每次重启都重放"的假绿。
