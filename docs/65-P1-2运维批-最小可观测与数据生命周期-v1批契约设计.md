## 2. K-A retention 任务与过期会话清扫

**表与默认保留期**（env 覆盖，分表 env 名 `ATLAS_RETENTION_<TABLE>_DAYS`，全局缺省 `ATLAS_RETENTION_DAYS`=90）：

| 表 | 时间列（实测 DDL） | 默认保留期 | 淘汰条件 |
|---|---|---|---|
| `audit_events` | `at` TEXT（UTC ISO） | 90 天 | `at < cutoff` |
| `runs` | `finished_at` TEXT | 90 天 | **仅终止态**：`finished_at IS NOT NULL AND finished_at < cutoff`；挂起态（`suspended_at IS NOT NULL`）**永不淘汰** |
| `webhook_deliveries` | `created_at` TEXT | 30 天 | `created_at < cutoff` |
| `interruptions` | `created_at` TEXT、`resumed_at` TIMESTAMPTZ | 30 天 | **仅已认领**：`resumed_at IS NOT NULL AND created_at < cutoff`；未认领挂起帧**永不淘汰**（删了运行永远挂起） |
| `graph_versions` | `created_at` TEXT | 365 天 | `created_at < cutoff` |
| `openapi_imports` | `created_at` TIMESTAMPTZ、`deleted_at` TEXT | 365 天 | 软删行（`deleted_at IS NOT NULL`）超期物理删；未软删行超期物理删 |
| `message_deliveries` | `created_at`（025 建表） | 30 天 | `created_at < cutoff` |
| `iam_sessions` | `expires_at`（011 加列） | —— | `expires_at IS NOT NULL AND expires_at <= now` 全量清扫（NULL 视为不过期，与 011 语义一致） |

**形状**：
- `storage/pg.py` 新增 `prune_expired(cutoffs: dict[str, str | None], *, session_sweep: bool = True) -> dict[str, int]`：单函数多表 `DELETE`（每表语句级 tenant 无关——retention 是全局运维动作，不受租户分区约束；docs/24 §1.2②的"语句级过滤"针对业务读写，淘汰无租户语义），返回 `{表名: 删除行数}`。入参 cutoffs 为 UTC ISO 字符串（`run_retention.py` 组装），`session_sweep` 控制会话清扫开关。内存档无操作（返回全 0）。
- 新 `scripts/ops/run_retention.py` CLI：读 env 组装 cutoffs（每表 `ATLAS_RETENTION_<TABLE>_DAYS`，缺省回退全局 `ATLAS_RETENTION_DAYS`）→ 调 `prune_expired` → 打印删除行数；`--dry-run` 只打印不执行；非 PG 档（内存）打印"no-op"退出 0。与 `apply_migrations.py` 同款薄 CLI 风格。
- 接线：`api/main.py` lifespan 启动时调 `run_retention_once()`（`security/bootstrap.py` 或新薄函数，非 PG 档 no-op、异常只 warning 不阻断启动——运维清扫绝不挡服务起；recover_pending 同款语义）。
- 测试：`prune_expired` 纯测（内存档 no-op；PG integration：audit 超期删/未超期留、runs 终止态删/挂起态留、interruptions 已认领删/未认领留、openapi 软删行删、会话清扫删过期留未过期；CLI dry-run 1 测）。

## 3. K-B 备份轮转与异地拷贝

- `backup.sh`（POSIX sh）改造：
  - 轮转：`KEEP=${ATLAS_BACKUP_KEEP:-7}`——备份完成后 `ls backups/atlas-*.dump | sort | head -n -KEEP | xargs rm -f`（按 UTC 时间戳文件名排序，保留最新 KEEP 份）。
  - 异地：`REMOTE_DIR=${ATLAS_BACKUP_REMOTE_DIR:-}`——非空时 `mkdir -p "$REMOTE_DIR" && cp -a <最新 dump> "$REMOTE_DIR/"`。
  - `--dry-run`：只打印"将保留/将删除/将拷贝"清单不执行（供冒烟与 CI 静态验证）。
- `restore.sh` 零改动；docs/30 §5.1 备份段同步（env 两枚 + dry-run 用法）。
- 测试：sh 脚本无 pytest 先例（同 docker-entrypoint.sh 口径），契约验收＝冒烟实测 dry-run 输出与真实轮转一次。

## 4. K-C `/metrics` 收口

- `api/main.py:524 prometheus_metrics()`：
  - 非 prod（`read_env_profile() != "prod"`）：**行为不变**（公开，demo/本地拉取照常）。
  - prod：`ATLAS_METRICS_TOKEN` 未配置 → **404**（fail-closed，与 J-1a 同语义，避免误配置即裸奔）；配置后必须 `Authorization: Bearer <token>`，缺失/不匹配 → **401**；放行后照常吐全量（含按租户聚合计数——已鉴权即闭合 S8 的"无鉴权泄露"）。
  - 端点实现走纯函数分支（`_metrics_auth_gate(request, token_env) -> Response | None`），便于单测；不引入新依赖（恒定时间比较 `hmac.compare_digest`）。
- 测试：非 prod 公开 200（既有 `test_metrics_is_public_and_prometheus_format` 保持）；prod 无 token 404；prod 有 token 无凭据 401；prod 正确 Bearer 200（Prometheus 格式断言复用）。

## 5. K-D 日志 formatter + request-id

- 新 `src/atlas/observability/logging.py`（零第三方依赖）：
  - `configure_logging()`：`logging.basicConfig(level=env ATLAS_LOG_LEVEL 默认 INFO)`，formatter＝`%(asctime)s %(levelname)s [%(name)s] %(request_id)s%(message)s`（asctime 用 UTC ISO——`logging.Formatter.converter = time.gmtime` 或自定义）；`RequestIdFilter` 从 contextvar 取 id，无则空串。幂等（重复调用不叠 handler）。
  - `request_id_var: ContextVar[str]` + `get_request_id()`/`set_request_id()`（try/finally 复位）。
  - `install_request_id_middleware(app)`：`@app.middleware("http")`——生成 `uuid4().hex[:12]`，`set_request_id`，响应头 `X-Request-Id`（成功与异常路径都带）。
- 接线：`api/main.py` 模块加载处（`assert_prod_secrets()` 同位置）调 `configure_logging()`；middleware 注册。
- 测试：请求响应带 `X-Request-Id` 且两请求互异；caplog 断言日志 record 含 `request_id=` 字段；configure_logging 幂等。

- **K-D middleware**：仅加响应头与日志字段，业务路径零改动；`configure_logging` 幂等防重复注册。
- **K-B 轮转**：`rm` 只作用于 `backups/atlas-*.dump` 模式，不碰用户其他文件；`--dry-run` 先验。
