## 1. 决策（七条，改任何一条先改本文）

- **D-1 运营 `promptTemplate` 插值后**就是**发给模型的用户消息**（`role:"user"` 的 content），不再回显式。为空串时才退回退款专用兜底文案（保住"直接调用 `decide_refund` 的既有调用方"零变化）。
- **D-2 结构化输出由系统消息强制**（`role:"system"` ＋ `response_format={"type":"json_object"}`），等价 docs/06 §6.2 的 `with_structured_output(DecisionSchema)`：运营 prompt 只管**业务指令**，输出形状由这一层管，避免模型回散文。**不给运营第二份 schema**（那会把契约变成两份）。
- **D-3 节点 `model` 非空时覆盖环境默认模型**（`LITELLM_MODEL`），仅本次调用生效；`source` 记为 `llm:{实际用的 model}`，使"这次到底谁答的"可从输出读出。
- **D-4 置信度闸门＝真挂起**（docs/06 §6.2 第 4 步）：`confidence < confidenceThreshold` ⇒ **复用既有 `ApprovalBroker`** 登记 pending＋发一个带 `approval` 载荷的 node_start＋阻塞等待，而非仅把 action 改成 `request_human_approval`。
  - 阈值**缺省 0.6**（对齐 docs/06 §6.2 与前端 default）；配置为非法值 ⇒ 回退缺省（不因脏配置中断运行）；`confidence` 缺失/非法 ⇒ 按 **0.0**（低置信 ⇒ fail-safe 挂起）。边界为**严格小于**：`confidence == threshold` 不挂起。
  - 人审映射（fail-safe，与 `human_approval` 的 `onTimeout=reject` 同口径）：**approved ⇒ `approve_refund`**；**rejected / 超时 ⇒ `request_human_approval`**。
  - broker 缺失时**不敢静默放行**：降级为 `request_human_approval` ＋ `resolvedBy:"no_broker"`，且**不阻塞**。
- **D-5 本挂起不写 interruption 帧（纯进程内）**：`api/main.py:215` 的续跑扫描器把 `kind=="approval"` 的帧一律按 human_approval 恢复，而 ai_decision 执行分支无 resume 处理 ⇒ 写帧会让重启重跑决策并产生**第二个 token**（悬挂 token＋误恢复）。**跨重启恢复随 D20 一并缓做**，本批明确放弃。
- **D-6 两条边界写清**：① **记忆检索**（06 §6.2 第 1 步）v1 由图接线承担——`memory/recall` 工具＋`{{path}}` 引用把记忆喂进 prompt，**节点内置隐式检索不在本批**；② **规则兜底（未配 `LITELLM_MODEL`）不读 `prompt`/`model`**——它没有语义理解能力，只按退款规则给确定性结论（离线 Demo 的决策壳）。
- **D-7 不改的东西**：不改 `refund_decision` 既有四字段名（`action`/`reason`/`confidence`/`source`，本批只做**超集扩展**）；不动 `human_approval` 节点；不新增迁移／端点／错误码／依赖；不解除任何缓做与单副本三道闸。

## 6. 残余风险（写清楚，别当成"R1 收干净了"）

1. **真 LLM 端到端未验**：本批只证到"接线成立"（prompt 就是 user message、model 生效、闸门双向）。"模型真按新 prompt 改变判定"要 1.1 的真 key，**不在本批**。
2. **低置信挂起无跨重启恢复**：进程内登记（D-5 有意不写帧），重启即失，且崩溃后该审批 token 无人能续——**这是本批有意引入的收紧**，与 D36 同族，已登记 docs/14。
3. **规则兜底不消费 prompt**：未配 `LITELLM_MODEL` 时，改 prompt **不改变输出**（D-6 ②）。运营在离线 Demo 档改 prompt 看不到效果，容易误判"功能没做"——这是 demo 档的已知语义，不是缺陷。
4. **置信度是模型自报值**：未校准；阈值 0.6 取自 docs/06 §6.2 与前端 default，**不是实测调优值**。
5. **只接了 `ai_decision` 一个节点**：06 §6.2 的"记忆检索"在图层面可达，但**节点内置隐式注入**不在本批；其余节点（condition/loop 等）的配置-运行一致性不在本批复核范围。
