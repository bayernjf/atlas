## 1. 决策（五条；改任何一条先改本文）

- **D-1 更新：`PUT /api/templates/{template_id}`（operate 权限），整体替换语义**：
  - 请求体与 POST 完全同形（`UserTemplateCreateRequest`：name 1-60 trim 非空、
    description 0-200、tags 每项 1-20 至多 8、graph 必填）；校验/422 文案逐字复用 POST，
    不另写一套；服务端同样 `parse_graph(graph)` 后原样存入。
  - **id、seq、created_at 全部不变**；更新不改排序位置（list 仍按 seq 倒序）。
  - 200 返回完整用户模板（与 POST 201 同投影：source="user"/deletable=true/createdAt 原值）。
- **D-2 存在性口径与 DELETE 一致**：内置 id 调 PUT → 404 `模板不存在：{id}`
  （不暴露"内置不可改"）；用户 id 不存在（含已删）→ 同 404。不做 405。
- **D-3 两档 store 同形加 `update`**：
  `update(template_id, *, name, description, tags, graph) -> UserTemplate | None`
  （不存在返 None）；`id/created_at` 沿用旧行，仅替换四个字段。PG 档单 UPDATE
  （WHERE tenant_id+id）、rowcount=0 返 None；不加 updated_at 列（没人消费，
  需要时随 D25 版本批再加）。
- **D-4 不做 PATCH**：v1 只有整体替换；部分字段更新、并发 CAS（If-Match/版本号）随
  D25 版本余部缓做。
- **D-5 前端：浏览器用户行加「编辑」，复用另存 Modal 的 edit 模式**：打开时预填
  name/description（tags 仍无控件、更新时沿用**旧 tags**——表单不暴露 tags，
  若把 tags 冲空会丢用户数据；故前端 PUT 体不带 tags，后端改为**字段缺省即保留**不可行
  （与整体替换矛盾）。**落点**：端点从旧模板读 tags 透传，即"请求体 tags 可缺省、
  缺省＝保留旧值；显式传 [] 才清空"——此条是对 D-1 整体替换的唯一例外，写明防歧义。
