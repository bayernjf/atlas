## 0. 已拍板决策（ADR T24）

1. **缺省交付形态切到 PG**：`docker compose up` 默认起 PostgreSQL 并以 `ATLAS_STORAGE_BACKEND=pg` 运行；进程内内存档仍是测试与本地 dev 缺省后端（代码默认值不变，避免动测试）。
2. **迁移方式沿用手写有序幂等 SQL + 极薄 stdlib 运行器**：不引 Alembic（守 docs/10 锁定清单外不扩依赖）。现有 001–008 全部 `IF NOT EXISTS` 幂等；新增 `schema_migrations` 登记表（迁移 009）与 `scripts/ops/apply_migrations.py`（psycopg 已在依赖内），按文件名顺序应用未执行迁移、每文件一事务、成功后登记；容器 entrypoint 先跑迁移再起 uvicorn。
3. **会话 PG 档接线纳入本批**：`PgSessionStore`（[pg.py:215](../src/atlas/storage/pg.py) 已存在但未接线）在 PG 档接入 `iam/deps.py` 全局 `session_store`，重启不再全登出。这是纯持久化管道、认证语义零变化；**密码哈希/JWT/账号生命周期仍归批 2**。
4. **DB 镜像固定 `pgvector/pgvector:pg16`**：迁移 001（vector 扩展）与 006（vector(256)）需要 pgvector；标签固定大版本 16。
5. **备份＝pg_dump 自定义格式 + 脚本化演练**：`scripts/ops/backup.sh`/`restore.sh`；备份/恢复作为本批验收硬点（真实演练一次），不接受只写文档不演练。本批不引入 Redis。

## 3. 迁移运行器契约

### 3.1 行为

- `scripts/ops/apply_migrations.py` 消费 `DATABASE_URL`（psycopg），逻辑：
  1. 确保 `schema_migrations(version TEXT PRIMARY KEY, applied_at TEXT)`（亦由 009 建表，双保险）；
  2. 列出 `db/migrations/*.sql` 按文件名排序，跳过已登记版本；
  3. 每个文件在单事务内执行，成功后登记 version 与 UTC 时间；失败即回滚并以非零码退出（atlas 不启动）。
- 迁移 009 内容仅为建 `schema_migrations`；运行器对 009 之前的库（已手动应用 001–008 的开发库）提供 `--mark-existing`：把已存在的 001–008 标记为已应用而不重跑（幂等 SQL 重跑也安全，二选一，落码时定并回填）。
- entrypoint：`docker/entrypoint.sh`（或 Dockerfile 内联）依次 `python -m scripts.ops.apply_migrations` 然后 `exec "$@"`；不引 bash 之外的工具（db 镜像内的 psql 不参与，atlas 运行镜像无 psql）。

### 3.2 不做

- 不做 downgrade/回滚迁移、不做 checksum 校验（v1 只按文件名单向前进）；checksum/down 随正式迁移体系需求重开。
- 不把迁移运行器接入应用进程内启动（只在容器启动入口；测试仍各自管理）。

## 5. 备份 / 恢复与演练

### 5.1 脚本

- `scripts/ops/backup.sh`：`docker compose exec -T db pg_dump -U <user> -d <db> -Fc` 输出到 `./backups/atlas-<utc-date>.dump`（backups 目录不入库或仅留 .gitkeep）。
  - **轮转（docs/65 K-B）**：`ATLAS_BACKUP_KEEP`（默认 7）——备份完成后只保留最新 N 份 `backups/atlas-*.dump`，其余删除（按 UTC 时间戳文件名排序；BSD/GNU head 兼容计数法）。
  - **异地（docs/65 K-B）**：`ATLAS_BACKUP_REMOTE_DIR`（可选）——非空时把最新 dump 拷贝到该目录（`mkdir -p` 自动建，`cp -a` 保持权限）。
  - `--dry-run`：只打印保留/删除/拷贝清单，不执行（冒烟与 CI 静态验证用）。
- `scripts/ops/restore.sh <file>`：`pg_restore --clean --if-exists -U <user> -d <db>`（在 db 容器内执行）；恢复前要求显式确认（脚本交互提示），防误覆盖。
- 不引入额外备份 sidecar/定时调度（定时备份由部署侧 cron 自建，异地只做目录级拷贝、不做加密/推送协议——docs/65 §6 非目标）。

### 5.2 演练验收（本批必须真实执行一次并留记录）

1. compose 全栈起好：建图、跑出一次 completed run、制造一次挂起审批、登录会话保持；
2. `backup.sh` 生成 dump；
3. `docker compose down`（保留卷）→ **删除命名卷** → 重新 `up`（经 001–009 全新建库）→ `restore.sh`；
4. 校验：图列表、runs（含挂起那条可继续决策）、recordings、monitoring、memories 行数与内容一致；旧 token 仍有效（不需重新登录）。
演练记录（命令与核验输出）回填本文顶部与 CHANGELOG；截图按需入 docs/assets。
