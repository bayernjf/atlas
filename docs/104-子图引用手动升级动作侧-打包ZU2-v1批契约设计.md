## 1. 问题

升级体检（`GET /api/graphs/{id}/subgraph-upgrades`，docs/28 批4⑪）只回答「本次发布将把哪些顶层 subgraph 引用钉到什么版本」——**只读**。草稿本身仍是裸 id 或旧版本引用；操作者看完体检，没有把引用**显式升级到目标版本**的动作，也无法在发布前把「升级后」的草稿存下来跑一次门禁回归确认兼容。

04 §14 的完整语义是「手动升级＋回归测试」：升级 = 把草稿里 subgraph 引用的 `config.graphId` 显式改写为 `sub_id@to_version` 并存回草稿；回归 = 升级后跑发布门禁（`run_release_gate`）确认升级后仍兼容。本批取回**升级动作**这一半（回归按钮 ReleaseModal 已有「运行门禁」）。

## 2. 形状

### 2.1 后端纯函数 `versioning/upgrades.py` 新增 `apply_subgraph_upgrades`

```python
def apply_subgraph_upgrades(
    graph_store: GraphRepository, graph_id: str, node_ids: list[str] | None = None
) -> list[dict[str, Any]] | None
```

- 取 latest 草稿（`graph_store.get(graph_id)`），不存在返 `None`（端点据此 404）。
- 计算 `subgraph_upgrade_plan(graph_store, graph_id)`；plan 为 None 同 404。
- 若 `node_ids` 为 None → 目标 = plan 全部项；否则目标 = plan 中 `node_id in node_ids` 的项。**指定但不在 plan 的 node_id**（非 subgraph 节点 / 该节点无版本变化）→ 抛 `ValueError(node_id)`（端点据此 422，中文 detail）。
- 对每个目标项：把草稿中该节点 `config["graphId"]` 改写为 `f"{sub_id}@{to_version}"`（显式钉版）。
- 用 `graph_store.update_draft(graph_id, draft)` 存回（不产新版本、不动已发布版本；与画布保存同路径）。
- 返回 `[{node_id, sub_id, from_version, to_version, first_pin}]`（即应用成功的项，from_version 为改写前的钉版/None）。

### 2.2 端点 `POST /api/graphs/{graph_id}/subgraph-upgrades`（operate）

- 权限：`require("operate")`（写草稿，与画布保存同级）。
- body：`{node_ids?: [str]}`，缺省 = 全部升级项。
- 成功：`200 {applied: [...]}`（applied 即 2.1 返回值）。
- 草稿不存在：404（中文 detail，照 GET 同端点口径）。
- 指定 node_id 不在 plan：422（中文 detail，含具体 node_id）。
- 空 plan（无升级项）：`{applied: []}`（幂等，不报错）。

### 2.3 前端 ReleaseModal 升级体检区

- 升级体检表格上方加「全部应用」按钮 + 表格行尾加「应用」操作列（仅当 upgrades.length > 0）。
- 点击 → `applySubgraphUpgrades(graphId, nodeIds?)` → 成功刷新 `loadUpgrades()`（升级后 plan 缩小，from==to 项消失）并提示；失败 inline 显示错误。
- 「应用后请重新运行门禁回归再发布」提示并入升级区 hint。
- i18n：`release.upgrade.apply` / `release.upgrade.applyAll` / `release.upgrade.applied`（zh/en 两档，进 PARITY_PAIRS）。

### 2.4 apiClient

- `applySubgraphUpgrades(graphId, nodeIds?)` → `POST` 该端点，返回 `{applied: SubgraphUpgrade[]}`。

## 3. 边界与非目标

- **不改发布语义**：升级只把引用显式钉到 `to_version`（= 子图最新发布版）；发布时 `_pin_subgraphs` 对已显式钉到最新版的引用不再变化（`versions[-1]` 同值）。未升级的裸引用/旧版本发布行为与现状完全一致。
- **不做任意版本 pin 编辑器**（docs/28 批4⑪ 明示非目标仍成立）：只允许升级到体检算出的 `to_version`，不允许手填任意版本。
- **不做子图草稿 dirty 检测**（docs/28 批4⑪ 口径不变）。
- **不递归**：只扫顶层 subgraph（与体检一致）。
- **回归测试**：复用 ReleaseModal 既有「运行门禁」（`run_release_gate`），本批不新增回归端点。
- **D21 整体不解除**：子图市场/组织共享/跨运营体远程引用/嵌套可视化编辑器触发条件不变。
